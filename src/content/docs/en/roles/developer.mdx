<Summary>
- For developers, AI is a tool that cuts down repetitive work like **understanding code, finding the cause of bugs, writing tests and docs, and review**.
- Tools that work directly with your code include Claude Code and Cursor, while a chat AI is enough for questions and design discussions.
- Code that AI produces should go in only **after you've read it, run it, and tested it**.
- Before you start, decide what you will and won't enter: secret keys, customer data, and internal code.

## Who this is for

This guide suits web, app, and server developers, people with side projects, and people who want to introduce AI tools to their team.

- You need to get up to speed on a codebase you've never seen before.
- You have a lot of repetitive testing, documentation, and review work.
- You need a standard for how far to trust the code AI gives you.

## Top 5 ways AI helps

### 1. Understand code you've never seen

Asking it to explain the file structure and what each function does shortens onboarding time. For work that involves reading an entire repository, coding tools like Claude Code and Cursor are a good fit ([Understand and fix existing code with Cursor](/en/coding/09-cursor/)).

<PromptBox>
I want to understand the structure of this repository. Explain the role of the main directories, the entry points, and the order in which data flows. Then tell me, in order, which files I should read first to modify [feature name]. Mark anything you're not sure about as a guess.
</PromptBox>

### 2. Narrow down the cause of a bug

Give it the error message and how to reproduce it, and you can get candidate causes ranked by priority. Remove secret keys and personal information before pasting.

<PromptBox>
I'm getting the error below. My environment is [language/framework/version], and the steps to reproduce are [reproduction steps]. Give me 3 possible causes in order of likelihood, and for each one, tell me how to check it, with the command or log location. Don't fix it right away; let's confirm the cause first.

[Error message and related code]
</PromptBox>

### 3. Write test code and documentation

You can quickly draft unit tests for existing functions, edge cases, a README, and comments. Also check that the generated tests **can actually fail**.

<PromptBox>
Write unit tests for the function below using [test framework]. Separate normal cases, boundary values, and invalid-input cases, and add a one-line comment for each test saying what it verifies. Don't change the implementation.

[Function code]
</PromptBox>

### 4. Assist with code review

You can get another check on bugs, error handling, and readability issues that are easy to miss in a PR's changes. Use it as a **first pass** rather than a replacement for human review.

<PromptBox>
Review the changes below. Look for problems in this order: potential bugs, missing error handling, security issues, performance issues, readability. Give each item a severity (high/medium/low) and a suggested fix. If there are no problems, say so. Don't nitpick just to have something to say.

[diff]
</PromptBox>

### 5. Automate repetitive work and build agents

Repetitive work like scheduled checks or deployment assistance can be handed off to skills, routines, and CI. The concepts are covered in [Delegate recurring tasks to agents](/en/coding/10-delegate-agents/), and how to build one yourself with the API is covered in [Build a work bot with tool use](/en/dev/01-tool-use/).

<PromptBox>
I want to automate [task name], which I repeat every week. My current manual process is [process]. Break it into steps that can be automated, and mark the approval points where a person must confirm. Also suggest how to roll back if it fails.
</PromptBox>

## What to watch out for

<Aside type="caution" title="Don't enter secret keys or customer data">
Don't put API keys, passwords, tokens, or customer personal information into prompts or pasted code. For company code, check your organization's AI usage policy first. The standards are in [Using AI while protecting personal and company information](/en/basics/05-privacy-safety/).
</Aside>

- **Verification**: AI can confidently write functions that don't exist or outdated usage. Confirm by running and testing ([how to fact-check](/en/basics/04-fact-checking/)).
- **Permissions**: For tools that run and modify code directly, keep approval units small, and have a person confirm hard-to-undo actions like deletion, deployment, and payments ([Using agents safely](/en/agents/05-agent-safety/)).
- **Licensing**: Generated code can resemble existing open-source code. Review it according to your organization's licensing policy.
- **Understand it before you merge it**: Don't merge code you don't understand. The person who has to fix it later is ultimately you.
