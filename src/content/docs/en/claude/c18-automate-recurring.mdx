<Summary>
- There are broadly **four** official ways to run recurring work automatically in Claude: (1) scheduled tasks in the Claude app, (2) Claude Code cloud **routines** (the official docs' new name is cloud scheduled tasks, as of 2026-10-26), (3) Claude Code desktop **local scheduled tasks**, and (4) **`/loop`**, which runs inside a session.
- The criteria for choosing are **where it runs, whether your computer has to be on, and whether it needs your local files**. If it has to run even when your computer is off, use the cloud (routines or app scheduled tasks); if it needs local files, use a desktop task; to check on something briefly, use `/loop`.
- Automatic runs happen **while no one is watching**. Design prompts to be self-contained, results to be reversible (drafts, branches, PRs), and the final commit to be made by a person.
- Routines are a **research preview**, so behavior and limits can change (as of 2026-10-13).
- The basics of routines (creating them, triggers, environments) are in [C13](/en/claude/c13-cloud-sessions/). This article focuses on **what to choose, how to design safely, and how to verify**.
</Summary>

## What you'll be able to do after this tutorial

- **Choose from a comparison table** the automation method that fits your work.
- Write prompts for automatic runs **to be self-contained**, and verify them with a test run and the run history.
- Know the limits and expiration rules so you can avoid **automations that stop silently**.
- Carry over a pattern this site uses, like "check official news every morning → open a PR with proposed edits," to your own work.

## Concepts to know first

### The four methods at a glance

| | Claude app scheduled tasks | Routines (cloud) | Desktop scheduled tasks | `/loop` |
| --- | --- | --- | --- | --- |
| Where it runs | Remote (per the official help) | Anthropic-managed cloud | Your computer | Your computer (an open session) |
| Does your computer need to be on? | No (but tasks that need local files or apps run only locally) | No | **Yes** (the app must be open and the computer awake) | **Yes** |
| Does a session need to stay open? | No | No | No | **Yes** |
| Local file access | Possible if you specify a folder (when running locally) | None (clones the repository fresh) | Yes | Yes |
| Triggers | Time (hourly, daily, weekdays, weekly, manual) | Schedule, API, GitHub events | Time (manual, hourly, daily, weekdays, weekly) | Interval |
| Minimum interval | Hourly (by preset) | 1 hour | 1 minute | 1 minute |
| Main use | Work documents, reports, summaries | Repository work (code, docs) | Local code and file work | Checking deploy or PR status |

The table above combines the official docs below. For Claude Code's three methods (routines, desktop, `/loop`) it follows the comparison table in the Run prompts on a schedule doc, and for app scheduled tasks it follows the Claude Cowork help.

<Aside type="note" title="Claude app scheduled tasks and Claude Code are different features">
App scheduled tasks save a prompt in Claude (Cowork) and run it on a set schedule, and can use the connectors, skills, and plugins you've connected. Each run creates a separate session. Routines, on the other hand, are a Claude Code feature that centers on **a repository and an environment**. For documents, summaries, and reports, app scheduled tasks are the natural fit; for code and repository work, routines are.
</Aside>

<Steps>

1. **Pick a task and do it by hand once**

   The jobs that suit automation are ones that **repeat, have a clear result, and don't need a person's judgment each time**. First do it directly in a conversation and write down in words what "success" is. That text becomes the prompt for the automatic run as is. To lock in a format with a skill, see [C8](/en/claude/c08-skills/).

2. **Write a self-contained prompt**

   An automatic run has no conversation, so there's no one to ask follow-up questions. The official docs also say the prompt matters most, and to state clearly what to do and what counts as success. Include these four things.

   - **What to do**: where to check and what to check
   - **Output**: where and in what form to leave it
   - **What not to do**: what must not be touched
   - **Report when done**: a one-line summary, with reasons for anything not done

   <PromptBox>
   Please check recent changes on [what to check, e.g., the list of official pages below]. Pick out only what has changed since the last check, and organize it in [format] at [output location]. Attach the source URL to each item, and for anything you couldn't verify, don't guess; write "couldn't verify." Do not modify [files or items that must not be touched]. When you're done, summarize what you checked and what you changed in three lines.
   </PromptBox>

3. **Set it up for your chosen method**

   **A. Claude app scheduled tasks.** According to the official help, in the new Claude experience (rolling out to Pro, Max, and Ultra), you can just say the task and its schedule in any conversation, like "Every Monday at 9am, summarize last week's team channel messages." After answering Claude's follow-up questions, check the proposed task name, schedule, and instructions and click **Schedule**. In the Cowork screen, go to **Scheduled** > **New task** in the left sidebar, choose Create with Claude or Set up manually, and set the name, prompt, approval mode, frequency (hourly, daily, weekdays, weekly, manual), model, and folder. You can see upcoming and past runs under Scheduled in the sidebar. Screens may differ depending on your account and app version.

   **B. Routines.** How to create them is in [Creating routines in C13](/en/claude/c13-cloud-sessions/). In short, create them from New task (New routine for some accounts) at claude.ai/code/routines, from Routines (choose Cloud) in the desktop app, or with `/schedule` in the CLI. All three are saved to the same account, so something created in one place shows up in the others. For example, say it like this.

   ```sh
   /schedule daily PR review at 9am
   /schedule in 2 weeks, open a cleanup PR that removes the feature flag
   ```

   If you state a point in time in natural language as in the second example, it becomes a one-time run. A one-time run turns itself off after it runs and shows as Ran. Intervals shorter than one hour are rejected.

   **C. Desktop local scheduled tasks.** In Routines on the Code tab, choose New routine > **Local** and set the name, description, instructions, frequency, and working folder. The folder is required. There's an option to use an isolated Git worktree for each run. Each run opens as a new session and you get a notification.

   **D. `/loop`.** It repeats while the session is open.

   ```sh
   /loop 5m check if the deployment finished and tell me what happened
   ```

   If you omit the interval, Claude picks one each time between 1 minute and 1 hour. If you only want to be notified once, just say it in natural language, like "remind me at 3pm to push the release branch."

4. **Do a test run and open the history**

   Use **Run now** on the routine's detail screen to run it once right away. Each run is kept as a new session, and when you open it you can see what Claude did. A green status in the list means "the session ended without an infrastructure error," **not that the task succeeded.** Blocked network requests, missing connector tools, and task-level failures show up inside the history, so be sure to open and read it. In the CLI, manage routines with `/schedule list`, `/schedule update`, and `/schedule run`, and you can also ask about run history, like "why didn't this morning's review do anything?" (Claude Code v2.1.227 or later, per the official docs).

   For desktop tasks, click Run now the first time and allow all the permission requests (always allow), and later runs won't stall.

5. **Check the conditions that cause silent stops**

   Automations can stop without any notification. Skim the table below once.

   <PromptBox label="Use this prompt to have your automation design reviewed">
   The task I want to run automatically is [task description] and the run method is [method]. Tell me three problems that could happen if this task goes wrong while no one is watching, the restriction sentences I should put in the prompt to prevent them, and how I can check the results of the run.
   </PromptBox>

</Steps>

## Quick reference

### Limits and expiration (as of 2026-10-13, subject to change)

| Method | Things to know |
| --- | --- |
| Routines | Scheduled runs: 100 per hour per account (including one-time runs); Run now and API runs: 30 per hour per routine, plus a separate per-account limit. There is no overage billing for these limits. If you exceed them, scheduled runs wait and Run now and similar actions fail. |
| Routine usage | Uses your subscription usage like interactive sessions. When you hit your usage limit, runs continue only if additional usage (usage credits) is turned on; otherwise they're rejected until the limit resets. |
| Routine GitHub connection | If the connection breaks or expires, runs are skipped for up to 72 hours. If you reconnect within that time, they resume automatically; after 72 hours they're turned off and you have to turn them back on yourself. |
| Routine suspension | They're put on hold while a subscription is paused. After it's reactivated, you have to turn them back on yourself. A Team/Enterprise Owner can also turn them off for the whole organization. |
| `/loop` (session scheduling) | A recurring task **runs one last time and is deleted 7 days after you create it**. Up to 50 per session. It runs only while Claude Code is running and idle, and missed runs aren't caught up; they run just once. On-the-hour settings can be delayed by a few minutes. |
| Desktop | Runs only when the app is open and the computer is awake. If a run is missed while asleep, it **catches up just once** after waking, for the most recent missed time (within the last 7 days), and older ones are discarded. |
| App scheduled tasks | Tasks that need local files or apps run only locally. |

### Avoid the top of the hour

The official docs say that for both routines and `/loop`, setting a time right on the hour (for example, 9:00) can make it start a few minutes late. Pick a time a few minutes past, like 9:07. Enter routine times in your own time zone and they're converted automatically.

## Case study: check official news every morning → open a PR with proposed edits

This site uses a routine that regularly checks whether tools' official docs and changelogs have changed, and if they have, **opens a PR with proposed edits**. I'll leave out account details and specific settings, and introduce only the general pattern.

<FlowSteps title="Flow of the official-news check routine" officialUrl="https://code.claude.com/docs/en/routines" steps={[
  { where: 'Schedule trigger', action: 'Starts every morning at a time that\'s not on the hour', result: 'A new cloud session opens' },
  { where: 'Repository clone', action: 'Check the official pages listed in the prompt, one by one', result: 'A list of what changed' },
  { where: 'Inside the repository', action: 'Fix the related docs and push to a branch with the claude/ prefix', result: 'A proposed-edits branch' },
  { where: 'GitHub', action: 'Create a PR', result: 'A person reviews it' },
  { where: 'A person', action: 'Reads the PR and decides whether to merge', result: 'Reflected on the site' },
]} />

This design is safe for these reasons.

- **It only produces reversible results.** The routine pushes to a branch with the `claude/` prefix and doesn't apply anything directly to the default branch. A person does the merge.
- **The prompt is specific.** It includes which pages to check and a rule not to guess or write down anything it couldn't verify.
- **Only the repository is connected.** Unneeded connectors are removed to narrow what the routine can reach.
- **Verification happens in the PR.** The commits and PR the routine makes are recorded under your GitHub user, so you need to read the content before merging.

<PromptBox label="Example prompt for an official-news check routine">
Check the official pages [list of URLs] that this repository's [list of docs to check] are based on. If anything differs from the menu names, prices, limits, or feature descriptions written in the docs, fix those docs, and reflect the supporting URL in the sources at the bottom of the doc. Don't fix items you couldn't verify; write them in the PR description as "couldn't verify." Push to a new branch and create a PR, and in the PR description lay out what changed and the evidence in a table. Do not apply anything directly to the default branch.
</PromptBox>

## Common sticking points

### `/schedule` says "Unknown command"

- **Cause**: `/schedule` requires a claude.ai subscription login. It doesn't appear if you authenticate with a Console API key or a cloud provider such as Amazon Bedrock.
- **Fix**: Make sure you're logged in with a claude.ai account. For the exact conditions, see Troubleshooting in the official Routines docs.

### It says "Routines are turned off by organization policy"

- **Cause**: On Team/Enterprise, an Owner can turn off routines for the whole organization with the "Scheduled tasks (Was Routines)" toggle under Organization settings > Capabilities > Remote sessions, and then existing routines stop and you can't create new ones.
- **Fix**: Ask your organization Owner to check the setting.

### The routine is green but there's no result

- **Cause**: A green status only means the session ended without an error, not that the task succeeded.
- **Fix**: Open the run history and check for blocked network requests or missing connector tools. For domains that aren't allowed, you need to fix the environment's network settings ([C13](/en/claude/c13-cloud-sessions/)).

### The desktop scheduled task didn't run this morning

- **Cause**: The computer may have been asleep or the app may have been closed. Skipped runs are recorded in the history with the reason.
- **Fix**: A single catch-up run happens after waking. If the timing matters, put a condition in the prompt like "if it's past 5pm, skip it and just summarize what was missed." If it needs to run even when the computer is off, switch to a routine or an app scheduled task.

### `/loop` disappeared after a week

- **Cause**: Session-scheduled recurring tasks expire after 7 days.
- **Fix**: Move long-running tasks to a routine or a desktop scheduled task.

## Practical tips

- **Have it produce reversible results.** Automate only up to a draft, a branch, or a PR, and have a person do the final commit such as sending, merging, or deleting.
- **Keep permissions and connections to a minimum.** Routines act without approval within what the selected repository, the environment's network and variables, and the included connectors can reach. Connectors are all included by default, so keep only what you need.
- **Don't put in personal information.** Environment variables and prompts are reused repeatedly where no one is watching. For handling secrets, follow the environment settings in [C13](/en/claude/c13-cloud-sessions/).
- **Start with a low frequency.** Automatic runs use up usage. Start at about once a week, look at the results and usage, and then increase.
- **Read the results regularly.** Even if an automation quietly produces wrong results, there may be no notification. Skim the run history periodically.
- **Use API triggers carefully.** The token is shown only once, and text you pass in is wrapped as untrusted data, so it takes effect only if the prompt explicitly references it. Keep the token secret.
