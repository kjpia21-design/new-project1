<Summary>
- A Project is **a self-contained workspace with its own chat history and knowledge base**. Everyone can use them (including free users), and free allows up to 5 (as of 2026-10-10).
- Documents, text, and code you add to **knowledge** are used as background in every conversation in that Project. **Instructions** apply rules like tone and role to every conversation.
- Context that isn't in the knowledge base isn't shared between conversations. The point is that you no longer have to paste the same material every time.
- On Team/Enterprise you can share Projects, with two permissions: Can view (view and chat) and Can edit (edit instructions and knowledge, manage members).
- Each Project has its own memory space, so it doesn't mix with other Projects or regular chats.
</Summary>

## What you'll be able to do

- Create a Project and add materials (knowledge) and instructions to make a "Claude workroom just for your team."
- Understand the difference between knowledge and instructions, and decide what goes where.
- (Team/Enterprise) Share a Project with colleagues and divide up permissions.
- Archive Projects you no longer use, and tell apart the new "Projects" beta from existing Projects.

## Concepts to know first

| Term | Meaning |
| --- | --- |
| **Project** | A self-contained workspace with its own chat history and knowledge base. |
| **Project knowledge** | Documents, text, and code you add to the Project. Used as background material in every conversation in that Project. |
| **Project instructions** | Rules such as tone and role. They apply to every conversation in the Project. |
| **RAG mode** | Turns on in paid plans (Pro/Max/Team/Enterprise) when knowledge nears the context limit. It expands capacity up to 10x. |
| **Can view / Can edit** | Sharing permissions. View lets people look and chat only; edit also lets them edit instructions and knowledge and manage members. |
| **Project memory** | A memory space and Project summary that each Project has separately. It's kept apart from other Projects and regular chats. |

### Knowledge vs. instructions: what goes where?

- Put **reference material that doesn't change** (work manuals, glossaries, sample past reports) in knowledge.
- Put **rules to follow every time** ("use a polite tone," "keep tables to 3 columns or fewer," "start by asking one question") in instructions.
- If instructions get long, Claude may miss some rules. Keep only the essentials and move the rest into knowledge documents. For prompt-writing tips, see [C4. How to write good prompts](/en/claude/c04-prompting/) too.

<Aside type="note" title="Numbers not in the official docs">
- The upper limits on file size and count aren't given in the official docs (confirmed 2026-10-13), so this tutorial doesn't state any numbers either. Follow the guidance shown on screen when you upload.
- The official docs say nothing about a general-availability date for the new "Projects" beta.
- The detailed behavior of Project memory is explained only in the memory doc, not the Projects doc. See [C9. Memory and personal settings](/en/claude/c09-memory-settings/) for details.
</Aside>

<Steps>

1. **Create a Project**

   Go to Projects in the left sidebar or claude.ai/projects, and click **+ New Project** at the upper right.

   Enter a name and description. They're for people to tell Projects apart, and **Claude can't see them.** On Team/Enterprise you can also choose private or organization-wide visibility at this point.

   <ScreenshotPlaceholder caption="Clicking + New Project in the Project list and entering a name and description" officialUrl="https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects" />

2. **Add knowledge**

   Click **+** on the right side of the Project page to add files or text. Good examples are things you need every time, such as your team's report template, glossary, or sample past meeting notes.

   <ScreenshotPlaceholder caption="Adding files or text with + on the right side of the Project page" officialUrl="https://support.claude.com/en/articles/9519177-how-can-i-create-and-manage-projects" />

3. **Write instructions**

   Click **Set project instructions**, enter your instructions, and save. Start short at first.

   <PromptBox label="Instruction example (paste into Set project instructions)">
   You're an assistant that helps our team write weekly reports. Always write in a polite, professional tone, and organize each report in this order: "one-line summary → what I did this week → next week's plan → where I need help." Follow the tone of the report template in knowledge, and don't make up numbers that aren't in the materials; ask me instead.
   </PromptBox>

4. **Chat inside the Project**

   Start a new conversation from the Project page. Knowledge and instructions automatically become the background, so short requests are fine.

   <PromptBox>
   This week I did (1) meetings with 3 new clients, (2) a redesign of the quote template, and (3) prep for the inventory count. Write a draft weekly report using the template in knowledge.
   </PromptBox>

   Check that the answer follows the knowledge template, and if it doesn't, add one more rule line to the instructions.

5. **(Team/Enterprise) Share**

   Click **Share project**, add members, pick a permission (Can view or Can edit), and click **Share**. You can add individuals by email, add in bulk, or make it available to the whole organization. In organizations where an admin has turned off sharing, you can't use this menu.

   <ScreenshotPlaceholder caption="Adding members and choosing permissions in the Share project window" officialUrl="https://support.claude.com/en/articles/9517075-what-are-projects" />

</Steps>

## Quick reference

### What you can do with Projects

| What you want to do | How |
| --- | --- |
| Create one | Sidebar Projects or claude.ai/projects > + New Project |
| Add materials | + on the right side of the Project page |
| Set rules | Set project instructions |
| Share (Team/Enterprise) | Share project > add members > permission > Share |
| Archive | The Project's "..." menu > Archive (sharing, members, and knowledge are kept) |
| Delete | Unarchive first, then delete |

### Differences by plan (as of 2026-10-10)

| Item | Details |
| --- | --- |
| Availability | All users (including free) |
| Free plan | Up to 5 Projects |
| RAG mode | Paid plans (Pro/Max/Team/Enterprise): capacity expands up to 10x |
| Sharing | Team/Enterprise |
| Connectors | On Team/Enterprise, they work only in private Projects. Chats with synced content can't be shared |

### Telling the two kinds of "Project" apart (as of 2026-10-10)

| | Existing Projects | New "Projects" beta |
| --- | --- | --- |
| Structure | Knowledge + instructions + multiple conversations | The Project is a single conversation. Claude splits the work into parallel cloud threads |
| Availability | Available now | Staged rollout starting with Claude Code (some Pro/Max), with a waitlist |
| Usage | Regular usage | Counted against your plan limit |
| What you need | Nothing | Install the Claude GitHub App on each repository, and use the environment in the Project settings |

Existing chat and Cowork Projects stay as they are.

## Common sticking points

### Claude doesn't seem to use the materials I uploaded

- **Cause**: Your question may not connect to the material, or the instructions may not have a rule that says "follow the materials."
- **Fix**: Point at the material in your request, like "using the report template in knowledge." Add a line to the instructions too.

### The Project says it doesn't know what we discussed in another conversation

- **Cause**: Context that isn't in the knowledge base isn't shared between conversations. Project memory is also kept apart from other Projects and regular chats.
- **Fix**: Put anything you keep needing directly into knowledge or instructions.

### I don't see the Share menu

- **Cause**: Sharing is a Team/Enterprise feature, and admins can turn it off.
- **Fix**: Check your plan and ask your organization admin.

### I can't share connector data in a Project with teammates

- **Cause**: On Team/Enterprise, connectors work only in private Projects, and chats with synced content can't be shared.
- **Fix**: Do connector-dependent work in a private Project, and organize the results you want to share separately and upload them. Connectors are covered in [C7. Connectors](/en/claude/c07-connectors/).

### I can't delete a Project

- **Cause**: You have to unarchive it before you can delete it.
- **Fix**: Unarchive the archived Project, then delete it.

## Practical tips

- **Put only "things that don't change" in knowledge.** For content that changes often, it's more accurate to tell Claude in the conversation.
- **Start the instructions short and fix them as you chat.** Each time you get an off-target answer, add one rule line.
- **Split Projects by type of work.** Splitting them up, such as weekly reports, customer replies, and planning documents, keeps knowledge and memory from mixing.
- **Check the sharing scope first for sensitive material.** If you make it organization-wide, members of the organization can see it.
- **Archive finished Projects.** Sharing settings and knowledge are kept, and your list just gets tidier.
