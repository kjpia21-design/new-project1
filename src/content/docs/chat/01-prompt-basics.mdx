<Summary>
- 업무 프롬프트는 **역할 · 목적 · 맥락 · 형식 · 제약 · 예시** 6칸만 채우면 대부분 해결돼요.
- 기준은 하나예요. 맥락을 모르는 동료에게 이 요청을 보여줬을 때 바로 일할 수 있는가?
- 이 튜토리얼의 근거는 Claude 공식 가이드예요. 원리는 글로 일을 시키는 기본기라 다른 도구에도 통하지만, ChatGPT·Gemini의 프롬프트 공식 가이드는 따로 대조하지 않았어요. 각 도구의 공식 도움말도 함께 확인하세요.
- 한 번에 완벽하게 쓰려 하지 말고, 첫 결과를 보고 **후속 질문으로 다듬으세요.**
- 고객 정보나 사내 기밀은 붙여넣기 전에 한 번 더 생각하세요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 막연한 요청을 6칸 틀로 구체적인 요청으로 바꿀 수 있어요.
- 메일, 회의록 정리, 기획 아이디어, 번역·윤문 같은 업무별 템플릿을 바로 복사해 쓸 수 있어요.
- 결과가 별로일 때 어느 칸이 비었는지 찾아 고칠 수 있어요.
- AI에 넣으면 안 되는 정보를 구분할 수 있어요.

## 먼저 알아둘 개념

Claude 전용 기법(모델 선택, effort, XML 태그 세부 등)은 [C4. 프롬프트 잘 쓰는 법](/new-project1/claude/c04-prompting/)에서 다뤄요. 여기서는 어떤 도구에서든 쓸 수 있는 **업무 틀**에 집중해요.

| 칸 | 질문 | 예시 |
| --- | --- | --- |
| **역할** | 누구처럼 답해야 하나요? | 10년 차 영업기획 매니저 |
| **목적** | 이 결과로 무엇을 하나요? | 팀장에게 주간 보고 |
| **맥락** | 배경과 독자는? | 독자는 숫자에 민감한 임원 |
| **형식** | 어떤 모양으로 받나요? | 5줄 요약 + 표 1개 |
| **제약** | 지킬 것과 피할 것은? | A4 한 장, 전문용어 풀어서 |
| **예시** | 이런 느낌으로 | 지난번에 잘 쓴 문단 붙이기 |

공식 가이드가 말하는 기본 태도는 Claude를 "뛰어나지만 우리 규범을 모르는 신입 직원"처럼 대하라는 거예요. 황금률은 맥락이 거의 없는 동료에게 프롬프트를 보여줬을 때 헷갈려 하면 AI도 헷갈린다는 것이에요.

<Aside type="caution" title="넣기 전에 확인하세요">
Claude 공식 도움말은 금융 정보(주민등록번호, 카드·계좌번호), 건강 기록, 비밀번호, 기밀 업무 문서를 입력할 때 주의하라고 안내해요. 개인·회사 정보는 이름과 숫자를 가린 뒤 쓰는 습관을 들이세요. 학습 사용 여부와 설정은 도구·플랜마다 달라서 각 서비스의 개인정보 설정에서 확인해야 해요. 더 자세한 내용은 [3편](/new-project1/chat/03-data-analysis/)에서 다뤄요.
</Aside>

## 단계별 따라하기

<Checklist items={[
  '내 업무 요청 하나를 골라 6칸으로 나눠 봤어요',
  '나쁜 예와 좋은 예의 차이를 직접 비교해 봤어요',
  '이유를 한 문장 덧붙여 봤어요',
  '결과를 보고 후속 질문으로 한 번 이상 다듬었어요',
  '자주 쓰는 템플릿 한 개를 메모장에 저장했어요',
]} />

<Steps>

1. **일을 6칸으로 쪼개기**

   요청하기 전에 메모장에 6칸을 짧게 적어요. 비는 칸이 있으면 그 칸이 결과의 약점이 돼요.

   나쁜 예:

   <PromptBox>
   거래처에 보낼 메일 써줘.
   </PromptBox>

   좋은 예:

   <PromptBox>
   너는 B2B 영업 담당자야. 납품이 3일 늦어지는 상황을 거래처 구매팀장에게 알리는 메일을 써줘. 독자는 이미 한 번 일정이 밀려 예민한 상태야. 사과, 원인 한 줄, 새 납품일(10월 20일), 보상 제안 순서로, 200자 안팎의 정중한 문체로 써줘. 변명처럼 들리는 표현은 빼줘.
   </PromptBox>

2. **이유를 덧붙이기**

   "~하지 마"만 던지면 AI는 왜인지 몰라요. 공식 가이드도 규칙보다 이유를 설명하는 쪽이 낫다고 해요. 그리고 "하지 마" 대신 "무엇을 하라"로 말하세요.

   <PromptBox>
   이 글은 사내 메신저에 올릴 거라 길면 안 읽어. 그래서 세 문장 이내로, 이어지는 문장으로 써줘.
   </PromptBox>

3. **업무별 템플릿 가져다 쓰기**

   아래 템플릿은 6칸 틀을 적용해 만든 **예시**예요. `[ ]` 안만 바꿔 쓰세요. 공식 문서에 한국어 예문이 있는 것은 아니에요.

   **회의록 정리**

   <PromptBox>
   아래 회의 메모를 팀장 보고용으로 정리해줘. 결정사항, 할 일(담당자·기한 포함), 미결 사항 세 부분으로 나누고, 메모에 없는 담당자나 기한은 지어내지 말고 "확인 필요"라고 적어줘.

   [회의 메모 붙여넣기]
   </PromptBox>

   **기획 아이디어 넓히기**

   <PromptBox>
   [제품/행사]의 홍보 아이디어를 10개 제안해줘. 대상은 [고객층], 예산은 [금액], 기간은 [기간]이야. 각 아이디어마다 한 줄 설명과 예상되는 어려움을 같이 적고, 실현 가능성이 높은 순으로 정렬해줘.
   </PromptBox>

   **번역·윤문**

   <PromptBox>
   아래 글을 [독자]가 읽기 쉽게 고쳐줘. 의미는 바꾸지 말고, 문장은 짧게, 어려운 한자어는 쉬운 말로 바꿔줘. 바꾼 부분은 원문과 나란히 표로 보여줘.

   [원문]
   </PromptBox>

   **표 만들기**

   <PromptBox>
   아래 내용을 항목, 내용, 담당, 기한 네 열의 표로 정리해줘. 정보가 없는 칸은 비워 두지 말고 "미정"이라고 적어줘.

   [내용]
   </PromptBox>

4. **긴 자료와 예시 넣기**

   긴 자료를 함께 줄 때는 자료를 위에, 요청을 아래에 두세요. 공식 가이드는 긴 문서(20k 토큰 이상)에서 이렇게 하면 응답 품질이 좋아질 수 있다고 안내해요. 원하는 말투가 있으면 예시를 1~3개 보여 주세요. 공식 가이드는 예시를 3~5개 권장해요.

   <PromptBox>
   [자료 붙여넣기]

   위 자료를 보고, 아래 말투 예시처럼 고객 안내문을 써줘.
   예시: "안녕하세요, 고객님. 문의 주신 건은 오늘 오후까지 확인해 연락드리겠습니다."
   </PromptBox>

5. **후속 질문으로 다듬기**

   첫 결과는 초안이에요. 한 가지씩 고쳐 달라고 하세요.

   <PromptBox>
   두 번째 문단이 너무 딱딱해. 같은 내용으로 더 부드럽게, 길이는 그대로 다시 써줘.
   </PromptBox>

   <ScreenshotPlaceholder caption="후속 질문으로 초안을 다듬는 대화 화면" />

</Steps>

## 빠른 참조표

| 증상 | 비어 있는 칸 | 고치는 법 |
| --- | --- | --- |
| 너무 평범하고 뻔해요 | 맥락, 목적 | 독자와 쓰임새를 알려 주세요 |
| 형식이 매번 달라요 | 형식, 예시 | 원하는 출력 모양을 예시로 보여 주세요 |
| 길이가 안 맞아요 | 제약 | 분량을 글자 수·줄 수로 쓰세요 |
| 말투가 안 맞아요 | 역할, 예시 | 독자를 정하고 말투 예시를 주세요 |
| 없는 내용을 지어내요 | 제약 | "자료에 없으면 확인 필요라고 적어줘"를 넣으세요 |
| 규칙을 무시해요 | 맥락 | 규칙 옆에 이유를 한 문장 붙이세요 |

## 자주 막히는 지점

### 길게 썼는데도 결과가 별로예요

- **원인**: 길이가 아니라 정보 종류가 문제일 수 있어요. 배경만 길고 형식과 제약이 없는 경우가 많아요.
- **해결**: 6칸 표로 어느 칸이 비었는지 점검하세요.

### AI가 그럴듯하지만 틀린 내용을 써요

- **원인**: 자료에 없는 부분을 AI가 채워 넣었을 수 있어요.
- **해결**: 근거가 되는 자료를 붙여 주고, "자료에 없는 내용은 쓰지 말고 확인 필요라고 적어줘"라고 하세요. 숫자와 고유명사는 직접 확인하세요.

### 같은 요청을 매번 다시 써야 해서 번거로워요

- **원인**: 템플릿을 저장하지 않아서예요.
- **해결**: 자주 쓰는 틀은 메모장에 저장하세요. Claude는 프로젝트 지침으로 반복 지시를 저장할 수 있어요([C5](/new-project1/claude/c05-projects/)).

### 고객 정보가 섞인 자료를 올려도 되는지 모르겠어요

- **원인**: 도구와 플랜마다 학습·보관 정책이 달라요.
- **해결**: 회사 보안 지침을 먼저 확인하고, 이름·연락처·계좌 같은 식별 정보는 지우거나 가명으로 바꿔서 올리세요.

## 실전 팁

- **신입 직원에게 업무 지시하듯 쓰세요.** 동료에게 부탁할 때 필요한 정보를 그대로 적으면 돼요.
- **간단한 질문으로 시작해서 점점 구체화하세요.** 공식 시작 가이드도 이 흐름을 안내해요.
- **잘 나온 프롬프트는 저장하세요.** 다음에 `[ ]`만 바꿔 쓰면 시간이 크게 줄어요.
- **도구가 달라도 틀은 같아요.** 같은 프롬프트를 두 도구에 넣어 비교하는 방법은 [5편](/new-project1/chat/05-compare-assistants/)에서 다뤄요.
