<Summary>
- An agent's mistake isn't **a wrong answer**, it's **a wrong action**. A sent email, a completed payment, or a deleted file is hard to undo.
- The three big principles are **minimum permissions, approval before anything irreversible, and checking the log for what was done**.
- All four products say in their official docs that "agents can make mistakes." Even with approval features, use them on the premise that **you check things through to the end**.
- One confirmed fact: **none of the products had an official doc confirming you can set a payment cap (spending limit) on the agent side.** Instead, block it with limits on the card side and approval steps.
- Check the list below from the top, and if any of the 8 items blocks you, don't grant that permission yet.
</Summary>

## What you'll be able to do after this tutorial

- Explain what can happen when you give an agent payment, email, or account permissions.
- Follow a checklist to use before you start and while you're using it.
- Compare the safety features that Muse, Grok Bot, Dots, and Claude officially provide, and set things up to suit your situation.

## Concepts to know first

### Why agents are risky

| Risk | What can happen |
| --- | --- |
| **Irreversible actions** | A sent email, a completed payment, or a permanent deletion can't be canceled. The Dots docs say "stopping doesn't undo actions already completed," and the Grok Bot docs say "approval doesn't undo work that's already done." |
| **Excessive permissions** | If you give send and delete permissions when you only needed to read email, one mistake does much more damage. |
| **Hidden instructions (prompt injection)** | The emails or web pages an agent reads can hide text telling it "act like this." Meta also says it marks external data as "untrusted" and blocks this with classifiers and human approval, and the Claude connector docs warn about instructions hidden in text from external services. |
| **Credential exposure** | Passwords and one-time codes sent in regular chat stay in the conversation history. |
| **Shared environments** | Several agents may share one computer, or logins may be left on a shared device. |
| **Runaway costs** | Running multiple agents for a long time can exhaust limits and roll over into pay-as-you-go billing. |
| **Privacy and training** | Your conversations and work are stored by the service provider. Whether they're used for training varies by product and setting. |

### Official safety features by product at a glance

All as of 2026-10-10, and all read directly from each product's official pages.

| Item | Meta Muse | Grok Bot | ChatGPT Dots | Claude |
| --- | --- | --- | --- | --- |
| Approval | Human approval for sensitive actions like sending email and purchases. Scope can be chosen from one time to permanent | Approval cards (Allow once, Always allow, Deny) and model-based Auto Review | Four levels of custom rules: act without asking, act when I say so, confirm before acting, hand off to me | Connectors ask for approval before sending, replying, deleting, and so on. Chrome has Manual, Auto, and Skip modes |
| Payments | Stripe Link one-time cards hide your real card details from merchants and the agent. Sites with a saved payment method need human approval every time | Payment confirmation is entered by you taking over the computer. No dedicated payment method or spending cap found in the docs | No payment-specific feature found in the docs | Chrome doesn't make purchases or handle card details, regardless of permissions |
| Passwords | Direct input goes to a secure store that Muse can't see. The agent sees only a proxy token | You enter passwords, two-factor authentication, CAPTCHAs, and payment confirmation yourself. Don't send them in chat | Site login information is passed through a private flow outside the conversation. Reusing a saved login needs your confirmation | In 1Password login requests (macOS beta), Claude can't see the password |
| Logs | An activity log (audit trail) shows what it did and will do | The docs describe a routine run history (last 20 per routine) | The Activity screen shows delegated tasks | Cloud sessions apply results after you review the diff |
| Stopping and revoking | You can change access and disconnect. The agent stops while you're operating the browser directly | The docs lay out an access revocation procedure (stop routines, log out, disconnect connectors, delete files) | Pause, stop delegated tasks, delete recurring tasks, delete the dot (can't be undone) | Computer use can be stopped at any time. Connectors can be disconnected |
| Official warning | "Muse will make mistakes" | "Auto Review doesn't replace least privilege and explicit approval" | "Your dot can make mistakes" | Warns that risk remains in Chrome even with safety classifiers |

## Step by step

  '5. I never put passwords or one-time codes in chat',

### 1. Start with read-only

For the first few days, hand off only **tasks that change nothing**, like summarizing, sorting, and researching. It's not too late to grant write permissions after you've seen how the agent works. C11 points the same way. The computer use docs recommend starting with simple tasks, using specific prompts, and watching closely at the beginning.

<PromptBox>
Read my inbox for the past week and sum up in three lines only the emails that need a reply. Don't write or send replies, and don't move or delete any emails.
</PromptBox>

### 2. Keep connected services to a minimum (least privilege)

- First decide whether you need **read-only** email access or sending too. The Dots docs say existing ChatGPT app permissions apply, so you can split it as "allow reading email, don't allow sending." Muse also separates read and write permissions when the service supports it.
- Claude connectors inherit your own permissions and ask for approval by default before sending, sharing, or deleting. Turn off tools you don't need. We cover this in detail in [C7. Connectors](/claude/c07-connectors/).
- Disconnect services you don't use. Third-party services are subject to their own infrastructure and terms.
- For automatically running tasks like routines, **check the connectors included by default** and remove the ones you don't need. The routine summary table in [C13](/claude/c13-cloud-sessions/) says "all connectors are included by default."
- With Grok Bot, all Bots share one cloud computer, so it says **don't use a Bot as a security boundary**. Splitting sensitive services across Bots doesn't isolate them.

### 3. Turn on approval steps

Set irreversible things (sending, deleting, permission changes, payments, agreeing to terms) to **always ask**.

- **Dots**: Under Settings > Personalization > Custom rules (on mobile, Customize > Custom rules), you can choose "confirm before acting" or "hand off to me." The docs say the rules are "guidance the dot tries to follow and can get wrong," and they don't grant new app or computer access. If you write "show me a draft and don't send" in the instructions, drafting isn't read as permission to send.
- **Grok Bot**: Choose **Always allow** on the approval card carefully. Per the docs, Ask first takes priority over Allow automatically. Approvals for tasks started by routines or other Bots expire after about 10 minutes and won't run.
- **Muse**: The terms say not to take state-changing actions (sending messages, financial transactions, deleting data, changing settings) without prior human review, and to be careful about giving advance approval too.
- **Claude in Chrome**: Manual approves every action, Auto proceeds with safety checks, and Skip runs without checks. Start with Manual. It asks about file downloads and entering sensitive information even on sites you've set to "always allow." This is covered in [C11](/claude/c11-chrome-computer-use/).

<Aside type="caution" title="Routines run autonomously without approval">
Claude routines run without anyone watching. Commits and PRs are made under your GitHub username, and branches are pushed with a `claude/` prefix. When you create a routine, keep the repositories, environment (network level), and connectors narrow. First see the "Routine summary" in [C13](/claude/c13-cloud-sessions/).
</Aside>

### 4. Pay with a limited method, and approve every time

<Aside type="caution" title="Agent-side spending caps aren't confirmed">
In the Grok Bot docs we couldn't confirm a dedicated payment method or spending cap feature, and in the Dots docs we couldn't confirm a payment feature at all. Muse has Stripe Link one-time cards and approval before purchases, but Meta says this protection is limited to "eligible purchases." This checklist is written on the premise that **you create the spending cap yourself**.
</Aside>

- For the card you use with an agent, use **a separate card with a low limit, or a one-time card**. Don't connect your main card.
- For purchases, transfers, and permission changes, **state the boundary** in your request. For example: "Only find product candidates, don't pay." The Grok Bot docs also recommend setting boundaries in the request for purchases, financial transfers, deletions, permission changes, and agreeing to terms.
- Do payment confirmation yourself. Grok Bot has you take over the computer and enter payment confirmation yourself. Muse, when it detects a checkout page, has a person approve the purchase details every time.
- The Muse terms say the user is responsible for all of Muse's actions, and limit liability to "$250 or the amount paid in 12 months, whichever is greater." It isn't a structure where the service compensates you in full for financial harm.
- Claude's computer use blocks investment and trading platforms and crypto apps by default, and recommends against using it for banking, healthcare, and government apps, or for work involving financial accounts, legal documents, or medical information.

### 5. Don't put passwords or codes in chat

- For passwords, passkeys, two-factor codes, and CAPTCHAs, use each product's **dedicated input path**. Grok Bot says not to send passwords or one-time codes in regular chat, and supported connections use a "secure secret request" (masked, excluded from the conversation history and the model). Dots passes login information to the browser outside the conversation.
- Muse's email connector filters out one-time codes, password reset links, and magic login links. Still, it's safer to keep that kind of email from landing in a mailbox you've connected to the agent's account.
- In Claude cloud environments, environment variables and setup scripts are readable by anyone who uses them, so **don't store secrets there.** Pro/Max can use network secrets (a proxy attaches the key to requests).
- When you share a session, first check whether the conversation contains credentials. If you set it to Public, any user logged in to claude.ai can see it.

### 6. Set usage and cost limits

- **Claude**: Under Settings > Usage, in the **extra usage (usage credits)** section, you can set a **monthly spending limit** or leave it off. If it's on, you keep going pay-as-you-go after hitting the limit, and routines also keep running with the overage billed pay-as-you-go when extra usage is on. For the limit structure, see [C2. Plans and usage limits](/claude/c02-plans-limits/).
- **Grok Bot**: Weekly usage resets every week (The X Subscription shares it with Grok and Cursor), and when it runs out, prepaid credits or on-demand (pay-as-you-go) usage on legacy Cursor plans may be billed (on by default for Teams). Check your billing settings after signing up.
- **Dots**: Conversations with the dot don't count against ChatGPT usage limits, but Work/Codex tasks the dot starts or manages count against those products' limits.
- **Muse**: There may be an option to buy additional AI usage, and the terms say credits are non-refundable and can't be exchanged for cash.

### 7. Check the logs and results

- Even if the agent says it's "done," check the result. The Dots docs themselves say "a completed run doesn't guarantee the outcome was achieved."
- Muse has an activity log, Dots has the Activity and Scheduled screens, and Claude cloud sessions have a diff review screen for results. Pick a day every few days to skim **what it did**.
- For recurring tasks (Scheduled in Dots, routines in Grok Bot, routines in Claude), open the list periodically and delete what you no longer need.
- Pause in Dots stops only the current main task. Delegated tasks and scheduled runs have to be stopped separately, and hanging up a call doesn't stop the work.

### 8. Privacy and training settings, and shared devices

**Training and privacy**

| Product | What to check |
| --- | --- |
| Muse | The setting that uses your interactions for AI training is **on at first.** You can turn it off under Settings > Data controls, and turning it off applies to earlier interactions too. Meta says the current architecture doesn't prevent Meta from accessing data when needed. |
| Grok Bot | Cloud data storage is required, so Cursor accounts in Legacy Privacy Mode can't start. Opting out of training follows your Cursor account and privacy settings, and the Bot's computer currently runs in the US. |
| Dots | ChatGPT data controls apply to eligible conversations and tasks. The docs say proactive research and private notes aren't used to directly train models. It checks for permission before sharing private conversation content with others. |
| Claude | It doesn't train models on Gmail, Drive, or Calendar connector data. For conversations you don't want kept on record, you can use an incognito chat. General training settings for chat content aren't covered in this guide. Check your account settings. |

**Shared devices**

- Don't leave an agent app logged in on a public PC or a family device. Log out after using it.
- In Dots, connecting your computer is optional and only one machine at a time. A computer you've connected is accessible while the app is open. Don't turn it on for shared devices.
- Claude's computer use **has no sandbox and can see everything on your screen.** Close sensitive apps and windows before using it.
- With Grok Bot, all Bots share one computer, so when a task is done it recommends logging out of services, cleaning up temporary files, and revoking connector approvals. Deleting a Bot doesn't delete the files and browser sessions on the shared computer.
- When you share a Grok Bot with a share link, its **settings (configuration) are exposed**. Don't put secrets, customer information, or internal URLs in them.

## Quick reference

### One-page checklist (print it out)

| Question | If yes | If no |
| --- | --- | --- |
| Can this task be done with read-only access? | Don't grant write permissions | Go on to the next |
| Does it include irreversible actions? | Have it ask for approval every time | Auto-allow is possible |
| Does money change hands? | A low-limit card, and I confirm every time | Go on to the next |
| Does it need a password or code? | Only through the dedicated input path | Go on to the next |
| Do I really need to connect this service? | Split read and write permissions | Don't connect it |
| Did I check the training and storage settings? | Continue | Check them first |

### Signs to watch for

| Sign | Response |
| --- | --- |
| Approval requests suddenly increased | Read what's being requested, and if you don't recognize it, Deny it and stop the task |
| I see emails or purchases I didn't send | Revoke the permissions and check the activity log. Actions already taken can't be undone |
| An email or web page has text like "tell the agent to do this" | It could be a hidden instruction. Stop that task and handle it yourself |
| Usage is dropping faster than usual | Check your recurring task list and tasks running in parallel |

## Common sticking points

### Approval windows pop up too often and it's annoying

- **Cause**: The default setting stops at irreversible actions.
- **Fix**: Allow read tasks, and leave only sending, deleting, and payments on approval. Give auto-allow narrowly, starting with one trusted recurring task. The Grok Bot docs also say Auto Review doesn't replace explicit approval.

### I want to cancel an email the agent sent by mistake

- **Cause**: Changes already made in connected apps and messages already sent can't be undone by stopping the agent or deleting it (Dots docs).
- **Fix**: Contact the recipient directly, revoke that permission, and set the approval steps again.

### I'm not sure whether it's okay to give an agent a card

- **Cause**: Payment protection differs by product, and spending cap settings aren't confirmed.
- **Fix**: Create a separate card with a lowered limit in your card company's app, and for the first month have it do nothing beyond sorting candidates, with no payment.

## Practical tips

- **Turn permissions on only when needed and off when done.** You can disconnect at any time.
- **Write "what not to do" in your request.** Explicitly forbidding sending, deleting, and paying reduces the chance of mistakes.
- **Keep each task small.** With a big task, it's hard to check intermediate results.
- **Official docs change often.** Menu names and defaults may have changed since this guide's as-of date (2026-10-10), so check directly on the settings screen.
