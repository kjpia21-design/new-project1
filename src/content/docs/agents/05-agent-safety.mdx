## 이 튜토리얼로 할 수 있게 되는 것

- 에이전트에게 결제, 이메일, 계정 권한을 줄 때 어떤 일이 벌어질 수 있는지 설명할 수 있어요.
- 시작 전과 사용 중에 확인할 점검표를 따라 할 수 있어요.
- Muse, Grok Bot, Dots, Claude가 공식적으로 제공하는 안전 기능을 비교해서 내 상황에 맞게 설정할 수 있어요.

## 먼저 알아둘 개념

### 에이전트가 위험한 이유

| 위험 | 어떤 일이 벌어지나요 |
| --- | --- |
| **되돌릴 수 없는 행동** | 보낸 메일, 끝난 결제, 영구 삭제는 취소할 수 없어요. Dots 문서도 "중지해도 이미 완료한 행동은 되돌려지지 않는다", Grok Bot 문서도 "승인은 이미 끝난 작업을 되돌리지 못한다"고 밝혀요. |
| **과한 권한** | 메일 읽기만 필요한데 보내기·삭제 권한까지 주면, 실수 한 번의 피해가 커져요. |
| **숨은 지시 (프롬프트 인젝션)** | 에이전트가 읽는 메일이나 웹페이지에 "이렇게 행동해"라는 문장이 숨어 있을 수 있어요. Meta도 외부 데이터를 "신뢰 불가"로 표시하고 분류기와 사람 승인으로 막는다고 설명하고, Claude 커넥터 문서도 외부 서비스의 글에 숨은 지시를 주의하라고 해요. |
| **자격 증명 노출** | 비밀번호, 일회용 코드를 일반 채팅에 보내면 대화 기록에 남아요. |
| **공유되는 환경** | 한 컴퓨터를 여러 에이전트가 같이 쓰거나, 공유 기기에 로그인이 남을 수 있어요. |
| **비용 폭주** | 에이전트를 여러 개, 오래 돌리면 한도를 소진하고 종량제 청구로 넘어갈 수 있어요. |
| **개인정보와 학습** | 대화와 작업 내용이 서비스 제공자에게 저장돼요. 학습에 쓰일지는 제품과 설정마다 달라요. |

### 제품별 공식 안전 기능 한눈에

모두 2026-10-10 기준이고, 제품 공식 페이지를 직접 읽은 내용이에요.

| 항목 | Meta Muse | Grok Bot | ChatGPT Dots | Claude |
| --- | --- | --- | --- | --- |
| 승인 | 이메일 발송·구매 같은 민감 작업은 사람 승인. 범위는 1회~영구 중에서 선택 | 승인 카드(Allow once, Always allow, Deny)와 모델 기반 Auto Review | 사용자 규칙 4단계: 묻지 않고 실행, 내가 말할 때 실행, 실행 전 확인, 나에게 넘기기 | 커넥터는 전송·답장·삭제 등 전에 승인. Chrome은 Manual·Auto·Skip 모드 |
| 결제 | Stripe Link 일회용 카드로 실제 카드 정보를 판매자와 에이전트에게 숨김. 저장된 결제 수단 사이트는 매번 사람이 승인 | 결제 확인은 사용자가 직접 컴퓨터를 인수해 입력. 전용 결제 수단·지출 상한은 문서에서 못 찾음 | 결제 전용 기능은 문서에서 못 찾음 | Chrome은 권한과 상관없이 구매·카드 정보 처리를 하지 않음 |
| 비밀번호 | 직접 입력은 보안 저장소로 가고 Muse는 못 봄. 에이전트에는 대리 토큰만 보임 | 비밀번호·2단계 인증·CAPTCHA·결제 확인은 사용자가 직접 입력. 채팅에 보내지 말 것 | 사이트 로그인 정보는 대화 밖 비공개 흐름으로 전달. 저장된 로그인 재사용은 사용자 확인 필요 | 1Password 로그인 요청(macOS 베타)에서 Claude는 비밀번호를 볼 수 없음 |
| 기록 | 활동 로그(audit trail)로 한 일과 할 일 확인 | 문서에 루틴 실행 기록(루틴당 최근 20개) | Activity 화면에서 위임 작업 확인 | 클라우드 세션은 결과 diff 검토 후 반영 |
| 중단·회수 | 접근 변경·연결 해제 가능. 직접 브라우저 조작 중에는 에이전트가 멈춤 | 접근 회수 절차(루틴 중지, 로그아웃, 커넥터 해제, 파일 삭제)를 문서에 정리 | Pause, 위임 작업 중지, 반복 작업 삭제, dot 삭제(되돌릴 수 없음) | 컴퓨터 사용은 언제든 중단 가능. 커넥터는 연결 해제 |
| 공식 경고 | "Muse는 실수를 할 것이다" | "Auto Review는 최소 권한과 명시적 승인을 대체하지 않는다" | "Your dot can make mistakes" | Chrome은 안전 분류기가 있어도 위험이 남는다고 경고 |

### 1. 첫 시작은 읽기 전용으로

처음 며칠은 요약, 분류, 조사처럼 **아무것도 바꾸지 않는 작업**만 맡기세요. 에이전트가 어떻게 일하는지 보고 나서 쓰기 권한을 주면 늦지 않아요. C11도 같은 방향이에요. 컴퓨터 사용 문서는 간단한 작업부터, 구체적 프롬프트로, 초반에는 지켜보라고 권해요.

<PromptBox>
받은편지함에서 최근 일주일 메일을 읽고, 답장이 필요한 것만 세 줄로 정리해 주세요. 답장을 쓰거나 보내지 말고, 메일을 옮기거나 지우지도 마세요.
</PromptBox>

### 2. 연결 서비스는 최소로 (최소 권한)

- 메일은 **읽기만** 필요한지, 보내기까지 필요한지 먼저 정하세요. Dots 문서는 기존 ChatGPT 앱 권한이 적용돼서 "메일 읽기만 허용, 보내기는 불허"처럼 나눌 수 있다고 해요. Muse도 서비스가 지원하면 읽기와 쓰기 권한을 분리해요.
- Claude 커넥터는 내 권한을 그대로 상속하고, 전송·공유·삭제 전에 기본적으로 승인을 물어요. 필요 없는 도구는 꺼 두세요. 자세한 내용은 [C7. 커넥터](/new-project1/claude/c07-connectors/)에서 다뤄요.
- 안 쓰는 서비스는 연결을 해제하세요. 서드파티 서비스는 자체 인프라와 약관이 적용돼요.
- 루틴처럼 자동으로 도는 작업은 **기본 포함된 커넥터를 점검**해서 필요 없는 것을 빼세요. [C13](/new-project1/claude/c13-cloud-sessions/)의 루틴 요약표에 "전체 커넥터가 기본 포함된다"고 나와 있어요.
- Grok Bot은 모든 Bot이 한 클라우드 컴퓨터를 공유하므로 **Bot을 보안 경계로 쓰지 말라**고 해요. 민감한 서비스는 Bot마다 나누는 것으로는 격리되지 않아요.

### 3. 승인 단계 켜기

되돌릴 수 없는 일(발송, 삭제, 권한 변경, 결제, 약관 동의)은 **항상 묻도록** 설정하세요.

- **Dots**: 설정 > 개인 설정 > 권한 > Custom rules에서 "실행 전 확인"이나 "나에게 넘기기"를 고를 수 있어요. 규칙은 "dot이 따르려 하는 지침이며 실수할 수 있다"고 문서가 밝히고, 앱·컴퓨터 접근을 새로 주지는 않아요. 지침에 "초안을 보여 주고 보내지 마"라고 쓰면 초안 작성이 발송 권한으로 읽히지 않아요.
- **Grok Bot**: 승인 카드에서 **Always allow**는 신중히 고르세요. 문서상 Ask first가 Allow automatically보다 우선해요. 루틴이나 다른 Bot에서 시작된 작업의 승인은 약 10분 뒤 만료돼 실행되지 않아요.
- **Muse**: 약관이 상태를 바꾸는 행동(메시지 발송, 금융 거래, 데이터 삭제, 설정 변경)은 사전 사람 검토 없이 하지 말라고 하고, 사전 승인을 주는 것도 신중하라고 해요.
- **Claude in Chrome**: Manual은 매 동작 승인, Auto는 안전 검사를 하며 진행, Skip은 검사 없이 실행이에요. 처음에는 Manual로 시작하세요. 파일 다운로드와 민감 정보 입력은 "항상 허용"한 사이트에서도 물어요. [C11](/new-project1/claude/c11-chrome-computer-use/)에 정리돼 있어요.

<Aside type="caution" title="루틴은 승인 없이 자율 실행돼요">
Claude 루틴은 사람이 지켜보지 않는 상태로 돌아요. 커밋과 PR이 내 GitHub 사용자 이름으로 남고, 브랜치는 `claude/` 접두사로 올라가요. 루틴을 만들 때는 저장소, 환경(네트워크 수준), 커넥터를 좁게 정하세요. [C13](/new-project1/claude/c13-cloud-sessions/)의 "루틴 요약"을 먼저 보세요.
</Aside>

### 4. 결제는 한도 있는 수단으로, 매번 승인

<Aside type="caution" title="에이전트 쪽 지출 상한은 확인되지 않았어요">
Grok Bot 문서에서는 전용 결제 수단과 지출 상한 기능을 확인하지 못했고, Dots 문서에서는 결제 기능 자체를 확인하지 못했어요. Muse는 Stripe Link 일회용 카드와 구매 전 승인이 있지만, 이 보호는 "적격 구매"에 한정된다고 Meta가 밝혀요. 이 점검표는 **지출 상한을 내가 직접 만든다**는 전제로 쓰였어요.
</Aside>

- 에이전트에게 쓰는 카드는 **한도가 낮은 별도 카드나 일회용 카드**로 하세요. 주 카드는 연결하지 마세요.
- 구매·이체·권한 변경은 요청문에 **경계를 명시**하세요. 예: "상품 후보까지만 찾고, 결제는 하지 마세요." Grok Bot 문서도 구매, 금융 이체, 삭제, 권한 변경, 약관 동의는 요청에서 경계를 정하라고 권해요.
- 결제 확인은 내가 직접 하세요. Grok Bot은 결제 확인을 사용자가 컴퓨터를 직접 인수해 입력하게 해요. Muse는 결제 페이지를 감지하면 구매 세부 내용을 매번 사람이 승인하게 해요.
- Muse 약관은 사용자가 Muse의 모든 행동에 책임을 지고, 책임 한도를 "$250 또는 12개월간 지불액 중 큰 쪽"으로 제한한다고 규정해요. 금융 피해가 나도 서비스가 전부 보상해 주는 구조가 아니에요.
- Claude의 컴퓨터 사용은 투자·거래 플랫폼과 암호화폐 앱을 기본으로 막고, 은행·의료·정부 앱, 금융 계좌·법률 문서·의료 정보 작업에는 쓰지 말라고 권고해요.

### 5. 비밀번호와 코드는 채팅에 쓰지 않기

- 비밀번호, 패스키, 2단계 인증 코드, CAPTCHA는 각 제품의 **전용 입력 경로**를 쓰세요. Grok Bot은 일반 채팅에 비밀번호나 일회용 코드를 보내지 말라고 하고, 지원되는 연결은 "secure secret request"(가려짐, 대화 기록과 모델에서 제외)예요. Dots는 로그인 정보를 대화 밖 브라우저로 전달해요.
- Muse의 이메일 커넥터는 일회용 코드, 비밀번호 재설정 링크, 매직 로그인 링크를 걸러내요. 그래도 그런 메일은 에이전트 계정에 연결한 메일함에 오지 않게 하는 쪽이 안전해요.
- Claude 클라우드 환경에서는 환경변수와 설정 스크립트를 쓰는 사람 누구나 읽을 수 있으니 **비밀을 저장하지 마세요.** Pro/Max는 네트워크 시크릿(프록시가 요청에 키를 붙여 줌)을 쓸 수 있어요.
- 세션을 공유할 때는 대화에 자격 증명이 들어 있는지 먼저 확인하세요. 공개(Public)로 하면 claude.ai에 로그인한 모든 사용자가 볼 수 있어요.

### 6. 사용량·비용 한도 정하기

- **Claude**: 설정(Settings) > 사용량(Usage)의 Usage credits에서 **월 지출 한도**를 정하거나 꺼 둘 수 있어요. 켜 두면 한도 도달 후 종량제로 이어서 쓰고, 루틴도 한도에 닿으면 usage credits가 켜져 있을 때 초과분이 종량제로 계속 실행돼요. 한도 구조는 [C2. 요금제와 사용량 한도](/new-project1/claude/c02-plans-limits/)를 보세요.
- **Grok Bot**: Bot 전용 주간 사용량이 있고, 소진 시 on-demand(종량제) 사용량이 Cursor로 청구될 수 있어요(Teams는 기본 켜짐). 가입 후 청구 설정을 확인하세요.
- **Dots**: dot과의 대화는 ChatGPT 사용 한도에 포함되지 않지만, dot이 시작·관리하는 Work/Codex 작업은 해당 제품 한도에 포함돼요.
- **Muse**: 추가 AI 사용량 구매 옵션이 있을 수 있고, 크레딧은 환불·현금 교환이 안 된다고 약관에 있어요.

### 7. 로그와 결과를 확인하기

- 에이전트가 "완료"라고 해도 결과를 확인하세요. Dots 문서가 "완료된 실행이 결과 달성을 보장하지 않는다"고 직접 말해요.
- Muse는 활동 로그, Dots는 Activity와 Scheduled 화면, Claude 클라우드 세션은 결과 diff 검토 화면이 있어요. 며칠에 한 번 **무엇을 했는지** 훑어보는 날을 정하세요.
- 반복 작업(Dots의 Scheduled, Grok Bot의 루틴, Claude의 루틴)은 목록을 주기적으로 열어 필요 없는 것을 지우세요.
- Dots의 Pause는 현재 주 작업만 멈춰요. 위임 작업과 예약 실행은 따로 멈춰야 하고, 통화를 끊는다고 작업이 멈추지는 않아요.

### 8. 개인정보·학습 설정과 공유 기기

**학습과 개인정보**

| 제품 | 확인할 것 |
| --- | --- |
| Muse | 상호작용을 AI 학습에 쓰는 설정이 **처음에 켜져 있어요.** 설정(Settings) > 데이터 컨트롤(Data controls)에서 끌 수 있고, 끄면 이전 상호작용에도 적용돼요. Meta는 현재 구조가 Meta가 필요할 때 데이터에 접근하는 것을 막지 않는다고 밝혀요. |
| Grok Bot | 클라우드 데이터 저장이 필수라 Cursor의 Legacy Privacy Mode 계정은 시작할 수 없어요. 학습 거부는 Cursor 계정과 개인정보 설정을 따르고, Bot의 컴퓨터는 현재 미국에서 실행돼요. |
| Dots | ChatGPT 데이터 제어가 적격 대화와 작업에 적용돼요. 능동적 리서치와 비공개 노트로는 모델을 직접 학습시키지 않는다고 문서가 밝혀요. 비공개 대화 내용을 다른 사람에게 공유하기 전에는 허락을 확인해요. |
| Claude | Gmail, Drive, Calendar 커넥터 데이터로는 모델을 학습하지 않아요. 기록을 남기고 싶지 않은 대화는 시크릿(incognito) 채팅을 쓸 수 있어요. 채팅 내용의 일반 학습 설정은 이 문서에서 다루지 않아요. 계정 설정에서 확인하세요. |

**공유 기기**

- 공용 PC나 가족 기기에 에이전트 앱을 로그인해 두지 마세요. 쓰고 나면 로그아웃하세요.
- Dots는 내 컴퓨터 연결이 선택 기능이고 한 번에 한 대만 돼요. 연결을 켠 컴퓨터는 앱이 열려 있는 동안 접근 대상이에요. 공유 기기에서는 켜지 마세요.
- Claude의 컴퓨터 사용은 **샌드박스가 없어서 화면에 보이는 모든 것을 볼 수 있어요.** 사용 전에 민감한 앱과 창을 닫아 두세요.
- Grok Bot은 모든 Bot이 같은 컴퓨터를 공유하므로, 작업이 끝나면 서비스에서 로그아웃하고 임시 파일을 정리하고 커넥터 승인을 해제하라고 권해요. Bot을 지워도 공유 컴퓨터의 파일과 브라우저 세션은 지워지지 않아요.
- Grok Bot을 공유 링크로 공유하면 **설정(구성)이 노출**돼요. 비밀, 고객 정보, 내부 URL을 넣지 마세요.

## 자주 막히는 지점

### 승인 창이 너무 자주 떠서 귀찮아요

- **원인**: 기본 설정이 되돌릴 수 없는 일에서 멈추도록 되어 있어요.
- **해결**: 읽기 작업은 허용하고, 보내기·삭제·결제만 승인으로 남기세요. 자동 허용은 믿을 수 있는 반복 작업 한 가지부터 좁게 주세요. Grok Bot 문서도 Auto Review가 명시적 승인을 대체하지 않는다고 해요.

### 에이전트가 잘못 보낸 메일을 취소하고 싶어요

- **원인**: 연결 앱에서 이미 한 변경이나 보낸 메시지는 에이전트를 멈추거나 지워도 되돌려지지 않아요(Dots 문서).
- **해결**: 수신자에게 직접 연락하고, 그 권한을 해제한 뒤 승인 단계를 다시 설정하세요.

### 에이전트에게 카드를 줘도 되는지 모르겠어요

- **원인**: 결제 보호는 제품마다 다르고, 상한 설정은 확인되지 않았어요.
- **해결**: 카드사 앱에서 한도를 낮춘 별도 카드를 만들고, 첫 달에는 결제 없이 후보 정리까지만 맡기세요.

## 실전 팁

- **권한은 필요할 때만 켜고 끝나면 끄세요.** 연결 해제는 언제든 가능해요.
- **요청문에 "하지 말 것"을 쓰세요.** 보내기, 지우기, 결제하기를 명시적으로 금지하면 실수 확률이 줄어요.
