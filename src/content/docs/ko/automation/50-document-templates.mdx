<Summary>
- 템플릿을 한 번 만들어 두세요(고정 섹션, 채울 칸, 어조, 예시). 그러면 같은 프롬프트를 매번 다시 쓰지 않아도 돼요.
- **Claude 프로젝트**는 문서와 지침을 한곳에 모아 둬요. Anthropic 설명으로는 파일을 프로젝트 지식에 올리고, 프로젝트의 모든 대화에 적용되는 프로젝트 지침을 정해요. 프로젝트는 모든 사용자가 쓸 수 있고, 무료 계정은 최대 5개예요.
- **Claude 스킬**은 반복 작업 흐름을 묶어 둬요. skill.md 파일이 든 폴더를 ZIP으로 만들어 Customize > Skills에 올려요. 코드 실행이 켜져 있어야 해요.
- **Google Docs**에는 직접 채워 쓰는 문서용 템플릿 갤러리가 따로 있어요.
- 템플릿에는 사람의 데이터가 아니라 구조만 넣으세요. 실제 개인정보, 비밀번호, 회사 기밀 양식은 공유할 템플릿에 넣지 마세요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 계속 다시 쓰던 문서를 채울 칸이 분명한 템플릿으로 바꿀 수 있어요.
- 저장한 프롬프트, Claude 프로젝트, Claude 스킬, Google Docs 템플릿 중 맞는 것을 고를 수 있어요.
- 실제처럼 보이는 가짜 입력으로 템플릿을 시험할 수 있어요.
- 개인정보와 회사 소유 양식을 엉뚱한 곳에 넣지 않을 수 있어요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **템플릿** | 매번 빈칸만 채우면 되는 고정된 문서 구조. |
| **채울 칸(필드)** | 템플릿 안의 표시된 빈칸. 예: 날짜, 고객명. |
| **프로젝트 지식** | Claude 프로젝트에 올린 파일. 프로젝트의 모든 대화에서 쓰여요. |
| **프로젝트 지침** | 프로젝트마다 한 번 정해 두면 모든 대화에 적용되는 글. |
| **스킬** | 특정 반복 작업 방식을 Claude에게 알려 주는, skill.md 파일이 든 폴더. |

<Aside type="note" title="참고할 점 (2026-11-02 기준)">
- 이 글은 머리말의 공식 문서 5개를 바탕으로 해요. 실제 계정에서 단계를 실행해 보지는 않았으니, 메뉴 이름은 도움말 기준이에요.
- Anthropic 프로젝트 문서는 새 버전의 프로젝트가 베타로 단계적으로 배포 중이라고 해요. 이 글은 그 문서처럼 현재 버전을 설명해요. 화면이 다를 수 있어요.
- ChatGPT, Gemini, Microsoft Word의 템플릿·재사용 기능에 대한 공식 도움말은 읽지 않아서 설명하지 않아요. Google Docs 템플릿은 도움말 한 페이지만 근거로 해요.
- 스킬 파일 이름: 도움말은 skill.md라고 적어요. 다른 Claude 제품이 다른 대소문자를 요구하는지는 확인하지 못했어요.
- 기능과 메뉴는 자주 바뀌어요. 화면에서 직접 확인하세요.
</Aside>

## 따라 하기

먼저 문서 하나만 고르세요. 매주 쓰는 문서의 템플릿이 가장 빨리 효과를 봐요.

<Checklist items={[
  '반복해서 쓰는 문서 하나를 골랐다',
  '지난 실제 사례 두세 개를 모으고 이름과 사적인 내용을 지웠다',
  '매번 바뀌는 부분(필드)과 고정된 부분을 표시했다',
  '회사나 고객이 정한 공식 양식이 있는지 확인했다',
  '실제 내용을 넣기 전에 가짜 입력으로 템플릿을 시험했다',
]} />

<Steps>

1. **사례를 모으고 사적인 내용 지우기**

   완성된 문서 두세 개를 모으세요. 올리거나 붙여 넣기 전에 실제 이름, 숫자, 주소, 기밀 내용은 자리표시자로 바꾸세요.

2. **AI가 패턴을 찾게 하기**

   <PromptBox>
   아래는 제 주간 업무 보고서 세 개예요. 사적인 내용은 이미 지웠어요. 매번 같은 부분과 바뀌는 부분을 찾아 주세요. 고정 섹션 제목, 대문자로 표시한 채울 칸, 섹션별 분량 목표, 제가 쓰는 어조를 담은 템플릿을 제안해 주세요. 템플릿만 보여 주고, 칸을 채우려면 제가 답해야 할 질문도 목록으로 알려 주세요.
   </PromptBox>

3. **채울 칸을 분명히 쓰기**

   칸 목록은 짧게 유지하세요. 칸마다 무엇을 넣는지, 언제 비워도 되는지 적으세요. 이 사이트의 프롬프트 상자 안에는 중괄호를 쓰지 않으니 날짜, 고객명처럼 말로 표시하세요.

4. **다시 쓸 곳에 저장하기**

   - **저장한 프롬프트**: 메모에 템플릿을 보관해요. 간단하고 어떤 채팅 AI에서도 써요.
   - **Claude 프로젝트**: claude.ai/projects에서 **+ New Project**를 눌러 이름을 정해요. Claude는 프로젝트 이름과 설명을 볼 수 없다는 점에 유의하세요. 프로젝트 지식의 **+** 버튼으로 사례를 올리고, **Set project instructions**를 눌러 템플릿과 규칙을 붙여 넣은 뒤 **Save instructions**를 눌러요. Anthropic은 Claude가 이 지침을 프로젝트의 모든 대화에 쓰고, 프로젝트 지식에 넣지 않은 맥락은 대화 간에 공유되지 않는다고 설명해요.
   - **Claude 스킬**: 프롬프트보다 큰 작업 흐름용이에요. 아래 스킬 단계를 보세요.
   - **Google Docs 템플릿**: 사람이 직접 채워 쓰는 문서용이에요. Docs에서 **파일 > 새로 만들기 > 템플릿에서**로 템플릿을 넣고, **파일 > 사본 만들기**로 나만의 원본을 복제해 쓸 수 있어요.

5. **새 내용으로 쓰기**

   <PromptBox>
   저장한 템플릿으로 이번 주 보고서를 써 주세요. 제 메모는 이래요: (여기에 메모를 붙여 넣기). 메모로 채울 수 있는 칸은 모두 채우고, 메모에 없는 칸은 추측하지 말고 입력 필요라고 적어 주세요.
   </PromptBox>

   "입력 필요" 규칙이 중요해요. AI가 숫자, 날짜, 이름을 지어내지 못하게 막아 줘요.

6. **선택: 템플릿을 스킬로 묶기**

   Anthropic 설명으로 스킬은 최소한 skill.md 파일이 든 디렉터리예요. 파일은 이름(최대 64자)과 설명(최대 200자)이 든 YAML 머리말로 시작해요. Claude가 설명을 보고 스킬을 쓸지 정하기 때문이에요. 본문에 템플릿, 규칙, 예시를 넣으세요. 추가하려면 스킬 폴더가 루트가 되도록 ZIP으로 묶고, **Customize > Skills**에서 **+** 버튼, **+ Create skill**, **Upload a skill** 순으로 선택해요. 스킬에는 코드 실행이 켜져 있어야 하고, 올린 사용자 지정 스킬은 공유하기 전에는 동료에게 보이지 않아요.

   <PromptBox>
   제 주간 업무 보고서용 skill.md 파일을 쓰도록 도와 주세요. 이름, 언제 쓰는지 알려 주는 한 문장 설명, 고정 섹션 제목, 채울 칸, 정보가 없으면 입력 필요라고 쓰는 규칙, 가짜 데이터로 만든 짧은 예시 하나를 넣어 주세요.
   </PromptBox>

7. **시험하고 개선하기**

   서로 다른 가짜 입력 두세 개로 템플릿을 돌려 보세요. 스킬이라면 Anthropic은 스킬을 불러야 하는 여러 프롬프트를 시도해 보고, Claude가 기대한 때 쓰지 않으면 설명을 고치라고 해요. 결과물만이 아니라 템플릿 자체를 고치세요.

8. **결과는 항상 검토하기**

   템플릿은 일관된 구조를 줄 뿐 내용이 맞다는 보장은 아니에요. 보내기 전에 읽고, 사실·숫자·이름을 원본과 대조하세요. [AI 답변 믿어도 될까: 사실 확인하는 법](/ko/basics/04-fact-checking/)을 참고하세요.

</Steps>

| 방법 | 잘 맞는 일 | 공식 문서 내용 |
| --- | --- | --- |
| 메모에 저장한 프롬프트 | 일회성이거나 아무 채팅 AI | 설정 필요 없음 |
| Claude 프로젝트 | 여러 대화에서 같은 문서와 지침 | 모든 사용자, 무료 계정은 프로젝트 5개 한도, 유료 플랜은 지식이 한도에 가까워지면 RAG 사용 |
| Claude 스킬 | 규칙이나 파일이 필요한 반복 작업 | 코드 실행 필요, ZIP 업로드, 업로드 후 테스트 |
| Google Docs 템플릿 | 사람이 직접 채우는 문서 | 사본이 새 파일로 열림, 일부 템플릿 기능은 업무·학교 계정 필요 |

### 공유

| 위치 | 도움말 내용 |
| --- | --- |
| 프로젝트 (Team·Enterprise) | 구성원과 공유 가능, 보기(Can view) 또는 편집(Can edit), 소유자가 공유를 끌 수 있음 |
| 스킬 (Team·Enterprise) | 공유받은 스킬은 받는 사람이 보기 전용, 소유자는 조직에 게시 가능 |
| 스킬 (개인 플랜) | 올린 사용자 지정 스킬은 공유 전에는 동료에게 안 보임 |

## 자주 막히는 곳

### Claude가 템플릿을 무시해요

- **원인**: 지침이 모호하거나 템플릿이 예전 대화에만 있어요. Anthropic은 프로젝트 지식에 넣지 않은 맥락은 대화 간에 공유되지 않는다고 해요.
- **해결**: 템플릿을 프로젝트 지침이나 프로젝트 지식에 넣고 프로젝트에서 새 대화를 시작하세요.

### 스킬이 작동하지 않아요

- **원인**: 설명이 언제 쓰는지 불분명해요. Anthropic은 Claude가 설명을 보고 스킬을 부를지 정한다고 해요.
- **해결**: 설명을 구체적으로 고치고 여러 프롬프트로 시험하세요.

### ZIP 업로드가 거부되거나 스킬이 안 보여요

- **원인**: Anthropic은 폴더 이름이 스킬 이름과 같아야 하고, ZIP 루트가 낱개 파일이 아니라 스킬 폴더여야 한다고 해요.
- **해결**: 그 구조대로 다시 묶으세요. 코드 실행이 켜져 있는지도 확인하세요.

### 결과에 지어낸 내용이 있어요

- **원인**: AI가 빈칸을 그럴듯한 추측으로 채웠어요.
- **해결**: "입력 필요" 규칙을 넣고, 원본 메모를 더 주고, 사실을 하나씩 확인하세요.

## 실전 팁

- **공식 양식을 존중하세요.** 회사, 학교, 고객이 정한 문서 형식이 있으면 그것을 쓰세요. AI는 내용 초안에 쓰고, 필수 양식을 새로 디자인하는 데 쓰지 마세요. 먼저 소속 기관의 AI 규정을 확인하세요.
- **템플릿에 개인정보를 넣지 마세요.** 템플릿은 재사용되고 가끔 공유돼요. 이름, 주민등록번호 같은 식별번호, 건강·금융 정보는 넣지 마세요. [개인정보·회사 정보 안전하게 지키며 쓰기](/ko/basics/05-privacy-safety/)를 참고하세요.
- **비밀을 녹화하지 마세요.** Anthropic은 스킬을 녹화할 때 비밀번호를 입력하거나 민감 정보를 띄우지 말고, 스킬에 API 키나 비밀번호를 직접 적지 말라고 경고해요. 내려받은 스킬은 켜기 전에 검토하세요.
- **공유는 신중하게.** Team·Enterprise 플랜에서는 공유한 프로젝트나 스킬을 누가 볼 수 있는지 확인한 뒤 회사 자료를 넣으세요.
- **문서 종류마다 템플릿 하나.** Anthropic은 스킬을 하나의 작업 흐름에 집중시키라고 권해요.
- **버전 메모를 남기세요.** 템플릿 맨 위에 날짜를 적고, 형식이 바뀌면 갱신하세요.
