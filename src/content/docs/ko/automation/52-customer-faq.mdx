<Summary>
- 흐름은 **실제 문의 모으기(개인정보 가리기) → 정책 적어 두기 → AI로 문의 묶고 FAQ 초안 → 답변 유형별 템플릿 → 프로젝트·Gem에 정책 보관 → 모든 답변은 발송 전 검토**예요.
- Claude 프로젝트, ChatGPT 프로젝트, Gemini Gem은 모두 공유 파일과 지침을 한곳에 둘 수 있어요. Anthropic 도움말은 프로젝트 지침이 그 프로젝트의 모든 채팅에 적용된다고 설명해요.
- **정책은 회사가 정해요.** 환불 조건, 배송 날짜, 가격은 직접 정하고, AI는 문장만 다듬게 하세요.
- 붙여 넣기 전에 **고객 이름, 이메일, 주문번호, 전화번호를 가리세요.**
- **AI는 초안, 발송은 사람이.** 이 글의 연습은 실제 고객 메일로 실행하지 않았어요. 프롬프트와 예시 FAQ는 이 사이트가 만든 예시예요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 지난 고객 문의를 **주제별로 묶고** 짧은 FAQ로 정리할 수 있어요.
- 답변 유형마다 사람이 빈칸만 채우면 되는 **답변 템플릿**을 만들 수 있어요.
- 정책·말투·템플릿을 프로젝트(또는 Gem)에 보관해 매번 붙여 넣지 않아도 돼요.
- AI 초안과 고객 사이에 **검토 단계**를 둘 수 있어요.

문서 템플릿 전반은 [AI로 반복 문서 템플릿 만들기](/ko/automation/50-document-templates/)를, 영업·고객 지원 업무 전체는 [영업·고객 지원을 위한 AI 활용 가이드](/ko/roles/sales-support/)를 보세요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **FAQ** | 자주 묻는 질문과 승인된 짧은 답을 모은 목록. 고객이나 직원이 읽어요. |
| **답변 템플릿** | 고정 문구와 빈칸([고객 이름], [주문 상태] 등)으로 이루어진 답장. 사람이 빈칸을 채워요. |
| **정책 시트** | 배송 기간, 환불 조건, 운영 시간, 하지 않는 일 등 실제 규칙을 한 장에 적은 것. AI는 이 범위를 넘으면 안 돼요. |
| **프로젝트 / Gem** | 자체 파일과 지침을 가진 저장된 작업 공간. 모든 채팅이 같은 맥락으로 시작해요. |
| **가리기(마스킹)** | AI 서비스에 올리기 전에 개인정보를 CUSTOMER_A 같은 표시로 바꾸는 일. |

<Aside type="caution" title="고객 정보">
지난 메일과 채팅에는 이름, 주소, 주문번호, 때로는 결제·건강 정보가 들어 있어요. 붙여 넣기 전에 표시로 바꾸고, 회사 규정을 먼저 확인하세요. [개인정보·회사 정보 안전하게 지키며 쓰기](/ko/basics/05-privacy-safety/)를 보세요. 공유해도 되는지 모르겠으면 넣지 마세요.
</Aside>

- 고객 지원 답변 작성의 정확도에 대한 공식 수치는 찾지 못했고 직접 시험하지도 않았어요.
- 프로젝트 파일의 크기 한도는 서비스별로 자세히 읽지 않았어요. 앱에 표시된 한도를 확인하세요.

### 서비스별 공유 파일·지침 보관 방식 (2026-11-09 확인)

| 서비스 | 공식 도움말 내용 | 확인하지 못한 것 |
| --- | --- | --- |
| **Claude** | 프로젝트는 무료 계정을 포함한 모든 사용자가 쓸 수 있고, 무료는 최대 5개까지 만들 수 있어요. 문서·텍스트·코드를 프로젝트 지식에 추가하고 프로젝트 지침을 설정하면 프로젝트의 모든 채팅에 쓰여요. 프로젝트 지식에 넣지 않으면 채팅 사이에 맥락이 공유되지 않아요. Team·Enterprise는 비공개 또는 공유가 가능하고 "보기"·"편집" 권한이 있어요. | 내 계정에 프로젝트 새 베타 버전이 이미 적용됐는지. |
| **ChatGPT** | 웹에서 프로젝트는 관련 채팅, 파일, 지침, 소스를 한곳에 모아요. 프로젝트 지침은 모든 채팅에 적용돼요. ChatGPT 프로젝트는 내 컴퓨터 폴더에 직접 접근하지 않으므로 소스를 업로드하거나 연결해야 해요. | 요금제별 제공 여부와 파일 한도(읽은 페이지에 없음). |
| **Gemini** | 이름과 지침으로 Gem을 만들고, "Knowledge"에서 기기, Google 드라이브, NotebookLM 노트북의 파일을 추가할 수 있어요. 당분간 Gem은 Gemini Live와 함께 쓸 수 없어요. | 전환된 Gem이 스킬로 얼마나 똑같이 동작하는지(날짜와 파일 한도는 Google 전환 안내 페이지에 있어요). |

## 따라 하기

가상의 고객이나 가린 사본으로 먼저 연습하세요.

<Checklist items={[
  '이름, 이메일, 전화번호, 주문번호를 표시로 바꿨다',
  '실제 정책을 한 장에 적었다 (배송, 환불, 운영 시간, 예외)',
  '발송 전에 답변을 검토할 사람이 정해져 있다',
  'AI가 가격, 날짜, 약속을 지어내지 못하게 할 것이다',
  '이 문서를 이 AI 서비스에 올려도 된다',
]} />

<Steps>

1. **실제 문의 모으기**

   이메일, 채팅, 메시지로 고객이 실제로 한 질문 10~20개를 복사하세요. 개인정보는 가리세요. 상상한 질문보다 실제 질문이 낫습니다. 고객이 쓰는 표현이 보이거든요.

2. **정책 시트는 직접 쓰기**

   배송 기간, 환불·교환 조건, 운영 시간, 문의처를 한 장에 적으세요. **하지 않는 일**도 적으세요. 환불 조건과 가격은 사업상 결정이므로 AI가 지어내면 안 돼요.

3. **AI에게 문의 묶기**

   <PromptBox>
   아래는 고객 문의를 모은 거야. 주제별로 묶어줘(예: 배송, 환불, 계정, 제품 사용). 묶음마다 짧은 주제 이름, 문의 개수, 예시 하나를 알려줘. 아직 답변은 쓰지 마. 문의: [가린 문의 붙여넣기]
   </PromptBox>

4. **정책 시트만 근거로 FAQ 초안 쓰기**

   <PromptBox>
   아래 정책 시트만 근거로, 위 주제별로 짧은 답변을 쓴 FAQ를 만들어줘. 정책 시트에 없는 내용은 답하지 말고 "결정 필요"라고 써줘. 시트에 없는 가격, 날짜, 약속은 추가하지 마. 말투는 친절하고 쉽게. 정책 시트: [정책 붙여넣기]
   </PromptBox>

   모든 줄을 정책 시트와 대조하세요. "결정 필요" 줄은 AI가 아니라 내가 채울 빈틈이에요.

5. **답변 유형을 템플릿으로**

   <PromptBox>
   FAQ의 [주제] 답변을 이메일 답변 템플릿으로 바꿔줘. 정책 문구는 그대로 두고, 사람이 채워야 할 부분(예: [고객 이름], [주문 상태])은 대괄호 빈칸으로 만들어줘. 맨 끝에 발송 전에 확인할 점을 한 줄로 적어줘.
   </PromptBox>

   배송 지연, 환불 요청, 아직 답할 수 없는 질문처럼 흔한 상황마다 템플릿을 하나씩 만드세요.

6. **프로젝트·Gem에 저장**

   - **Claude**: 프로젝트를 만들고 정책 시트와 템플릿을 프로젝트 지식에 추가하고, 말투 규칙은 프로젝트 지침에 적으세요.
   - **ChatGPT**: 프로젝트를 만들고 같은 파일을 올리고, 지침을 프로젝트에 적으세요.
   - **Gemini**: 지침으로 Gem을 만들고 Knowledge에 파일을 추가하세요. 먼저 Google의 Gem→스킬 전환 안내를 확인하세요.

   실제 고객 정보가 없는 지침 예시예요.

   <PromptBox>
   너는 고객 답변 초안을 쓰는 도우미야. 첨부한 정책 시트와 템플릿만 사용해. 가격, 날짜, 환불 조건, 약속을 절대 지어내지 마. 정책에 없는 질문이면 그렇다고 말하고 직원이 정해야 할 것을 알려줘. 모든 초안 맨 위에 "검토 필요 초안"이라고 표시해. 답변은 짧고 정중하게.
   </PromptBox>

7. **답변 초안 받고 검토하기**

   프로젝트나 Gem의 새 채팅에 가린 고객 메시지를 붙여 넣고 알맞은 템플릿으로 초안을 요청하세요. 보내기 전에 사람이 아래 검토표를 확인하고, 실제 이름과 주문 정보를 다시 넣은 뒤, 회사 메일이나 지원 도구에서 직접 발송하세요.

8. **정책이 바뀌면 갱신하기**

   규칙이 바뀌면 정책 시트를 먼저, 그다음 FAQ와 템플릿을 고치세요. 프로젝트·Gem의 옛 파일을 바꾸고 날짜를 적어 두세요.

</Steps>

## 한눈에 보는 요약

### 발송 전 검토표

| 확인 | 이유 |
| --- | --- |
| 정책 일치 | 답변의 모든 규칙이 정책 시트에 있다 |
| 숫자·날짜 | 가격, 기한, 금액은 AI가 아니라 내 기록에서 가져온다 |
| 약속 | 회사가 정하지 않은 약속이 없다 |
| 말투 | 정중하고 고객을 탓하지 않는다 |
| 개인정보 | 해당 고객의 정보만 있고 다른 건의 정보가 없다 |
| 어려운 경우 | 불만, 안전, 법률, 건강 문의는 사람이 처리한다 |

### 오류를 줄이는 프롬프트 규칙

| 규칙 | 이유 |
| --- | --- |
| "정책 시트만 사용" | 답변이 내 규칙 안에 머문다 |
| "결정 필요라고 쓰기" | 빈틈이 보인다 |
| "가격·날짜 추가 금지" | 지어낸 내용을 막는다 |
| "검토 필요 초안 표시" | 사람이 확인해야 함을 상기시킨다 |
| 대괄호 빈칸 | 사람이 채울 부분이 드러난다 |

## 자주 막히는 부분

### AI가 없는 정책을 지어내요

- **원인**: 정책 시트에 없는 질문이라 AI가 빈틈을 채워요.
- **해결**: 규칙이 있다면 시트에 추가하세요. 없다면 "결정 필요" 지시를 유지하고 직접 결정하세요.

### 답변 말투가 매번 달라요

- **원인**: 말투를 적어 두지 않았거나 채팅마다 맥락 없이 시작해요.
- **해결**: 말투 규칙과 승인된 예시 답변 두세 개를 프로젝트·Gem에 넣으세요. Anthropic 도움말은 프로젝트 지식에 넣지 않은 맥락은 채팅 사이에 공유되지 않는다고 설명해요.

### Gem이나 프로젝트 화면이 이 글과 달라요

- **원인**: 서비스가 바뀌는 중이에요. Google은 Gem을 스킬로 옮길 예정이고, Anthropic은 프로젝트 새 버전을 단계적으로 내보내고 있어요.
- **해결**: 화면에 보이는 메뉴를 따르고 링크된 도움말을 확인하세요.

## 실전 팁

- **작게 시작하세요.** 가장 자주 오는 질문 다섯 개부터요.
- **기록을 남기세요.** 정책이 바뀐 날짜와 템플릿을 승인한 사람을 적어 두세요.
- **민감한 문의를 AI에게만 맡기지 마세요.** 불만, 분쟁 중인 환불, 안전, 건강, 법률 문의는 사람이 처리해야 해요. 이 글은 법률 조언이 아니에요.
- **사실을 확인하세요.** [AI 답변 믿어도 될까: 사실 확인하는 법](/ko/basics/04-fact-checking/)을 보세요.
- **권리와 윤리를 살피세요.** [AI 결과물, 써도 될까? 저작권·윤리 기초](/ko/basics/09-ai-copyright-ethics/)을 보세요.
- **필요하면 고객에게 알리세요.** 답변에 AI를 썼다고 밝혀야 하는 회사·지역 규정이 있다면 따르세요. 그런 규정은 조사하지 않았어요.
