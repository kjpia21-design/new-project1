<Summary>
- **Claude Design**은 Claude와 대화하면서 디자인, 클릭되는 프로토타입, 원페이저 같은 시각 결과물을 만드는 기능이에요. 아티팩트의 템플릿 중 하나라서 **어느 대화에서나**, Artifacts 탭에서, Claude Code에서 쓸 수 있어요(2026-10-31 기준).
- Free, Pro, Max, Ultra, Team, Enterprise 플랜에서 쓸 수 있고 기본으로 켜져 있어요. Enterprise는 2026-10-15부터 기본 켜짐이에요.
- 예전의 **독립 버전(claude.ai/design)은 2026-12-14에 종료**돼요. 거기서 만든 프로젝트와 디자인 시스템은 그날 전에 Claude로 옮겨야 해요.
- 첫 결과는 시작점이에요. **채팅(큰 변경), 인라인 코멘트(특정 부분), 캔버스 직접 편집(간단한 시각 수정)** 세 가지로 다듬어요.
- 별도 사용량은 없고 **다른 Claude 사용량과 같은 한도**를 써요. 한도에 닿으면 리셋될 때까지 못 쓰고, usage credits를 켜 두었다면 계속할 수 있어요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 화면 시안이나 원페이저를 대화 한두 번으로 만들어 캔버스에서 확인할 수 있어요.
- 채팅, 인라인 코멘트, 직접 편집 중 상황에 맞는 수정 방법을 골라 쓸 수 있어요.
- 결과를 PDF, PPTX, HTML 등으로 내보내거나 팀에 공유하고, 개발 단계로 Claude Code에 넘길 수 있어요.
- 독립 버전 종료 일정과 한계를 알고 안전하게 옮길 준비를 할 수 있어요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **Claude Design** | 대화와 캔버스를 짝지어 디자인을 만드는 기능이에요. 대화에서 설명하면 옆의 캔버스에 실제로 동작하는 디자인이 만들어져요. |
| **캔버스와 아트보드** | 디자인은 아트보드(화면 한 장) 여러 개가 놓인 캔버스예요. 아트보드 안에는 글, 도형, 이미지 같은 레이어가 들어 있어요. |
| **디자인 시스템** | 조직의 색, 글꼴, 컴포넌트 규칙 모음이에요. 붙여 두면 Claude가 그 규칙으로 만들고, 결과가 규칙과 맞는지 스스로 점검해서 고쳐요. |
| **인라인 코멘트** | 캔버스의 특정 위치를 눌러 "여기만 바꿔 줘"라고 남기는 메모예요. |
| **/design, /design-sync** | Claude Code에서 쓰는 명령이에요. `/design`은 디자인을 만들고 고치고 동기화하고, `/design-sync`는 디자인 시스템을 가져와요. |

이 기능은 [C6. 아티팩트](/ko/claude/c06-artifacts/)와 같은 틀 위에서 움직여요. 공유 방식과 일반 내보내기는 C6에 이미 정리돼 있어서 이 글에서는 디자인에 필요한 부분만 다뤄요. 문서·슬라이드까지 이어 만드는 방법은 [C8. 스킬](/ko/claude/c08-skills/)의 내장 스킬이나 [C21](/ko/claude/c21-office-agents/)을 함께 보세요.

<Aside type="caution" title="독립 버전(claude.ai/design)은 2026-12-14에 닫혀요">
도움말에 따르면 독립 버전은 닫히는 날까지 계속 동작하고, 기존 프로젝트도 그때까지 거기에 남아요. Claude로 옮기는 기능은 유료 플랜부터 순차적으로 열리고 있어요. **디자인 시스템은 닫히기 전에 Claude로 옮기라**고 안내돼요. 이 글은 Claude 안의 Design(통합 버전) 기준이에요(2026-10-31 기준).
</Aside>

<Aside type="note" title="확인되지 않은 점">
Design에서 쓸 수 있는 모델, 한국어 화면·한국어 글꼴 지원 범위, 플랜별 구체 사용량 수치는 이번에 읽은 공식 도움말에서 확인하지 못했어요. 한국어 결과가 필요하면 직접 시험해 보고 글꼴이 깨지지 않는지 확인하세요.
</Aside>

## 단계별 따라하기

<Steps>

1. **시작할 곳 고르기**

   가장 쉬운 방법은 아무 대화에서 "이 제안서로 원페이저 만들어 줘", "방금 얘기한 온보딩 흐름을 목업으로 만들어 줘"처럼 요청하는 거예요. 메시지 입력창에서 출력(Output) > 디자인(Design)을 고르거나, Artifacts 탭에서 Design 템플릿을 골라도 돼요. Claude Code에서는 터미널과 데스크톱 모두 `/design`을 쓸 수 있어요. iOS·Android 앱에서도 요청할 수 있고, 결과는 나중에 Artifacts 탭에서 전체 화면으로 볼 수 있어요. 다만 공유 설정은 웹이나 데스크톱에서만 바꿀 수 있어요.

   <ScreenshotPlaceholder caption="메시지 입력창의 출력(Output) 메뉴에서 Design을 고르는 화면" officialUrl="https://support.claude.com/en/articles/14604416-get-started-with-claude-design" />

2. **(선택) 디자인 시스템과 참고 자료 붙이기**

   새 프로젝트는 조직의 디자인 시스템을 자동으로 이어받는다고 안내돼요. 직접 붙일 때는 GitHub 저장소, 디자인 파일, 업로드한 파일, 또는 Claude Code의 `/design-sync`로 로컬 코드베이스에서 가져와요. 스크린샷, 경쟁 제품 화면, 와이어프레임, 기존 슬라이드나 문서도 "이런 느낌으로"의 참고 자료로 올릴 수 있어요. 도움말은 **스타일, 글꼴, 컴포넌트가 다 있는 완전한 디자인 시스템**을 가져올수록 결과가 좋고, 가져온 결과물은 원본 품질을 그대로 따라간다고 해요.

3. **목표, 배치, 내용, 대상을 적어 요청하기**

   공식 도움말이 꼽는 좋은 프롬프트의 네 요소는 **목표, 배치, 내용, 대상**이에요. 디자이너가 아니어도 구체적일수록 좋아요. 필요한 정보가 모자라면 Claude가 먼저 되물어요.

   <PromptBox>
   동네 도서관의 독서 모임 신청 페이지를 만들어 주세요. 대상은 40~60대 주민이고 모바일에서 주로 열어요. 맨 위에 모임 소개 한 줄과 신청 버튼, 그 아래에 일정 3개 카드(날짜·책 제목·정원), 맨 아래에 신청 폼(이름, 연락 방법 선택)을 넣어 주세요. 글자는 크게, 색은 차분한 톤으로, 모바일 화면 기준으로 만들어 주세요.
   </PromptBox>

   이 프롬프트는 예시예요. 실제 이름이나 연락처 같은 개인정보는 넣지 말고 가짜 값을 쓰세요.

4. **세 가지 방법으로 다듬기**

   첫 결과는 시작점이에요. 도움말은 수정 도구를 이렇게 나눠 써요.

   | 방법 | 이럴 때 | 예시 |
   | --- | --- | --- |
   | **채팅** | 전체 분위기, 구조, 새 섹션 등 큰 변경, 설명이 필요한 요청 | "색을 더 어둡고 단순하게", "대안 레이아웃 2~3개 보여 줘" |
   | **인라인 코멘트** | 특정 부분만 콕 집어 바꿀 때 | 버튼을 눌러 "여백을 더 크게", "라디오 버튼 대신 드롭다운으로" |
   | **캔버스 직접 편집** | 끌어서 옮기기, 크기 조절, 정렬 같은 빠른 시각 수정 | 요소를 끌어 정렬 |

   코멘트가 반영되지 않으면 같은 내용을 채팅에 붙여 넣으라고 안내돼요. 코멘트가 간헐적으로 사라지는 문제가 알려져 있어서예요. 다른 방향을 시험하고 싶다면 "지금 것을 저장하고 완전히 다른 접근으로 해 봐"라고 말하면 현재 작업을 저장했다고 알려 줘요. 도움말은 아직 버전 기록 기능이 없다고 밝히고 있어요.

   <FlowSteps title="결과물 다듬는 순서" officialUrl="https://support.claude.com/en/articles/14604416-get-started-with-claude-design" steps={[
     { where: '채팅', action: '목표·배치·내용·대상을 적어 첫 시안 요청', result: '캔버스에 첫 디자인이 나와요' },
     { where: '채팅', action: '구조나 분위기 같은 큰 변경을 요청' },
     { where: '캔버스', action: '고칠 부분에 인라인 코멘트를 남기거나 직접 끌어 편집' },
     { where: '우측 상단 내보내기(Export) 또는 공유(Share)', action: '형식을 고르거나 접근 수준을 정하기' },
   ]} />

5. **내보내기와 공유**

   프로젝트를 볼 때 오른쪽 위의 내보내기(Export) 버튼에서 형식을 골라요(2026-10-31 기준).

   | 목적 | 선택지 |
   | --- | --- |
   | 파일로 저장 | .zip 다운로드, PDF, PPTX, Google Slides, 독립 실행 HTML |
   | 다른 도구로 보내기 | Canva, Gamma, HubSpot, Miro, Netlify, Replit, v0, Vercel, Wix, Lovable 등 도움말 목록 |
   | 개발로 넘기기 | 로컬 코딩 에이전트로 보내기, Claude Code 웹으로 보내기 |

   만든 디자인은 처음엔 나만 볼 수 있어요. 공유(Share)에서 누가 열 수 있는지, 보기·댓글·편집 중 무엇을 할 수 있는지 정해요. Team과 Enterprise의 공유 규칙은 [C6](/ko/claude/c06-artifacts/)과 같은 아티팩트 규칙을 따라요.

6. **개발 단계로 넘기기 (Claude Code)**

   디자인이 소프트웨어로 만들어질 단계라면 Claude Code로 넘기라고 안내돼요. Claude Code는 스크린샷에서 다시 시작하지 않고 기존 작업을 이어받아요. Claude Code에서 `/design`을 쓰면 디자인을 코드베이스로 가져오거나, 코드를 동작하는 프로토타입으로 내보내거나, 처음부터 끝까지 만들게 할 수 있어요. Claude Code 자체는 [C12](/ko/claude/c12-claude-code-overview/)를 보세요.

</Steps>

## 자주 막히는 지점

### 인라인 코멘트가 반영되지 않아요

- **원인**: 코멘트가 가끔 Claude가 읽기 전에 사라지는 문제가 알려져 있어요. 페이지에 안 보여도 코멘트 보기에서는 확인할 수 있어요.
- **해결**: 같은 내용을 채팅에 직접 붙여 넣으세요.

### "chat upstream error"가 나와요

- **원인**: 도움말이 알려진 한계로 적은 오류예요. 원인은 설명되어 있지 않아요.
- **해결**: 같은 프로젝트 안에서 새 채팅 탭을 열어 보세요.

### 디자인을 못 쓰겠다고 나와요

- **원인**: 사용량 한도에 닿으면 한도가 리셋될 때까지 Design을 쓸 수 없어요. Design 전용 한도는 없어졌어요.
- **해결**: 한도가 리셋될 때까지 기다리거나, usage credits를 켜 두었다면 계속 쓸 수 있어요. 한도 구조는 [C2](/ko/claude/c02-plans-limits/)를 보세요.

### 큰 코드 저장소를 연결했더니 느려요

- **원인**: 아주 큰 저장소를 웹에서 연결하면 지연이나 브라우저 문제가 생길 수 있어요.
- **해결**: Claude Code에서 `/design-sync`로 연결하는 쪽을 고려하라고 안내돼요.

### 속성 패널의 레이어 목록에서 엉뚱한 것이 지워져요

- **원인**: 레이어 목록에서 Delete, Backspace, 잘라내기는 목록의 행이 아니라 캔버스에서 선택된 것에 적용돼요.
- **해결**: 지우기 전에 해당 행에서 Return을 눌러 선택하세요.

### 둘 이상이 동시에 편집하면 이상해요

- **원인**: 여러 명의 동시 편집은 아직 기본적인 수준이라 안정적이지 않을 수 있다고 안내돼요.
- **해결**: 한 번에 한 사람이 편집하고, 나머지는 보기·댓글로 참여하세요.

## 실전 팁

- **간단하게 시작해 점점 더하세요.** 핵심 레이아웃과 내용부터 만들고, 동작·예외 상황·마감 다듬기는 나중에 요청하라고 안내돼요.
- **피드백은 구체적으로.** "이상해"보다 "입력 칸 사이 간격을 8px로 줄여 줘"가 훨씬 잘 먹혀요.
- **대안을 2~3개 요청하세요.** 방향이 불확실할 때 비교하는 쪽이 추측하는 것보다 빨라요.
- **반응형을 일찍 말하세요.** 모바일, 태블릿, 데스크톱 중 어디에서 쓸지 처음에 적으세요.
- **Claude를 검토자로 쓰세요.** 접근성, 대비, 정보 위계, 사용성 점검을 Claude에게 요청할 수 있어요. 최종 판단은 사람이 하세요.
- **브랜드 자료와 개인정보를 구분하세요.** 실제 고객 이름, 연락처, 내부 자료는 시안에 넣지 말고 가짜 값으로 시안을 만드세요. 올린 자료와 코드 저장소가 어디까지 쓰이는지는 조직 정책을 먼저 확인하세요.
- **키보드·스크린리더 사용자**를 위한 이동 방법도 공식 도움말에 표로 있어요. 새 텍스트·아트보드·도형을 캔버스에 놓는 일은 마우스나 트랙패드가 필요하고, 키보드만 쓴다면 Claude에게 추가를 요청하라고 안내돼요.
