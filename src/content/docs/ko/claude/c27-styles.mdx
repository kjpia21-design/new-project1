<Summary>
- **Claude Code 출력 스타일**은 공식 문서에서 확인했어요. 스타일은 한 세션 동안 Claude의 역할·말투·답변 형식을 정하는 지침이에요. 기본 제공: **Proactive, Concise, Explanatory, Learning**, 그리고 표준 상태인 **Default**.
- `/output-style <스타일>` 또는 `/config` > Output style로 바꿔요. Markdown 파일로 **직접 만든 스타일**도 쓸 수 있어요.
- Claude 앱에서는 공식 개인화 문서가 세 가지를 안내해요: 계정 전체 **Instructions(지침)**, **프로젝트 지침**(유료 플랜), 말투·형식을 필요할 때 적용하는 **스킬**.
- 스타일은 Claude가 따르는 지침이지 보장이 아니에요. 매번 반드시 일어나야 하는 일에는 문서가 hook을 안내해요.
- 범위 안내: 채팅 앱의 별도 "스타일" 선택 기능은 공식 도움말 페이지에서 찾지 못해서 이 글에서 설명하지 않아요(2026-11-02 기준).
</Summary>

답이 너무 길거나 딱딱하거나 수다스럽다면, 매번 프롬프트에 쓰지 말고 한 번에 알려 줄 수 있어요. 프롬프트 요령은 [C4. 프롬프트](/ko/claude/c04-prompting/), Claude의 기억은 [C9. 메모리·설정](/ko/claude/c09-memory-settings/)을 보세요.

## 이 글을 마치면 할 수 있는 것

- Claude Code의 기본 출력 스타일을 고르고 각각 무엇이 바뀌는지 알아요.
- 간단한 사용자 정의 출력 스타일을 써 봐요.
- 지침, 프로젝트 지침, 스킬, 출력 스타일 중 무엇을 쓸지 골라요.
- 확인하지 못한 부분이 무엇인지 알아요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **출력 스타일(Output style)** | Claude Code에서 한 세션의 모든 답변에 대해 Claude의 역할·말투·형식을 정하는 지침이에요. |
| **지침(Instructions, 계정)** | 모든 대화에 적용되는 계정 전체 설정이에요. |
| **프로젝트 지침** | 한 프로젝트 안의 대화에만 적용되는 안내예요. |
| **스킬(Skill)** | 쓸 때 말투·형식을 조정하거나 전문성을 더해 주는 묶음 동작이에요. |
| **Frontmatter** | Markdown 파일 맨 위 `---` 줄 사이에 설정을 적는 부분이에요. |

## 단계별 따라하기

  '원하는 방식을 짧고 분명한 지침으로 적었다',

<Steps>

1. **기본 스타일 네 가지 보기**

   Claude Code는 소프트웨어 개발용 표준 지침인 Default 스타일로 시작해요. 다른 기본 스타일은 그 지침을 유지하고 자기 지침을 더해요. 공식 표 기준: **Proactive**는 바로 작업을 시작하고 일상적인 결정은 합리적으로 가정해요. **Concise**는 결과부터 말하고 서두·진행 설명·요약을 빼요(Claude Code v2.1.237 이상). **Explanatory**는 선택의 이유를 짧은 "Insight" 블록으로 덧붙여요. **Learning**은 같은 블록에 더해 작은 코드 조각을 `TODO(human)`으로 남겨 내가 직접 쓰게 해요.

2. **스타일 바꾸기**

   터미널에서 `/output-style concise`처럼 실행하거나(인자 없이 실행하면 목록과 현재 스타일 표시), `/config`에서 Output style을 골라요. 선택은 해당 프로젝트의 `.claude/settings.local.json`에 저장돼요. 다음 메시지부터 새 스타일이 적용돼요. 설정 파일의 `outputStyle` 값은 대소문자를 구분해서 `explanatory`처럼 틀리면 Default가 돼요. 모든 프로젝트의 기본값은 `~/.claude/settings.json`에 설정해요.

   <PromptBox label="작은 작업으로 Explanatory 써 보기">
   숫자 목록의 평균을 구하는 함수를 추가해 줘. 빈 목록 검사도 넣고, 내가 무엇을 검토해야 하는지 알려 줘.
   </PromptBox>

3. **나만의 출력 스타일 만들기**

   사용자 정의 스타일은 frontmatter와 지침이 있는 Markdown 파일이에요. `~/.claude/output-styles`(사용자) 또는 `.claude/output-styles`(프로젝트)에 저장해요. `name`을 쓰지 않으면 파일 이름이 스타일 이름이에요. 선택 항목으로 `description`, `keep-coding-instructions`가 있고, 말하는 방식만 바꾸고 코딩은 그대로 하게 하려면 후자를 `true`로 해요. 공식 예시는 모든 설명을 Mermaid 다이어그램으로 시작하는 스타일이에요. 터미널에서는 스타일 파일을 만들거나 고친 뒤 Claude Code를 다시 시작해야 읽혀요.

   ```md
   ---
   name: 쉬운 말
   description: 일상 언어로 짧게 답하기
   keep-coding-instructions: true
   ---
   일상적인 말로 답하세요. 전문 용어는 처음 쓸 때 풀이하세요. 더 달라고 하기 전에는 열 줄 이내로 답하세요.
   ```

4. **Claude 앱: 지침, 프로젝트, 스킬**

   공식 개인화 문서는 이렇게 안내해요. 이니셜 > Settings > "Your Claude"(예전 화면은 "Account")에서 지침을 적으면 모든 대화에 적용돼요. 프로젝트 지침은 그 프로젝트의 대화에만 적용돼요(문서는 이 용도를 유료 플랜으로 안내하고, 프로젝트 자체는 무료 계정도 최대 5개까지 가능해요). 스킬은 쓸 때 말투·형식을 조정하거나 나만의 소통 방식을 적용해요. [C5. 프로젝트](/ko/claude/c05-projects/), [C8. 스킬](/ko/claude/c08-skills/)을 참고하세요.

   <PromptBox label="고쳐 쓸 시작 지침">
   쉽고 친근한 말로 답해 줘. 결론을 먼저, 그다음 뒷받침 내용을 세 가지 이내로 써 줘. 요청이 불분명하면 추측하지 말고 질문을 한 가지만 해 줘.
   </PromptBox>

5. **알맞은 도구 고르기**

   Claude Code 문서의 비교: 특정 말투·길이·형식으로 모든 답변을 받고 싶으면 출력 스타일, 프로젝트 규칙을 알려 주려면 CLAUDE.md, 한 가지 종류의 작업에는 스킬, 매번 예외 없이 일어나야 하면 hook이에요. 함께 쓸 수 있어요.

</Steps>

<Aside type="caution" title="지침에 비밀을 넣지 마세요">
지침과 스타일 파일은 Claude가 읽는 일반 텍스트예요. 비밀번호·키·개인 정보를 적지 마세요. 시크릿 채팅 문서는 프로필 정보(사용자 정의 스타일, 개인 설정 등)를 시크릿 채팅에서도 Claude가 쓸 수 있다고 안내해요. 기본 원칙은 [개인정보·회사 정보 지키며 AI 쓰기](/ko/basics/05-privacy-safety/)를 보세요.
</Aside>

## 한도와 알아둘 점

- **보장 아님**: 문서는 출력 스타일이 Claude가 따를 지침일 뿐 항상 또는 절대 일어나는 것을 보장하지 않는다고 해요.
- **안전 관련 내용은 그대로**: Concise에서도 오류 보고, 실패한 테스트 출력, 보안 경고, 삭제 같은 작업의 확인은 전체 내용을 유지해요.
- **Proactive와 권한**: Proactive로 바꿔도 권한 모드는 그대로이고 권한 확인 창도 전과 같이 나타나요.
- **우선순위**: 프로젝트 자체 설정 파일이 사용자 설정의 `outputStyle`보다 우선해요.
- **다른 환경**: 문서에 따르면 `/output-style`은 Remote Control을 통한 모바일 앱·웹에서도 쓸 수 있고(기본 스타일만, v2.1.269 이상), VS Code 확장에서는 Output styles 메뉴로 고를 수 있어요(v2.1.257 이상).

<Aside type="note" title="확인하지 못한 것">
Claude 채팅 앱의 "스타일" 선택 기능에 대한 공식 도움말 문서는 찾지 못했어요(추측한 문서 주소는 404였고 도움말 검색에도 나오지 않았어요). 찾은 것은 시크릿 채팅 문서에서 프로필 정보에 "custom styles"를 언급한 한 줄뿐이에요. 그래서 이 글은 Claude Code의 출력 스타일과 개인화 문서에 나온 지침·프로젝트 지침·스킬만 다루고, 채팅 앱의 스타일 메뉴나 기본 이름, 지원 플랜은 설명하지 않아요. Claude Code를 직접 실행하지는 않았고 명령과 동작은 공식 문서 기준이에요. 버전과 메뉴는 바뀌니 링크를 다시 확인하세요.
</Aside>

## 빠른 참고

| 하고 싶은 일 | 방법 |
| --- | --- |
| Claude Code 답변을 짧게 | `/output-style concise` |
| 이유를 곁들여 설명받기 | `/output-style explanatory` |
| 직접 코드 일부 써 보며 배우기 | `/output-style learning` |
| 원래대로 | `/output-style default` |
| 나만의 말투·형식 | `.claude/output-styles`의 Markdown 파일 |
| 모든 대화에 규칙 | Settings > Your Claude > Instructions |
| 한 프로젝트에만 규칙 | 프로젝트 지침 |

## 자주 막히는 부분

### 스타일 이름이 적용되지 않아요

- **원인**: 설정 파일의 `outputStyle`은 대소문자를 구분해요.
- **해결**: `concise`가 아니라 `Concise`로 쓰거나, 대소문자를 무시하는 `/output-style` 명령을 쓰세요.

### 새로 만든 스타일이 목록에 없어요

- **원인**: 터미널에서는 Claude Code를 시작할 때 스타일 파일을 읽어요.
- **해결**: Claude Code를 다시 시작하고 폴더(`~/.claude/output-styles` 또는 `.claude/output-styles`)를 확인하세요.

### Claude가 스타일 일부를 무시해요

- **원인**: 스타일은 강제가 아니라 안내예요.
- **해결**: 지침을 더 짧고 구체적으로 쓰세요. 매번 꼭 필요한 일은 문서가 hook을 안내해요.

## 실전 팁

- 길이·말투·형식 중 한 가지만 바꿔 보고 결과를 보세요.
- 지침은 "결론 먼저, 근거 세 가지"처럼 구체적인 규칙으로 쓰세요.
- 프로젝트 사실은 CLAUDE.md나 프로젝트 지침에, 스타일은 말투·형식에 쓰세요.
- 만든 스타일 파일은 가끔 점검하고 안 쓰는 것은 지우세요.
