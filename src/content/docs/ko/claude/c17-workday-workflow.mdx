<Summary>
- 이 글은 새 기능을 소개하는 글이 아니라 **C5~C10에서 배운 기능을 하루 안에 이어 붙이는 조합 사례**예요.
- 흐름은 **아침(프로젝트 + 커넥터) → 오전(스킬로 형식 고정) → 점심 전후(Research) → 오후(아티팩트로 결과물) → 퇴근 전(메모리·정리)** 이에요.
- 각 도구의 역할은 달라요. 프로젝트는 **자료와 규칙**, 커넥터는 **내 데이터 접근**, 스킬은 **작업 방식**, Research는 **조사**, 아티팩트는 **결과물**, 메모리는 **이어 쓰기**를 맡아요.
- 처음부터 전부 쓰지 마세요. **프로젝트 하나**로 시작해서 불편한 곳에 하나씩 보태는 편이 오래가요.
- 사례는 가상의 업무 담당자 한 명의 하루예요. 화면 구성은 계정과 앱 버전, 플랜에 따라 다를 수 있어요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 내 업무를 **프로젝트 단위**로 나누고, 하루 동안 어떤 기능을 언제 꺼내 쓸지 그릴 수 있어요.
- 같은 일을 반복할 때 **무엇을 프로젝트 지침에, 무엇을 스킬에, 무엇을 매번 요청에** 넣을지 구분할 수 있어요.
- 조사 → 정리 → 공유 가능한 결과물까지 **한 흐름**으로 이어갈 수 있어요.
- 개인정보·권한 문제를 하루 흐름의 어느 지점에서 점검해야 하는지 알 수 있어요.

## 먼저 알아둘 개념

가상의 인물 **민지**(소규모 팀의 기획 담당)의 하루로 설명할게요. 민지는 매주 고객사 제안 한 건을 맡고, 주간 진행 보고를 써요.

| 기능 | 하루 중 맡는 역할 | 자세한 내용 |
| --- | --- | --- |
| **프로젝트** | 제안서 자료와 말투·형식 규칙을 한곳에 두고, 업무별로 대화를 분리 | [C5](/ko/claude/c05-projects/) |
| **커넥터** | Gmail·Google Calendar·Drive의 내 자료를 Claude가 읽게 함 | [C7](/ko/claude/c07-connectors/) |
| **스킬** | "보고서는 이 형식으로"처럼 작업 방식을 폴더로 고정 | [C8](/ko/claude/c08-skills/) |
| **Research** | 여러 출처를 단계적으로 조사해 인용 달린 보고서 작성 | [C10](/ko/claude/c10-research/) |
| **아티팩트** | 결과물(문서·슬라이드·작은 도구)을 대화 옆에서 만들고 공유 | [C6](/ko/claude/c06-artifacts/) |
| **메모리** | 대화에서 나온 선호와 맥락을 다음 대화로 이어감 | [C9](/ko/claude/c09-memory-settings/) |

## 단계별 따라하기

<Checklist items={[
  '업무용 프로젝트를 하나 만들고 지침과 자료를 넣었어요',
  '(선택) Gmail·Calendar 커넥터를 연결하고 아침 정리를 시켜 봤어요',
  '반복 문서 하나를 스킬이나 지침으로 형식을 고정했어요',
  'Research로 조사를 하나 돌리고 인용 링크를 직접 열어 확인했어요',
  '결과물을 아티팩트로 만들고 공유 범위를 확인했어요',
  '메모리와 프로젝트 지침에 남길 것을 정리했어요',
]} />

<Steps>

1. **아침: 프로젝트를 열고 하루를 정리해요**

   업무마다 프로젝트를 나눠 두면 자료와 규칙이 섞이지 않아요([C5](/ko/claude/c05-projects/)). 민지는 "고객사 제안" 프로젝트의 **지식**에 제안서 양식과 지난 제안서를, **지침**에 "존댓말로, 결론부터, 표는 3열 이하로" 같은 규칙을 넣어 뒀어요. 변하지 않는 자료는 지식에, 매번 달라지는 내용은 대화에서 알려 주는 편이 정확해요.

   Gmail·Google Calendar 커넥터를 연결해 두었다면([C7](/ko/claude/c07-connectors/)) 오늘 일정과 읽을 메일을 한 번에 정리시킬 수 있어요. 커넥터는 내 권한 범위에서만 읽고, 메일 전송 같은 쓰기 작업은 기본적으로 승인을 물어요.

   <PromptBox>
   오늘 내 캘린더의 일정과, 어제 이후 받은 메일 중 답장이 필요해 보이는 것을 골라서 정리해 주세요. 일정은 시간순 표로, 메일은 보낸 사람·요지·권장 답장 시점으로 정리하고, 메일은 보내지 말고 초안 작성이 필요한 것만 표시해 주세요.
   </PromptBox>

   <Aside type="caution" title="커넥터는 필요한 것만 켜세요">
   대화마다 커넥터를 켜고 끌 수 있어요. 오늘 작업에 필요 없는 커넥터는 꺼 두면 엉뚱한 자료를 읽을 위험이 줄어요. 고객 이름이나 연락처가 담긴 메일은 정리 결과를 외부에 붙여넣기 전에 한 번 더 확인하세요.
   </Aside>

2. **오전: 반복 문서는 형식을 고정해요**

   주간 진행 보고처럼 매주 같은 구조의 문서는 **스킬**로 만들어 두면 좋아요([C8](/ko/claude/c08-skills/)). 스킬은 Claude가 필요할 때 불러오는 지침 폴더예요. 스킬을 쓰려면 코드 실행(code execution)이 켜져 있어야 하고, Customize > Skills에서 토글로 켜고 꺼요.

   스킬까지 만들기 부담스럽다면 프로젝트 지침에 형식을 적는 것으로 시작해도 충분해요. 어디에 둘지는 이렇게 가르면 쉬워요.

   | 내용 | 두는 곳 |
   | --- | --- |
   | 이 프로젝트에서 항상 지킬 말투·규칙 | 프로젝트 **지침** |
   | 이 프로젝트에서 계속 참고할 자료 | 프로젝트 **지식** |
   | 여러 프로젝트에서 쓰는 작업 절차(보고서 형식 등) | **스킬** |
   | 오늘만 해당하는 요청 | 대화에서 직접 |

   <PromptBox>
   이번 주 진행 보고 초안을 써 주세요. 아래 메모를 바탕으로, 지난주 한 일 / 이번 주 할 일 / 막힌 점 / 요청 사항 네 부분으로 나눠 주세요. 메모에 없는 수치나 일정은 지어내지 말고 [확인 필요]로 표시해 주세요.

   [여기에 이번 주 메모를 붙여넣으세요]
   </PromptBox>

3. **점심 전후: 조사가 필요하면 Research를 써요**

   고객사의 업계 동향처럼 여러 출처를 모아 비교해야 하는 조사는 한두 번의 검색보다 **Research**가 알맞아요([C10](/ko/claude/c10-research/)). 공식 도움말은 Research를 5회 이상의 도구 호출과 1~3분이 걸리는 포괄적 조사에 쓰라고 안내해요. 일반 대화와 같은 한도를 쓰고, 더 빨리 소진될 수 있어요. 그래서 점심 전에 질문을 구체적으로 적어 한 번에 돌리는 편이 좋아요.

   <PromptBox>
   [업계/분야]의 최근 1년 동향을 조사해 주세요. 우리 고객사([고객사 규모와 상황 한 줄])가 제안서에서 다뤄야 할 주요 변화 3~5가지를 뽑고, 각각 근거 출처를 달아 주세요. 출처가 약하거나 서로 엇갈리는 내용은 따로 표시해 주세요.
   </PromptBox>

   <Aside type="caution" title="인용 링크는 직접 열어 보세요">
   보고서에 인용이 붙어 있어도 틀릴 수 있어요. 제안서에 쓸 숫자와 주장은 인용 링크를 눌러 원문에서 확인한 뒤에 쓰세요.
   </Aside>

4. **오후: 결과물은 아티팩트로 만들어요**

   조사와 초안이 모이면 보여 줄 수 있는 결과물로 만들어요. 아티팩트는 대화 옆에 열리는 문서·슬라이드·작은 도구예요([C6](/ko/claude/c06-artifacts/)). 새 아티팩트는 비공개로 시작하고, 공유(Share) 메뉴에서 범위를 정해요. 요금제에 따라 공유 방식이 다르니 먼저 C6의 표를 확인하세요.

   <PromptBox>
   위 조사 결과와 제안서 양식(프로젝트 자료)을 바탕으로 고객사 제안서 요약 문서를 만들어 주세요. 1쪽 분량으로, 제목 / 핵심 제안 3가지 / 근거 / 다음 단계 순서로 구성해 주세요. 근거에는 출처를 달고, 확인되지 않은 수치는 넣지 마세요.
   </PromptBox>

   <Aside type="note" title="공유 전 점검">
   고객 이름, 연락처, 내부 단가가 들어 있지 않은지 공유 전에 한 번 읽어 보세요. 링크를 받은 사람이 어디까지 볼 수 있는지는 C6의 권한 설명을 확인하세요.
   </Aside>

5. **퇴근 전: 다음 날을 위해 정리해요**

   오늘 대화에서 반복해서 고친 지시가 있다면 그것이 프로젝트 지침에 추가할 후보예요. 예를 들어 "표는 3열 이하로 줄여 줘"를 세 번 말했다면 지침에 한 줄 넣으세요. 메모리는 대화 중 주제 단위로 자동 저장되고, 설정(Settings) > Your Claude(예전 화면은 Memory)에서 무엇이 저장됐는지 보고 고치거나 지울 수 있어요([C9](/ko/claude/c09-memory-settings/)). 프로젝트마다 메모리 공간이 따로 있어서 다른 업무와 섞이지 않아요.

   <PromptBox>
   오늘 우리 대화에서 내가 반복해서 정정하거나 요청한 형식·말투 규칙이 있으면 정리해 주세요. 프로젝트 지침에 한 줄씩 추가할 수 있도록 짧은 문장으로 제안해 주세요.
   </PromptBox>

</Steps>

### 조합할 때 기억할 제약

- 지식에 없는 맥락은 **대화 사이에 공유되지 않아요.** 다른 대화의 내용을 프로젝트가 자동으로 아는 것은 아니에요([C5](/ko/claude/c05-projects/)).
- 커넥터는 **내 권한을 그대로 상속**해요. 팀 프로젝트에서 커넥터 데이터를 팀원과 공유할 수 없는 경우가 있어요([C7](/ko/claude/c07-connectors/)).
- Research와 스킬, 아티팩트는 플랜과 조직 설정에 따라 보이지 않을 수 있어요. 메뉴가 없으면 Team/Enterprise는 Owner 설정을 확인하세요.
- 가격·한도는 바뀌어요. 내 사용량은 설정(Settings) > 사용량(Usage)에서 확인하세요.

## 자주 막히는 지점

### 기능을 다 썼는데 결과가 오히려 산만해요

- **원인**: 커넥터를 전부 켜고, 지침에 규칙이 너무 많고, 지식에 관련 없는 자료가 섞였을 수 있어요.
- **해결**: 오늘 작업에 필요한 커넥터만 켜고, 지침은 짧게 줄이고, 자료는 업무별 프로젝트로 나누세요.

### 어제 한 이야기를 오늘 프로젝트가 몰라요

- **원인**: 대화 사이에는 지식 베이스에 있는 자료만 공유돼요. 메모리는 주제 단위로 저장되지만 모든 내용이 담기지는 않아요.
- **해결**: 계속 필요한 결정은 프로젝트 지식이나 지침에 직접 적어 두세요.

### Research 결과의 숫자를 믿어도 될지 모르겠어요

- **원인**: 인용이 있어도 출처가 약하거나 해석이 어긋날 수 있어요.
- **해결**: 인용 링크를 직접 열어 원문을 확인하고, 확인되지 않은 수치는 "확인 필요"로 남기게 프롬프트에 적으세요.

### 공유한 아티팩트를 상대가 못 열어요

- **원인**: 플랜별 공유 방식과 권한이 달라요.
- **해결**: [C6](/ko/claude/c06-artifacts/)의 공유 방식 표와 "공유하려 했는데 상대가 못 열어요" 항목을 확인하세요.

## 실전 팁

- **프로젝트 하나로 시작하세요.** 가장 자주 하는 업무 하나만 프로젝트로 만들고, 한 주 써 본 뒤 커넥터와 스킬을 보태세요.
- **지침은 대화하며 키우세요.** 어긋난 답이 나올 때마다 한 줄씩 보태면 돼요.
- **조사는 질문을 모아서 한 번에 돌리세요.** Research는 한도를 더 쓸 수 있어요.
- **쓰기 작업은 사람이 확인하세요.** 메일 전송이나 공유는 초안 → 내가 확인 → 실행 순서를 지키세요.
- **민감한 자료는 프롬프트와 지식에 넣기 전에 한 번 더 생각하세요.** 개인정보와 거래처 정보는 [개인정보와 보안](/ko/basics/05-privacy-safety/) 기준으로 다루세요.
- **매일 같은 시간에 하는 일은 자동화를 검토하세요.** 단, 자동 실행은 사람이 보지 않는 동안 돌아요. 안전한 설계는 C18에서 다뤄요.
