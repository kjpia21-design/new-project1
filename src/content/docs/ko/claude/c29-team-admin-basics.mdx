<Summary>
- Claude 관리 작업은 대부분 **Organization settings**(조직 설정)에서 해요. 보이는 것과 바꿀 수 있는 것은 **역할**(User, Admin, Owner, Primary Owner)에 따라 다르고, 일부 기능은 **Enterprise에만** 있어요(2026-11-06 기준 공식 페이지).
- 안전한 순서: Owner 역할 확인, **도메인 확인**, **SSO** 설정 후 필수 적용 전에 테스트, 구성원 **프로비저닝** 방식 선택, 그다음 데이터 보관·감사 로그·새 보안 센터 확인.
- 되돌리기 어려운 설정이 있어요. SSO 필수 적용은 접속을 막을 수 있고, 보관 기간을 줄이면 데이터가 영구 삭제되며, 도메인 캡처는 되돌릴 수 없어요. 저장 전에 경고를 꼭 읽으세요.
- Enterprise **보안 센터**(베타)는 내 설정을 Anthropic 권장 구성과 비교해 보여 주는 읽기 전용 페이지예요. 참고용 안내이지 보안 인증이 아니에요.
- 이 글은 기본 지도일 뿐 법률·컴플라이언스 조언이 아니에요. 설정을 바꾸기 전에 링크한 공식 페이지와 보안 담당자와 확인하세요.
</Summary>

방금 관리자가 되었다면 설정 메뉴가 크게 느껴질 수 있어요. 이 글은 공식 도움말이 기본으로 다루는 부분만 짧게 짚어요. 플랜 비교는 [C2. 요금제와 한도](/ko/claude/c02-plans-limits/), 구성원이 프로젝트·대화를 공유하는 방법은 [C24. 프로젝트·대화 공유](/ko/claude/c24-sharing-projects/), Slack 기능은 [C28. Slack의 Claude Tag](/ko/claude/c28-claude-tag/)를 보세요.

## 이 글을 마치면 할 수 있는 것

- 기본 역할 4가지와 각 역할이 닿는 설정을 설명해요.
- 도메인을 확인하고 SSO·프로비저닝이 구성원에게 주는 영향을 이해해요.
- 어떤 데이터·세션 관리 기능이 있고 어떤 플랜이 필요한지 알아요.
- 보안 센터를 찾아 상태 표시의 뜻을 읽어요.
- 짧은 도입 체크리스트를 만들고 IT·보안팀에 물어볼 것을 정해요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **Organization settings** | 계정 메뉴에서 여는 Claude의 관리 영역이에요. 구성원, 결제, 보안, 데이터 관리가 여기에 있어요. |
| **Primary Owner** | 가장 높은 단일 역할이에요. Team·Enterprise 조직에는 한 명만 둘 수 있고, 좌석(라이선스) 하나를 써요. 공식 페이지에 따르면 개인에 묶이지 않은 서비스 계정도 될 수 있어요. |
| **Owner / Admin / User** | Owner와 Admin은 구성원과 설정을 관리해요. 닿는 설정은 서로 달라요(1단계 참고). User에게는 관리 권한이 없어요. |
| **사용자 지정 역할(Custom role)** | Enterprise 전용이에요. 역할이 Custom인 구성원은 기본 권한이 없고, 소속 그룹에 할당된 사용자 지정 역할로 접근이 정해져요. |
| **도메인 확인** | DNS TXT 레코드를 추가해 회사 이메일 도메인이 내 것임을 증명하는 절차예요. SSO 전에 필요해요. |
| **SSO / JIT / SCIM** | SSO는 ID 공급자(IdP)로 로그인하는 방식이에요. JIT는 첫 로그인 때 계정을 만들고, SCIM은 IdP의 추가·삭제를 동기화해요(Enterprise 전용). |
| **상위 조직(Parent organization)** | 도메인 확인과 SSO 설정을 저장하는 단위로, 여러 Claude·Console 조직이 공유할 수 있어요. |

## 단계별 따라 하기

<Steps>

1. **바꾸기 전에 역할부터 정리하기**

   공식 역할 페이지에는 기본 역할 4가지가 있어요. Primary Owner는 조직에 한 명뿐이에요. 결제(Billing)는 Owner와 Primary Owner가 열 수 있고, 구성원 페이지에 따르면 Admin은 Organization settings > Members에서 구성원을 관리할 수 있지만 Billing은 열 수 없어요. SSO 설정, 조직 지침 설정, 데이터 보관 관리는 각 기능 페이지에 Owner 또는 Primary Owner가 필요하다고 나와 있어요. Enterprise에는 더 세밀한 접근을 위한 사용자 지정 역할과 그룹(예: 커넥터 권한)이 있고 별도 페이지에서 설명해요. 먼저 구성원 목록을 내보내세요. Organization settings > Members > Export CSV(Admin 이상)예요.

   <PromptBox label="역할 표 초안">
   나는 직원 40명인 Claude Team 플랜의 새 관리자야. 한 페이지짜리 표 초안을 만들어 줘. 열은 사람 또는 그룹, 필요하다고 생각하는 역할(User, Admin, Owner), 공식 역할 페이지에서 확인해야 할 질문이야. 이름은 가상으로 쓰고 확실하지 않은 부분은 확인하지 못함으로 표시해 줘.
   </PromptBox>

2. **도메인 확인하기**

   Organization settings > Organization and access의 Domains에서 도메인을 추가하고 Verify를 선택한 다음, DNS 공급자에 `anthropic-domain-verification-`으로 시작하는 TXT 레코드를 게시해요. 기존 TXT 레코드 옆에 추가하고, 값 전체를 정확히 복사하고, 화면을 떠나기 전에 꼭 저장하세요. 도메인이 Pending 상태가 되면 콘솔이 값을 다시 보여 주지 않아요. 페이지는 약 10분을 기다리라고 하고, DNS 전파에는 24~48시간이 걸릴 수 있다고 해요. 도메인 확인만으로는 기존 사용자의 접근이 바뀌지 않아요. 확인 후에는 **Restrict organization creation** 토글이 나타나고, 켜면 확인된 도메인으로 새 Claude·Console 조직(개인 계정 포함)을 만들 수 없어요. 의도를 갖고 정하세요.

3. **SSO 설정, 테스트, 그다음 필수 적용 결정**

   SSO는 Team 플랜, Enterprise 플랜, Console 조직에서 쓸 수 있고, Claude에서는 Owner 또는 Primary Owner가 설정해야 해요. Authentication에서 Setup SSO를 선택하고 IdP별 안내를 따르세요(페이지에는 Okta, Entra ID, Google, OneLogin, JumpCloud, Duo가 SAML로 나와요). 기본 제공 테스트를 실행한 뒤에야 **Require SSO**를 고려하세요. 필수 적용하면 Anthropic 앱에 배정되지 않은 사람이 로그인하지 못할 수 있고, Require SSO가 켜진 상태에서 서명 인증서나 클라이언트 시크릿이 만료되면 고치러 들어갈 사람이 아무도 없다고 경고해요. IdP에서 만료일을 적어 두고 미리 갱신하세요. 모든 관리자가 잠겼다면 Owner 또는 Primary Owner의 이메일로 Support에 연락해요.

4. **구성원 추가·제거 방식 고르기**

   기본값은 **초대만(invite only)**이에요. 직접 추가·제거하고, 초대는 21일 후 만료돼요. 대기 중인 초대도 이미 좌석을 차지해요. **JIT**는 IdP의 Anthropic 앱에 배정된 사람이 처음 로그인할 때 계정을 만들고, 모든 플랜에서 쓸 수 있어요. 공식 페이지에 따르면 JIT는 구성원을 자동으로 제거하지 않아서, 배정을 해제하면 로그인은 못 해도 관리자가 제거할 때까지 좌석을 유지해요. **SCIM**은 Enterprise 전용이고 IdP에 따라 구성원을 자동으로 추가·제거해요. 그룹 매핑으로 IdP 그룹에 따라 역할과 좌석 유형을 지정할 수 있어요. 좌석이 없으면 새 사용자를 프로비저닝할 수 없으니 미리 확인하세요.

5. **세션·구성원 보안 설정 살펴보기**

   Enterprise에서는 Admin 이상이 Organization settings > Organization and access에서 **Shortened session length**를 켤 수 있어요(페이지의 선택지는 1, 7, 14, 28일). 선택한 기간보다 오래된 세션은 바로 만료돼요. 기기를 잃어버렸다면 구성원 페이지의 **Sign out everywhere**(베타)가 있어요. 구성원을 제거하지 않고 모든 기기의 세션을 끝내며, 세션은 개인 계정에 속하므로 다른 조직에서도 로그아웃돼요. IdP에서 제거해 주지는 않아요. Enterprise에는 공개 베타의 IP 허용 목록도 있어요. 도움말은 설정 방법을 API 문서로 안내하고, 조직 밖으로 공유한 아티팩트는 허용 목록의 제한을 받지 않는다고 적어요.

6. **데이터 보관 설정과 감사 로그 위치 알기**

   Enterprise에서 Owner는 Organization settings > Data and Privacy에서 사용자 지정 보관 기간을 설정할 수 있어요(최소 30일, 마지막 활동 기준이며 기본은 무기한 보관). 기간을 줄이면 저장하는 즉시 오래된 데이터가 영구 삭제 대상이 되고 복구할 수 없어요. 페이지에 따르면 claude.ai/design의 Claude Design, Claude Tag, Claude Managed Agents, 클라우드에서 Claude Code를 실행하는 기능에는 적용되지 않아요. 감사 로그는 Enterprise 전용이에요. Owner가 Data and Privacy의 Export logs로 최근 180일치를 이메일로 받고, 다운로드 링크는 24시간 유효해요. 채팅 제목과 내용은 감사 로그에 없고 식별자만 있어요.

7. **보안 센터를 열고 안내를 읽기**

   Enterprise에서 계정 메뉴의 Organization settings를 열고 Security posture를 선택해요. 이 페이지(베타)는 컨트롤을 Org, chats, Cowork, Claude Code로 묶어 현재 값, 권장 값, 상태(Passed, Failed, Not attested, Shown for information)를 보여 줘요. 읽기 전용이고 Owner와 Primary Owner만 볼 수 있으며, PDF 보고서를 만들 수 있지만 페이지는 이것이 보안 인증이 아니라고 밝혀요. 기기 관리처럼 읽을 수 없는 컨트롤은 Owner가 확인 기록(attestation)을 남길 수 있어요. Failed는 명령이 아니라 해당 컨트롤 페이지를 읽어 보라는 신호로 받아들이세요.

   <PromptBox label="점검 회의 계획">
   다음 주에 IT 담당자와 우리 회사의 Claude 보안 설정을 점검할 거야. 30분짜리 안건을 질문 5개로 써 줘. 예를 들어 SSO는 누가 관리하는지, 퇴사자는 누가 처리하는지, 데이터를 얼마나 보관할지 같은 것들이야. Claude 기능을 지어내지 말고, 공식 도움말을 확인해야 답할 수 있는 질문에는 표시해 줘.
   </PromptBox>

8. **조직 전체 지침은 마지막에**

   Team·Enterprise Owner는 모든 대화에 적용되는 조직 지침을 설정할 수 있어요(최대 3,000자, 반영까지 최대 1시간). 구성원의 개인 지침과 충돌하면 Claude는 조직 지침을 우선해요. 짧게 쓰고 테스트하세요. 큰 규모의 Enterprise 설정에는 추론 훅(모든 프롬프트와 도구 호출을 직접 운영하는 서버가 확인한 뒤에 Claude가 진행하며 Owner·Primary Owner가 관리)과 중앙 관리(베타, admin.claude.com의 상위 조직 콘솔)도 있어요. 계획하기 전에 보안팀과 함께 해당 페이지를 읽으세요.

</Steps>

<Aside type="caution" title="되돌리기 어려운 설정 세 가지">
SSO를 필수로 하면 IdP에 배정되지 않은 사람이 잠길 수 있어요. 보관 기간을 줄이고 저장하면 데이터가 영구 삭제돼요. 도메인 캡처(Enterprise 전용)는 공식 페이지가 되돌릴 수 없는 설정이라고 설명해요. 켜면 30일 안에 이전하지 않은 도메인의 계정은 비활성화되고 유료 개인 구독은 일할 환불과 함께 취소돼요. 구성원 목록을 내보내고, 구성원에게 먼저 알리고, 확인 화면을 읽으세요.
</Aside>

## 플랜별로 무엇이 있나

공식 요금 페이지의 보안·관리 표에 나온 차이예요. 가격과 플랜 구성은 바뀔 수 있으니 구매 전에 다시 확인하세요.

| 기능 | Team | Enterprise |
| --- | --- | --- |
| SSO, 도메인 확인, 조직 생성 제한 | 있음 | 있음 |
| 사용량 분석, 조직 지침 설정 | 있음 | 있음 |
| 도메인 캡처, 내 도메인 계정 이전 | 없음 | 있음 |
| 역할 기반 접근, SCIM, 감사 로그 | 없음 | 있음 |
| Compliance API, 사용자 지정 데이터 보관 | 없음 | 있음 |
| 추론 훅, HIPAA 대응 옵션 | 없음 | 있음 |

요금 페이지는 Team의 Standard 좌석을 연간 결제 시 월 $20(월 결제 $25), Enterprise를 연간 결제 시 좌석당 월 $20에 사용량은 API 요율로 청구하며 최소 20석이라고 적어요(2026-11-06 기준). JIT는 SSO 도움말에서 Team과 Enterprise에 나오고 SCIM은 Enterprise 전용이에요.

## 한계와 알아둘 점

- **베타 표기**: 보안 센터, 중앙 관리, Sign out everywhere, IP 허용 목록은 공식 페이지에 베타 또는 공개 베타로 표시돼 있어요. 내용이 바뀔 수 있어요.
- **Admin은 Owner가 아니에요**: 설정에 Owner 또는 Primary Owner라고 되어 있으면 Admin에게는 보이지 않아요. 계정을 공유하지 말고 알맞은 역할을 요청하세요.
- **직원 데이터 접근**: 데이터 소유 도움말에 따르면 Primary Owner가 계정과 데이터를 관리하고, 대화가 담길 수 있는 데이터 내보내기를 요청할 수 있어요. 조직이 무엇에 접근할 수 있는지 구성원에게 알리세요.
- **컴플라이언스 보증이 아니에요**: HIPAA, 보관, 업종 규정은 별도의 법률 문제예요. 이 글은 다루지 않아요.

<Aside type="note" title="확인하지 못한 것">
위에 적은 공식 도움말과 2026-11-06 요금 페이지를 읽었어요. 실제 조직을 관리해 보지는 않아서 모든 메뉴 이름과 동작은 해당 페이지 기준이고 직접 테스트한 것이 아니에요. 화면은 다를 수 있어요. 11-05 Enterprise 보안 기능을 발표한 Anthropic 블로그 글 전문은 뉴스 페이지에서 주소를 찾지 못해 읽지 못했고, 각 기능은 도움말 페이지 기준으로 적었어요. IdP별 설정 가이드, 사용자 지정 역할·그룹·사용 한도 페이지, Compliance API 페이지, Admin API 레퍼런스, IP 허용 목록 API 문서는 자세히 읽지 않았어요. 역할 페이지의 권한 표는 추출 과정에서 열 구분이 사라져서, 다른 페이지가 글로 밝힌 역할 요건만 적었어요. 내 조직에서 각 베타가 켜져 있는지는 확인하지 못했어요.
</Aside>

## 자주 막히는 부분

### 도메인이 계속 Pending이에요

- **원인**: TXT 레코드가 루트 도메인이 아닌 곳에 있거나, 아직 전파되지 않았거나, 값이 정확히 일치하지 않거나, 도메인을 지우고 다시 추가해 새 값이 생겼을 수 있어요.
- **해결**: TXT 레코드를 조회하고 접두사를 포함한 전체 값을 비교하고, DNS 전파를 기다린 뒤 Refresh를 누르세요. 값이 맞는데도 Pending이면 Support에 문의하세요.

### SSO 필수 적용 후 로그인이 안 돼요

- **원인**: IdP의 Anthropic 앱에 배정되지 않았거나 인증서·시크릿이 만료됐을 수 있어요.
- **해결**: IdP에서 배정하거나 Manage SSO에서 인증서·시크릿을 갱신하세요. 로그인할 관리자가 없다면 Owner 이메일로 Support에 연락하세요.

### 퇴사자가 아직 구성원 목록에 있어요

- **원인**: JIT는 구성원을 제거하지 않고, IdP에서 배정을 해제하면 로그인만 막혀요.
- **해결**: Organization settings > Members에서 제거하거나 Enterprise에서 SCIM을 쓰세요. 세션을 바로 끝내야 하면 Sign out everywhere를 쓰세요.

### Security posture나 Data and Privacy 옵션이 안 보여요

- **원인**: Owner가 아닌 Admin이거나 Team 플랜일 수 있어요. 보안 센터는 Enterprise 기능이고 Owner와 Primary Owner만 열 수 있어요.
- **해결**: 내 역할과 플랜을 확인하고 Owner에게 요청하세요.

## 실전 팁

- Owner 역할을 맡을 수 있는 사람을 최소 두 명 두고, Primary Owner가 누구인지 적어 두세요.
- 한 번에 하나씩 바꾸고, 전체 적용 전에 시범 그룹으로 테스트하세요.
- 설정을 바꿀 때마다 이유와 날짜를 공유 기록에 남기세요. Enterprise 감사 로그는 사건을 기록하지만 이유는 내 메모가 설명해 줘요.
- 관리자 문서 초안을 Claude에게 부탁할 때 실제 비밀번호, DNS 토큰, 고객 데이터는 넣지 마세요. [개인정보·회사 정보 지키며 AI 쓰기](/ko/basics/05-privacy-safety/)를 보세요.
- 조직 작업을 자동화하려면 [Claude Admin API로 조직 관리하기](/ko/dev/22-admin-api/)를 보고 키를 비공개로 지키세요.
