- **멀티 에이전트**는 리드 에이전트 하나가 일을 쪼개 다른 에이전트들에게 나눠 주고, 각자 자기 컨텍스트 창에서 일한 결과를 다시 모으는 방식이에요.
- Anthropic 문서는 두 가지 모양을 설명해요. **서브에이전트**는 한 세션 안에서 일하고 결과를 돌려줘요. **에이전트 팀**은 따로 도는 세션들이 작업 목록을 공유하고 서로 메시지를 주고받아요. 에이전트 팀은 실험 기능이고 기본으로 꺼져 있어요.
- 서로 독립적인 조각으로 나뉘는 일(예: 여러 주제를 동시에 조사)에 가장 잘 맞아요. 단계가 서로 이어지거나 같은 파일을 함께 고치는 일에는 덜 맞아요.
- 비용이 더 들어요. Anthropic 엔지니어링 글은 자체 데이터에서 에이전트가 채팅보다 약 4배, 멀티 에이전트 시스템이 약 15배 토큰을 썼다고 해요. Claude Code 문서는 에이전트 팀이 한 세션보다 토큰을 훨씬 많이 쓴다고 해요.
- 이 글은 개념 설명이에요. 직접 해 보는 방법은 [코딩 12편: 서브에이전트 만들기](/ko/coding/39-claude-code-subagents/)와 [개발 3편: Agent SDK](/ko/dev/03-agent-sdk/)를 보세요. 사실은 **2026-11-06**에 읽은 공식 페이지 기준이에요.

## 이 글을 마치면 할 수 있는 것

- 리드 에이전트, 서브에이전트, 팀원이 무엇인지 쉬운 말로 설명할 수 있어요.
- 여러 에이전트로 나눌 만한 일과 한 에이전트가 나은 일을 구분할 수 있어요.
- 멀티 에이전트가 실제로 따를 수 있는 위임 요청을 쓸 수 있어요.
- 결과에서 무엇을 확인해야 하는지, 왜 비용이 늘어나는지 알 수 있어요.

## 먼저 알아 둘 개념

| 용어 | 뜻 |
| --- | --- |
| **에이전트** | 도구를 반복해서 쓰며 목표를 향해 일하는 모델이에요. Anthropic 연구 글은 "LLMs autonomously using tools in a loop"라고 표현해요. |
| **멀티 에이전트 시스템** | 여러 에이전트가 한 일을 함께 하는 구조예요. |
| **리드 에이전트(오케스트레이터)** | 계획을 세우고, 조각을 나눠 주고, 결과를 합치는 에이전트예요. |
| **서브에이전트** | 리드가 좁은 일을 시키려고 시작하는 도우미예요. 자기 컨텍스트 창, 시스템 프롬프트, 도구 접근, 권한이 따로 있고 요약을 돌려줘요. |
| **팀원(teammate)** | Claude Code 에이전트 팀에서, 다른 팀원에게 직접 메시지를 보내고 공유 목록에서 작업을 가져가는 별도의 Claude Code 인스턴스예요. |
| **컨텍스트 창** | 에이전트 하나가 한 번에 담아 둘 수 있는 양이에요. 서브에이전트와 팀원은 각자 가져요. |

에이전트 하나만 쓰는 기초는 [에이전트 1편: 에이전트 비교](/ko/agents/01-agents-compared/)를 보세요.

<Aside type="note" title="'에이전트'의 두 가지 뜻">
Anthropic의 "Building effective agents" 글은 **워크플로**(모델과 도구를 미리 정한 코드 경로로 돌림)와 **에이전트**(모델이 스스로 진행과 도구 사용을 정함)를 구분해요. 이 글의 멀티 에이전트는 두 번째 종류예요. 리드가 일하면서 나누는 방식을 정해요.
</Aside>

## 한 장면으로 보기

작은 프로젝트 팀을 떠올려 보세요. 매니저가 요청을 읽고, 쪼개고, 사람마다 분명한 지시를 주고, 돌아온 결과를 합쳐요.

1. **나**는 리드에게 목표를 설명해요.
2. **리드**는 일을 나누고 도우미를 시작해요.
3. **각 도우미**는 자기 공간에서 일하고 결과를 보내요.
4. **리드**는 결과를 합쳐 하나의 답으로 줘요.

Anthropic은 Research 기능을 이렇게 설명해요. 리드 에이전트가 계획을 세우고, 병렬 에이전트를 만들어 동시에 검색하게 해요. 이를 오케스트레이터-워커 패턴이라고 불러요.

## 두 가지 모양: 서브에이전트와 팀

Claude Code 문서는 둘을 이렇게 비교해요.

| | 서브에이전트 | 에이전트 팀 |
| --- | --- | --- |
| 도는 곳 | 한 세션 안 | 별도의 Claude Code 인스턴스, 하나가 리드 |
| 컨텍스트 | 자기 창, 결과가 호출자에게 돌아감 | 자기 창, 완전히 독립 |
| 소통 | 호출자에게 결과를 돌려줌 | 팀원끼리 직접 메시지 |
| 조율 | 메인 에이전트가 관리 | 공유 작업 목록과 메시지 |
| 잘 맞는 일 | 결과만 필요한 좁은 일 | 토론과 협업이 필요한 복잡한 일 |
| 토큰 비용 | 낮음: 결과를 요약해서 돌려줌 | 높음: 팀원마다 별도 인스턴스 |
| 상태 | 사용 가능 | 실험 기능, 기본 꺼짐 |

문서는 팀을 만들기 전에 더 가벼운 방법으로 되는지 먼저 확인하라고 해요.

### 서브에이전트가 잘하는 것 (공식)

- **컨텍스트 분리**: 중간 도구 호출과 결과는 서브에이전트 안에 남고, 마지막 메시지만 부모에게 돌아와요.
- **병렬 처리**: 서로 독립적인 하위 작업을 동시에 돌릴 수 있어요.
- **전문 지시**: 서브에이전트마다 자기 시스템 프롬프트를 둘 수 있어요.
- **도구 제한**: 서브에이전트가 쓸 수 있는 도구를 제한할 수 있어요.

Claude Code 페이지는 서브에이전트가 보내는 요청도 메인 대화와 같은 사용 한도에 포함된다고 덧붙여요.

### 에이전트 팀이 더하는 것 (공식)

팀원들은 작업 목록을 공유하고, 작업을 가져가고, 서로 메시지를 보내요. 사용자도 어느 팀원에게든 직접 말할 수 있어요. 문서는 조사와 리뷰, 새 모듈 개발, 경쟁 가설로 하는 디버깅, 여러 층에 걸친 작업을 가장 강한 사용처로 들어요. 에이전트 팀은 환경 변수로 켜고, 문서에는 알려진 제한(예: in-process 팀원은 세션 재개가 안 됨, 세션당 팀 하나)이 적혀 있어요. 쓰기 전에 [공식 페이지](https://code.claude.com/docs/en/agent-teams)를 꼭 읽어 보세요.

## 도움이 되는 때와 아닌 때

| 잘 맞는 경우 | 잘 안 맞는 경우 |
| --- | --- |
| 독립적인 여러 주제나 자료를 동시에 조사 | 앞 결과가 있어야 다음을 할 수 있는 단계들 |
| 컨텍스트 창 하나로는 너무 큰 일 | 빠르고 좁은 수정 |
| 같은 자료를 보안·성능·테스트처럼 다른 관점으로 리뷰 | 여러 에이전트가 같은 파일을 고치는 일 |
| 출력이 길고 요약만 필요한 일 | 나와 자주 주고받아야 하는 일 |

표는 공식 페이지 내용을 따랐어요. Claude Code 문서는 반복 작업이나 맥락을 공유하는 단계에는 메인 대화를 쓰라고 하고, 에이전트 팀은 순차 작업, 같은 파일 편집, 의존성이 많은 일에는 덜 효과적이라고 해요. Anthropic 연구 글도 비슷해요. 모든 에이전트가 같은 컨텍스트를 공유해야 하거나 에이전트 사이 의존성이 많은 영역은 지금은 잘 맞지 않고, 코딩 작업은 연구보다 병렬로 나눌 부분이 적다고 해요.

## 왜 비용이 더 드나

출처가 다르므로 세 가지 공식 설명을 따로 적어요.

- **Anthropic 엔지니어링 글(2025년 6월, 자체 내부 데이터):** 에이전트는 채팅보다 보통 약 4배, 멀티 에이전트 시스템은 약 15배 토큰을 써요. 추가 성능값을 치를 만큼 가치가 큰 일이어야 한다고 해요. 한 회사가 특정 시스템에서 잰 수치이지 내 작업이나 오늘의 모델에 대한 약속이 아니에요.
- **Claude Code 에이전트 팀 페이지:** 에이전트 팀은 한 세션보다 토큰을 훨씬 많이 써요. 팀원마다 컨텍스트 창이 따로 있고, 사용량은 활동 중인 팀원 수에 따라 늘어요. 일상적인 작업에는 한 세션이 더 경제적이라고 해요.
- **Claude Code 서브에이전트 페이지:** 서브에이전트는 도는 동안 자기 토큰을 쓰고, 자세한 결과를 돌려주는 서브에이전트가 많으면 컨텍스트를 많이 차지할 수 있어요.

우리가 직접 재 본 값은 없어요. 내 플랜이 사용량을 어떻게 세는지는 [에이전트 9편: 에이전트 비용과 사용 한도](/ko/agents/09-agent-usage-limits/)를 보세요.

### 1. 일이 나뉘는지 확인하기

A 조각이 B 조각을 기다리지 않고 끝날 수 있는지 물어보세요. 아니라면 에이전트 하나가 나을 가능성이 커요. "Building effective agents"의 조언도, 가능한 가장 단순한 해법을 찾고 필요할 때만 복잡도를 더하라는 거예요.

### 2. 조각마다 분명한 지시 주기

Anthropic 연구 글은 "반도체 부족을 조사해"처럼 짧은 지시를 주면 서브에이전트가 일을 잘못 이해하거나 서로 같은 검색을 반복했다고 해요. 서브에이전트마다 목표, 출력 형식, 쓸 도구와 출처에 대한 안내, 분명한 작업 경계가 필요하다고 해요.

<PromptBox>
작은 팀이 쓸 노트 앱 세 가지를 비교하고 싶어. 앱마다 하나씩, 세 부분으로 나눠 줘. 각 도우미는 (1) 공식 사이트와 도움말만 쓰고, (2) 가격·지원 플랫폼·공유 기능을 표로 정리하고, (3) 확인하지 못한 것은 "확인 못 함"으로 표시해. 도우미끼리 겹치지 않게 해. 끝나면 표 세 개를 합쳐 차이점을 정리해 줘. 우선 도우미 세 명으로만 시작해.
</PromptBox>

### 3. 처음에는 작은 팀으로

Claude Code 에이전트 팀 페이지는 대부분의 작업에서 팀원 3~5명으로 시작하라고 하고, 집중한 팀원 셋이 산만한 다섯보다 나은 경우가 많다고 해요. Anthropic 연구 글은 초기 버전이 간단한 질문에도 서브에이전트를 50개 띄운 적이 있고, 그래서 질문의 복잡도에 맞춰 노력을 조절하는 규칙을 넣었다고 해요.

### 4. 돌아온 결과 검토하기

리드는 도우미가 보고한 것만 봐요. 도우미가 틀릴 수도 있고 둘이 서로 다른 말을 할 수도 있어요. 합쳐진 답에 [에이전트 7편: 에이전트 작업 검토하기](/ko/agents/07-reviewing-agent-work/)의 루틴을 쓰고, 중요한 주장은 출처를 열어 보세요.

## Claude Code 짧은 예 (이 글을 위해 실행하지는 않음)

Claude Code를 쓴다면 일상적인 말로 서브에이전트를 부탁할 수 있어요. 서브에이전트 페이지에는 이런 프롬프트가 나와요.

```text
Research the authentication, database, and API modules in parallel using separate subagents
```

그러면 Claude가 영역마다 서브에이전트를 두고 조사한 뒤 결과를 합쳐요. 에이전트 팀은 기능을 켠 뒤, 공식 예시처럼 관점별로 팀원을 만들어 달라고 요청해요. 이 프롬프트들을 직접 실행하지는 않았으니 내 프로젝트에서는 결과가 다를 수 있어요. 서브에이전트를 직접 만드는 방법은 [코딩 12편](/ko/coding/39-claude-code-subagents/), 코드에서 정의하는 방법은 [개발 3편](/ko/dev/03-agent-sdk/)에 있어요.

| 서브에이전트가 서브에이전트를 시작할 수 있나요? | 기본값으로는 메인 대화 아래 세 겹까지 가능해요 (Claude Code 문서). |
| 동시에 도는 서브에이전트 수 제한이 있나요? | 기본값으로 한 세션에서 20개가 돌고 있으면 새로 시작하는 데 실패해요 (Claude Code 문서, 설정으로 변경 가능). |
| 팀원이 자기 팀을 만들 수 있나요? | 아니요. 에이전트 팀 페이지는 중첩 팀이 없고 리드만 팀을 관리한다고 적어요. |
| 에이전트 팀은 안정적인가요? | 실험 기능으로 표시되어 있고 기본으로 꺼져 있어요. |

## 자주 막히는 부분

### 리드가 위임하지 않고 혼자 했어요

- **원인**: 위임은 리드가 정해요. 서브에이전트 페이지는 Claude가 각 서브에이전트의 설명(description)을 보고 위임할 때를 정한다고 해요.
- **해결**: "조각마다 따로 서브에이전트를 써 줘"처럼 분명히 요청하세요.

### 도우미들이 같은 일을 반복했어요

- **원인**: Anthropic 연구 글이 짚었듯, 모호하거나 겹치는 지시예요.
- **해결**: 도우미마다 서로 다른 목표와 경계를 주세요.

### 답은 자신 있어 보이는데 앞뒤가 안 맞아요

- **원인**: 도우미들이 따로 일했고 합치는 과정에서 의견 차이가 가려졌을 수 있어요.
- **해결**: 최종 답 전에 도우미들 사이의 충돌을 먼저 나열해 달라고 하세요.

### 생각보다 사용량이 빨리 줄었어요

- **원인**: 도우미마다 자기 토큰을 써요.
- **해결**: 도우미 수를 줄이거나, 일상적인 일에는 에이전트 하나를 쓰세요.

## 실전 팁

- **하나로 시작하세요.** 일이 분명히 나뉠 때만 도우미를 더하세요.
- **새 동료에게 쓰듯 지시하세요.** 목표, 형식, 한계를 적어요.
- **위험한 행동은 내가 정하세요.** 도우미도 도구를 쓰고, 문서에 따르면 서브에이전트의 도구는 제한할 수 있어요. [에이전트 5편: 안전하게 쓰기](/ko/agents/05-agent-safety/)를 보세요.
- **달라질 수 있다고 생각하세요.** 같은 프롬프트도 매번 다르게 나뉠 수 있어요.
- **숫자는 금방 낡아요.** 4배와 15배는 한 시스템에 대한 2025년 글의 수치예요.
