- 이 편은 [6편](/ko/coding/06-claude-code-start/)의 다음 단계예요. 6편이 "한 장짜리 페이지"였다면, 여기서는 **입력하고 저장되는 작은 가계부 웹앱**을 만들어요.
- 설치와 로그인은 [C12](/ko/claude/c12-claude-code-overview/)에 있어요. 이 편은 반복하지 않아요.
- 요령은 세 가지예요. **뼈대부터 → 기능을 하나씩 → 매번 눈으로 확인.** 큰 요청 하나보다 작은 요청 여러 개가 훨씬 잘 돼요.
- 안전 습관도 같이 익혀요. 변경 내용 확인, 비밀정보(비밀번호·API 키) 넣지 않기, 되돌리기, 작업 폴더 밖은 건드리지 않기.
- Claude Code는 Pro 이상 유료 플랜에서 쓸 수 있어요([C2](/ko/claude/c02-plans-limits/), 2026-11-02 기준).
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 만들고 싶은 앱을 문장으로 설명해서 **동작하는 가계부 웹페이지**를 얻을 수 있어요.
- 내 컴퓨터의 브라우저에서 결과를 열어 보고, 잘 되는지 **직접 시험하는 방법**을 알게 돼요.
- "이것 좀 바꿔 줘"를 반복하며 **조금씩 다듬는 흐름**을 익혀요.
- 위험한 상황(비밀정보 노출, 의도치 않은 변경)을 **미리 줄이는 습관**을 갖게 돼요.

## 먼저 알아둘 개념

이 방식을 흔히 **바이브 코딩**이라고 불러요. 코드를 직접 쓰지 않고, 원하는 것을 말로 설명하고 결과를 보면서 고쳐 달라고 하는 작업 방식이에요(이 사이트에서 편의상 쓰는 표현이에요).

| 용어 | 이 실습에서의 뜻 |
| --- | --- |
| **작업 폴더** | Claude Code가 읽고 쓰는 범위예요. 빈 폴더 하나에서 시작해요. |
| **권한 모드** | Claude가 묻지 않고 해도 되는 동작 범위예요. `Shift+Tab`으로 바꿔요. 모드 설명은 [C14](/ko/claude/c14-claude-code-features/)를 보세요. |
| **계획 모드** | 파일을 바꾸지 않고 계획만 제안하는 모드예요. |
| **체크포인트** | Claude가 파일을 바꾸기 전에 남기는 되돌리기 지점이에요. `/rewind`로 열어요. |
| **확인 방법** | 결과가 맞는지 보는 방법이에요. 이 실습에서는 "브라우저에서 직접 눌러 보기"예요. |

공식 문서는 Claude에게 **스스로 확인할 방법을 주라**고 권해요. 테스트, 빌드, 스크린샷처럼 결과를 읽을 수 있는 신호가 있으면 결과 품질이 좋아져요. 그리고 "검증할 수 없다면 내보내지 말라"고 해요(2026-11-02 확인). 이 편의 프롬프트에는 그래서 "만든 뒤에 이렇게 시험해 줘"가 들어 있어요.

<Aside type="note" title="이 실습의 가계부는 연습용이에요">
브라우저에 데이터를 저장하는 아주 단순한 앱이에요. 실제 은행 연동, 로그인, 여러 기기 동기화는 들어 있지 않아요. 진짜 개인 금융 정보는 넣지 말고 **연습용 예시 데이터**로만 시험하세요.
</Aside>

## 단계별 따라하기

<Checklist items={[
  '빈 폴더 gaegebu를 만들고 그 안에서 claude를 시작했어요',
  '계획 모드에서 계획을 먼저 받고 읽어 봤어요',
  '뼈대(입력 폼 + 목록)를 만들고 브라우저에서 열었어요',
  '지출 한 건을 직접 입력해서 시험했어요',
  '합계와 삭제 기능을 한 번에 하나씩 추가했어요',
  '새로고침해도 데이터가 남는지 확인했어요',
  '일부러 되돌리기를 한 번 해 봤어요',
  '비밀정보를 폴더에 넣지 않았는지 점검했어요',
]} />

<Steps>

1. **빈 폴더에서 시작하기**

   바탕화면 등에 `gaegebu`라는 빈 폴더를 만들고, 터미널을 그 폴더에서 열어 `claude`를 실행해요. 터미널이 처음이라면 [6편](/ko/coding/06-claude-code-start/)과 [C12](/ko/claude/c12-claude-code-overview/)를 먼저 보세요. 시작 화면의 권한 모드 표시도 6편에서 설명해요.

   ```sh
   cd ~/Desktop/gaegebu
   claude
   ```

   처음에는 편집할 때마다 확인을 묻는 모드로 두는 것이 안전해요. `Shift+Tab`을 누르면 모드가 바뀌고 화면 아래에 현재 모드가 보여요.

2. **무엇을 만들지 먼저 말하고 계획 받기**

   만들고 싶은 것을 한 번에 다 말하지 말고, **최소한의 첫 버전**부터 정해요. 계획 모드(`Shift+Tab`을 눌러 plan mode로, 또는 `claude --permission-mode plan`)에서 시작하면 파일을 바꾸기 전에 계획을 볼 수 있어요.

   <PromptBox>
   간단한 가계부 웹페이지를 만들고 싶어. 나는 코딩을 전혀 몰라. 첫 버전은 이것만 해 줘. (1) 날짜, 항목, 금액을 입력하는 칸과 추가 버튼 (2) 입력한 내역이 아래 표로 쌓이는 것. 파일은 index.html 하나로만 만들고, 인터넷에 연결하거나 외부 서비스를 쓰지 말아 줘. 어떤 파일을 어떻게 만들지 쉬운 말로 계획부터 알려 줘.
   </PromptBox>

   계획에서 볼 것은 세 가지예요. 파일이 `index.html` 하나인지, 외부 서비스에 연결하지 않는지, 내가 말한 기능만 들어 있는지요. 아니면 말로 고쳐 달라고 하세요.

3. **승인하고 뼈대 만들기**

   계획이 괜찮으면 승인해서 실행해요. 변경을 확인하는 화면이 나오면 **어떤 파일을 만드는지**만 보면 돼요. 폴더 안의 `index.html`이 맞으면 Yes를 선택해요. 승인 화면 읽는 법은 [6편](/ko/coding/06-claude-code-start/)의 3단계에 있어요.

   <ScreenshotPlaceholder caption="Claude Code가 파일 변경을 승인해 달라고 묻는 화면" officialUrl="https://code.claude.com/docs/en/quickstart#step-4-make-your-first-code-change" />

4. **내 컴퓨터에서 열어 보고 직접 눌러 보기**

   `index.html`을 더블클릭하면 브라우저에서 열려요. 열리지 않거나 헷갈리면 Claude에게 물어보세요.

   <PromptBox>
   만든 index.html을 내 컴퓨터 브라우저에서 여는 방법을 알려 줘. 그리고 잘 동작하는지 내가 직접 해 볼 시험 목록을 3개만 만들어 줘. 예를 들면 "항목 1건을 입력하고 추가를 누르면 표에 보여야 한다" 같은 식으로.
   </PromptBox>

   목록대로 **직접 입력하고 눌러 봐요.** 예시 데이터는 "10월 1일 / 점심 / 9000" 정도면 충분해요. 코드를 읽지 못해도 화면은 읽을 수 있어요. 문제가 있으면 본 대로 설명하세요. "추가를 눌렀는데 표에 아무것도 안 생겨"처럼요.

   <Aside type="tip" title="파일 대신 주소로 열고 싶다면">
   브라우저마다 파일을 직접 연 페이지의 저장 기능이 다르게 동작할 수 있어요. 데이터가 저장되지 않는다면 "내 컴퓨터에서 이 페이지를 간단한 로컬 서버로 여는 방법을 알려 줘"라고 요청해 보세요. Claude가 명령을 실행하려고 하면 승인을 묻는 화면이 나오니, 어떤 명령인지 읽어 보고 허용하세요. 공식 문서에서 이 부분의 정확한 동작은 확인하지 못했어요.
   </Aside>

5. **기능을 하나씩 추가하기**

   뼈대가 잘 보이면 기능을 **한 번에 하나씩** 추가해요. 한 번에 여러 개를 시키면 어디가 잘못됐는지 찾기 어려워요. 아래 요청을 순서대로 하나씩 해 보세요.

   <PromptBox>
   입력한 내역이 새로고침해도 사라지지 않도록, 이 브라우저 안에 저장되게 해 줘. 외부 서버에는 아무것도 보내지 말아 줘. 바꾼 뒤에 내가 어떻게 시험하면 되는지도 알려 줘.
   </PromptBox>

   <PromptBox>
   표 맨 아래에 전체 합계 금액을 보여 주고, 각 줄 끝에 삭제 버튼을 달아 줘. 삭제 전에는 정말 지울지 한 번 물어봐 줘.
   </PromptBox>

   <PromptBox>
   금액은 숫자만 입력할 수 있게 하고, 항목이나 금액이 비어 있으면 추가되지 않게 해 줘. 그리고 지출 말고 수입도 입력할 수 있게 구분 칸을 하나 추가해 줘.
   </PromptBox>

   요청할 때마다 브라우저를 새로고침(F5)하고, 방금 바뀐 부분만 직접 눌러 확인해요. 막히면 [빠른 참조표](#빠른-참조표)의 문장 틀을 쓰세요.

6. **다듬기: 화면 보고 말하기**

   기능이 되면 모양을 다듬어요. 화면을 보고 **구체적으로** 말할수록 결과가 좋아져요. "더 예쁘게"보다는 아래처럼요.

   <PromptBox>
   글자를 조금 키우고, 표의 줄마다 번갈아 연한 배경색을 넣어 줘. 수입은 파란색, 지출은 빨간색 글씨로 보여 줘. 휴대폰 화면에서도 가로로 넘치지 않게 해 줘. 바뀐 점을 3줄 이내로 요약해 줘.
   </PromptBox>

   화면 일부를 캡처해서 붙여 넣고 "이 모양처럼 만들어 줘"라고 할 수도 있어요. 공식 모범 사례도 화면 변경은 이미지를 보여 주고 결과와 비교하게 하는 방식을 예로 들어요.

   <ScreenshotPlaceholder caption="완성된 가계부 페이지 예시 (연습용 데이터)" />

7. **마음에 안 들면 되돌리기**

   일부러 이상한 변경을 요청해 보고 되돌려 보세요. 세션에서 `Esc`를 두 번 누르거나 `/rewind`를 입력하면 이전 체크포인트로 대화와 코드를 되돌리는 메뉴가 열려요. 되돌릴 대상은 대화만, 코드만, 둘 다 중에서 고를 수 있어요(공식 문서 2026-11-02 기준).

     { where: 'Claude Code 세션', action: 'Esc를 두 번 누르거나 /rewind 입력', result: '되돌릴 지점 목록' },

     { where: '프롬프트', action: '더 구체적으로 다시 요청하기', result: '새 시도' },
   ]} />

   <Aside type="caution" title="되돌리기의 한계">
   체크포인트는 Claude의 파일 편집 도구로 바뀐 것만 기록해요. 터미널 명령이나 외부 프로세스로 바뀐 것은 기록되지 않고, 공식 문서도 Git을 대체하지 않는다고 해요. 중요한 결과물은 별도 폴더에 복사해 두세요. Git 사용은 [8편](/ko/coding/08-cloud-github/)에서 다뤄요.
   </Aside>

8. **안전 점검하고 마무리하기**

   앱이 마음에 들면 다음 점검을 하고 끝내요. 자세한 이유는 아래 [안전하게 쓰기](#안전하게-쓰기)에 있어요.

   <PromptBox>
   이 폴더의 모든 파일을 훑어보고 다음을 알려 줘. (1) 비밀번호, API 키, 개인정보로 보이는 내용이 있는지 (2) 인터넷으로 데이터를 보내는 코드가 있는지 (3) 파일 목록과 각 파일의 역할. 아직 아무것도 바꾸지 말고 보고만 해 줘.
   </PromptBox>

   내일 이어서 하고 싶다면 같은 폴더에서 `claude -c`(가장 최근 대화 이어가기)나 `claude -r`(고르기)를 쓰세요. 안내 메모(CLAUDE.md) 만드는 법은 [6편](/ko/coding/06-claude-code-start/)의 7단계를 보세요.

</Steps>

## 안전하게 쓰기

코드를 모른다고 해서 위험한 것은 아니지만, **"AI가 알아서 했겠지"** 하고 넘어가는 습관이 가장 위험해요. 아래 다섯 가지를 지키면 대부분의 사고를 막을 수 있어요.

| 습관 | 이유와 방법 |
| --- | --- |
| **승인 화면을 읽는다** | 어떤 파일을 만들거나 바꾸는지, 실행하려는 명령이 무엇인지 봐요. 모르는 명령이면 "이 명령이 뭘 하는지 설명해 줘"라고 먼저 물어요. |
| **작은 요청, 자주 확인** | 한 번에 한두 가지만 바꾸고 브라우저로 확인해요. 공식 문서도 같은 문제로 두 번 넘게 고쳤다면 `/clear`로 새로 시작해 더 구체적으로 요청하라고 해요. |
| **비밀정보를 넣지 않는다** | 비밀번호, API 키, 카드·계좌 번호, 주민등록번호는 대화에도, 폴더 안 파일에도 두지 마세요. Claude Code는 작업 폴더의 파일을 읽을 수 있어요. |
| **자동 승인은 천천히** | 편집 자동 승인이나 자동 모드는 익숙해진 뒤에 되돌릴 수 있는 폴더에서만 쓰세요. 권한이 어떻게 평가되는지는 아래에 설명해요. |
| **공개 전에 점검한다** | 웹에 올리면 누구나 볼 수 있어요. 개인 내역이 들어 있지 않은지 꼭 확인하세요. 공개 방법은 [8편](/ko/coding/08-cloud-github/)에 있어요. |

### 읽으면 안 되는 파일을 막아 두기 (선택)

폴더에 `.env` 같은 비밀 설정 파일이 있다면 Claude가 읽지 못하게 규칙을 걸 수 있어요. 공식 문서의 권한 규칙은 `deny`(거부), `ask`(확인), `allow`(허용) 순으로 평가되고, **거부가 항상 우선**해요. `Read(./.env)`는 현재 폴더의 `.env` 읽기를 가리키는 규칙 형식이에요. 프로젝트 설정 파일 `.claude/settings.json`에 이렇게 적어요.

```json
{
  "permissions": {
    "deny": ["Read(./.env)"]
  }
}
```

세션 안에서 `/permissions`를 입력하면 현재 규칙과 그 규칙이 어느 설정 파일에서 왔는지 볼 수 있어요. 다만 공식 문서는 Bash 규칙이 같은 프로그램의 다른 호출 형태까지 막아 주지는 않는다고 설명해요. 규칙은 보조 장치일 뿐이니, **가장 확실한 방법은 비밀정보를 작업 폴더에 두지 않는 것**이에요. 이 규칙이 모든 경우에 막아 주는지는 공식 문서에서 확인하지 못했어요.

<Aside type="caution" title="'Yes, and don't ask again'은 신중히">
이 선택지를 고르면 허용 규칙이 저장돼서 이후 같은 종류의 동작을 묻지 않고 실행해요. 공식 문서에 따르면 영구 저장되는 경우 `.claude/settings.local.json`에 기록돼요. 잘 모르는 명령이라면 이번 한 번만 허용하세요.
</Aside>

## 자주 막히는 지점

### 만들 때마다 파일이 늘어나요

- **원인**: 요청에서 범위를 정하지 않았어요.
- **해결**: "파일은 index.html 하나로만"이라고 명시하세요. 이미 늘었다면 되돌리고 다시 요청하세요.

### 새로고침하면 입력한 내역이 사라져요

- **원인**: 저장 기능이 없거나, 파일로 연 페이지에서 브라우저가 저장을 막았을 수 있어요(브라우저마다 달라질 수 있어요).
- **해결**: "새로고침해도 남게 해 줘"를 다시 요청하고, 그래도 안 되면 4단계 팁처럼 로컬 서버로 여는 방법을 물어보세요.

### 고칠수록 더 이상해져요

- **원인**: 대화에 실패한 시도가 쌓여서 헷갈리는 상태일 수 있어요.
- **해결**: 공식 문서의 권장대로 `/clear`로 새로 시작하고, 지금 상태와 원하는 결과를 더 구체적으로 적어서 요청하세요. 그 전에 `/rewind`로 잘 되던 시점으로 되돌릴 수도 있어요.

### 승인 질문이 너무 자주 나와요

- **원인**: 확인을 묻는 모드는 변경마다 승인을 요구해요.
- **해결**: 익숙해지면 `Shift+Tab`으로 편집 자동 승인 모드를 쓸 수 있지만, 빈 폴더나 Git 저장소처럼 되돌릴 수 있는 곳에서만 쓰세요. 모드 설명은 [C14](/ko/claude/c14-claude-code-features/)에 있어요.

### Claude가 자신 있게 말하는데 화면이 달라요

- **원인**: Claude가 "됐다"고 말해도 실제로는 빠뜨린 부분이 있을 수 있어요.
- **해결**: 말만 믿지 말고 직접 눌러 보세요. 공식 문서도 성공 주장 대신 실행 결과나 스크린샷 같은 증거를 보여 달라고 하라고 권해요.
