<Summary>
- MCP(Model Context Protocol)는 Claude Code가 이슈 트래커, 데이터베이스, 디자인 도구 같은 바깥 도구를 직접 읽고 쓰게 해 주는 공개 표준이에요. 데이터를 채팅에 복사해 붙일 필요가 줄어요.
- 서버는 `claude mcp add`로 추가해요. **원격** 서버는 `--transport http <이름> <URL>`(권장), **로컬** 프로그램은 `claude mcp add <이름> -- <명령> [인자]`(stdio)예요. `--`는 Claude의 옵션과 서버 명령을 나눠 줘요.
- **범위(scope)**가 누가 서버를 쓰는지 정해요. `local`(기본, 나만·이 프로젝트만, `~/.claude.json`에 저장), `project`(프로젝트 루트의 `.mcp.json`으로 공유), `user`(나만·모든 프로젝트)예요.
- `claude mcp list`나 세션 안의 `/mcp`로 확인해요. 로그인이 필요한 서버는 `! Needs authentication`으로 보이고, `/mcp`나 `claude mcp login <이름>`으로 OAuth를 마쳐요.
- **안전**: 공식 문서는 서버마다 믿을 수 있는지 먼저 확인하라고 해요. 바깥 내용을 가져오는 서버는 프롬프트 인젝션 위험이 있어요. `.mcp.json`의 프로젝트 서버는 먼저 승인을 물어봐요. 데이터베이스는 읽기 전용 계정을 쓰고, 토큰은 커밋하는 파일에 넣지 마세요.
- 2026-11-02에 공식 페이지를 읽었어요. `claude mcp` 명령을 실행하거나 서버에 연결해 보지는 않았어요. 아래 명령과 출력은 모두 문서 내용이에요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 호스팅(HTTP) 서버와 로컬(stdio) 서버를 Claude Code에 추가하기
- 알맞은 범위를 고르고 서버가 어느 파일에 저장되는지 알기
- OAuth 로그인이 필요한 서버에 로그인하고, 서버를 확인·삭제하기
- 내가 만들지 않은 서버를 연결하기 전에 할 안전 점검 알기

## 먼저 알아둘 개념

[자동화 5](/ko/automation/20-connectors-mcp/)에서 MCP를 쉬운 말로 설명해요. AI가 내 도구를 쓰게 해 주는 공용 콘센트 같은 거예요. [개발 5](/ko/dev/05-mcp-server/)에서는 직접 서버를 만들어 봐요. 이 튜토리얼은 Claude Code 쪽, 즉 서버를 연결하는 명령과 파일을 다뤄요. MCP 도구의 권한 규칙은 [코딩 13](/ko/coding/40-settings-permissions/)과 같은 체계를 따라요.

### 연결하는 세 가지 방법 (공식 문서, 2026-11-02)

| 종류 | 언제 | 명령 형태 |
| --- | --- | --- |
| 원격 HTTP | URL이 있는 호스팅 서비스. 문서는 HTTP를 권장 옵션이라고 해요 | `claude mcp add --transport http <이름> <URL>` |
| 로컬 stdio | 내 컴퓨터에서 도는 프로그램(로컬 접근이 필요할 때) | `claude mcp add [옵션] <이름> -- <명령> [인자...]` |
| 원격 SSE | 지원 중단 예정(deprecated). 가능하면 HTTP를 써요 | `claude mcp add --transport sse <이름> <URL>` |

문서는 WebSocket 서버(`"type": "ws"`)도 설명해요. `.mcp.json`이나 `claude mcp add-json`으로 설정하고, `--transport` 플래그는 `ws`를 받지 않아요. 이 튜토리얼은 더 다루지 않아요.

### 범위(scope)

| 범위 | 적용되는 곳 | 팀과 공유 | 저장 위치 |
| --- | --- | --- | --- |
| Local(기본) | 현재 프로젝트만 | 아니요 | `~/.claude.json` |
| Project | 현재 프로젝트만 | 예, 버전 관리로 | 프로젝트 루트의 `.mcp.json` |
| User | 내 모든 프로젝트 | 아니요 | `~/.claude.json` |

MCP의 "local 범위"는 `.claude/settings.local.json`(코딩 13의 일반 로컬 설정 파일)이 아니라 `~/.claude.json`에 저장돼요. 같은 서버 이름이 여러 범위에 있으면 Claude Code는 우선순위가 가장 높은 정의로 한 번만 연결해요. 순서는 local, project, user, 플러그인 서버, claude.ai 커넥터예요. 범위끼리 필드를 합치지는 않아요.

<Steps>

1. **믿을 만한 서버인지 먼저 확인하기**

   추가하기 전에 이 서버를 믿을 수 있는지 판단해요. 공식 문서는 "서버를 연결하기 전에 믿을 수 있는지 확인하세요. 바깥 내용을 가져오는 서버는 프롬프트 인젝션 위험에 노출될 수 있어요"라고 안내해요(원문: "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk."). 제공 업체의 공식 문서나 Anthropic Directory의 검토된 커넥터에서 찾은 서버를 우선하고, 서버가 어떤 도구를 제공하는지 읽어 보세요.

2. **호스팅(HTTP) 서버 추가하기**

   공식 빠른 시작은 로그인이 필요 없는 Anthropic 문서 서버를 연결해요. Claude 세션 안이 아니라 터미널에서 실행해요.

   ```bash
   claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp
   ```

   `Added ...` 줄이 나오면 설정이 기록됐다는 뜻이고, 서버가 연결됐다는 뜻은 아니에요. 기본값은 local 범위예요.

3. **연결 확인하기**

   ```bash
   claude mcp list
   ```

   서버마다 상태가 보여요. 문서가 정리한 상태예요.

   | 상태 | 뜻 |
   | --- | --- |
   | `✔ Connected` | 사용할 수 있어요 |
   | `! Needs authentication` | 서버에 닿지만 브라우저 로그인이나 `--header`로 넘기는 토큰이 필요해요 |
   | `✘ Failed to connect` | 서버가 응답하지 않았어요 |
   | `⏸ Pending approval` | 아직 승인하지 않은 프로젝트 범위 서버예요 |
   | `✘ Blocked by enterprise managed policy` | 조직 정책이 막아요. 관리자에게 물어보세요 |

   세션 안에서는 `/mcp`가 같은 패널을 보여 줘요. `claude mcp get <이름>`은 자세한 내용과 서버가 어느 범위에 있는지 알려 줘요.

4. **써 보기**

   `claude`를 시작하고 서버가 필요한 일을 부탁해요. 서버 이름을 말하면 다른 도구가 아니라 그 서버에서 답이 나와요.

   <PromptBox>
   Use the claude-code-docs server to look up what MCP_TIMEOUT does
   </PromptBox>

   Claude가 서버를 처음 호출할 때 Claude Code가 권한을 물으면 내용을 읽고 승인해요. Claude의 출력에서 도구 호출에 서버 이름이 붙어 있어서, 답이 서버에서 왔는지 확인할 수 있어요.

5. **로그인(OAuth)이 필요한 서버 추가하기**

   Sentry, Linear, Notion 같은 호스팅 서비스는 MCP 서버를 OAuth 뒤에 둬요. 문서 예시는 Sentry예요.

   ```bash
   claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
   ```

   추가한 뒤 `claude mcp list`에 `! Needs authentication`이 보이는 건 문서에 따르면 정상이에요. 세션에서 `/mcp`를 열고 서버를 고른 뒤 **Authenticate**를 선택하고 브라우저에서 승인해요. 셸에서 `claude mcp login sentry`로 할 수도 있고, `claude mcp logout sentry`는 저장된 인증을 지워요. 문서에 따르면 토큰은 안전하게 저장되고 자동으로 갱신돼요.

   OAuth 대신 고정 토큰을 쓰는 서버는 추가할 때 넘겨요.

   ```bash
   claude mcp add --transport http secure-api https://api.example.com/mcp \
     --header "Authorization: Bearer your-token"
   ```

   <Aside type="caution" title="진짜 토큰을 공유 파일에 넣지 마세요">
   `--header`로 넘긴 값은 설정에 저장돼요. local·user 범위는 저장소 밖의 `~/.claude.json`이에요. project 범위는 커밋하는 `.mcp.json`에 들어가요. 문서에 따르면 `.mcp.json`에서 환경 변수를 참조할 수 있으니 `"Authorization": "Bearer ${API_KEY}"`처럼 쓰고 진짜 값은 셸 환경에 두세요. 설정되지 않았고 `:-기본값`도 없는 `${VAR}`는 `claude mcp list`와 `/mcp`에 경고가 떠요.
   </Aside>

6. **로컬(stdio) 서버 추가하기**

   공식 빠른 시작은 Claude에게 브라우저를 주는 Playwright 서버를 예로 들어요. `npx`로 실행하니 Node.js 18 이상이 필요해요.

   ```bash
   claude mcp add playwright -- npx -y @playwright/mcp@latest
   ```

   `--` 뒤는 Claude Code가 서버를 시작할 때 실행하는 명령이에요. stdio가 기본이라 `--transport`는 필요 없어요. npx가 패키지를 내려받는 동안에는 첫 `claude mcp list`가 `✘ Failed to connect`로 보일 수 있고, 문서는 잠시 기다렸다가 다시 실행하라고 해요.

   환경 변수를 넣을 때는 서버 이름이 `--env` 바로 뒤에 오면 안 된다고 문서가 경고해요. 둘 사이에 `--transport stdio` 같은 다른 옵션을 넣어요.

   ```bash
   claude mcp add --env AIRTABLE_API_KEY=YOUR_KEY --transport stdio airtable \
     -- npx -y airtable-mcp-server
   ```

   <Aside type="danger" title="로컬 서버는 내 컴퓨터에서 도는 프로그램이에요">
   stdio 서버는 내 사용자 권한으로 실행돼요. 패키지와 배포자를 믿을 수 있는 명령만 추가하고, 출처를 모르는 명령은 붙여 넣지 마세요. 문서의 데이터베이스 예시는 질의가 데이터를 바꾸지 못하게 읽기 전용 계정을 써요. 데이터베이스 서버는 모두 그렇게 하세요.
   </Aside>

7. **팀과 서버 공유하기 (project 범위)**

   ```bash
   claude mcp add --transport http shared-server --scope project https://example.com/mcp
   ```

   프로젝트 루트에 `.mcp.json`이 만들어지고, 이 파일을 커밋해요.

   ```json
   {
     "mcpServers": {
       "shared-server": {
         "type": "http",
         "url": "https://example.com/mcp"
       }
     }
   }
   ```

   대화형 세션에서 Claude Code는 프로젝트 범위 서버를 쓰기 전에 사람마다 승인을 물어봐요. 그래서 내려받은 저장소가 내 동의 없이 프로세스를 띄우지 못해요. 승인 선택을 되돌리려면 `claude mcp reset-project-choices`를 실행해요. `url`은 있는데 `type`이 없는 JSON 항목은 오류예요. `type`이 없으면 stdio로 읽기 때문이에요.

   <Aside type="caution" title="무인 실행은 물어보지 않아요">
   문서에 따르면 `claude -p` 실행, Agent SDK 세션, 일부 클라우드 세션에서는 승인 프롬프트를 보여 줄 수 없어서 프로젝트 범위 서버를 묻지 않고 불러와요. 서버를 빼려면 `disabledMcpjsonServers`에 넣거나, `--setting-sources`로 프로젝트 설정을 제외하거나, `--strict-mcp-config`로 시작해요. 무인으로 돌리기 전에 저장소의 `.mcp.json`을 읽어 보세요.
   </Aside>

8. **서버 삭제하기**

   ```bash
   claude mcp remove claude-code-docs
   ```

   원격 서버를 삭제하면 Claude Code가 저장해 둔 OAuth 토큰과 클라이언트 등록도 지워요. 발급한 서비스 쪽에서 토큰을 취소하지는 않아요. 서비스가 취소를 지원하면 먼저 `claude mcp logout <이름>`을 실행해요. 문서는 연결된 서버마다 Claude의 컨텍스트 창 일부를 쓴다고도 알려 주니, 안 쓰는 서버는 지우세요.

## 빠른 참고

### 공식 문서의 명령

| 명령 | 하는 일 |
| --- | --- |
| `claude mcp add --transport http <이름> <URL>` | 원격 HTTP 서버 추가 |
| `claude mcp add <이름> -- <명령> [인자]` | 로컬 stdio 서버 추가 |
| `claude mcp add-json <이름> '<json>'` | JSON 블록으로 추가 (셸에 맞게 이스케이프) |
| `claude mcp add-from-claude-desktop` | Claude Desktop에서 가져오기 (macOS와 WSL만) |
| `claude mcp list` / `get <이름>` | 상태와 함께 목록 / 자세히 보기 |
| `claude mcp login <이름>` / `logout <이름>` | OAuth 로그인 실행 / 저장된 인증 지우기 |
| `claude mcp remove <이름>` | 서버 삭제 (필요하면 `--scope <범위>`) |
| `/mcp` | 세션 안의 상태·로그인 패널 |

### 출력 크기

문서에 따르면 도구 출력이 10,000토큰을 넘으면 Claude Code가 경고하고, 기본 최대치는 25,000토큰이에요. Claude Code를 시작하기 전에 `MAX_MCP_OUTPUT_TOKENS` 환경 변수로 한도를 바꿀 수 있어요. 아주 큰 결과는 대화 대신 파일에 저장돼요.

### 조직 관리

관리자는 관리형 MCP 설정(`managed-mcp.json`, `allowedMcpServers`, `deniedMcpServers`)으로 서버를 배포하거나 제한할 수 있어요. 막힌 서버는 `Blocked by enterprise managed policy`로 보일 수 있어요. 이 튜토리얼은 그 설정을 다루지 않으니 공식 관리형 MCP 페이지를 보세요.

## 자주 막히는 부분

### `claude mcp add`가 "Added"라고 했는데 서버가 안 돼요

- **원인**: 이 명령은 자격 증명이나 명령이 실행되는지 확인하지 않고 설정만 저장해요.
- **해결**: `claude mcp list`나 `/mcp`로 확인해요. stdio 패키지를 아직 내려받는 중이면 기다렸다 다시 해요.

### 상태가 "Needs authentication"이에요

- **원인**: 서버가 401이나 403으로 응답하며 로그인을 요구해요.
- **해결**: `/mcp`에서 Authenticate를 고르거나 `claude mcp login <이름>`을 실행해요. `claude -p`에는 `/mcp` 패널이 없으니 먼저 대화형 세션에서 로그인해요.

### 서버를 추가했는데 다른 프로젝트 폴더에서는 안 보여요

- **원인**: 기본이 local 범위라서 추가한 프로젝트에서만 불러와요.
- **해결**: 모든 프로젝트에는 `--scope user`, 공유하려면 `--scope project`로 다시 추가해요. 범위는 추가할 때 정해지니 삭제하고 다시 추가해야 해요.

### 상태가 "Pending approval"이에요

- **원인**: 아직 승인하지 않은 `.mcp.json` 서버예요.
- **해결**: 그 폴더에서 `claude`를 대화형으로 실행해 승인해요. 신뢰하지 않은 폴더에서는 저장소에 커밋된 승인이 무시돼요.

### 추가 명령이 "already exists"로 실패해요

- **원인**: 같은 범위에 같은 이름이 있어요.
- **해결**: 기존 항목을 먼저 삭제하거나 다른 이름을 써요. 이름에는 글자, 숫자, 하이픈, 밑줄만 쓸 수 있어요.

## 실전 팁

- 실제로 쓰는 서버만 추가하세요. 연결된 서버마다 도구 이름과 안내가 Claude의 컨텍스트에 들어가요.
- `--scope project`는 팀 전체가 필요하고 개인 비밀이 필요 없는 서버에만 쓰세요.
- 오래 쓰는 토큰을 붙여 넣기보다 OAuth를 우선하고, 서버가 주는 가장 좁은 권한을 쓰세요(문서의 GitHub 예시처럼 선택한 저장소로 제한한 세분화 토큰 등).
- 읽기 전용으로 시작하세요. 데이터베이스 서버에는 읽기 전용 계정을 주세요.
- 서버가 돌려주는 텍스트는 믿을 수 없는 입력으로 다루세요. 바깥 내용을 읽은 뒤 Claude가 갑자기 이상한 작업을 제안하면 멈추고 확인하세요.
- MCP 도구도 권한 체계를 거치니 규칙으로 허용·거부할 수 있어요. [코딩 13](/ko/coding/40-settings-permissions/)을 보세요.
- 문서의 세부 사항은 버전에 따라 달라요(예: HTTP에서 SSE로의 자동 전환은 v2.1.265 이상). 플래그가 없다면 `claude --version`을 문서와 비교해 보세요.
