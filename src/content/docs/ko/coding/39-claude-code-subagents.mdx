<Summary>
- **서브에이전트**는 **자기만의 컨텍스트 창**, 시스템 프롬프트, 도구 접근, 권한을 가지고 일한 뒤 요약을 돌려주는 도우미예요. 곁다리 작업이 로그·검색 결과·파일 내용으로 메인 대화를 가득 채울 때 써요.
- 서브에이전트는 **YAML 프런트매터가 있는 마크다운 파일**이에요. 본문이 시스템 프롬프트이고 필수 항목은 `name`과 `description`뿐이에요. `.claude/agents/`(이 프로젝트, git으로 공유 가능) 또는 `~/.claude/agents/`(내 모든 프로젝트)에 둬요.
- `tools`(허용 목록)나 `disallowedTools`(차단 목록)로 제한하고, `model`(`sonnet`, `opus`, `haiku`, `fable`, 전체 모델 ID, `inherit`)을 골라요.
- 부르는 방법은 세 가지예요. 프롬프트에 이름 쓰기, **@멘션**으로 실행 보장하기, `claude --agent <이름>`으로 세션 전체를 그 서브에이전트로 돌리기.
- 서브에이전트의 요청도 메인 대화와 같은 사용량 한도에 합산돼요(공식 문서).
- 2026-11-01에 예제 파일을 `claude plugin validate`(Claude Code 2.1.316)로 검증했고, 리뷰어를 쓰는 프롬프트를 실제로 한 번 보냈어요. 아래 표의 모든 옵션을 다 시험한 것은 아니에요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 연습 프로젝트에서 읽기 전용 리뷰어와 테스트 실행 서브에이전트 만들기
- Claude에게 파일을 쓰게 할지 직접 쓸지 정하고, 저장 위치 고르기
- 이름, @멘션, 세션 전체로 서브에이전트를 부르고 어느 쪽이 실행을 보장하는지 알기
- 서브에이전트 파일이 조용히 무시되는 이유 찾기

## 먼저 알아둘 개념

[C14](/ko/claude/c14-claude-code-features/)에서 훅, MCP와 함께 서브에이전트를 한 단계로 소개했어요. 이 튜토리얼은 직접 만들어 보는 실습판이에요. 훅([코딩 10](/ko/coding/37-claude-code-hooks/))은 정해진 순간에 코드를 실행하고, 서브에이전트는 Claude가 일을 맡기는 별도의 일꾼이에요.

| 용어 | 뜻 |
| --- | --- |
| **서브에이전트** | 자기 컨텍스트 창, 시스템 프롬프트, 도구 접근, 권한을 가진 전문 도우미. 요약만 돌려줘요. |
| **프런트매터** | 파일 맨 위 `---` 사이의 설정(`name`, `description`, `tools`, `model` 등). |
| **description** | Claude가 *언제* 맡길지 알려 주는 항목. 가장 중요한 줄이에요. |
| **위임(delegation)** | Claude가 서브에이전트에게 일을 넘기는 것. description에 맞으면 자동으로, 내가 부탁해도 일어나요. |
| **범위(scope)** | 파일 위치: 프로젝트(`.claude/agents/`), 사용자(`~/.claude/agents/`), 플러그인, 관리 설정, CLI 플래그. |

### 서브에이전트 파일 위치 (공식 문서, 2026-11-01 기준)

| 위치 | 범위 | 우선순위 |
| --- | --- | --- |
| 관리 설정(Managed settings) | 조직 전체 | 1 (가장 높음) |
| `--agents` CLI 플래그 | 현재 세션만 | 2 |
| `.claude/agents/` | 현재 프로젝트 | 3 |
| `~/.claude/agents/` | 내 모든 프로젝트 | 4 |
| 플러그인의 `agents/` 디렉터리 | 플러그인이 켜진 곳 | 5 (가장 낮음) |

이름이 같은 서브에이전트가 있으면 우선순위가 높은 위치가 이겨요. Claude Code는 `.claude/agents/`와 `~/.claude/agents/`를 재귀적으로 훑기 때문에 `agents/review/` 같은 하위 폴더를 써도 되고, 식별은 `name` 필드로만 해요.

<Aside type="note" title="기본 제공 서브에이전트가 이미 있어요">
Claude Code는 스스로 쓰는 기본 서브에이전트를 갖고 있어요. **Explore**(읽기 전용 코드 탐색), **Plan**(계획 모드의 조사), **general-purpose** 등이에요. 같은 종류의 일꾼을 같은 지시로 계속 부르게 될 때 직접 만들어요.
</Aside>

## 단계별 따라하기

<Steps>

1. **범위를 정하고 프로젝트 열기**

   연습 폴더에서 터미널을 열고 `claude`를 시작하세요. 서브에이전트는 프로젝트의 `.claude/agents/` 폴더에 저장할게요. 커밋해서 팀과 공유할 수 있어요. 어디서나 쓰는 개인 도우미라면 `~/.claude/agents/`를 쓰세요.

   `.claude/agents/` 폴더가 아직 없다면 세션을 시작하기 **전에** 만들거나, 첫 파일을 추가한 뒤 Claude Code를 다시 시작하세요. 공식 문서에 따르면 실행 중인 세션은 새로 생긴 `agents` 디렉터리를 감지하지 못해요. 폴더가 있으면 그 안의 파일 수정은 몇 초 안에 반영돼요.

2. **읽기 전용 리뷰어를 직접 쓰기**

   `.claude/agents/doc-reviewer.md`로 저장하세요.

   ```markdown
   ---
   name: doc-reviewer
   description: Reviews Markdown documentation for unclear steps, typos, and broken internal links. Use proactively after docs are edited. Read-only.
   tools: Read, Grep, Glob
   model: sonnet
   color: blue
   ---

   You are a careful documentation reviewer. You never edit files.

   When invoked:
   1. Find the Markdown files the user named, or the ones changed recently if none were named.
   2. Read each file and check for unclear steps, typos, and internal links that point to files that do not exist.
   3. Report in three groups: Must fix, Should fix, Nice to have.

   For every item give the file, the line or heading, the problem, and a suggested rewrite.
   End with one sentence saying whether the docs are ready to publish.
   ```

   문서에 따른 각 부분의 역할이에요. `name`과 `description`은 필수예요. `tools`는 허용 목록이에요(여기서는 읽기·검색만 가능해서 파일을 고치거나 쓸 수 없어요). `tools`를 빼면 서브에이전트에게 쓸 수 있는 모든 도구를 물려받아요. `model`은 `sonnet`, `opus`, `haiku`, `fable`, 전체 모델 ID, `inherit`를 받아요. `color`는 작업 목록에서 보이는 색만 바꿔요. 본문이 **시스템 프롬프트**예요. 서브에이전트는 이 프롬프트와 작업 디렉터리 같은 기본 환경 정보만 받고, Claude Code 전체 시스템 프롬프트는 받지 않아요.

   필드 이름은 camelCase이고 정확히 맞아야 해요. Claude Code는 **인식하지 못하는 필드를 오류 없이 무시해요**. 그래서 `disallowedtools` 같은 오타는 아무 일도 하지 않아요.

   <PromptBox>
   .claude/agents/ 에 doc-reviewer라는 프로젝트 서브에이전트를 만들어 주세요. 마크다운 문서에서 불분명한 단계, 오타, 깨진 내부 링크를 점검하고, 읽기 전용(Read, Grep, Glob만)이어야 하며, 결과를 Must fix, Should fix, Nice to have로 나눠 보고해요. 파일을 쓴 뒤 내용을 보여 주세요.
   </PromptBox>

   위 프롬프트가 다른 방법이에요. 문서는 Claude에게 파일을 써 달라고 부탁해도 된다고 해요. 결과, 특히 `tools` 줄을 확인한 뒤에 믿고 쓰세요.

3. **이름으로 부르기**

   오타가 있고 없는 파일로 링크가 걸린 작은 `README.md`를 만들고 이렇게 부탁하세요.

   ```text
   Use the doc-reviewer subagent to review README.md
   ```

   특별한 문법은 없어요. 서브에이전트 이름을 말하면 Claude가 위임할지 정해요. 대화 기록에는 서브에이전트 이름과 짧은 작업 설명이 담긴 도구 호출 줄, 예를 들면 `doc-reviewer(...)`로 나타나요.

   **실행한 것:** 임시 폴더에 7줄짜리 README(오타, 없는 `setup.md`로의 링크, 모호한 단계)를 두고, Claude Code 2.1.316에서 일회성 `claude -p` 프롬프트로 시도했어요. 답은 리뷰어의 세 묶음(Must fix, Should fix, Nice to have)으로 왔고, 깨진 링크와 오타를 짚었으며 파일은 고치지 않았어요. 내 결과의 표현은 다를 수 있어요.

4. **test-runner를 쓰고 할 수 있는 일을 제한하기**

   문서의 두 번째 패턴은 메인 대화로 가는 출력을 *줄이는* 일꾼이에요. `.claude/agents/test-runner.md`로 저장하세요.

   ```markdown
   ---
   name: test-runner
   description: Runs the project's tests and reports only the failures with the likely cause. Use when a test run would flood the conversation with output.
   tools: Bash, Read, Grep, Glob
   model: haiku
   maxTurns: 15
   ---

   You run tests and summarize the result. You do not change any files.

   1. Find the test command (check package.json, Makefile, or README).
   2. Run it once.
   3. Reply with: pass/fail counts, then for each failure the test name, the error message, and your best guess at the cause.
   Do not paste full logs.
   ```

   `maxTurns`는 멈추기 전까지의 에이전트 턴 수 상한이고, 한도에 닿으면 출력이 부분 결과로 표시돼요. 이 파일은 검증만 했고 실제 테스트 모음에 대고 **실행해 보지는 않았어요**.

   <Aside type="caution" title="Bash로도 파일을 바꿀 수 있어요">
   "You do not change any files"는 지시일 뿐 잠금이 아니에요. `Bash`가 있는 서브에이전트는 파일을 쓰는 명령을 실행할 수 있어요. 확실한 보장이 필요하면 `Read, Grep, Glob`만 주거나 권한 규칙을 쓰세요. 문서에는 `Bash(git push *)`처럼 지정자가 붙은 `disallowedTools` 항목도 Bash **도구 전체**를 빼 버린다고 나와요. 특정 명령만 막으려면 `permissions.deny`에 Bash 거부 규칙을 쓰세요. 그 규칙은 메인 대화와 서브에이전트 모두에 적용돼요.
   </Aside>

   `tools`와 `disallowedTools`는 함께 쓸 수 있어요. `disallowedTools`가 먼저 적용되고, 남은 도구에서 `tools`가 해석돼요. MCP 서버 전체는 `tools`에 `mcp__github__*`를 쓰면 그 서버의 도구를 주고, `disallowedTools`에 `mcp__github`를 쓰면 막아요.

5. **@멘션으로 특정 서브에이전트 지정하기**

   자연어는 Claude가 정해요. 특정 서브에이전트의 실행을 보장하려면 `@`를 입력하고 파일을 멘션하듯 목록에서 고르세요.

   ```text
   @"doc-reviewer (agent)" look at the README changes
   ```

   내 메시지 전체는 그대로 Claude에게 가고, Claude가 서브에이전트에게 줄 작업 프롬프트를 써요. @멘션은 *어느* 서브에이전트가 실행되는지를 정할 뿐, 받는 프롬프트를 정하지는 않아요. `@agent-doc-reviewer`처럼 직접 입력해도 돼요.

   **세션 전체**를 서브에이전트로 돌리려면, 그 도구 제한과 모델이 메인 스레드에 적용되도록 `claude --agent doc-reviewer`로 시작하세요. 프로젝트의 기본값으로 하려면 `.claude/settings.json`에 `"agent": "doc-reviewer"`를 넣어요. 둘 다 있으면 CLI 플래그가 우선해요. `--agent` 플래그와 설정은 시험해 보지 못했어요.

   <FlowSteps title="서브에이전트를 부르는 세 가지 방법" officialUrl="https://code.claude.com/docs/en/sub-agents" steps={[
     { where: '프롬프트', action: '이름 쓰기: "Use the doc-reviewer subagent to ..."', result: 'Claude가 위임할지 정해요' },
     { where: '프롬프트', action: '@를 입력하고 서브에이전트 고르기', result: '이번 작업에서 그 서브에이전트가 실행되는 것이 보장돼요' },
     { where: '터미널', action: 'claude --agent doc-reviewer', result: '세션 전체가 그 서브에이전트의 도구와 모델로 돌아요' },
   ]} />

6. **로드됐는지 확인하고, 안 됐으면 고치기**

   프런트매터에 문제가 있으면 Claude Code는 **세션에 알리지 않고 서브에이전트 파일을 건너뛰어요**. 이런 경우예요. `name`이 없음, 여는 `---`가 첫 줄이 아님, `name`이 `-`로 시작하거나 `:`를 포함하거나 256자를 넘음, `name`은 있는데 `description`이 없음, YAML을 읽을 수 없음.

   문서가 소개하는 확인법 두 가지가 있어요. `claude --debug`를 실행해 디버그 로그(`~/.claude/debug/<세션 ID>.txt`)를 보세요. 철자가 틀린 필드는 `does not recognize or apply`로 검색하면 되고, Claude Code v2.1.296 이상이 필요해요. 또는 세션 전에 `claude plugin validate .claude/agents`(v2.1.233 이상)를 실행하면, 이름을 준 디렉터리에서 프런트매터를 읽을 수 없는 파일을 알려 줘요. 읽히지만 `name`이 없는 파일은 알려 주지 않아요. 우리 두 파일은 "Validation passed"가 나왔어요.

   `/agents` 명령에 대해: 문서에 따르면 지금은 Claude에게 부탁하거나 에이전트 폴더를 직접 고치라는 안내를 출력해요. Claude Code v2.1.197 이하에서는 대화형 마법사가 열렸어요. 화면이 다르면 버전을 확인하세요.

</Steps>

## 빠른 참조표

### 프런트매터 필드 (공식 문서, 2026-11-01 기준)

| 필드 | 필수 | 하는 일 |
| --- | --- | --- |
| `name` | 예 | 고유 ID(256자 이하). 파일명과 같을 필요는 없어요. `:` 금지. |
| `description` | 예 | Claude가 언제 위임할지. "use proactively"를 넣으면 자동 사용을 유도해요. |
| `tools` | 아니요 | 허용 목록(쉼표 구분 또는 YAML 목록). 빼면 서브에이전트가 쓸 수 있는 모든 도구를 물려받아요. |
| `disallowedTools` | 아니요 | 물려받았거나 나열된 도구에서 빼는 차단 목록. |
| `model` | 아니요 | `sonnet`, `opus`, `haiku`, `fable`, 전체 모델 ID, `inherit`. |
| `permissionMode` | 아니요 | `default`, `acceptEdits`, `auto`, `dontAsk`, `bypassPermissions`, `plan`. 메인 대화의 모드가 우선할 수 있어요. |
| `maxTurns` | 아니요 | 이 턴 수 후 멈춤. |
| `skills` | 아니요 | 시작할 때 컨텍스트에 미리 넣을 스킬. |
| `mcpServers` | 아니요 | 이 서브에이전트가 쓸 MCP 서버. |
| `hooks` | 아니요 | 이 서브에이전트에만 적용되는 수명 주기 훅. |
| `memory` | 아니요 | 지속 메모리 범위: `user`, `project`, `local`. |
| `isolation` | 아니요 | `worktree`면 임시 git 워크트리에서 실행. |
| `background`, `effort`, `color`, `omitClaudeMd`, `autoCompactWindow`, `initialPrompt` | 아니요 | 문서를 보세요. 일부는 최신 Claude Code 버전이 필요해요. |

플러그인 서브에이전트는 보안상 `hooks`, `mcpServers`, `permissionMode`를 무시해요. 필요하면 파일을 `.claude/agents/`로 복사하세요.

### 모델 결정 순서 (공식 문서)

Claude Code는 서브에이전트의 모델을 이 순서로 골라요. (1) Claude가 그 호출에 넘긴 모델, (2) 파일의 `model`, (3) 환경 변수 `CLAUDE_CODE_SUBAGENT_MODEL`, (4) 메인 대화의 모델. 모델을 나눠 쓰는 법은 [C15](/ko/claude/c15-model-division/)를 보세요.

### 한도와 기본값

| 항목 | 값 (공식 문서) |
| --- | --- |
| 서브에이전트 description 합계 | 15,000토큰을 넘으면 시작할 때 경고(기본 제공 제외), 모두 로드는 돼요 |
| 동시 서브에이전트 | 기본 20개. 21번째는 `Concurrent subagent limit reached`로 실패해요(`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`로 변경) |
| 중첩 | 기본적으로 서브에이전트가 메인 대화 아래 세 층까지 서브에이전트를 만들 수 있어요(`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`, 1이면 중첩 끔) |
| 기본 실행 방식 | Claude가 띄우는 서브에이전트는 **백그라운드**에서 더 작은 내장 도구 집합으로 시작해요 |

## 자주 막히는 지점

### Claude가 새 서브에이전트를 못 찾아요

- **원인**: 세션이 시작된 뒤에 `.claude/agents/`(또는 `~/.claude/agents/`)를 만들었거나, 파일이 건너뛰어졌어요.
- **해결**: Claude Code를 다시 시작하고 프런트매터를 확인하세요(6단계).

### Claude가 자동으로 위임하지 않아요

- **원인**: `description`이 모호하거나 다른 서브에이전트와 비슷해요.
- **해결**: *언제* 쓰는지 구체적으로 쓰고, "use proactively"를 넣거나, @멘션하세요.

### 나열한 도구를 쓸 수 없어요

- **원인**: 백그라운드 서브에이전트는 제한된 내장 도구만 유지하고, 서브에이전트에게 아예 주어지지 않는 도구도 있어요. 유효한 항목이 하나도 없는 `tools` 목록은 항목 이름을 알려 주는 오류와 함께 실행에 실패할 수 있어요.
- **해결**: 문서의 도구 목록과 이름·대소문자를 대조하세요.

### `permissionMode`를 정했는데도 권한 질문이 떠요

- **원인**: 메인 대화의 모드가 서브에이전트의 모드를 덮어쓸 수 있어요. 예를 들어 메인 세션이 `bypassPermissions`, `acceptEdits`, auto 모드면 서브에이전트도 그 모드로 돌아요.
- **해결**: 메인 세션의 모드를 의도적으로 정하세요. 문서의 권한 모드 절을 보세요.

### 서브에이전트의 요약에 세부 내용이 빠져요

- **원인**: 설계상 요약만 돌아와요.
- **해결**: 시스템 프롬프트에서 돌려받고 싶은 세부 내용(파일 이름, 줄 번호, 실행한 명령)을 정확히 요청하세요.

## 실전 팁

- 서브에이전트 하나는 **하나의 일**을 잘하게 하고, 한 서브에이전트만 맞도록 description을 쓰세요.
- 필요한 최소한의 도구만 주세요. 리뷰어에게 `Edit`나 `Write`는 거의 필요 없어요.
- 싸고 기계적인 일(테스트 실행, 로그 읽기)은 `haiku`에, 판단이 필요한 일은 더 강한 모델에 두고, 실제 작업 몇 개로 결과를 비교해 보세요.
- 프로젝트 서브에이전트는 커밋해서 팀원이 같은 도우미를 쓰게 하고, 코드처럼 다뤄 `tools` 줄의 변경을 검토하세요.
- 길고 시끄러운 곁다리 작업은 서브에이전트에, 주고받는 대화·빠른 수정·여러 단계가 맥락을 공유하는 일은 메인 대화에서 하세요(문서의 안내예요).
- 서브에이전트 사용량도 플랜 한도에 합산되니, 서브에이전트를 많이 병렬로 돌리면 사용량이 더 빨리 줄어요.
