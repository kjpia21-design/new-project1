<Summary>
- "확장 사고(extended thinking)"는 Claude가 답하기 전에 먼저 추론하게 하는 기능의 예전 이름이에요. 지금 공식 문서는 현재 방식을 **적응형 사고(adaptive thinking)**라고 불러요. `thinking: {"type": "adaptive"}`를 쓰면 Claude가 요청마다 생각할지, 얼마나 생각할지 스스로 정해요.
- 예전 수동 방식 `thinking: {"type": "enabled", "budget_tokens": N}`은 **레거시이며 지원 중단(deprecated)**으로 표시돼 있어요. 문서에 따르면 Claude 4.7 이후 모델은 이 방식을 **400 오류**로 거부해요. Opus 5.5, Sonnet 5.5, Haiku 5.5도 포함돼요.
- Claude 5 계열(Opus 5.5, Sonnet 5.5, Haiku 5.5 포함)은 thinking이 **기본으로 켜져** 있어요. 생각 텍스트는 `display: "summarized"`로 설정하지 않으면 숨겨져요. 숨기면 스트리밍이 빨라질 뿐 **요금은 줄지 않아요**.
- 생각의 깊이는 토큰 예산이 아니라 `output_config.effort`(`low`, `medium`, `high`, `xhigh`, `max`)로 조절해요. 기본값은 Opus 5.5·Haiku 5.5가 `medium`, 대부분의 다른 모델은 `high`예요. effort는 부드러운 안내이고, 확실한 상한은 `max_tokens`예요.
- 생각 토큰은 **출력 토큰으로 과금**되고 `max_tokens`에 포함돼요. 응답의 `usage.output_tokens_details.thinking_tokens`로 생각에 쓴 토큰 수를 볼 수 있어요.
- thinking 모드, `budget_tokens`, 최상위 effort를 바꾸면 **프롬프트 캐시 지점이 무효화**돼요. Opus 5.5는 thinking을 끌 수 없고, Sonnet 5.5와 Haiku 5.5는 각자 규칙이 있어요(표 참고).
- 2026-11-02에 공식 페이지 4개를 읽었고, 스크립트의 출력 로직을 로컬 스텁으로 실행했어요. 하지만 **실제 API 호출은 하지 못했어요**(API 키와 `anthropic` 패키지가 없었어요). SDK 코드는 문서 기준이고 끝까지 테스트하지 않았어요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 적응형 사고와 예전 `budget_tokens` 방식의 차이를 설명하고, 내 모델에 맞는 쪽을 골라요.
- thinking을 켜고 요청해서 thinking·text 블록을 읽고, 생각에 쓴 토큰 수를 확인해요.
- 토큰 예산 대신 `effort`와 `max_tokens`로 깊이와 비용을 조절해요.
- 흔한 함정을 피해요: 예전 문법에서 나는 400 오류, 비어 있는 thinking 필드, 잘린 답, 사라진 캐시 적중.

## 먼저 알아둘 개념

한 번에 답하는 모델은 첫 시도에서 전부 맞혀야 해요. thinking을 켜면 Claude가 먼저 문제를 풀어 봐요(질문 다시 정리하기, 접근 시도하기, 중간 결과 확인하기). 그다음 답해요. 문서는 수학, 코딩, 분석, 긴 에이전트 작업 같은 복잡한 일에 도움이 된다고 해요. 대신 토큰과 시간이 들기 때문에 모든 요청에 켜고 싶지는 않을 거예요.

| 용어 | 뜻 |
| --- | --- |
| **thinking 블록** | `text` 블록 앞에 오는 `thinking` 콘텐츠 블록. `thinking` 필드와 암호화된 `signature`가 있어요. |
| **적응형 사고** | `thinking: {"type": "adaptive"}`. Claude가 요청마다 생각할지, 얼마나 깊이 할지 정해요. |
| **확장 사고(수동 방식)** | `thinking: {"type": "enabled", "budget_tokens": N}`. 고정 예산. 문서상 레거시이고 지원 중단이에요. |
| **`display`** | `"summarized"`는 추론의 읽을 수 있는 요약을, `"omitted"`는 빈 `thinking` 필드를 돌려줘요. |
| **`effort`** | `output_config.effort`. 응답 전체에 얼마나 공을 들일지 정해요. 생각의 빈도와 깊이도 포함돼요. |

thinking 블록에서 읽는 내용은 **날것의 사고 과정이 아니에요**. 문서는 다른 모델이 만든 요약이라고 해요. 요금은 보이는 요약이 아니라 전체 생각 기준으로 나와요.

이 편은 effort를 비용 조절 수단으로 소개한 [개발 2](/ko/dev/02-cost-optimization/)와, `thinking_delta` 스트림 이벤트를 보여 준 [개발 15](/ko/dev/15-streaming/) 위에 있어요. 배치에서도 쓸 수 있어요([개발 16](/ko/dev/16-batch-api/)).

<Aside type="caution" title="예전 글의 'budget_tokens'">
오래된 글과 샘플 코드는 `budget_tokens`를 써요. 현재 문서는 그 방식을 레거시로 표시해요. 새 모델에 그대로 복사하면 400 오류가 나요. 먼저 1단계의 모델 표를 확인하세요.
</Aside>

1. **내 모델이 각 설정에 어떻게 반응하는지 확인하기**

   공식 문서에 모델별 표가 있어요. 이 사이트에서 많이 쓰는 모델 행만 옮겼어요(400 오류는 API가 요청을 거부한다는 뜻이에요).

   | 모델 | `thinking` 필드 없음 | `"adaptive"` | `"enabled"` + `budget_tokens` | `"disabled"` |
   | --- | --- | --- | --- | --- |
   | Opus 5.5 | 적응형 사고 | 적응형 사고 | 400 오류 | 400 오류 |
   | Sonnet 5.5 | 적응형 사고 | 적응형 사고 | 400 오류 | 400 오류 (`"between_tools"` 사용) |
   | Haiku 5.5 | 적응형 사고 | 적응형 사고 | 400 오류 | `high` effort 이하에서 thinking 꺼짐 |
   | Opus 4.8 / 4.7 | thinking 꺼짐 | 적응형 사고 | 400 오류 | thinking 꺼짐 |
   | Opus 4.6 / Sonnet 4.6 | thinking 꺼짐 | 적응형 사고 | 확장 사고(지원 중단) | thinking 꺼짐 |
   | Opus 4.5 / Sonnet 4.5 / Haiku 4.5 | thinking 꺼짐 | 400 오류 | 확장 사고 | thinking 꺼짐 |

   읽는 법: Claude 5.5 모델은 아무 설정 없이도 thinking이 켜지고, 예전 예산 문법은 거부돼요. 지원 중단 표시 없이 `budget_tokens`를 받는 쪽은 4.5 세대뿐이고, 그 모델들에서는 거꾸로 `"adaptive"`가 오류예요. Sonnet 5.5의 가장 낮은 설정은 `thinking: {"type": "between_tools"}`로, 요청 앞부분의 생각을 끄는 설정이에요(`high` effort 이하에서 가능). 문서는 보내기 전에 Models API의 `capabilities.thinking.types`로 지원 여부를 확인할 수 있다고도 해요. 그 페이지는 열어 보지 않았어요(세부 내용 확인하지 못함).

2. **요청을 보내고 블록 읽기**

   `think_demo.py`로 저장하세요. 요약된 생각 텍스트를 요청하고, effort를 medium으로 두고, 블록과 토큰 구분을 출력해요.

   ```python
   import anthropic

   client = anthropic.Anthropic()

   response = client.messages.create(
       model="claude-opus-5-5",
       max_tokens=16000,  # thinking tokens count toward this limit
       thinking={"type": "adaptive", "display": "summarized"},
       output_config={"effort": "medium"},
       messages=[
           {
               "role": "user",
               "content": "What is the greatest common divisor of 1071 and 462?",
           }
       ],
   )


   def show(response):
       saw_thinking = False
       for block in response.content:
           if block.type == "thinking":
               saw_thinking = True
               print("Thinking summary:", block.thinking or "(empty)")
           elif block.type == "text":
               print("Answer:", block.text)
       if not saw_thinking:
           print("(Claude chose not to think on this request)")

       usage = response.usage
       details = getattr(usage, "output_tokens_details", None)
       thinking_tokens = getattr(details, "thinking_tokens", None)
       print("stop_reason:", response.stop_reason)
       print("billed output_tokens:", usage.output_tokens)
       print("of which thinking_tokens:", thinking_tokens)


   show(response)
   ```

   요청 형태(`type`과 `display`가 든 `thinking`, `max_tokens: 16000`, 모델 `claude-opus-5-5`)는 문서의 예제 그대로예요. 문서는 요약이 유클리드 호제법 단계 같은 짧은 글이고 그 뒤에 답이 온다고 보여 주지만, 정확한 문구는 실행할 때마다 달라요. `thinking`과 함께 `output_config`에 `effort`를 두는 것은 effort 페이지에 있는 방식이에요. 다만 둘을 한 요청에 합친 문서 예제는 찾지 못했어요. 문서화된 두 매개변수를 우리가 조합한 것으로 보세요.

3. **`display`를 의도해서 고르기**

   `display`의 안정 값은 두 개예요.

   - `"summarized"`: `thinking` 필드에 읽을 수 있는 요약이 들어가요. Opus 4.6, Sonnet 4.6과 그 이전 모델의 기본값이에요.
   - `"omitted"`: `thinking` 필드는 비어 있지만 암호화된 `signature`는 그대로 와요. Claude 5.5 모델, Opus 4.8, Opus 4.7의 기본값이에요. 문서가 말하는 장점은 스트리밍 때 첫 텍스트 토큰이 빨리 나온다는 거예요. 생각 텍스트를 스트리밍하지 않기 때문이에요.

   과금은 어느 쪽이든 같아요. 전체 생각 토큰 값을 내요. 문서의 표현으로 "생략은 지연을 줄일 뿐 비용을 줄이지 않아요." 세 번째 값 `"updates"`는 베타이고 베타 헤더가 필요해서 다루지 않아요. 쉬운 요청에서 Claude가 생각을 건너뛰면 `display`와 상관없이 thinking 블록이 아예 없어요. 모든 답이 thinking 블록으로 시작한다고 가정하는 코드는 쓰지 마세요.

4. **예산 말고 `effort`로 깊이 조절하기**

   적응형 모드에서는 생각 토큰 예산을 정하지 않아요. 문서가 말하는 조절 수단은 둘이에요.

   | 조절 수단 | 하는 일 |
   | --- | --- |
   | `output_config.effort` | 생각의 빈도와 깊이(그리고 응답 전체의 분량)에 대한 **부드러운** 안내 |
   | `max_tokens` | 생각과 답을 합친 총 출력의 **확실한 상한** |

   문서의 단계 설명: `low`는 생각을 최소화하고 단순한 작업에서는 건너뛸 수 있어요. `medium`은 보통 수준이고 단순한 질문에서는 건너뛸 수 있어요. `high`는 도움이 되는 대부분의 요청에서 생각해요. `xhigh`와 `max`는 더 깊어요(모델마다 지원이 달라요). 기본값은 Opus 5.5와 Haiku 5.5가 `medium`, 다른 모델이 `high`이고, 기본값을 직접 적어도 생략한 것과 같게 동작해요. 문서는 effort를 직접 지정하고 내 작업에서 테스트하라고 권해요. 생각 비용이 부담될 때는 effort를 먼저 낮추라고 해요. `adaptive`는 생각 모드이지 effort 값이 아니에요. effort에 넣지 마세요.

   프롬프트 문구로도 조절할 수 있어요(예: 시스템 프롬프트에 "애매하면 바로 답하세요"). 하지만 문서는 문구에 민감하고 effort를 낮추는 쪽이 보통 더 나은 첫 수단이라고 해요. Sonnet 5.5와 Haiku 5.5는 프롬프트로 "덜 생각해"라고 해도 믿을 만하게 줄지 않는다고도 적혀 있어요.

5. **토큰과 비용 보기**

   생각 토큰은 텍스트를 생략해도 출력 토큰으로 과금되고, `max_tokens`에 포함돼요. `stop_reason`이 `max_tokens`이면 답이 잘린 거예요. 문서가 주는 해결책은 둘이에요. `max_tokens`를 올리거나 effort를 낮추세요. 그 요청들에 추론이 필요하면 상한을 올리고, 과하게 생각한 경우라면 effort를 낮추면 돼요.

   응답의 `usage.output_tokens_details.thinking_tokens`는 `output_tokens` 중 추론에 쓴 몫이에요(문서 샘플: 출력 348토큰 중 312가 thinking). 과금 총량은 계속 `output_tokens`예요. 스트리밍에서는 이 구분이 마지막 `message_delta` 이벤트에만 나와요. 가격은 공식 가격 페이지를 보세요. 그 페이지는 열어 보지 않아서 이 튜토리얼에는 가격표가 없어요(확인하지 못함).

6. **스트리밍·도구·캐싱과 함께 쓰기**

   - **스트리밍**([개발 15](/ko/dev/15-streaming/)): thinking 블록은 `thinking_delta` 이벤트로 오고, 블록이 끝나기 직전에 `signature_delta` 하나가 와요. `display: "omitted"`이면 각 thinking 블록이 빈 문자열의 `thinking_delta`를 보낸 뒤 서명을 보내요. 문서는 `max_tokens`가 21,333보다 크면 SDK가 스트리밍을 요구한다고도 해요. HTTP 타임아웃을 피하려는 클라이언트 쪽 검사예요. 이벤트가 필요 없으면 SDK의 `.stream()`으로 받고 최종 메시지만 가져오면 돼요.
   - **도구**: 도구 사용 턴 안에서는 어시스턴트의 thinking 블록을 `tool_use` 블록과 함께 **완전하고 수정하지 않은 채** 되돌려 보내야 해요. 수정된 블록은 400 오류로 거부돼요. 블록을 type으로 거를 때는 `redacted_thinking` 블록도 남기세요. 이전 턴의 thinking이 문맥에 남는지는 모델마다 달라요. API가 알아서 걸러 주므로 전부 되돌려 보내라는 것이 문서의 권장이에요. 도구 사용 턴 중간에 thinking을 켜고 끄지 마세요. 문서에 따르면 API가 그 요청에서 thinking을 조용히 꺼요.
   - **강제 도구 사용**: 적응형 사고에서는 `tool_choice`의 `any`나 이름 지정이 가능해요. 단 Opus 5.5, Sonnet 5.5, Fable 5.1, Mythos 5.1은 400 오류로 거부해요. 그 모델들은 `auto`와 엄격한 도구 사용 또는 구조화 출력을 쓰세요.
   - **캐싱**([개발 2](/ko/dev/02-cost-optimization/)): thinking 모드 전환, `budget_tokens` 변경, 최상위 effort 변경은 새 캐시 접두사를 시작해요. 메시지 단위 지점은 항상 놓쳐요. 캐시를 쓰는 대화 하나에는 설정 하나만 쓰세요. 생각이 많은 작업에는 1시간 캐시 지속 시간도 문서가 권해요.
   - **배치**([개발 16](/ko/dev/16-batch-api/)): 개발 16은 공식 배치 페이지가 확장 사고를 배치 가능 기능으로 든다고 적었어요. 이번에는 그 페이지를 다시 열지 않았어요. Thinking 페이지 자체는 레거시 예산이 32k를 넘을 때만 배치를 권해요.

   <PromptBox>
   Python anthropic SDK로 claude-opus-5-5 모델을 호출하고 있어요. 어려운 추론 질문 하나를 thinking type을 adaptive, display를 summarized로 하고 output_config effort를 low로 보내고, 같은 질문을 high로도 보내는 짧은 스크립트를 써 주세요. 각 답, thinking 블록이 나왔는지, output_tokens, usage.output_tokens_details.thinking_tokens를 출력하고 두 실행을 비교하는 짧은 표도 만들어 주세요. 공식 thinking·effort 페이지에 있는 매개변수만 쓰세요.
   </PromptBox>

</Steps>

## 그 밖에 알아둘 한계 (Thinking 페이지 기준)

- **샘플링 매개변수**: Opus 5.5, Sonnet 5.5, Haiku 5.5를 포함한 최신 모델들에서 기본값이 아닌 `temperature`, `top_p`, `top_k`는 thinking 사용 여부와 상관없이 400 오류예요. 문서는 API 버전 `2026-10-21`부터는 모든 모델에서 이 매개변수들이 400 오류라고도 해요. 그 마이그레이션 페이지는 열어 보지 않았어요.
- **프리필**: Claude 4.6 이후 모델은 thinking 여부와 상관없이 미리 채운 마지막 어시스턴트 턴을 400 오류로 거부해요.
- **최대 출력**: 표에 Opus 5.5, Sonnet 5.5, Haiku 5.5는 128K, 4.5 모델은 64K로 나와요.
- **레거시 방식 규칙**(4.5 세대 모델에 머무를 때만): `budget_tokens`는 1,024 이상이고 `max_tokens`보다 작아야 해요. 엄격한 상한이 아니라 목표치예요. 문서는 단순한 작업은 1,024 근처에서, 복잡한 작업은 16,000 이상에서 시작하고, 예산이 32k를 넘으면 배치를 쓰라고 해요.
- **이전**: `budget_tokens`를 빼고 `thinking: {"type": "adaptive"}`를 설정한 뒤 `output_config: {"effort": ...}`로 깊이를 조절하세요. 문서는 문법만이 아니라 동작이 바뀐다고 경고해요. 고정 예산은 모든 요청에서 생각하지만, 적응형은 쉬운 요청에서 건너뛸 수 있어요.

## 한눈에 보기

| 항목 | 값 (공식 문서, 2026-11-02) |
| --- | --- |
| 켜기(현재) | `thinking: {"type": "adaptive"}` (Claude 5 계열은 기본 켜짐) |
| 레거시 | `thinking: {"type": "enabled", "budget_tokens": N}`, 지원 중단. Claude 4.7 이후는 400 오류 |
| 텍스트 보기 | `thinking: {"type": "adaptive", "display": "summarized"}` |
| Effort | `output_config: {"effort": "low" \| "medium" \| "high" \| "xhigh" \| "max"}` |
| 기본값 | Opus 5.5·Haiku 5.5는 `medium`, 나머지는 `high` |
| 확실한 상한 | `max_tokens` (생각 + 답) |
| 과금 | 생각은 출력 토큰으로 전체 과금. `display`와 무관 |
| 토큰 구분 | `usage.output_tokens_details.thinking_tokens` |
| 캐시 | thinking 모드, `budget_tokens`, effort를 바꾸면 캐시 지점 무효화 |
| Managed Agents | thinking은 항상 켜져 있고 Managed Agents가 설정. 에이전트에 `thinking` 필드 없음 |

## 자주 막히는 부분

### `budget_tokens`나 `type: "enabled"`가 언급된 400 오류

- **원인**: 모델이 Claude 4.7 이후라서 레거시 형태를 거부해요.
- **해결**: `thinking: {"type": "adaptive"}`를 쓰고 `output_config.effort`를 설정하세요. 문서의 문제 해결 페이지가 오류 메시지별 해결법을 정리해 두었지만 열어 보지 않았어요.

### `thinking` 필드가 비어 있어요

- **원인**: `display`가 `"omitted"`예요. Claude 5.5 모델의 기본값이에요.
- **해결**: 읽고 싶으면 `display: "summarized"`로 설정하세요. 어느 쪽이든 생각은 과금돼요.

### thinking 블록이 아예 없어요

- **원인**: 적응형 사고는 모델이 선택해요. 쉬운 요청이나 낮은 effort에서는 Claude가 건너뛸 수 있어요.
- **해결**: 정상이에요. 더 생각하게 하려면 `effort`를 올리고, 블록이 항상 있다고 가정하지 마세요.

### 답이 잘려요 (`stop_reason: "max_tokens"`)

- **원인**: 답이 끝나기 전에 생각이 `max_tokens`를 다 썼어요.
- **해결**: `max_tokens`를 올리거나 `effort`를 낮추세요.

### 캐시 적중이 사라졌어요

- **원인**: 요청 사이에 thinking 모드, `budget_tokens`, 최상위 effort가 바뀌었어요.
- **해결**: 캐시를 쓰는 대화 하나에서는 고정하세요. 일부 모델은 캐시를 유지하는 메시지별 effort 변경(베타)을 지원해요. effort 페이지를 보세요.

### 보이는 생각 텍스트와 과금 토큰이 안 맞아요

- **원인**: 보이는 텍스트는 요약이에요. 과금은 전체 생각 기준이에요.
- **해결**: 실제 수치는 `usage.output_tokens_details.thinking_tokens`로 보세요.

## 실전 팁

- 모델 기본값으로 시작한 뒤, 내 작업 샘플로 `low`와 `high`를 비교하세요. 품질, 지연, `output_tokens`를 재 보세요.
- thinking을 켰으면 `max_tokens`를 넉넉히 두세요. 짧은 답 기준의 값은 자주 모자라요.
- 앱에서 추론을 보여 줄 일이 없으면 `display: "omitted"`로 스트리밍을 빠르게 하세요.
- 추론을 읽겠다고 답 본문에 사고 과정을 쓰게 하지 마세요. 일부 모델은 그런 요청을 거부할 수 있다고 문서가 말해요(`reasoning_extraction`). thinking 블록을 읽으세요.
- 실제 API로는 실행하지 못했어요. 첫 실행은 테스트로 보고 결과를 직접 확인하세요.
