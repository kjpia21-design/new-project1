<Summary>
- Admin API는 프롬프트가 아니라 **조직**을 관리해요. 구성원과 역할, 초대, 워크스페이스와 워크스페이스 구성원, API 키를 다루고, 개인 계정에서는 쓸 수 없어요.
- **Admin API 키**(`sk-ant-admin...`로 시작, `x-api-key` 헤더로 전송)는 일반 워크스페이스 키와 달라요. Console에서 **admin** 역할을 가진 구성원만 Admin keys 페이지에서 만들 수 있어요. 공식 문서는 다른 자격 증명도 둘 소개해요. `org:admin` 범위의 OAuth 베어러 토큰, 그리고 워크스페이스에 묶이지 않은 개인 키·서비스 계정 키예요.
- Console의 Admin 키는 **범위를 고를 수 없어요.** 모든 키가 Admin API 키를 받는 모든 엔드포인트에 전체 접근 권한을 가져요. 비밀 값은 한 번만 보이니 시크릿 관리자에 보관하세요.
- Admin API로는 **API 키를 만들 수 없어요**(Console에서 만들어요). 기존 키를 읽고, 이름을 바꾸고, 상태를 바꿀 수는 있어요. admin 역할 구성원은 API로 삭제할 수 없어요.
- 요청에는 `x-api-key`와 `anthropic-version` 헤더를 붙여요. 공식 예제는 `anthropic-version: 2026-10-21`을 써요. 일부 엔드포인트는 베타라 `anthropic-beta` 헤더가 더 필요해요(예: Claude Enterprise의 로그아웃 엔드포인트).
- 사용량·비용 보고서는 [개발 11](/ko/dev/11-usage-cost-api/)에서 다뤄요. 이 편은 구성원·워크스페이스·키 관리예요.
- 2026-11-06에 공식 페이지 네 곳을 읽었어요. **API는 호출하지 않았어요**(Admin 키 없음). Python 예제는 문법 검사만 통과해서 실행 결과는 없어요. 아래 쓰기 호출도 실행하지 않았어요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- Admin API 키, 일반 API 키, `org:admin` OAuth 토큰의 차이를 설명할 수 있어요.
- Admin 키를 안전하게 만들고 코드·저장소에 넣지 않고 보관할 수 있어요.
- 읽기 전용 호출로 구성원, 워크스페이스, API 키를 조회할 수 있어요.
- Admin API로 바꿀 수 있는 것(역할, 초대, 워크스페이스 구성원, 키 상태)과 못 하는 것을 알 수 있어요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **조직** | 구성원, 워크스페이스, 결제를 담는 Claude Console의 최상위 계정이에요. |
| **워크스페이스** | 조직 안에서 프로젝트·환경·팀을 나누는 묶음이에요. ID는 `wrkspc_`로 시작해요. 모든 조직에는 이름 변경·보관·삭제가 안 되는 Default Workspace가 있어요. |
| **Admin API 키** | 조직을 관리하는 키예요. Console 조직에서는 `sk-ant-admin01-`로 시작해요. |
| **일반 API 키** | Messages API 같은 모델 호출용 키예요. Admin API가 기대하는 키가 아니에요. |
| **조직 역할** | `user`, `claude_code_user`, `developer`, `billing`, `admin` 중 하나예요(owner와 primary owner도 admin 권한을 모두 가져요). |

<Aside type="note" title="이 편에서 확인한 것과 못 한 것">
사실 정보는 머리말의 공식 페이지 네 곳을 2026-11-06에 읽은 내용이에요. Admin API 키가 없어서 실제 API에는 **요청을 보내지 않았어요.** Python 예제는 문법 검사만 통과했어요. curl 명령은 공식 예제의 형태를 그대로 옮겼어요. 읽기 전용부터 실행해 보고 API 레퍼런스와 비교하세요. 개별 엔드포인트 레퍼런스 페이지는 열지 않아서 매개변수·응답 필드의 세부 내용은 이 편에서 확인하지 못했어요.
</Aside>

<Steps>

1. **알맞은 자격 증명 고르기**

   공식 문서에 따르면 Admin API는 세 가지 자격 증명을 받아요.

   | 자격 증명 | 보내는 방법 | 참고 |
   | --- | --- | --- |
   | Admin API 키(`sk-ant-admin...`) | `x-api-key` 헤더 | admin 역할 구성원만 발급할 수 있어요. 대부분의 엔드포인트에 써요. |
   | `org:admin` 범위 OAuth 베어러 토큰 | `authorization: Bearer` 헤더 | admin, owner, primary owner가 받을 수 있어요. 서비스 계정·페더레이션 발급자·페더레이션 규칙 엔드포인트는 이 토큰만 받아요. |
   | 워크스페이스에 묶이지 않은 개인 키·서비스 계정 키 | `x-api-key` 헤더 | 연결된 계정과 같은 권한을 가져요. |

   Claude Enterprise(claude.ai) 조직은 claude.ai에서 키를 만들고(접두사 `sk-ant-api01-`), `read:members`, `write:members` 같은 **범위를 고를 수 있어요.** Admin API 페이지 중 Enterprise에는 구성원·초대 엔드포인트만 해당해요. 이 편은 Console 조직 기준이에요.

2. **Admin 키 만들기(Console)**

   공식 안내: 조직 admin으로 로그인해 Console의 [Admin keys](https://platform.claude.com/settings/admin-keys) 페이지를 열고, **Create admin key**를 눌러 이름과 키 만료 기간을 정하고 **Add**를 누른 뒤, 표시된 비밀 값(`sk-ant-admin01-`로 시작)을 복사해요. 전체 비밀 값은 한 번만 보여요.

   <Aside type="caution" title="Admin 키는 강력해요">
   Console Admin 키는 범위를 고를 수 없어서, 키 하나로 Admin 키를 받는 모든 엔드포인트에 닿아요. 마스터 비밀번호처럼 다루세요. 시크릿 관리자에 보관하고, 커밋하지 말고, 채팅창에 붙여 넣지 말고, 만료 기간을 정해 교체하도록 하세요. 도구 하나에 전용 키를 쓰면 폐기하기 쉬워요(전용 키는 제 제안이고, 공식 모범 사례는 각 키의 `expires_at`을 점검하고 주기적으로 교체하라는 내용이에요).
   </Aside>

3. **키 설정하고 내가 누구인지 확인하기**

   메모에는 자리표시자를 쓰고, 실제 값은 시크릿 관리자에서 읽어 오세요.

   ```bash
   export ANTHROPIC_ADMIN_KEY="your-admin-key-here"

   curl --fail-with-body -sS "https://api.anthropic.com/v1/organizations/me" \
     -H "x-api-key: $ANTHROPIC_ADMIN_KEY" \
     -H "anthropic-version: 2026-10-21"
   ```

   공식 문서에 따르면 이 호출은 자격 증명이 속한 조직을 `id`, `type`(`organization`), `name`으로 돌려줘요. 상태: 여기서는 **실행하지 않았어요.** 성공하면 읽기 전용 호출 한 번으로 키와 조직을 함께 확인한 셈이에요.

4. **구성원·워크스페이스·키 조회하기(읽기 전용)**

   공식 문서의 목록 요청이에요. 각각 한 페이지를 돌려줘요.

   ```bash
   # 구성원
   curl "https://api.anthropic.com/v1/organizations/users?limit=10" \
     -H "x-api-key: $ANTHROPIC_ADMIN_KEY" \
     -H "anthropic-version: 2026-10-21"

   # 워크스페이스 (Default Workspace는 include_default=true일 때만 나와요)
   curl "https://api.anthropic.com/v1/organizations/workspaces?limit=10&include_archived=false" \
     -H "x-api-key: $ANTHROPIC_ADMIN_KEY" \
     -H "anthropic-version: 2026-10-21"

   # 활성 API 키
   curl "https://api.anthropic.com/v1/organizations/api_keys?limit=10&status=active" \
     -H "x-api-key: $ANTHROPIC_ADMIN_KEY" \
     -H "anthropic-version: 2026-10-21"
   ```

   응답의 각 API 키에는 `expires_at`(만료가 없으면 `null`)과 키가 대신하는 신원인 `principal`이 들어 있어요. 상태: **실행하지 않았어요.** 공식 키 예제는 `workspace_id=wrkspc_...`로도 거르고 있어요.

   SDK는 같은 엔드포인트를 `client.organization` 아래에 제공해요. `admin_audit.py`로 저장하세요. 읽기 전용이고, Admin 키가 평소 모델 호출용 키와 섞이지 않게 다른 변수 이름을 써요.

   ```python
   import os
   import anthropic

   client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_ADMIN_KEY"])

   org = client.organization.retrieve()
   print(f"organization: {org.name} ({org.id})")

   for key in client.organization.api_keys.list(limit=10, status="active"):
       print(f"{key.id}: {key.name} ({key.status})")
   ```

   상태: **실행하지 않았어요.** `python3 -I -m py_compile` 문법 검사만 통과했어요. 공식 문서에 따르면 목록 반복은 필요할 때 다음 페이지를 자동으로 가져오므로 `limit`은 전체 개수가 아니라 페이지 크기예요.

5. **바꿀 수 있는 것 이해하기**

   | 리소스 | 공식 문서에서 할 수 있다고 한 일 |
   | --- | --- |
   | 구성원 | 조회, 역할 변경, 삭제. admin 역할 구성원은 삭제할 수 없어요. |
   | 초대 | 만들기(이메일과 역할), 조회, 삭제. 초대는 21일 뒤 만료되고 바꿀 수 없어요. |
   | 워크스페이스 | 만들기, 조회, 목록, 수정, 보관. 기본값으로 조직당 최대 100개(보관된 것은 제외). |
   | 워크스페이스 구성원 | 추가, 조회, 역할 변경, 삭제. 역할: Workspace User, Limited Developer, Developer, Admin (Workspace Billing은 상속되며 직접 지정할 수 없어요). |
   | API 키 | 조회, 이름·상태 수정. 키를 **만들 수는 없어요.** |

   역할 상속이 중요해요. 조직 admin은 모든 워크스페이스에서 자동으로 Workspace Admin이 되고, 조직 user와 developer는 워크스페이스마다 직접 추가해야 해요. 사용자를 삭제하면 키에도 영향이 있어요. 개인 키는 작동을 멈추고, 서비스 계정 키는 서비스 계정이 보관되기 전까지 계속 작동하며, 워크스페이스 키는 계속 작동해요.

6. **쓰기 호출: 먼저 확인하기**

   쓰기 호출은 실제 접근 권한을 바꿔요. ID를 확인하고, 되돌리기 어려운 작업은 다른 사람에게 한 번 더 확인받으세요. 공식 문서의 요청 형태예요.

   ```bash
   # 사용자 초대 (공식 문서의 예시 주소와 역할)
   curl "https://api.anthropic.com/v1/organizations/invites" \
     -H "x-api-key: $ANTHROPIC_ADMIN_KEY" \
     -H "anthropic-version: 2026-10-21" \
     -H "content-type: application/json" \
     -d '{"email": "user@example.com", "role": "developer"}'

   # 키 비활성화 (실제 ID는 먼저 목록 호출로 찾으세요)
   curl "https://api.anthropic.com/v1/organizations/api_keys/apikey_EXAMPLE" \
     -H "x-api-key: $ANTHROPIC_ADMIN_KEY" \
     -H "anthropic-version: 2026-10-21" \
     -H "content-type: application/json" \
     -d '{"status": "inactive"}'
   ```

   상태: **실행하지 않았어요.** `apikey_EXAMPLE`은 자리표시자예요. 공식 수정 예제는 `status`와 `name`을 함께 보내요. `status`만 보내도 되는지는 확인하지 못했으니 API 레퍼런스를 확인하세요.

   Claude Enterprise 조직용으로, User management 페이지에 구성원을 모든 곳에서 로그아웃시키는 **베타** 엔드포인트가 있어요. `POST /v1/organizations/users/{id}/sign_out`에 `anthropic-beta: admin-user-sign-out-2026-10-08` 헤더와 `write:members` 범위의 키를 써요. 그 사람의 Claude 계정 전체에 적용되고, API 키는 멈추지 않으며, primary owner에게는 쓸 수 없어요. 이 엔드포인트는 호출하지 않았어요.

   <PromptBox>
   Claude Console 조직을 관리하고 있어요. 팀을 떠나는 사람을 위한 오프보딩 체크리스트를 써 주세요. 조직에서 제거하기, 개인 API 키와 서비스 계정 키와 워크스페이스 키가 각각 어떻게 되는지, 그 사람이 만든 키 점검 방법, 삭제 호출 전에 두 번째 사람이 확인할 것을 포함해 주세요. API 필드를 지어내지 말고, 확실하지 않으면 공식 Admin API 레퍼런스를 확인하라고 알려 주세요. 실제 키나 ID는 넣지 말고 자리표시자를 쓰세요.
   </PromptBox>

</Steps>

## 자주 막히는 부분

### 호출이 401이나 인증 오류를 돌려줘요

- **원인**: 일반 워크스페이스 키를 썼거나 헤더가 틀렸어요.
- **해결**: `x-api-key`에 Admin 키(또는 허용되는 다른 자격 증명)를 쓰세요. 대화형 OAuth 토큰은 수명이 짧아서, 요청이 401을 돌려주기 시작하면 export 명령을 다시 실행하라고 공식 문서가 안내해요.

### 개인 계정이라 Admin API를 못 써요

- **원인**: 공식 문서에 따르면 Admin API는 개인 계정에서 쓸 수 없어요.
- **해결**: Console의 Organization 페이지에서 먼저 조직을 만드세요.

### Enterprise 키에서 403이 나요

- **원인**: 엔드포인트가 요구하는 범위가 키에 없어요.
- **해결**: 공식 문서에 따르면 403 메시지에 키가 가진 범위와 필요한 범위가 나와요. 범위는 만들 때 정해지므로 새 키를 만드세요.

### 삭제한 사용자의 키가 제각각 동작해요

- **원인**: 키 종류(개인, 서비스 계정, 워크스페이스)에 따라 달라요.
- **해결**: 오프보딩 전후에 목록 호출로 키를 점검하세요.

## 실전 팁

- 읽기 전용 점검부터 하세요. 구성원 목록, 키 목록, `expires_at` 값이 예상과 같은지 비교해 보세요.
- Admin 키를 CI 로그나 스크린샷에 남기지 마세요. "시크릿 관리자에 보관" 외에는 공식 문서의 내용이 아니라 일반적인 보안 습관이에요.
- 짧게 쓰고 버리는 자동화 접근은 장기 키 대신 Workload Identity Federation을 쓰라고 공식 문서가 안내해요. 그 페이지는 이 편에서 다루지 않았어요.
- 사람이 떠날 때는 구성원 제거와 키 정리가 별개 단계라는 점을 기억하세요.
