- 개발자에게 AI는 **코드 이해, 버그 원인 찾기, 테스트·문서 작성, 리뷰** 같은 반복 작업을 줄여 주는 도구예요.
- 코드를 직접 다루는 도구로는 Claude Code, Cursor 등이 있고, 질문과 설계 상담은 대화형 AI로도 충분해요.
- AI가 만든 코드는 **내가 읽고, 실행하고, 테스트한 뒤에** 반영해야 해요.
- 비밀키·고객 데이터·사내 코드는 입력 범위를 정하고 시작하세요.
</Summary>

## 이런 분께

웹·앱·서버 개발자, 사이드 프로젝트를 하는 분, 팀에 AI 도구를 도입하려는 분께 맞는 가이드예요.

- 처음 보는 코드베이스를 빨리 파악해야 해요.
- 반복되는 테스트, 문서, 리뷰 작업이 많아요.
- AI가 준 코드를 어디까지 믿고 써야 할지 기준이 필요해요.

## AI가 특히 도움 되는 일 TOP 5

### 1. 처음 보는 코드 이해하기

파일 구조와 함수의 역할을 설명해 달라고 하면 온보딩 시간이 줄어요. 저장소 전체를 읽는 작업은 Claude Code나 Cursor 같은 코딩 도구가 잘 맞아요([Cursor로 기존 코드 이해하고 고치기](/ko/coding/09-cursor/)).

<PromptBox>
이 저장소의 구조를 파악하고 싶어. 주요 디렉터리의 역할, 진입점, 데이터가 흐르는 순서를 설명해 줘. 그리고 [기능명]을 수정하려면 어느 파일부터 읽어야 하는지 순서대로 알려 줘. 확실하지 않은 부분은 추측이라고 표시해 줘.
</PromptBox>

### 2. 버그 원인 좁히기

에러 메시지와 재현 방법을 주면 원인 후보를 우선순위로 받을 수 있어요. 비밀키와 개인정보는 지우고 붙여 넣으세요.

<PromptBox>
아래 에러가 발생해. 환경은 [언어/프레임워크/버전]이고, 재현 방법은 [재현 순서]야. 가능한 원인을 가능성이 높은 순서로 3가지 알려 주고, 각각 어떻게 확인하면 되는지 명령이나 로그 위치를 알려 줘. 바로 고치지 말고 원인 확인부터 하자.

[에러 메시지와 관련 코드]
</PromptBox>

### 3. 테스트 코드와 문서 작성

기존 함수에 대한 단위 테스트, 경계 조건, README, 주석 초안을 빠르게 만들 수 있어요. 생성된 테스트가 **실제로 실패할 수 있는지**도 확인하세요.

<PromptBox>
아래 함수에 대한 단위 테스트를 [테스트 프레임워크]로 작성해 줘. 정상 케이스, 경계값, 잘못된 입력 케이스를 나누어 쓰고, 각 테스트가 무엇을 검증하는지 한 줄 주석으로 적어 줘. 구현을 바꾸지는 마.

[함수 코드]
</PromptBox>

### 4. 코드 리뷰 보조

PR 변경 내용에서 놓치기 쉬운 버그, 예외 처리, 가독성 문제를 한 번 더 점검받을 수 있어요. 사람 리뷰를 대체하지 말고 **첫 번째 점검**으로 쓰세요.

<PromptBox>
아래 변경 내용을 리뷰해 줘. 버그 가능성, 예외 처리 누락, 보안 문제, 성능 문제, 가독성 순으로 문제를 찾고, 각 항목에 심각도(높음/중간/낮음)와 수정 제안을 붙여 줘. 문제가 없으면 없다고 말해 줘. 억지로 지적하지 마.

[diff]
</PromptBox>

### 5. 반복 작업 자동화와 에이전트 만들기

정해진 점검이나 배포 보조 같은 반복 업무는 스킬, 루틴, CI에 맡길 수 있어요. 개념은 [반복 업무를 에이전트에게 맡기기](/ko/coding/10-delegate-agents/)에서, API로 직접 만드는 방법은 [도구 사용으로 업무 봇 만들기](/ko/dev/01-tool-use/)에서 다뤄요.

<PromptBox>
매주 반복하는 [작업명]을 자동화하려고 해. 현재 수동 절차는 [절차]야. 이를 자동화할 수 있는 단계로 나누고, 사람이 반드시 확인해야 하는 승인 지점을 표시해 줘. 실패했을 때 되돌리는 방법도 같이 제안해 줘.
</PromptBox>

## 주의할 점

<Aside type="caution" title="비밀키와 고객 데이터는 입력하지 마세요">
API 키, 비밀번호, 토큰, 고객 개인정보는 프롬프트와 코드 붙여넣기에 넣지 마세요. 회사 코드는 소속 조직의 AI 사용 정책을 먼저 확인하세요. 기준은 [개인정보·회사 정보 안전하게 지키며 쓰기](/ko/basics/05-privacy-safety/)에 있어요.
</Aside>

- **검증**: AI는 존재하지 않는 함수나 오래된 사용법을 자신 있게 쓸 수 있어요. 실행과 테스트로 확인하세요([사실 확인법](/ko/basics/04-fact-checking/)).
- **권한**: 코드를 직접 실행하고 수정하는 도구는 승인 단위를 작게 두고, 삭제·배포·결제 같은 되돌리기 어려운 작업은 사람이 확인하세요([에이전트 안전하게 쓰기](/ko/agents/05-agent-safety/)).
- **라이선스**: 생성된 코드가 기존 오픈소스와 비슷할 수 있어요. 조직의 라이선스 정책에 맞게 검토하세요.
- **이해하고 반영하기**: 이해하지 못한 코드를 그대로 병합하지 마세요. 나중에 고칠 사람은 결국 나예요.
