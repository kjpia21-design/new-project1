<Summary>
- 스킬은 **지침·스크립트·리소스가 담긴 폴더**예요. Claude가 전문 작업에 필요할 때 동적으로 불러와요.
- Free/Pro/Max/Team/Enterprise에서 쓸 수 있고 코드 실행(code execution)이 켜져 있어야 해요. Claude Code와 API에서도 써요.
- Excel, Word, PowerPoint, PDF 내장 스킬은 요청에 맞으면 Claude가 자동으로 골라요.
- 스킬의 핵심 파일은 frontmatter(`name`, `description`)가 있는 마크다운이에요. 파일명은 문서마다 `skill.md`와 `SKILL.md`로 달라요. **Claude Code 문서 기준은 `SKILL.md`**예요.
- 신뢰할 수 있는 출처의 스킬만 설치하고, 활성화하기 전에 번들 파일(특히 스크립트)을 읽으세요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 내장 스킬이 언제 쓰이는지 알고, 스킬을 켜고 끌 수 있어요.
- 간단한 커스텀 스킬을 만들어 claude.ai에 올릴 수 있어요.
- Claude Code에서 `SKILL.md`로 스킬을 만들고 `/스킬이름`으로 실행할 수 있어요.
- 스킬의 보안 위험을 알고 안전하게 쓸 수 있어요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **스킬(Skill)** | 지침·스크립트·리소스가 담긴 폴더예요. Claude가 필요할 때 동적으로 불러와요. |
| **내장 스킬** | Anthropic이 제공하는 Excel, Word, PowerPoint, PDF 생성·처리 스킬이에요. |
| **커스텀 스킬** | 내가 만드는 스킬이에요. 폴더 이름이 스킬 이름과 같아야 하고, 마크다운 파일이 필요해요. |
| **frontmatter** | 파일 맨 위 `---` 사이의 YAML 설정이에요. 이름과 설명 등을 적어요. |
| **description** | Claude가 이 스킬을 언제 쓸지 판단하는 근거예요. 구체적으로 쓸수록 잘 불려와요. |
| **`/skill-name`** | Claude Code에서 스킬을 직접 호출하는 명령이에요. description에 맞으면 Claude가 자동으로 불러오기도 해요. |

### 파일 이름은 `skill.md`일까요, `SKILL.md`일까요?

| 문서 | 표기 |
| --- | --- |
| claude.ai 지원센터의 "How to create custom skills" | `skill.md` (소문자로만 표기) |
| Claude Code 문서 | `SKILL.md` (대문자) |

두 표기가 문서마다 달라요. 이 튜토리얼에서는 두 문서의 예시를 각각 그대로 소개하고, **Claude Code 문서 기준은 `SKILL.md`**라고 밝혀요. 직접 만들 때는 `SKILL.md`(대문자)로 쓰는 편이 안전해 보이지만, claude.ai 업로드에서 대소문자가 어떻게 처리되는지는 확정하지 못했어요. 업로드가 안 되면 지원센터 문서의 표기(`skill.md`)로 바꿔 보세요.

### 두 가지 frontmatter 규칙

| | claude.ai (지원센터) | Claude Code |
| --- | --- | --- |
| `name` | 필수, 최대 64자 | 선택. 기본값은 폴더 이름 |
| `description` | 필수, 최대 200자 | 권장. 핵심 용도를 앞에 쓰기 |
| 그 외 | 선택 `dependencies` (예: python>=3.8) | `when_to_use`, `argument-hint`, `disable-model-invocation`, `user-invocable`, `allowed-tools`, `context: fork`, `model`, `effort`, `paths`, `hooks` 등 |

<Aside type="note" title="확인되지 않은 점">
- claude.ai 업로드의 파일 크기 제한은 확인하지 못했어요.
- "Create skill" 대화로 만들기와 화면 녹화로 만들기(Cowork, Pro/Max/Team, Mac)는 본문을 직접 읽지 못해서 다루지 않아요.
- 업로드 메뉴 이름(Customize > Skills > + > Create skill > Upload a skill)은 지원센터 문서와 검색 요약을 합친 것이라, 화면 표기를 우선하세요.
</Aside>

## 단계별 따라하기

<Checklist items={[
  '설정에서 코드 실행 및 파일 생성을 켰어요',
  '내장 스킬이 쓰이는 요청을 해 봤어요',
  '스킬 폴더와 파일을 만들었어요',
  'ZIP으로 만들어 claude.ai에 업로드하고 켰어요',
  '관련 요청으로 스킬이 불려오는지 테스트했어요',
  '(선택) Claude Code에서 SKILL.md 스킬을 만들어 실행했어요',
]} />

<Steps>

1. **코드 실행 켜기**

   설정(Settings) > Capabilities에서 **Code execution and file creation**을 켜요. 그다음 Customize > Skills에서 스킬별로 토글을 켜고 꺼요. Team/Enterprise는 Owner가 조직 설정(Organization settings) > Plugins & skills(Policy 탭)에서 코드 실행과 스킬을 먼저 켜야 해요.

2. **내장 스킬 체험하기**

   코드 실행이 켜져 있으면 요청에 맞는 내장 스킬을 Claude가 자동 선택해요. 분기 실적 발표자료를 요청하면 PowerPoint 스킬이 쓰이는 식이에요.

   <PromptBox>
   첨부한 월별 매출 표를 바탕으로 3분기 실적 발표용 PowerPoint 5장을 만들어 줘. 장마다 핵심 메시지 한 줄과 표 또는 그래프 하나를 넣어 줘.
   </PromptBox>

3. **커스텀 스킬 폴더 만들기**

   회의록을 매번 같은 형식으로 요약하는 스킬을 만들어 봐요. 폴더 이름은 스킬 이름과 같게 하세요. 아래는 claude.ai용 예시예요. 지원센터 문서는 `skill.md`로 적고, `name`과 `description`이 필수예요.

   ```text
   meeting-notes/
   └── skill.md
   ```

   ```markdown
   ---
   name: meeting-notes
   description: 회의 메모를 결정사항, 할 일, 미결 사항으로 정리한다. 회의록 요약을 요청할 때 사용한다.
   ---

   # 회의록 요약

   ## 지침
   회의 메모를 받으면 아래 순서로 정리한다.
   1. 한 줄 요약
   2. 결정사항 (번호 목록)
   3. 할 일 (담당자 / 기한 / 내용 표)
   4. 미결 사항

   메모에 없는 담당자나 기한은 지어내지 말고 "미정"이라고 쓴다.
   ```

   하나의 스킬은 하나의 워크플로에 집중하는 것이 좋아요. 입출력 예시를 본문에 넣으면 더 안정적이에요.

4. **ZIP으로 묶어 올리기**

   ZIP의 **루트에 스킬 폴더**가 있어야 해요. 파일이 ZIP 루트에 흩어져 있으면 안 돼요.

   ```text
   meeting-notes.zip
   └── meeting-notes/
       └── skill.md
   ```

   Customize > Skills에서 **+** > **Create skill** > **Upload a skill**을 고르고 ZIP을 선택한 뒤, 목록에서 토글을 켜요.

   <ScreenshotPlaceholder caption="Customize > Skills에서 ZIP을 업로드하고 토글을 켜는 화면" />

5. **테스트하고 description 다듬기**

   관련 요청을 여러 가지로 보내 스킬이 불려오는지 확인해요. 불려오지 않으면 description을 더 구체적으로 고쳐요.

   <PromptBox>
   오늘 팀 회의 메모야. 정리해 줘. 신제품 일정은 11월 말로 하기로 했고, 디자인 시안은 박 대리가 다음 주 금요일까지, 가격 정책은 아직 결론이 안 났어.
   </PromptBox>

6. **Claude Code에서 스킬 만들기 (선택)**

   Claude Code는 파일 기반 스킬을 써요. 개인 스킬은 `~/.claude/skills/<이름>/SKILL.md`, 프로젝트 스킬은 `.claude/skills/<이름>/SKILL.md`에 둬요. 공식 문서의 예제를 그대로 따라 해 봐요. 변경 사항을 요약하고 위험 요소를 알려 주는 스킬이에요.

   ```markdown
   ---
   description: Summarizes uncommitted changes and flags anything risky. Use when the user asks what changed, wants a commit message, or asks to review their diff.
   ---

   ## Current changes

   !`git diff HEAD`

   ## Instructions

   Summarize the changes above in two or three bullet points, then list any risks you notice such as missing error handling, hardcoded values, or tests that need updating. If the diff is empty, say there are no uncommitted changes.
   ```

   이 내용을 `~/.claude/skills/summarize-changes/SKILL.md`로 저장하고, git 저장소에서 `/summarize-changes`를 실행해요. `` !`git diff HEAD` `` 줄은 Claude Code가 명령을 실행해 결과로 바꾼 뒤 Claude에 전달해요. 저장소 안에서 변경을 만든 뒤 실행해야 내용이 있어요.

   <Aside type="note" title="Claude Code 스킬 참고">
   - 같은 이름이면 enterprise > personal > project 순으로 우선해요. 커스텀 명령은 스킬로 통합됐어요.
   - 같은 계정에서 claude.ai에 켜 둔 스킬은 Claude Code v2.1.273 이상에서 세션 시작 때 동기화되어 `/skills`에 나타나요.
   - 개인 스킬은 Cowork나 클라우드 세션에는 적용되지 않아요(공식 문서 기준).
   </Aside>

</Steps>

## 빠른 참조표

### claude.ai 스킬 요약

| 항목 | 내용 |
| --- | --- |
| 사용 가능 | Free/Pro/Max/Team/Enterprise (코드 실행 필요) |
| 켜는 곳 | Settings > Capabilities > Code execution and file creation, 그다음 Customize > Skills |
| 필수 구조 | 폴더 이름 = 스킬 이름, 안에 `skill.md`(지원센터 표기) |
| 필수 frontmatter | `name`(64자 이하), `description`(200자 이하) |
| ZIP | ZIP 루트에 스킬 폴더 |
| Team/Enterprise | Owner가 Plugins & skills(Policy 탭)에서 켜기 |

### Claude Code 스킬 위치

| 위치 | 경로 | 적용 범위 |
| --- | --- | --- |
| 개인 | `~/.claude/skills/<name>/SKILL.md` | 이 컴퓨터의 모든 프로젝트 |
| 프로젝트 | `.claude/skills/<name>/SKILL.md` | 해당 저장소 (커밋하면 팀과 공유) |
| 플러그인 | `<plugin>/skills/<name>/SKILL.md` | 플러그인이 켜진 곳 |
| 엔터프라이즈 | 관리 설정 디렉터리 | 조직이 배포한 모든 사용자 |

### Claude Code 번들 스킬

`/doctor`, `/code-review`, `/batch`, `/debug`, `/loop`, `/claude-api`, `/verify`, `/run`

### 공유 (Team/Enterprise)

| 방법 | 내용 |
| --- | --- |
| 특정 사람에게 공유 | Enterprise는 그룹도 가능. 보기 전용, 업데이트 자동 반영 |
| 조직 라이브러리에 게시 | 검토가 필요한 조직도 있음 |

## 자주 막히는 지점

### 업로드한 ZIP이 인식되지 않아요

- **원인**: ZIP 안 구조가 맞지 않을 수 있어요. 파일이 루트에 흩어져 있거나 폴더 이름이 스킬 이름과 다를 수 있어요.
- **해결**: `my-skill.zip` 안에 `my-skill/` 폴더가 있고 그 안에 파일이 있는 구조로 다시 묶으세요. 파일명 대소문자(`skill.md`/`SKILL.md`)도 확인하세요.

### 스킬이 안 불려와요

- **원인**: description이 모호하거나 요청과 맞지 않을 수 있어요. 코드 실행이 꺼져 있거나 토글이 꺼져 있을 수도 있어요.
- **해결**: description에 "언제 쓰는지"를 구체적으로 쓰고, 여러 가지 요청으로 테스트하세요. 설정과 토글을 확인하세요.

### Team/Enterprise에서 스킬 메뉴가 없어요

- **원인**: Owner가 코드 실행과 스킬을 아직 켜지 않았을 수 있어요.
- **해결**: Owner에게 Organization settings > Plugins & skills(Policy 탭)를 확인해 달라고 요청하세요.

### `/summarize-changes`에서 아무 내용도 안 나와요

- **원인**: 커밋되지 않은 변경이 없으면 diff가 비어 있어요.
- **해결**: 파일을 하나 수정한 뒤 다시 실행하세요. 비어 있으면 "변경 없음"이라고 답하도록 만든 스킬이에요.

### 다른 사람이 만든 스킬을 써도 될지 모르겠어요

- **원인**: 스킬은 서드파티 패키지를 포함·설치할 수 있어 프롬프트 인젝션이나 데이터 유출 위험이 있어요.
- **해결**: 신뢰할 수 있는 출처의 스킬만 설치하고, 활성화 전에 번들 파일(특히 코드, 스크립트, 외부 네트워크 연결 지시)을 읽으세요. Enterprise는 스킬 스캔을 쓸 수 있어요.

## 실전 팁

- **하나의 스킬에는 하나의 워크플로를 담으세요.** 범위가 좁을수록 잘 불려와요.
- **간단한 마크다운으로 시작하세요.** 스크립트는 나중에 추가해도 돼요.
- **입출력 예시를 넣으세요.** 결과 형식이 안정돼요. agentskills.io 사양을 따르면 호환성이 좋아진다고 안내돼요.
- **API 키나 비밀번호를 스킬 안에 쓰지 마세요.** 하드코딩 금지예요.
- **바꿀 때마다 테스트하세요.** 여러 요청으로 불려오는지 확인하세요.
- **프롬프트와 함께 쓰세요.** 좋은 지침 작성은 [C4. 프롬프트 작성법](/new-project1/claude/c04-prompting/)과 같은 원리예요.
