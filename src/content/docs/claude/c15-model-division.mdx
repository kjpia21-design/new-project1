<Summary>
- 모든 일에 가장 큰 모델을 쓸 필요는 없어요. **어려운 판단(기획·검토)은 Opus, 많은 작업(구현)은 Sonnet**으로 나누면 비용과 사용량을 아낄 수 있어요.
- 가장 쉬운 방법은 `/model opusplan`이에요. 계획 모드에서는 Opus, 실행 단계에서는 Sonnet으로 자동 전환돼요.
- 서브에이전트의 모델은 정해진 **네 단계 순서**로 결정돼요. `/model`로 Opus로 바꾸면 모델을 상속하는 서브에이전트도 Opus가 돼요.
- API 가격은 Sonnet 5.5가 Opus 5.5의 절반이에요 (2026-10-10 기준, 아래 표).
- 이 사이트가 바로 이 방식으로 만들어졌어요. 아래 사례와 따라 해 볼 수 있는 명세 템플릿을 확인하세요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- `opusplan`과 서브에이전트 설정으로 "계획은 큰 모델, 실행은 작은 모델" 구조를 만들 수 있어요.
- 서브에이전트가 어떤 모델로 돌아가는지 결정 순서를 보고 예상할 수 있어요.
- 모델 선택이 비용·사용량에 주는 영향을 숫자로 이해할 수 있어요.
- 이 사이트의 제작 사례를 참고해, 내 프로젝트용 작업 명세를 직접 써 볼 수 있어요.

## 먼저 알아둘 개념

<C15ModelSplit />

| 용어 | 뜻 |
| --- | --- |
| **opusplan** | 계획 모드에서는 `opus`, 실행 단계에서는 `sonnet`을 쓰는 특별한 모델 별칭이에요. |
| **서브에이전트** | 자체 컨텍스트를 가진 보조 에이전트예요. 정의 파일의 `model`로 모델을 정할 수 있어요. ([C14](/new-project1/claude/c14-claude-code-features/)) |
| **상속(inherit)** | 서브에이전트가 메인 대화와 같은 모델을 쓰는 것이에요. |
| **effort** | 모델이 얼마나 깊게 생각할지 정하는 수준이에요 (low, medium, high, xhigh, max). |
| **orchestrator / worker** | 공식 문서의 모델 조합 패턴이에요. 대량 작업을 저비용 모델(worker)에게 위임하는 구조를 가리켜요. |

### 공식 가이드가 말하는 모델 선택 (2026-10-10 기준)

| 필요한 것 | 권장 모델 |
| --- | --- |
| 최고 성능 (몇 시간 도는 에이전트 세션, 다단계 딥 리서치) | Fable 5.1 |
| 복잡한 에이전트형 코딩, 엔터프라이즈 업무 | Opus 5.5 |
| 일상적 코딩·에이전트 업무의 속도와 성능 | Sonnet 5.5 |
| 최저 지연·최저 가격 (실시간, 대량 처리, 서브에이전트 작업) | Haiku 5.5 |

공식 문서는 "대부분의 워크로드는 Opus 5.5로 시작"하라고 안내해요. 그리고 effort를 조정하는 것이 모델을 바꾸는 것보다 나은 수단인 경우가 많다고 해요. 시작 전략은 두 가지예요. 효율 우선이면 Haiku 5.5로 시작해 부족할 때 올리고, 성능 우선이면 Opus 5.5로 시작해 effort를 낮추거나 모델을 내려 최적화해요.

### 가격 차이 (API, 100만 토큰당 입력/출력, 2026-10-10 기준)

| 모델 | 입력 / 출력 |
| --- | --- |
| Fable 5.1 | $10 / $50 |
| Opus 5.5 | $4 / $20 |
| Sonnet 5.5 | $2 / $10 |
| Haiku 5.5 | $0.10부터 / $0.50부터 |

Sonnet은 Opus의 절반, Fable은 Opus의 2.5배예요. 구독 사용량도 대화 길이, 기능, 모델, effort에 따라 달라져요. 자세한 한도 구조는 [C2. 요금제와 사용량 한도](/new-project1/claude/c02-plans-limits/), 모델 비교는 [C1](/new-project1/claude/c01-overview/), API 가격은 [C16](/new-project1/claude/c16-api/)에서 다뤄요.

Claude Code 비용 가이드는 이렇게 권해요. "Sonnet은 대부분의 코딩 작업을 잘 처리하고 Opus보다 저렴하다. Opus는 복잡한 아키텍처 결정이나 다단계 추론에 아껴 써라." 단순한 서브에이전트에는 `model: haiku`를 쓰라고 해요.

<Aside type="note" title="확인되지 않은 점">
`opusplan`은 계획 모드에서 `opus`, 실행에서 `sonnet` 별칭을 쓰는 방식이에요. Claude Code 모델 설정 문서(2026-10-10)의 표를 보면 Anthropic API에서는 `opus`가 Opus 5.5, `sonnet`이 Sonnet 5.5로 풀려요. Bedrock이나 Foundry 같은 다른 제공처에서는 버전이 달라질 수 있고 별칭은 시간이 지나면 바뀌어요. 버전을 고정하려면 전체 모델 이름이나 `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` 환경 변수를 쓰세요. 비용 가이드의 "Optimizing for cost and intelligence" 측정 사례는 읽지 않았어요.
</Aside>

<Steps>

1. **가장 쉬운 분업: opusplan**

   Claude Code 세션에서 입력하거나, 시작할 때 `--model`로 지정해요. 설정 파일의 `model`에 `opusplan`을 넣어도 돼요.

   ```text
   /model opusplan
   ```

   ```sh
   claude --model opusplan
   ```

   이제 계획 모드(`/plan`)에서는 Opus가 설계하고, 승인 후 구현 단계에서는 Sonnet이 코드를 써요. 두 단계 모두 100만 토큰 컨텍스트가 필요하면 `opusplan[1m]`을 쓰는데, `/model`로 지정하려면 Claude Code v2.1.265 이상이 필요해요. 그보다 낮은 버전은 `--model` 플래그나 `model` 설정을 쓰세요.

2. **서브에이전트마다 모델 지정하기**

   정의 파일의 frontmatter에 `model`을 적어요. 검색·로그 분석처럼 가벼운 일은 `haiku`, 리뷰는 `sonnet`처럼요.

   ```markdown
   ---
   name: code-reviewer
   description: Reviews code for quality and best practices
   tools: Read, Glob, Grep
   model: sonnet
   ---

   You are a code reviewer. When invoked, analyze the code and provide
   specific, actionable feedback on quality, security, and best practices.
   ```

3. **서브에이전트 모델 결정 순서 알아두기**

   Claude Code는 서브에이전트의 모델을 이 순서로 정해요.

   1. 호출할 때 지정한 `model` 파라미터
   2. 서브에이전트 정의의 `model` frontmatter (`inherit`이면 메인 대화 모델)
   3. 환경변수 `CLAUDE_CODE_SUBAGENT_MODEL` (모델 별칭이나 ID로 설정했을 때)
   4. 메인 대화의 모델

   <Aside type="caution" title="/model로 Opus로 바꾸면 서브에이전트도 Opus가 될 수 있어요">
   모델을 상속하는 서브에이전트는 시작될 때의 세션 모델을 따라가요. Opus로 바꾼 채 리서치나 테스트 실행을 위임하면 그 작업도 Opus로 돌아요. 위임 전에 모델을 바꾸거나, 서브에이전트 정의에 `model`을 명시하세요.
   </Aside>

4. **모든 서브에이전트를 한 모델로 (선택)**

   설정 파일의 환경변수로 일괄 지정할 수 있어요. `FORCE`를 `1`로 하면 정의나 호출에서 지정한 모델보다 우선해서 모든 서브에이전트에 적용돼요. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE`는 Claude Code v2.1.257 이상이 필요해요.

   ```json
   {
     "env": {
       "CLAUDE_CODE_SUBAGENT_MODEL": "haiku",
       "CLAUDE_CODE_SUBAGENT_MODEL_FORCE": "1"
     }
   }
   ```

   `CLAUDE_CODE_SUBAGENT_MODEL`만 설정해서는 내장 Explore·Plan 서브에이전트의 모델이 바뀌지 않아요. 실행 중인 서브에이전트의 모델은 `/tasks`로 볼 수 있어요.

   **워크플로 에이전트만 한 모델로**: 동적 워크플로(수십~수백 개 에이전트가 도는 스크립트)는 에이전트가 많아 비용이 크게 늘 수 있어요. `CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL`을 설정하면 워크플로 에이전트는 모두 그 모델로 돌고, 다른 서브에이전트는 각자 모델을 유지해요(v2.1.296 이상).

   ```json
   {
     "env": {
       "CLAUDE_CODE_WORKFLOW_SUBAGENT_MODEL": "sonnet"
     }
   }
   ```

   값 형식(별칭 또는 모델 ID)은 `CLAUDE_CODE_SUBAGENT_MODEL`과 같다고 보고 쓴 예시예요. 공식 환경변수 문서에는 아직 이 변수의 설명이 없어서, 변경 이력(CHANGELOG)의 설명만 확인했어요.

5. **어려운 순간만 상위 모델에게 묻기: `/advisor` (선택)**

   메인 모델은 빠른 모델로 두고, 계획을 세우기 전이나 같은 오류가 반복될 때, 끝났다고 선언하기 전에만 더 강한 모델의 조언을 받는 방법이에요. 조언은 Anthropic 서버에서 도는 advisor 도구가 해 주고, 언제 부를지는 Claude가 정해요.

   ```text
   /advisor opus
   ```

   - `/advisor`만 입력하면 선택 창이 열리고, `/advisor off`로 꺼요. 고른 모델은 `advisorModel` 설정에 저장돼요. 이번 세션만 쓰려면 `claude --advisor opus`로 시작해요.
   - 조언 모델은 메인 모델과 같거나 더 높은 등급이어야 해요. 예를 들어 Sonnet 5.5 메인에는 Fable, Opus 5 이상, Sonnet 5.5를 쓸 수 있어요.
   - 실험 기능이고 Anthropic API에서만 돼요(Bedrock, Vertex, Foundry 등은 안 돼요). 조언 호출은 조언 모델 요금으로 계산되고 구독 플랜에서는 한도에 합산돼요. 모델을 통째로 바꾸는 `/model`이나 `opusplan`과 달리 결정 순간에만 쓰는 방식이라, 공식 문서는 강한 모델을 계속 쓰는 것보다 보통 비용이 낮다고 안내해요.

6. **사용량 점검하기**

   `/usage`에서 스킬·서브에이전트·MCP별로 사용량이 어디에서 나가는지 볼 수 있어요. 에이전트 팀을 쓸 때는 팀원에게 Sonnet을 권하고 팀을 작게 유지하세요. 플랜 모드 팀원은 표준 세션 대비 약 7배의 토큰을 쓴다고 해요.

7. **이 사이트는 어떻게 만들었나: 실제 사례**

   아래 사례를 읽고, 8단계의 템플릿으로 내 프로젝트용 명세를 써 보세요. (사례는 이 사이트 제작 과정을 있는 그대로 정리한 거예요.)

   **구성.** 클라우드 세션 하나에서 **Opus 5.5가 기획**을 맡고, **구현은 Sonnet 5.5 서브에이전트**가 했어요. 서브에이전트의 모델은 Agent 도구의 `model` 파라미터로 지정했어요. 위의 결정 순서 1번에 해당해요.

   **Opus가 한 일.**

   1. 질문으로 요구사항을 정리해요.
   2. `docs/PLAN.md`를 써요.
   3. 단계별 작업 명세를 써요. (`docs/specs/step1-skeleton.md`, `step2-samples.md` 같은 단계별 명세 파일)
   4. 서브에이전트를 실행해요.
   5. 결과를 검토해요. 스크린샷을 확인하고 사실을 대조해요.
   6. 작은 수정은 직접 해요.
   7. 커밋하고 PR을 만들어요.

   **Sonnet이 한 일.**

   | 단계 | 맡긴 일 |
   | --- | --- |
   | 1단계 | 사이트 구현과 공식 문서 조사를 **두 에이전트가 병렬로** 진행 |
   | 2단계 | 템플릿과 샘플 2편 작성 |
   | 3단계 | 에이전트 4명이 튜토리얼 14편을 나눠 작성 |

   **검토에서 실제로 잡아낸 것.**

   - **홈 제목이 두 번 나오는 버그.** 원인은 홈 페이지 id를 판별하는 조건이었어요.
   - **조사 결과와 실제 화면의 차이.** 조사 에이전트는 "클라우드 세션 크레딧은 없다"고 결론 냈지만, 실제 설정 화면에는 그 항목이 표시되어 있었어요. 이 차이를 "공식 문서 미반영 항목"으로 정리했어요. ([C2](/new-project1/claude/c02-plans-limits/)에서 볼 수 있어요.)

   **교훈.**

   - 명세가 구체적일수록 서브에이전트의 결과가 좋아요.
   - 사실 확인과 최종 판단은 기획 모델이 맡아요.
   - 서브에이전트는 커밋하지 않게 하고 기획 쪽에서 모아 커밋하면 충돌이 없어요.

8. **내 작업 명세 써 보기**

   위 교훈을 반영한 명세 템플릿이에요. 괄호 안을 내 프로젝트에 맞게 바꿔서, 기획을 맡은 Opus 세션에서 서브에이전트용 명세 파일을 쓰게 하거나 직접 채워 쓰세요.

   <PromptBox label="작업 명세 템플릿 (복사해서 채워 쓰세요)">
   **작업 명세: (작업 이름)**

   **먼저 읽을 것**

Explore 서브에이전트는 구독·Console·게이트웨이에서 `opus` 별칭 모델로 돌아가요 (2026-10-10 기준).

## 자주 막히는 지점

### 가벼운 서브에이전트인데 사용량이 많이 나가요

- **원인**: 모델을 상속하는 서브에이전트가 메인 대화의 큰 모델(예: Opus)로 돌고 있을 수 있어요.
- **해결**: 정의에 `model: haiku` 또는 `sonnet`을 명시하고, `/tasks`로 실제 모델을 확인하세요. 내장 Explore는 별도 설정이 필요해요.

### `CLAUDE_CODE_SUBAGENT_MODEL`을 설정했는데 적용이 안 돼요

- **원인**: 이 변수는 기본값 역할이라서 호출 시 지정한 모델이나 정의의 `model`이 우선해요. 내장 Explore·Plan에는 영향을 주지 않아요.
- **해결**: 모두 강제하려면 `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1`을 함께 설정하세요 (v2.1.257 이상).

### "Opus limit" 같은 모델별 한도 메시지가 나와요

- **원인**: 특정 모델 계열의 한도에 닿은 거예요.
- **해결**: 다른 계열 모델로 `/model` 전환을 하면 작업을 이어갈 수 있어요. 다만 세션·주간 한도는 전 모델 공통이라 모델을 바꿔도 회복되지 않아요.

### 서브에이전트들이 같은 파일을 서로 고쳐요

- **원인**: 담당 범위가 겹치게 명세를 줬거나, 각자 커밋했을 가능성이 있어요.
- **해결**: 명세에 "수정 가능한 파일"을 에이전트별로 나눠 적고, 커밋은 기획 쪽에서만 하게 하세요.

## 실전 팁

- **모델을 바꾸기 전에 effort부터.** 공식 가이드는 effort 조정이 모델 교체보다 나은 경우가 많다고 해요.
- **Opus는 판단에, Sonnet은 반복에.** 아키텍처 결정과 최종 검토는 Opus, 명세가 분명한 구현은 Sonnet이 잘 맞아요.
- **명세를 구체적으로.** 파일 경로, 수정 가능 범위, 완료 기준, 보고 형식을 적을수록 결과가 좋아져요.
- **검토는 기획 모델이 직접.** 이 사이트에서도 사실 대조와 화면 확인에서 실제 버그와 오류를 잡았어요.
- **일찍 병렬화.** 서로 파일이 겹치지 않는 일은 에이전트를 나눠 동시에 돌리세요. 다만 병렬 실행은 그만큼 사용량도 써요.
- 엔터프라이즈 평균 비용 수치는 공식 비용 가이드에 있어요(개발자당 활성일 약 $13, 월 $150-250, 90%는 활성일 $30 미만). 내 사용량과는 다를 수 있어요.
