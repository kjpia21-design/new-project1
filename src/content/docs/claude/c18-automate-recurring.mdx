<Summary>
- Claude에서 반복 작업을 자동으로 돌리는 공식 방법은 크게 **네 가지**예요. ① Claude 앱의 예약 작업, ② Claude Code 클라우드 **루틴**(공식 문서의 새 이름은 클라우드 예약 작업, 2026-10-26 기준), ③ Claude Code 데스크톱 **로컬 예약 작업**, ④ 세션 안에서 도는 **`/loop`**.
- 고르는 기준은 **어디서 실행되나, 내 컴퓨터가 켜져 있어야 하나, 내 로컬 파일이 필요한가**예요. 컴퓨터를 꺼도 돌려야 하면 클라우드(루틴 또는 앱 예약 작업)를, 로컬 파일이 필요하면 데스크톱 작업을, 잠깐 상태를 확인하려면 `/loop`를 써요.
- 자동 실행은 **사람이 보지 않는 동안** 돌아요. 프롬프트는 자기완결적으로, 결과는 되돌릴 수 있는 형태(초안·브랜치·PR)로, 마지막 확정은 사람이 하게 설계하세요.
- 루틴은 **리서치 프리뷰**라 동작과 한도가 바뀔 수 있어요(2026-10-13 기준).
- 루틴의 기본(만들기, 트리거, 환경)은 [C13](/claude/c13-cloud-sessions/)에 있어요. 이 글은 **무엇을 고를지, 어떻게 안전하게 설계할지, 어떻게 확인할지**에 집중해요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 내 업무에 맞는 자동 실행 방식을 **비교표로 골라** 쓸 수 있어요.
- 자동 실행용 프롬프트를 **자기완결적으로** 쓰고, 시험 실행과 실행 기록으로 확인할 수 있어요.
- 한도와 만료 규칙을 알고 **조용히 멈추는 자동화**를 피할 수 있어요.
- 이 사이트가 쓰는 "매일 아침 공식 소식 확인 → 수정안 PR" 같은 패턴을 내 업무에 옮길 수 있어요.

## 먼저 알아둘 개념

### 네 가지 방식 한눈에 비교

| | Claude 앱 예약 작업 | 루틴 (클라우드) | 데스크톱 예약 작업 | `/loop` |
| --- | --- | --- | --- | --- |
| 실행 위치 | 원격(공식 도움말 기준) | Anthropic 관리 클라우드 | 내 컴퓨터 | 내 컴퓨터(열려 있는 세션) |
| 내 컴퓨터가 켜져 있어야 하나 | 아니요 (단, 로컬 파일·앱이 필요한 작업은 로컬에서만 실행) | 아니요 | **예** (앱이 열려 있고 컴퓨터가 깨어 있어야 해요) | **예** |
| 세션을 열어 둬야 하나 | 아니요 | 아니요 | 아니요 | **예** |
| 로컬 파일 접근 | 폴더를 지정하면 가능(로컬 실행 시) | 없음(저장소를 새로 클론) | 있음 | 있음 |
| 트리거 | 시간(매시간·매일·평일·매주·수동) | 스케줄, API, GitHub 이벤트 | 시간(수동·매시간·매일·평일·매주) | 간격 |
| 최소 간격 | 프리셋 기준 매시간 | 1시간 | 1분 | 1분 |
| 주 대상 | 업무 문서·리포트·요약 | 저장소 작업(코드·문서) | 로컬 코드·파일 작업 | 배포·PR 상태 확인 |

위 표는 아래 공식 문서를 합쳐 정리했어요. Claude Code의 세 방식(루틴, 데스크톱, `/loop`)은 Run prompts on a schedule 문서의 비교표를, 앱 예약 작업은 Claude Cowork 도움말을 기준으로 했어요.

<Aside type="note" title="Claude 앱 예약 작업과 Claude Code는 다른 기능이에요">
앱의 예약 작업은 Claude(Cowork)에서 프롬프트를 저장해 정해진 주기로 실행하고, 연결한 커넥터·스킬·플러그인을 쓸 수 있어요. 한 번 돌 때마다 별도 세션이 생겨요. 반면 루틴은 Claude Code 기능으로 **저장소와 환경**을 중심으로 돌아요. 문서·요약·리포트 업무는 앱 예약 작업, 코드·저장소 업무는 루틴이 자연스러워요.
</Aside>

## 단계별 따라하기

<Checklist items={[
  '자동으로 돌릴 업무를 하나 정하고 손으로 한 번 해 봤어요',
  '위 비교표로 실행 방식을 골랐어요',
  '자기완결적인 프롬프트를 썼어요',
  '시험 실행(Run now 등)을 하고 실행 기록을 열어 봤어요',
  '한도, 만료, 컴퓨터 상태 같은 조용히 멈출 조건을 점검했어요',
]} />

<Steps>

1. **업무를 고르고 손으로 한 번 해 봐요**

   자동화에 알맞은 일은 **반복되고, 결과가 분명하고, 사람이 매번 판단하지 않아도 되는 일**이에요. 먼저 대화에서 직접 해 보면서 "성공"이 무엇인지 말로 적어 보세요. 그 글이 그대로 자동 실행의 프롬프트가 돼요. 스킬로 형식을 고정하는 방법은 [C8](/claude/c08-skills/)을 참고하세요.

2. **자기완결적인 프롬프트를 써요**

   자동 실행에는 대화가 없어서 되물을 사람이 없어요. 공식 문서도 프롬프트가 가장 중요하고, 무엇을 할지와 성공 기준을 명확히 쓰라고 안내해요. 아래 네 가지를 넣으세요.

   - **할 일**: 어디서 무엇을 확인하는지
   - **산출물**: 어디에 어떤 형태로 남기는지
   - **하지 말 것**: 건드리면 안 되는 것
   - **끝났을 때 보고**: 한 줄 요약, 못 한 일은 이유와 함께

   <PromptBox>
   [확인할 대상, 예: 아래 공식 페이지 목록]의 최근 변경 사항을 확인해 주세요. 지난번 확인 이후 새로 바뀐 것만 골라서 [산출물 위치]에 [형식]으로 정리하세요. 출처 URL을 항목마다 붙이고, 확인하지 못한 내용은 추측하지 말고 "확인 못 함"으로 적으세요. [건드리면 안 되는 파일이나 항목]은 수정하지 마세요. 끝나면 무엇을 확인했고 무엇을 바꿨는지 세 줄로 요약해 주세요.
   </PromptBox>

3. **방식별로 만들어요**

   **A. Claude 앱 예약 작업.** 공식 도움말 기준으로, 새 Claude 경험(Pro·Max에 순차 적용)에서는 아무 대화에서 "매주 월요일 9시에 지난주 팀 채널 메시지를 요약해 줘"처럼 작업과 주기를 말하면 돼요. Claude가 되묻는 질문에 답한 뒤, 제안된 작업 이름·일정·지침을 확인하고 **Schedule**을 눌러요. Cowork 화면에서는 왼쪽 사이드바의 **Scheduled** > **New task**에서 Create with Claude 또는 Set up manually를 고르고, 이름·프롬프트·승인 방식·주기(매시간·매일·평일·매주·수동)·모델·폴더를 정해요. 예정된 실행과 지난 실행은 사이드바의 Scheduled에서 봐요. 화면 구성은 계정과 앱 버전에 따라 다를 수 있어요.

   **B. 루틴.** 만드는 방법은 [C13의 루틴 만들기](/claude/c13-cloud-sessions/)에 있어요. 요점만 말하면, claude.ai/code/routines의 New task(일부 계정은 New routine), 데스크톱 앱의 Routines(Cloud 선택), 또는 CLI의 `/schedule`로 만들어요. 세 곳은 같은 계정에 저장돼서 어디서 만들어도 다른 곳에 보여요. 예를 들어 이렇게 말해요.

   ```sh
   /schedule daily PR review at 9am
   /schedule in 2 weeks, open a cleanup PR that removes the feature flag
   ```

   두 번째처럼 시점을 자연어로 말하면 1회성 실행도 돼요. 1회 실행은 돌고 나면 자동으로 꺼지고 Ran으로 표시돼요. 1시간보다 짧은 간격은 거부돼요.

   **C. 데스크톱 로컬 예약 작업.** Code 탭의 Routines에서 New routine > **Local**을 골라 이름·설명·지침·주기와 작업 폴더를 정해요. 폴더가 필수예요. 실행마다 격리된 Git worktree를 쓰는 옵션이 있어요. 매 실행이 새 세션으로 열리고 알림이 와요.

   **D. `/loop`.** 세션이 열려 있는 동안 반복해요.

   ```sh
   /loop 5m check if the deployment finished and tell me what happened
   ```

   간격을 생략하면 Claude가 1분~1시간 사이에서 매번 정해요. 한 번만 알림을 받고 싶으면 "오후 3시에 릴리스 브랜치 push하라고 알려 줘"처럼 자연어로 말하면 돼요.

4. **시험 실행하고 기록을 열어 봐요**

   루틴 상세 화면의 **Run now**로 바로 한 번 돌려 보세요. 각 실행은 새 세션으로 남고, 열면 Claude가 무엇을 했는지 볼 수 있어요. 목록의 초록색 상태는 "세션이 인프라 오류 없이 끝났다"는 뜻이지 **작업이 성공했다는 뜻이 아니에요.** 막힌 네트워크 요청, 없는 커넥터 도구, 작업 수준 실패는 기록 안에 나오니 꼭 열어 읽으세요. CLI에서는 `/schedule list`, `/schedule update`, `/schedule run`으로 관리하고, "왜 오늘 아침 리뷰가 아무것도 안 했지?"처럼 실행 기록을 물어볼 수도 있어요(공식 문서 기준 Claude Code v2.1.227 이상).

   데스크톱 작업은 처음에 Run now를 눌러 권한 요청을 모두 허용(always allow)해 두면 이후 실행이 멈추지 않아요.

5. **조용히 멈추는 조건을 점검해요**

   자동화는 알림 없이 멈출 수 있어요. 아래 표를 한 번 훑어보세요.

   <PromptBox label="이 프롬프트로 자동화 설계를 점검받아 보세요">
   내가 자동으로 돌리려는 업무는 [업무 설명]이고 실행 방식은 [방식]이에요. 이 업무가 사람이 보지 않는 동안 잘못 돌았을 때 생길 수 있는 문제 3가지, 그것을 막기 위해 프롬프트에 넣을 제한 문장, 그리고 실행 결과를 내가 확인할 방법을 알려 주세요.
   </PromptBox>

</Steps>

## 빠른 참조표

### 한도와 만료 (2026-10-13 기준, 바뀔 수 있어요)

| 방식 | 알아둘 점 |
| --- | --- |
| 루틴 | 스케줄 실행 계정당 시간당 100회(1회성 포함), Run now·API 실행은 루틴당 시간당 30회와 계정당 별도 한도. 이 한도에는 초과 과금(overage)이 없어요. 한도를 넘으면 스케줄 실행은 대기하고, Run now 등은 실패해요. |
| 루틴 사용량 | 대화형 세션처럼 구독 사용량을 써요. 사용량 한도에 닿으면 추가 사용량(usage credits)이 켜져 있을 때만 이어서 돌고, 아니면 한도가 리셋될 때까지 거부돼요. |
| 루틴 GitHub 연결 | 연결이 끊기거나 만료되면 최대 72시간 동안 실행을 건너뛰어요. 그 안에 다시 연결하면 자동으로 재개되고, 72시간이 지나면 꺼져서 직접 켜야 해요. |
| 루틴 정지 | 구독이 일시중지된 동안은 보류돼요. 다시 활성화된 뒤 직접 켜야 해요. Team/Enterprise Owner가 조직 전체에서 끌 수도 있어요. |
| `/loop`(세션 예약) | 반복 작업은 만든 지 **7일 뒤 마지막으로 한 번 실행되고 삭제**돼요. 세션당 최대 50개. Claude Code가 실행 중이고 대기 상태일 때만 돌고, 놓친 실행은 따라잡지 않고 한 번만 실행돼요. 정각 설정은 몇 분 늦어질 수 있어요. |
| 데스크톱 | 앱이 열려 있고 컴퓨터가 깨어 있을 때만 실행돼요. 잠자는 동안 놓치면 깨어난 뒤 가장 최근 놓친 시각에 대해 **한 번만** 따라잡아 실행하고(최근 7일 이내), 오래된 것은 버려요. |
| 앱 예약 작업 | 로컬 파일·앱이 필요한 작업은 로컬에서만 실행돼요. |

### 정각을 피하세요

루틴과 `/loop` 모두 정각(예: 9:00)에 맞추면 몇 분 늦게 시작할 수 있다고 공식 문서가 안내해요. 9:07처럼 몇 분 지난 시각을 잡으세요. 루틴의 시각은 내 시간대로 입력하면 자동 변환돼요.

## 사례: 매일 아침 공식 소식 확인 → 수정안 PR

이 사이트는 도구의 공식 문서와 변경 이력이 바뀌었는지 정기적으로 확인하고, 바뀌었으면 **수정안을 PR로 올리는** 루틴을 써요. 계정 정보와 구체적인 설정은 빼고, 어떤 패턴인지만 일반화해서 소개할게요.

이 설계에서 안전한 이유는 이래요.

- **되돌릴 수 있는 결과물만 만들어요.** 루틴은 `claude/` 접두사 브랜치로 push하고, 기본 브랜치에 바로 반영하지 않아요. 병합은 사람이 해요.
- **프롬프트가 구체적이에요.** 어떤 페이지를 확인할지, 확인하지 못한 내용은 추측하지 말고 적지 말라는 규칙이 들어 있어요.
- **저장소만 연결해요.** 불필요한 커넥터는 빼서 루틴이 닿을 수 있는 범위를 줄여요.
- **확인은 PR에서 해요.** 루틴이 한 커밋과 PR은 내 GitHub 사용자로 남기 때문에, 병합 전에 내용을 읽어야 해요.

## 자주 막히는 지점

### `/schedule`이 "Unknown command"라고 나와요

- **원인**: `/schedule`은 claude.ai 구독 로그인이 필요해요. Console API 키나 Amazon Bedrock 같은 클라우드 제공자로 인증하면 보이지 않아요.
- **해결**: claude.ai 계정으로 로그인했는지 확인하세요. 자세한 조건은 공식 Routines 문서의 Troubleshooting을 보세요.

### "조직 정책으로 루틴이 꺼져 있다"고 나와요

- **원인**: Team/Enterprise에서는 Owner가 조직 설정(Organization settings) > Capabilities > Remote sessions의 "Scheduled tasks (Was Routines)" 토글로 조직 전체에서 루틴을 끌 수 있고, 그러면 기존 루틴도 멈추고 새로 만들 수 없어요.
- **해결**: 조직 Owner에게 설정 확인을 요청하세요.

### 루틴이 초록색인데 결과가 없어요

- **원인**: 초록 상태는 세션이 오류 없이 끝났다는 뜻일 뿐 작업 성공이 아니에요.
- **해결**: 실행 기록을 열어 막힌 네트워크 요청이나 누락된 커넥터 도구를 확인하세요. 허용되지 않은 도메인은 환경의 네트워크 설정을 고쳐야 해요([C13](/claude/c13-cloud-sessions/)).

### 데스크톱 예약 작업이 아침에 안 돌았어요

- **원인**: 컴퓨터가 잠자고 있었거나 앱이 닫혀 있었을 수 있어요. 건너뛴 실행은 기록에 이유와 함께 남아요.
- **해결**: 깨어난 뒤 한 번 따라잡기가 실행돼요. 시각이 중요하면 프롬프트에 "오후 5시가 넘었으면 건너뛰고 놓친 내용을 요약만 해 줘" 같은 조건을 넣으세요. 컴퓨터가 꺼져 있어도 돌아야 하면 루틴이나 앱 예약 작업으로 바꾸세요.

### `/loop`가 일주일 뒤 사라졌어요

- **원인**: 세션 예약 반복 작업은 7일 뒤 만료돼요.
- **해결**: 오래 가야 하는 작업은 루틴이나 데스크톱 예약 작업으로 옮기세요.

## 실전 팁

- **되돌릴 수 있는 결과물을 만들게 하세요.** 초안, 브랜치, PR까지만 자동으로 하고, 발송·병합·삭제 같은 확정은 사람이 하세요.
- **권한과 연결을 최소로 하세요.** 루틴은 선택한 저장소, 환경의 네트워크와 변수, 포함한 커넥터가 닿는 범위에서 승인 없이 동작해요. 커넥터는 기본으로 전부 포함되니 필요한 것만 남기세요.
- **개인정보를 넣지 마세요.** 환경변수와 프롬프트는 사람이 보지 않는 곳에서 반복 사용돼요. 비밀 값 처리는 [C13](/claude/c13-cloud-sessions/)의 환경 설정을 따르세요.
- **빈도를 낮게 시작하세요.** 자동 실행은 사용량을 써요. 처음에는 주 1회 정도로 시작해서 결과와 사용량을 본 뒤 늘리세요.
- **결과를 정기적으로 읽으세요.** 자동화가 조용히 엉뚱한 결과를 내도 알림이 없을 수 있어요. 주기적으로 실행 기록을 훑어보세요.
- **API 트리거는 신중하게 쓰세요.** 토큰은 한 번만 보이고, 전달한 텍스트는 신뢰할 수 없는 데이터로 감싸져서 프롬프트가 명시적으로 참조해야 반영돼요. 토큰은 비밀로 보관하세요.

<Aside type="caution" title="가격·한도는 바뀌어요">
루틴은 리서치 프리뷰라서 동작, 한도, API 형태가 바뀔 수 있어요. 이 글의 수치는 2026-10-13 기준이에요. 자주 확인되는 공식 문서는 출처 목록에 있어요.
</Aside>
