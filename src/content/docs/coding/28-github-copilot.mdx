<Summary>
- GitHub Copilot은 에디터 안에서 **코드를 제안(인라인 제안)하고, 질문에 답하고(Ask), 계획을 세우고(Plan), 파일을 직접 고치는(Agent)** AI 도구예요.
- 이 편은 **VS Code 기준**으로 설치 → 인라인 제안 → 채팅 → 에이전트 모드 → 맞춤 지침 순서로 따라가요.
- 코드 완성(인라인 제안)은 크레딧을 쓰지 않고 유료 플랜에서 무제한이에요. 채팅과 에이전트는 **GitHub AI Credits**를 써요(2026-10-14 기준).
- 에이전트가 만든 변경은 **내가 검토하고 수락**해요. 명령도 기본적으로 실행 전에 승인을 물어요.
- 가격은 미국 달러 기준이에요. 한국 제공 여부와 원화 가격은 공식 문서에서 확인하지 못했어요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- VS Code에 Copilot을 연결하고 로그인할 수 있어요.
- 타이핑하는 중에 나오는 **회색 제안**을 받아들이거나 무시할 수 있어요.
- 채팅의 **Ask·Plan·Agent** 모드를 구분해서 상황에 맞게 고를 수 있어요.
- 에이전트에게 작은 앱 만들기를 맡기고 **변경을 검토**할 수 있어요.
- 저장소에 **맞춤 지침 파일**을 두어 Copilot이 내 규칙을 따르게 할 수 있어요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **인라인 제안** | 코드를 입력하는 도중 회색 글씨로 나타나는 다음 코드 제안이에요. `Tab`으로 수락해요. |
| **Copilot Chat** | 에디터 옆의 채팅 창이에요. 열린 파일이나 선택한 코드를 기준으로 답해요. |
| **Ask 모드** | 코드 질문, 개념 설명, 코드 제안을 받는 모드예요. |
| **Plan 모드** | 코드를 바꾸기 전에 구현 계획을 만드는 모드예요. |
| **Agent 모드** | 높은 수준의 작업을 주면 Copilot이 어떤 파일을 고칠지 정하고, 편집하고, 필요하면 명령을 실행하며 반복해요. |
| **GitHub AI Credits** | 채팅·에이전트 등 AI 모델을 쓰는 기능이 소비하는 사용량 단위예요. 1 크레딧은 0.01달러예요. |
| **맞춤 지침** | 저장소에 두는 지침 파일이에요. 채팅 질문에 자동으로 더해져요. |

Claude Code와의 차이를 한 줄로 말하면, Copilot은 **에디터(IDE) 안에서 쓰는 도구**이고 Claude Code는 터미널·앱 등에서 쓰는 에이전트형 코딩 도구예요. 둘의 성능이나 가격 우열을 비교할 공식 근거는 이 편에서 확인하지 못했어요. 용도에 맞게 골라 쓰세요. Claude Code는 [C12](/claude/c12-claude-code-overview/)와 [6편](/coding/06-claude-code-start/), 에디터형 AI 도구는 [9편 Cursor](/coding/09-cursor/)를 보세요.

## 단계별 따라하기

<Checklist items={[
  'VS Code에서 GitHub에 로그인했어요',
  '인라인 제안을 Tab으로 수락해 봤어요',
  'Ask 모드로 파일 내용을 질문했어요',
  'Plan 모드로 계획을 먼저 받았어요',
  'Agent 모드로 작은 앱을 만들고 변경을 검토했어요',
  '맞춤 지침 파일을 만들었어요',
  '내 플랜의 크레딧 사용량을 확인했어요',
]} />

<Steps>

1. **Copilot 연결하고 로그인하기**

   먼저 Copilot을 쓸 수 있는 플랜이 있어야 해요(Free도 가능). 공식 문서에 따르면 VS Code에서는 처음 설정할 때 필요한 확장이 **자동으로 설치**돼요. 직접 내려받을 필요가 없어요. 화면의 안내에 따라 GitHub에 로그인하세요. 단계별 안내는 VS Code 문서의 "Set up GitHub Copilot in Visual Studio Code"로 연결돼요.

   <ScreenshotPlaceholder caption="VS Code에서 Copilot에 로그인하는 화면" officialUrl="https://docs.github.com/en/copilot/how-tos/set-up/install-copilot-extension" />

   다른 에디터를 쓴다면: JetBrains는 Plugins 설정의 Marketplace에서 GitHub Copilot 플러그인을 설치하고 재시작한 뒤 Tools 메뉴의 GitHub Copilot에서 Login to GitHub를 선택해요. Visual Studio, Eclipse, Xcode 방법은 위 설치 문서에 있어요. 로그인 문제는 공식 문서의 Troubleshooting 안내를 보세요.

2. **인라인 제안 받아 보기**

   새 JavaScript 파일(`*.js`)을 만들고 아래 함수 머리만 입력해 보세요. 공식 퀵스타트의 예시예요.

   ```js
   function calculateDaysBetweenDates(begin, end) {
   ```

   Copilot이 함수 내용을 **회색 글씨**로 제안해요. 마음에 들면 `Tab`으로 수락하고, 아니면 무시하고 계속 입력하세요. 제안 내용은 매번 다를 수 있어요. 코딩에 익숙하지 않다면 수락한 코드가 무슨 일을 하는지 다음 단계의 채팅으로 물어보세요.

   <Aside type="tip" title="비용">
   공식 문서에 따르면 코드 완성과 next edit suggestions는 AI 크레딧으로 청구되지 않고 유료 플랜에서 무제한이에요. Free는 코드 완성이 월 2,000회로 제한돼요(2026-10-14 기준).
   </Aside>

3. **Ask 모드로 코드 물어보기**

   코드 파일을 연 상태에서 채팅 창을 열어요. VS Code에서는 `Ctrl+Alt+I`(Windows/Linux) 또는 `Control+Command+I`(macOS)를 누르거나 제목 표시줄의 채팅 아이콘을 눌러요. 아이콘이 안 보이면 제목 표시줄을 우클릭해서 Command Center를 켜요. 채팅 창 아래의 모드 드롭다운에서 **Ask**를 고르고 질문해요.

   <PromptBox>
   what does this file do
   </PromptBox>

   한국어로 질문해도 되는지, 답변이 한국어로 나오는지는 공식 문서에서 확인하지 못했어요. 영어 예시는 퀵스타트에 나온 문장이에요.

   코드 한 줄을 선택하고 `explain this line`이라고 입력해도 돼요. Copilot은 열려 있는 파일이나 선택한 코드를 기준으로 답해서 설명을 따로 붙일 필요가 없어요. 답변 위의 `Used n references`를 열면 어떤 파일을 참고했는지 볼 수 있어요.

   쓸 수 있는 도구도 있어요.
   - `/` 슬래시 명령: 자주 쓰는 작업을 짧게 실행해요. `/`를 입력하면 목록이 나와요.
   - `#` 채팅 변수: 특정 파일 같은 문맥을 넣어요.
   - `@` 참가자와 `@github`: 특정 영역의 도우미나 GitHub 관련 기능을 불러요. `#web`을 넣으면 웹 검색을 쓸 수 있어요.
   - 에디터 안에서 바로 묻는 **인라인 채팅**: `Ctrl+I`(macOS는 `Command+I`)

4. **Plan 모드로 계획 먼저 받기**

   크고 모호한 작업은 계획부터 받는 편이 좋아요. 공식 문서도 큰 작업은 구현 계획을 먼저 만들어 보라고 안내해요. 모드 드롭다운에서 **Plan**을 선택하고 하고 싶은 일을 말해요.

   <PromptBox>
   Create a task manager web app with the ability to add, delete, and mark tasks as completed. Plan which files you will create before changing anything.
   </PromptBox>

   계획에서 만들 파일 목록과 순서를 읽어 보고, 마음에 들지 않으면 후속 메시지로 고치세요. Plan 모드의 자세한 사용법은 공식 문서의 "Using plan mode in your IDE"에 있어요. 이 편에서는 그 페이지를 직접 열어 확인하지 못했어요.

5. **Agent 모드로 작업 맡기기**

   모드 드롭다운에서 **Agent**를 고르고 작업을 설명해요. 위 퀵스타트의 예시를 그대로 써 볼 수 있어요. 빈 폴더를 VS Code로 열고 시작하면 결과를 확인하기 쉬워요.

   <PromptBox>
   Create a task manager web app with the ability to add, delete, and mark tasks as completed
   </PromptBox>

   Copilot이 파일을 만들고 편집하는 모습이 에디터에 흘러나와요. 작업 중에 터미널 명령 실행이 필요하면 **기본적으로 실행 전에 승인을 물어요.** 명령을 읽고 허용하거나 거절하세요. 관리자나 내 에디터 설정이 일부 명령을 자동 실행하게 할 수도 있어요.

   <FlowSteps title="에이전트에게 맡기고 결과 받기" officialUrl="https://docs.github.com/en/copilot/how-tos/copilot-in-your-ide/use-copilot-agents/use-agent-mode" steps={[
     { where: 'Copilot Chat 창', action: '모드 드롭다운에서 Agent 선택 후 작업 입력', result: '편집이 에디터에 스트리밍됨' },
     { where: '진행 중', action: '제안된 터미널 명령을 읽고 승인 또는 거절, 필요하면 후속 프롬프트로 방향 조정', result: '원하는 방향으로 수정됨' },
     { where: '에디터', action: '바뀐 내용을 검토하고 원치 않는 편집은 되돌리기', result: '검토된 변경만 남음' },
     { where: 'IDE 컨트롤', action: '변경 수락, 저장, 만족하면 커밋', result: '작업 완료' },
   ]} />

   <Aside type="caution" title="Agent 옵션이 안 보이면">
   모드 드롭다운에 Agent가 없다면 회사·조직 관리자가 내 IDE의 에이전트 모드를 꺼 놓았을 수 있어요(공식 문서 안내). 내 개인 설정 문제가 아닐 수 있으니 관리자에게 문의하세요.
   </Aside>

   만들어진 앱을 어떻게 실행하는지는 결과물에 따라 달라요. 막히면 채팅에 "how do I run this app?"처럼 물어보세요. 웹페이지 파일을 브라우저로 여는 감각은 [27편](/coding/27-first-app-with-claude-code/)에서 익힐 수 있어요.

6. **저장소 맞춤 지침 만들기**

   매번 같은 규칙을 반복해 말하기 싫다면 지침 파일을 만들어요. VS Code에서는 세 가지가 지원돼요(공식 문서, 기본 활성화).
   - **저장소 전체**: 저장소 루트에 `.github/copilot-instructions.md`를 만들고 일반 문장(Markdown)으로 규칙을 적어요. `.github` 폴더가 없으면 만들어요.
   - **경로별**: `.github/instructions/` 안에 `이름.instructions.md`를 만들고, 맨 위 frontmatter에 `applyTo`로 적용할 파일 패턴을 적어요.
   - **에이전트용**: `AGENTS.md`. 가까운 폴더의 파일이 우선해요. 저장소 루트 밖의 파일 지원은 기본으로 꺼져 있어요.

   <PromptBox>
   Create .github/copilot-instructions.md for this project. Rules: explain changes in simple Korean, keep everything in index.html, never add code that sends data to external servers, and ask me before deleting any file.
   </PromptBox>

   지침 파일은 채팅 질문에 자동으로 더해져요. 이런 규칙은 어디까지나 "부탁"이므로, 에이전트의 결과는 여전히 직접 확인해야 해요.

7. **사용량 확인하기**

   채팅과 에이전트는 크레딧을 써요. 공식 문서에 따르면 에이전트 모드는 **프롬프트마다** 크레딧을 소비하고, 한 작업에서 모델을 여러 번 부르기 때문에 간단한 채팅 질문보다 훨씬 많이 쓸 수 있어요. 모델 선택도 영향을 줘요(덜 비싼 모델로 바꾸면 허용량을 더 오래 쓸 수 있어요). 크레딧은 매월 1일 00:00:00 UTC에 초기화되고 이월되지 않아요. 사용량은 GitHub의 사용량 대시보드에서 볼 수 있다고 안내돼요.

</Steps>

| 코드를 치는 중 빠르게 이어 쓰고 싶다 | 인라인 제안 | `Tab`으로 수락, 크레딧 미소비 |
| 한 줄만 바로 묻고 싶다 | 인라인 채팅 | `Ctrl+I` / `Command+I` |

### 자주 쓰는 단축키 (VS Code, 공식 문서 기준)

| 동작 | Windows/Linux | macOS |
| --- | --- | --- |
| 채팅 열기 | `Ctrl+Alt+I` | `Control+Command+I` |
| 인라인 채팅 | `Ctrl+I` | `Command+I` |
| 퀵 채팅 | `Ctrl+Shift+Alt+L` | `Shift+Option+Command+L` |
| 인라인 제안 수락 | `Tab` | `Tab` |

## 자주 막히는 지점

### 모드 선택에 Agent가 없어요

- **원인**: 조직이나 엔터프라이즈 관리자가 내 IDE의 에이전트 모드를 꺼 놨을 수 있어요.
- **해결**: 관리자에게 문의하세요. 개인 계정이라면 플랜에 에이전트 모드가 포함되는지 공식 플랜 페이지에서 확인하세요(이 편에서는 확인하지 못했어요).

### 조직 계정이라 채팅이 안 돼요

- **원인**: 조직 소유자가 Copilot Chat을 끄면 조직을 통해 Copilot을 쓰는 사람은 채팅을 쓸 수 없어요(공식 문서 안내).
- **해결**: 조직 관리자에게 정책을 확인해 달라고 요청하세요.

### 로그인이나 인증에서 막혀요

- **원인**: 계정·네트워크·플랜 문제 등 여러 가지가 있어요.
- **해결**: 공식 문서의 "Troubleshooting common issues with GitHub Copilot"를 보세요. 이 편에서는 그 페이지를 열어 확인하지 못했어요.

### 제안이 엉뚱하거나 코드가 동작하지 않아요

- **원인**: 제안은 매번 달라질 수 있고, 틀릴 수도 있어요.
- **해결**: 수락하기 전에 읽고, 에이전트가 만든 변경은 직접 실행해서 확인한 뒤에 저장·커밋하세요. 공식 퀵스타트도 변경을 검토한 뒤 수락하라고 안내해요.

### 크레딧이 빨리 줄어요

- **원인**: 에이전트 모드와 긴 대화는 많이 소비해요.
- **해결**: 작은 작업은 Ask나 인라인 제안으로, 모델은 가벼운 것으로 바꿔 보세요. 크레딧이 소진되면 플랜 업그레이드, 추가 사용 예산 설정, 다음 달까지 대기 중에서 고르게 돼요(공식 문서, 2026-10-14 기준).

## 실전 팁

- **작은 작업부터 맡기세요.** 한 번에 앱 전체보다 기능 하나씩이 검토하기 쉬워요.
- **요청은 구체적으로.** 파일 이름, 지켜야 할 제약, 원하는 결과 예시를 함께 적으세요.
- **검토 없이 커밋하지 마세요.** 변경 내용을 읽고, 직접 실행해 보고 나서 저장·커밋하세요.
- **비밀정보는 코드 파일에 넣지 마세요.** 비밀번호와 API 키가 있는 파일이 작업 폴더에 있으면 채팅 문맥으로 쓰일 수 있어요. 파일 제외 설정(content exclusion)은 공식 플랜 표에 항목이 있지만 이 편에서는 사용법을 확인하지 못했어요.
- **Claude 모델을 쓸 수 있나요?** 공식 플랜 페이지의 모델 목록에 Claude 모델이 포함돼 있지만(2026-10-14 기준), 어느 플랜에서 어느 모델이 되는지는 표의 체크 표시를 읽지 못해 단정하지 않아요. Claude 자체의 요금제는 [C2](/claude/c02-plans-limits/)와 별개예요.
- **역할 분담 아이디어**: 코드를 치면서는 인라인 제안, 설명과 계획은 Ask·Plan, 여러 파일 작업은 Agent로 나눠 쓰면 크레딧도 아낄 수 있어요. 모델 역할 나누기 감각은 [C15](/claude/c15-model-division/)를 참고하세요.
