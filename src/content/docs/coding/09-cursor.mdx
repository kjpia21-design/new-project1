<Summary>
- Cursor는 AI가 들어간 **코드 편집기**예요. 폴더를 열고 AI에게 코드를 설명받거나, 파일 수정을 맡길 수 있어요.
- 기존 코드를 다룰 때는 **먼저 읽기 전용 Ask 모드로 이해하고, 그다음 Agent 모드로 작은 수정**을 맡기는 순서가 안전해요.
- Agent의 수정은 작업 중에 적용되고, diff 뷰에서 검토해 거부할 수 있어요.
- 프로젝트 지침은 **Rules**(`.cursor/rules`의 `.mdc` 파일)에 적어 두면 돼요. 민감한 코드는 **Privacy Mode**와 제외 설정을 확인하세요.
- 무료 Hobby 플랜이 있고 Pro는 월 $20예요(2026-10-10 기준). 메뉴와 모드 이름은 버전에 따라 바뀔 수 있어요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- Cursor를 설치하고 기존 코드 폴더를 열어 AI에게 구조를 설명받을 수 있어요.
- Ask 모드와 Agent 모드를 구분해서 쓸 수 있어요.
- Agent가 한 수정을 diff로 검토하고, 마음에 안 드는 부분을 거부할 수 있어요.
- 프로젝트 규칙(Rules)을 만들고, 민감한 코드를 다룰 때 확인할 것을 알아요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **Cursor** | AI 기능이 들어간 코드 편집기예요. 데스크톱 앱으로 설치해요. 터미널에서 쓰는 Cursor CLI도 있어요. |
| **Agent 모드** | 코드를 읽고 여러 파일을 편집하고 터미널 명령도 실행하는 모드예요. 코드베이스를 자동으로 검색하고, 편집을 작업 중에 적용해요. |
| **Ask 모드** | 읽기 전용 모드예요. 코드를 이해하고 구조를 탐색할 때 쓰고, 파일은 바꾸지 않아요. |
| **diff** | 바뀐 줄을 추가/삭제로 보여 주는 화면이에요. 수정을 받아들일지 거부할지 판단하는 기준이에요. |
| **Rules** | AI가 따를 프로젝트 지침이에요. `.cursor/rules` 폴더에 `.mdc` 파일로 두고 버전 관리와 함께 쓸 수 있어요. |
| **검색 색인** | Cursor가 코드를 빠르게 찾으려고 만드는 색인이에요. 공식 문서는 이 색인을 내 컴퓨터에서 만들고, 검색용으로 파일 경로나 코드를 업로드하거나 임베딩을 저장하지 않는다고 설명해요. 다만 Agent가 연 파일의 내용은 모델 요청에 포함될 수 있어요. |

### Cursor와 Claude Code, 어떻게 다른가요?

| | Cursor | Claude Code |
| --- | --- | --- |
| **형태** | 코드 편집기(데스크톱 앱), 터미널용 CLI도 있음 | 터미널·IDE 확장·데스크톱 앱·웹 |
| **편한 점** | 코드를 눈으로 보면서 AI에게 묻고 고치기 | 대화로 작업을 맡기고 클라우드에서도 실행 |
| **같이 쓰기** | Claude Code의 VS Code 확장은 Cursor에도 설치할 수 있어요 | 위 확장으로 Cursor 안에서 사용 가능 |
| **고를 때** | 코드를 직접 읽고 편집하며 AI를 곁에 두고 싶을 때 | 작업을 설명해서 맡기고 결과를 검토하고 싶을 때 |

어느 쪽이 더 낫다고 단정하기보다, 업무 방식에 맞는 도구를 고르세요. Claude Code 쪽은 [6편](/new-project1/coding/06-claude-code-start/)과 [C12](/new-project1/claude/c12-claude-code-overview/)를 보세요.

<Steps>

1. **설치하고 로그인하기**

   Cursor 공식 사이트에서 내 운영체제용 설치 파일을 받아요. 공식 퀵스타트는 macOS는 `.dmg`, Windows는 `.exe`, Linux는 apt·dnf 패키지를 권장한다고 안내해요. 설치 뒤 앱을 열고 로그인하세요. Windows는 10 이상, macOS는 12(Monterey) 이상이 필요해요. 요금은 아래 [요금제 표](#cursor-요금제)를 보세요. 한국어 UI 지원 여부는 공식 문서에서 확인하지 못했으니 앱 설정을 보세요.

   <ScreenshotPlaceholder caption="Cursor 첫 실행과 로그인 화면" />

2. **연습용 폴더 열기**

   처음에는 회사 저장소 원본이 아니라 **복사본**으로 연습하세요. Cursor를 열고 **File > Open Folder**에서 폴더를 선택하세요(공식 도움말 기준). Agent는 코드베이스를 자동으로 검색하지만, 파일이 아주 많으면 시간이 걸릴 수 있어요.

3. **Ask 모드로 코드 이해하기**

   Agent 패널을 열어요(맥은 Cmd+I, Windows·Linux는 Ctrl+I). 그다음 모드 선택 드롭다운에서 **Ask**를 고르거나 Shift+Tab으로 모드를 순환해요(공식 도움말 기준). Ask 모드는 읽기 전용이라 파일이 바뀌지 않아요.

   <PromptBox>
   이 프로젝트가 무엇을 하는지 코딩을 모르는 사람이 이해할 수 있게 설명해 줘. 주요 폴더 구조, 시작점이 되는 파일, 데이터가 어디서 어디로 흐르는지를 표로 정리해 줘. 확실하지 않은 부분은 추측이라고 표시해 줘.
   </PromptBox>

   공식 퀵스타트도 폴더를 연 뒤 Agent에게 "코드베이스를 설명하고 어디부터 읽을지 알려 달라"고 묻는 것을 제안해요. Cursor가 저장소를 검색해 관련 파일을 읽고 요약해 줘요.

   이어서 구체적으로 물어보세요.

   <PromptBox>
   로그인 실패 시 오류 메시지는 어디서 만들어지는지 찾아 줘. 관련 파일과 함수 이름, 그리고 그 파일을 고치면 영향받을 수 있는 다른 곳도 알려 줘. 아직 아무것도 수정하지 마.
   </PromptBox>

4. **Agent 모드로 작은 수정 맡기기**

   수정은 **작고 확인 가능한 것**부터 시작하세요. 모드를 **Agent**로 바꾸고 요청해요.

   <PromptBox>
   로그인 실패 시 보이는 오류 메시지를 "아이디 또는 비밀번호를 확인해 주세요"로 바꿔 줘. 이 문구가 들어 있는 다른 파일(테스트 포함)도 찾아서 같이 맞춰 줘. 그 밖의 코드는 건드리지 마. 수정한 파일 목록과 이유를 마지막에 정리해 줘.
   </PromptBox>

   Agent의 수정은 작업 중에 적용되고, 결과는 diff 뷰에서 확인해요. 잘못된 방향으로 가면 Stop으로 취소하고 방향을 다시 알려 주면 된다고 공식 모범 사례가 안내해요.

   <ScreenshotPlaceholder caption="Agent가 수정한 파일의 diff 화면" />

5. **diff 검토하고 거부하기**

   바뀐 파일을 하나씩 열어 보세요. 확인할 것은 (1) 요청한 곳만 바뀌었는지, (2) 관련 없는 파일이 같이 바뀌지 않았는지, (3) 줄 수가 갑자기 많이 늘지 않았는지예요. 원하지 않는 변경은 diff에서 거부할 수 있어요. 수정을 되돌리려면 이전 메시지에 마우스를 올리고 오른쪽 아래의 **Restore Checkpoint**를 누르세요. 그 시점 이후 Agent가 바꾼 파일이 롤백돼요(파일만 되돌리고 대화 메시지는 지워지지 않아요). Git을 쓴다면 변경 사항을 커밋하기 전에 이 검토를 먼저 하고, 되돌릴 일이 생기면 Git으로도 돌아갈 수 있어요.

   참고로 이전 메시지를 수정해 다시 보낼 때 Agent 모드에서는 파일을 그 시점으로 되돌릴지 묻는 동작이 릴리스 노트에 나와 있어요. 되돌리기 동작은 버전마다 다를 수 있으니 화면의 질문을 읽고 선택하세요.

6. **Rules로 프로젝트 지침 만들기**

   반복해서 말해야 하는 규칙은 Rules에 적어 두세요. 프로젝트 규칙은 `.cursor/rules`에 두고, 공식 문서에 따르면 프로젝트 규칙은 `.mdc` 확장자여야 해요(`.cursor/rules`의 일반 `.md`는 프런트매터를 지정할 수 없어 무시돼요). 일반 마크다운으로 쓰고 싶다면 `AGENTS.md`를 쓰세요. 적용 방식은 Always Apply, Apply Intelligently, Apply to Specific Files, Apply Manually가 있어요.

   <PromptBox>
   이 프로젝트에 맞는 Cursor 규칙 파일을 .cursor/rules 폴더에 만들어 줘. 항상 적용되는 규칙으로, (1) 설명과 주석은 한국어로 쓴다 (2) 요청하지 않은 파일은 수정하지 않는다 (3) 수정한 파일 목록을 마지막에 정리한다는 내용을 넣어 줘. 확장자는 .mdc로 하고 프런트매터 형식은 Cursor 공식 문서 기준에 맞춰 줘.
   </PromptBox>

   생성된 파일의 프런트매터가 공식 문서(Rules)와 맞는지 한 번 확인하세요. 팀 단위 규칙과 사용자 규칙도 있지만 이 실습에서는 프로젝트 규칙만 다뤄요.

7. **민감한 코드를 다루기 전에 확인하기**

   회사 코드나 고객 정보가 들어 있다면 다음을 먼저 확인하세요.

   - **Privacy Mode**: 공식 데이터 사용 페이지는 설정에서 Privacy Mode를 켜면 고객 데이터를 학습에 쓰지 않고, 모델 제공자와 데이터 비보존(ZDR) 계약을 유지한다고 설명해요. 다만 남용 탐지에 걸리면 저장될 수 있고, 일부 모델은 ZDR 범위 밖일 수 있다고도 밝히고 있어요. 현재 조건은 공식 페이지에서 직접 읽으세요.
   - **제외 설정**: 루트의 `.cursorignore`(`.gitignore` 문법)에 적은 파일은 Agent, Tab, Inline Edit과 @ 멘션에서 접근이 막혀요. 다만 Agent의 터미널과 MCP 도구는 이 설정으로 막을 수 없고, 공식 문서도 완전한 보호는 보장하지 않는다고 밝혀요. `.env`처럼 비밀 값은 처음부터 코드에 넣지 마세요.
   - **회사 방침**: 사내 코드를 외부 AI 서비스에 올려도 되는지는 회사 정책이 먼저예요. 정책이 없으면 보안 담당자에게 확인하세요.
   - `.env`, 비밀번호, API 키는 채팅에 붙여 넣지 마세요.

</Steps>

## 자주 막히는 지점

### AI가 코드와 다른 말을 해요

- **원인**: 관련 파일을 찾지 못했거나, 모르는 부분을 추측했을 수 있어요.
- **해결**: 질문에 파일 이름이나 함수 이름을 넣어 범위를 좁히고, "확실하지 않으면 추측이라고 표시해 줘"를 덧붙이세요. 답을 코드에서 직접 확인하는 습관이 가장 안전해요.

### Agent가 요청하지 않은 파일까지 수정했어요

- **원인**: 요청 범위를 정해 주지 않았을 수 있어요.
- **해결**: diff에서 불필요한 변경을 거부하세요. 다음 요청부터 "그 밖의 코드는 건드리지 마"를 쓰고, Rules에 같은 내용을 넣어 두세요.

### Rules 파일이 적용되지 않는 것 같아요

- **원인**: 공식 문서는 `.cursor/rules`의 프로젝트 규칙이 `.mdc` 파일이어야 하고 일반 `.md`는 무시된다고 설명해요.
- **해결**: 확장자를 `.mdc`로 하고 프런트매터를 공식 Rules 문서와 맞추고, 적용 방식을 Always Apply 등으로 지정하세요.

### 큰 저장소에서 느리거나 엉뚱한 파일이 참조돼요

- **원인**: 불필요한 파일(빌드 결과 등)이 검색 범위에 들어 있을 수 있어요. `.gitignore`에 적힌 파일과 lock 파일은 기본으로 제외돼요.
- **해결**: 필요 없는 폴더를 `.cursorignore`에 추가하고, 질문에 파일이나 폴더 이름을 `@`로 지정하세요.

### 요금이나 한도 때문에 막혀요

- **원인**: 플랜별 한도가 있어요.
- **해결**: 위 요금제 표를 보고, [공식 가격 페이지](https://cursor.com/pricing)에서 최신 조건을 확인하세요. 한도를 넘으면 추가 사용량 결제나 상위 플랜 업그레이드를 고를 수 있어요.

## 실전 팁

- **이해 → 계획 → 수정 순서.** Ask로 이해하고, 수정 계획을 말로 받아 본 뒤 Agent에 맡기세요.
- **작은 단위로 맡기세요.** 한 번에 한 가지 수정이 diff 검토에도, 되돌리기에도 편해요.
- **수정 후에는 실제로 실행해 보세요.** AI의 설명을 믿기 전에 프로그램이나 테스트가 동작하는지 눈으로 확인하세요.
- **Git으로 안전망을 만드세요.** 작업 전에 커밋해 두면 언제든 돌아갈 수 있어요.
- **도구를 섞어 써도 돼요.** Claude Code 확장을 Cursor에 설치할 수도 있어요. 클라우드에서 돌리고 싶은 작업은 [8편](/new-project1/coding/08-cloud-github/)처럼 맡길 수 있어요.
