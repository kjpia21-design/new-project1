<Summary>
- This isn't an installation guide. It's a **"make your first result" exercise**. Installation and concepts are covered in [C12. Claude Code overview](/claude/c12-claude-code-overview/).
- Starting from an empty folder, you'll build one web page in this order: **check the plan in plan mode → approve → files get created → check in the browser → ask for changes**.
- You don't need to read code. What you do need is the habit of **deciding in plain words what to build, and checking the changes on the approval screen**.
- If something goes wrong, you can roll back with `/rewind`. Work in small steps: one request, check, then the next request.
- Claude Code is available on paid plans (Pro or higher) (as of 2026-10-26).
</Summary>

## What you'll be able to do after this tutorial

- Start Claude Code in an empty folder and describe what you want to build in everyday sentences.
- Use plan mode to see "what it will do" first, then approve it so the real files get created.
- Open the result in your browser and ask for fixes in plain words.
- Know how to undo changes you don't like, and how to pick up the same project next time.

## Concepts to know first

Installation and the full glossary are covered in [C12](/claude/c12-claude-code-overview/). Here are just the parts you need for this exercise.

| Term | What it means in this exercise |
| --- | --- |
| **Terminal** | A window where you give your computer instructions in text. If it's your first time, the terminal guide in the official docs explains how to open it and paste commands. |
| **Working folder** | The area Claude Code can read and write. Making one empty folder and starting only there keeps things safe. |
| **Permission mode** | The range of actions Claude may take without asking. Change it with `Shift+Tab`. For this exercise, it's safest to stay in Manual mode, which asks before making changes. According to the official docs, the default starting mode in the terminal for Claude Code v2.1.283 and later is auto mode, so check the mode shown on the start screen (as of 2026-10-26). |
| **Plan mode** | A mode that only reads and proposes a plan without changing files. Edits are blocked until you approve. |
| **CLAUDE.md** | A guide note about your project. Claude reads it again in the next session. |

<Aside type="note" title="Which screen do I use?">
This exercise uses the terminal. If the terminal feels unfamiliar, you can do the same thing in the Code tab of the desktop app. The app is good for reviewing changes visually, and you don't have to install the CLI separately (a paid subscription is required). See the table in [C12](/claude/c12-claude-code-overview/) for how to choose.
</Aside>

## Step-by-step guide

This time you'll build a **"one-page web page for a meeting announcement"**. It shows the date, location, agenda, and things to bring. You can see the result without any coding knowledge, so it's a good first exercise. The steps are the same for any other topic.

<Checklist items={[

  'I got a plan first in plan mode',

  'I opened the generated index.html in my browser',

<Steps>

1. **Create an empty folder and start**

   Create an empty folder named `meeting-page` on your desktop or somewhere similar. Open a terminal, move into that folder, and run `claude`.

   ```sh
   cd ~/Desktop/meeting-page
   claude
   ```

   If it's your first time, a login prompt appears. Finish the authentication in your browser (see [C12](/claude/c12-claude-code-overview/) for details on how login works). The reason to start in an empty folder on purpose is that there are no existing files to touch, so mistakes cost you nothing.

   <ScreenshotPlaceholder caption="The first screen after running claude in an empty folder" officialUrl="https://code.claude.com/docs/en/quickstart#step-2-start-your-first-session" />

2. **Switch to plan mode and get a plan first**

   Press `Shift+Tab` to switch the permission mode to plan mode. If you started in auto mode, the modes cycle in the order Manual → Auto-accept edits → Plan mode, so you may need to press it several times. The current mode is shown in the status bar at the bottom of the screen. You can also start with `claude --permission-mode plan` from the beginning, or put `/plan` in front of your request. In plan mode, Claude only proposes a plan and doesn't change files.

   <PromptBox>
   I want to make a one-page web page for a meeting announcement. I know nothing about coding. The page should show the meeting title, date and time, location, 3 agenda items, and things to bring. First tell me, in plain language, which files you'll create and how the screen will look. Please make it as a single index.html file only.
   </PromptBox>

   When the plan appears, read it. It's enough to check that there's only one file name and that nothing connects to outside services. If there's a part you don't like, ask for it to be changed in plain words.

3. **Approve the plan and create the file**

   If the plan looks good, approve it to move on to execution. According to the official docs, the choices are "Yes, and use auto mode", "Yes, manually approve edits", and "No, keep planning" (the wording may vary depending on the situation). At first, "Yes, manually approve edits" is safest because you can check every edit. When Claude shows the changes and asks for approval, just check **which files will be created** and choose Yes.

   <Aside type="tip" title="What to look for on the approval screen">
   At first, you don't need to read the code. Just check (1) that the file is inside your working folder, (2) that it's the file you asked for (`index.html`), and (3) that nothing deletes files you didn't ask about or reaches outside the folder.
   </Aside>

4. **Check the result in your browser**

   There should now be an `index.html` in the folder. Double-click the file to open it in your browser. If you're not sure how to open it, ask Claude.

   <PromptBox>
   Tell me how to open the index.html you made on my computer. Then summarize what's on the page, one line at a time.
   </PromptBox>

   <ScreenshotPlaceholder caption="The meeting announcement page opened in a browser" />

5. **Ask for fixes in plain words**

   As you look at it, ask for the things you want to change one at a time. Doing just one or two things at once makes it easy to see what changed.

   <PromptBox>
   Make the title text bigger and change the 3 agenda items into a numbered list. Make the overall background light gray and use an easy-to-read default font. Before you change anything, tell me in one line what you'll change and how.
   </PromptBox>

   After you ask, refresh the browser (F5) to check. If you see an unfamiliar term, ask, "Explain the change you just made so even an elementary school kid could understand."

6. **Practice undoing changes**

   Try asking for a change you don't like on purpose, then undo it. Type `/rewind` in the session and a screen appears for going back to an earlier checkpoint. Follow the on-screen instructions for the exact wording of the options. For important results, it's even safer to copy them into a separate folder.

7. **Prepare for next time with CLAUDE.md**

   Create a guide note so Claude understands this project even if you reopen it tomorrow.

   <PromptBox>
   Save a CLAUDE.md that summarizes what this project is and which files it has. Include that I don't know coding, so explanations should use plain language, and that you should always tell me before changing any files.
   </PromptBox>

   The `/init` command analyzes your codebase and creates a starter CLAUDE.md. Since there are hardly any files yet, asking directly as above fits better. To continue the work later, use `claude -c` (continue the most recent conversation) or `claude -r` (pick one) in the same folder.

</Steps>

## Quick reference

### The flow for making your first result

| Step | What you do | What you use |
| --- | --- | --- |
| 1 | Start in an empty folder | `cd`, `claude` |
| 2 | Get a plan first | `Shift+Tab` or `claude --permission-mode plan` |
| 3 | Approve and create | The approval screen |
| 4 | Check with your eyes | Open `index.html` in the browser |
| 5 | Ask for one or two changes at a time | Everyday sentences |
| 6 | Undo | `/rewind` |
| 7 | A note for next time | CLAUDE.md, `claude -c` |

### Commands that help non-developers

| Command | Purpose |
| --- | --- |
| `/help` | List of commands |
| `/rewind` | Go back to a checkpoint |
| `/clear` | Start a new conversation (files stay as they are) |
| `/resume`, `claude -r` | Pick and continue an earlier conversation |
| `claude -c` | Continue the most recent conversation in this folder |
| `/init` | Create a CLAUDE.md |
| `Shift+Tab` | Cycle through permission modes |

### Sentence patterns that make better requests

| Situation | Try saying this |
| --- | --- |
| When you feel stuck | "Tell me 3 possible approaches in plain language. Don't change any files yet." |
| Check before changing | "Before you change anything, tell me in one line what you'll change and how." |
| When you don't understand | "Explain the change you just made as if to someone who doesn't know coding." |
| When wrapping up | "Write today's work and what's left in CLAUDE.md." |

## Common sticking points

### Claude created too many files

- **Cause**: Your request may not have set how many files to make.
- **Fix**: Roll back with `/rewind`, then ask again with a firm limit like "only one index.html file". Looking at the plan first in plan mode helps prevent this.

### I opened it in the browser but nothing shows or it looks broken

- **Cause**: The file may be saved in a different place, or the browser may be showing an old screen.
- **Fix**: Try refreshing (F5). If it's still the same, describe what you see to Claude, like "I opened it in the browser and got a blank screen. Find the cause and fix it."

### Having to keep clicking approve is a hassle

- **Cause**: Manual mode asks for approval on every change.
- **Fix**: Once you're comfortable, you can use `Shift+Tab` to switch to the mode that auto-approves file edits (`acceptEdits`, shown on screen as "accept edits"). Use it only in folders where you can undo changes (an empty folder or a Git repository). See [C14](/claude/c14-claude-code-features/) for what each mode means.

### It says `claude` can't be found / I can't log in

- **Cause**: You may be using a terminal you left open from before the installation, or your plan may be Free.
- **Fix**: Open a new terminal and check with `claude --version`. Claude Code is available on paid plans (Pro or higher) (as of 2026-10-26). For more fixes, see [the sticking points in C12](/claude/c12-claude-code-overview/).

### How do I show the result to other people?

- **Method**: You can send the `index.html` file itself by email or similar. If you want to publish it at a web address, see [Tutorial 8, the GitHub Pages deployment exercise](/coding/08-cloud-github/). Before publishing, be sure it doesn't contain personal information like names or contact details.

## Practical tips

- **Always start small.** A "one-page page" is easier to succeed with than a "whole homepage".
- **Check with what you can see.** Even if you can't read code, you can read a browser screen. Describe wrong parts by what's on screen.
- **Ask for just one or two changes at a time.** It makes it easier to find where things broke.
- **Don't include personal information or company secrets.** Start with practice sample content.
- **If you want to keep going**, try the Code tab in the desktop app or a free course like Claude Code 101 from Claude Academy.
