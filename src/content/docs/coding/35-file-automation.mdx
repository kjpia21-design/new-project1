## 이 튜토리얼로 할 수 있게 되는 것

- 폴더 속 여러 엑셀(또는 CSV) 파일을 **하나의 표로 합치는 일**을 말로 맡길 수 있어요.
- 파일 이름을 "날짜_거래처_종류" 같은 규칙으로 **일괄 정리**하되, 바꾸기 전에 미리보기를 받는 방법을 알게 돼요.
- CSV의 빈 줄, 중복, 형식 흐트러짐을 정리하되 **원본은 그대로 두고 새 파일로** 받을 수 있어요.
- 잘못됐을 때 돌아갈 수 있는 **백업, 승인 화면, `/rewind`의 역할과 한계**를 구분해서 알게 돼요.

## 먼저 알아둘 개념

| 용어 | 이 실습에서의 뜻 |
| --- | --- |
| **작업 폴더** | Claude Code가 읽고 쓰는 범위예요. 연습용 복사본 폴더 하나에서만 시작해요. |
| **백업** | 작업 전에 폴더를 통째로 복사해 둔 것이에요. 이 편의 가장 중요한 안전장치예요. |
| **승인 화면** | Claude가 파일을 바꾸거나 명령을 실행하기 전에 "해도 될까요?" 하고 묻는 화면이에요. |
| **계획 모드** | 파일을 바꾸지 않고 계획만 제안하는 모드예요. `Shift+Tab`으로 바꿔요. |
| **체크포인트와 `/rewind`** | Claude가 파일을 바꾸기 전 상태를 기록해 두고, `/rewind`로 그 시점으로 되돌리는 기능이에요. |

### 어떤 일에 잘 맞나요?

Claude Code는 이름처럼 코딩 도구지만, 폴더 안의 파일을 읽고 쓰고 명령을 실행할 수 있어서 반복적인 파일 작업에도 쓸 수 있어요. 이 편의 예시와 프롬프트는 이 사이트가 만든 연습 과제이고 공식 문서의 예시는 아니에요. 아래처럼 **규칙이 분명하고 결과를 눈으로 확인할 수 있는 일**이 잘 맞아요.

| 잘 맞는 일 | 조심할 일 |
| --- | --- |
| 같은 양식의 엑셀·CSV 여러 개를 하나로 합치기 | 서식·수식·차트가 많은 문서를 그대로 보존해야 하는 일 |
| 파일 이름에 날짜·번호·거래처를 규칙대로 붙이기 | 원본이 하나뿐이고 복사본이 없는 중요 파일 |
| CSV의 빈 줄 제거, 중복 확인, 열 이름 통일 | 개인정보·급여처럼 외부로 나가면 안 되는 자료 (아래 [안전하게 쓰기](#안전하게-쓰기) 참고) |

<Aside type="note" title="확인되지 않은 점">
Claude Code가 엑셀(.xlsx) 파일을 어떤 방식으로 읽고 쓰는지는 공식 문서에서 확인하지 못했어요. 작업 방식은 Claude가 정하고, 필요한 프로그램을 설치하거나 실행해야 하면 승인을 물어요. 컴퓨터 환경에 따라 결과가 다를 수 있으니 **결과 파일은 반드시 직접 열어 확인**하세요. 엑셀의 수식, 서식, 여러 시트가 그대로 보존되는지도 확인하지 못했어요.
</Aside>

### 왜 백업이 먼저인가요?

[27편](/coding/27-first-app-with-claude-code/)에서 `/rewind`를 소개했지만, 파일 정리 작업에서는 한계를 꼭 알아야 해요. 공식 체크포인트 문서(2026-10-26 확인)에 따르면 다음과 같아요.

- Claude의 **파일 편집 도구**로 바뀐 것은 추적되어 되돌릴 수 있어요.
- 하지만 `rm`(삭제), `mv`(이동·이름 변경), `cp`(복사) 같은 **명령으로만 바뀐 파일은 추적되지 않고 `/rewind`로 되돌릴 수 없어요.** (Claude가 편집 도구로 이미 고친 파일이라면 그 뒤 명령이 만든 변화도 함께 되돌려진다고 해요.) 파일 이름 일괄 변경은 보통 명령으로만 이뤄져서 되돌리기 대상이 아니에요.
- 체크포인트는 세션당 최근 100개까지 파일 스냅샷을 보관하고, 기본 설정에서는 세션이 마지막으로 저장된 뒤 약 30일이 지나면 스냅샷이 지워져요.
- 내가 Claude Code 밖에서 직접 바꾼 파일은 대개 기록되지 않아요.
- 문서도 체크포인트는 Git 같은 버전 관리를 대체하지 않는다고 말해요.

즉 파일 작업에서는 **`/rewind`보다 작업 전 폴더 복사가 더 믿을 만한 안전장치**예요.

## 단계별 따라하기

  '결과 파일을 직접 열어서 행 수와 합계를 맞춰 봤어요',
  '파일 이름 변경은 미리보기를 먼저 받은 뒤 실행했어요',
  '연습이 끝난 뒤에야 실제 폴더 복사본에 같은 요청을 했어요',

<Steps>

1. **백업 만들고 연습 폴더 준비하기**

   탐색기(윈도우)나 Finder(맥)에서 작업할 폴더를 통째로 **복사해서 다른 위치에 붙여 넣으세요.** 이름 끝에 `_백업`을 붙여 두면 헷갈리지 않아요. 그다음 연습용으로 `연습` 폴더를 새로 만들고, 같은 양식의 엑셀 3~5개를 **복사해서** 넣어요. 실제 급여, 고객 연락처 같은 민감한 자료는 쓰지 말고 연습용 예시 데이터로 시작하세요.

   이 폴더가 Git으로 관리되는 곳이라면 Git도 좋은 안전장치지만, 처음이라면 폴더 복사가 가장 쉬워요. Git은 [8편](/coding/08-cloud-github/)에서 다뤄요.

2. **연습 폴더에서 Claude Code 시작하고 계획 모드로 두기**

   터미널을 `연습` 폴더에서 열어 `claude`를 실행해요. 터미널이 처음이라면 [6편](/coding/06-claude-code-start/)을 먼저 보세요. 처음에는 변경마다 확인을 묻는 기본 모드로 두고, `Shift+Tab`을 눌러 **계획 모드**로 바꿔요. 공식 권한 모드 문서(2026-10-26 확인)에 따르면 기본(Manual) 모드는 읽기만 묻지 않고 실행하고, 계획 모드는 파일을 조사하며 계획을 제안할 뿐 승인 전에는 소스를 편집하지 않아요.

   ```sh
   cd ~/Desktop/연습
   claude
   ```

3. **엑셀 합치기: 먼저 읽기만 시키기**

   곧바로 합치게 하지 말고, **폴더에 뭐가 있는지 읽고 보고하게** 해요. 열 이름이 파일마다 다르거나 맨 위에 제목 줄이 있으면 합치기가 틀어지기 쉬워서, 먼저 확인하는 게 좋아요.

   <PromptBox>
   이 폴더에 있는 엑셀 파일들을 읽고 알려 줘. (1) 파일 이름과 각 파일의 시트 이름 (2) 각 시트의 열 이름이 파일마다 같은지 다른지 (3) 데이터 행이 몇 개인지. 아직 아무것도 바꾸거나 새로 만들지 말고 보고만 해 줘. 읽는 데 프로그램 설치가 필요하면 먼저 어떤 걸 설치할지 알려 줘.
   </PromptBox>

   프로그램을 설치하거나 명령을 실행하겠다고 승인을 물으면, 화면에 나온 명령을 읽고 모르겠으면 "이 명령이 뭘 하는지 설명해 줘"라고 먼저 물어보세요. 여기서 `pip`이나 `npm` 같은 설치 명령이 나올 수 있는데, 컴퓨터에 프로그램을 추가하는 명령이라 **뭘 설치하는지 이름을 확인**하고 허용하세요.

4. **합치기 요청하기: 원본은 그대로, 새 파일로**

   보고 내용이 맞으면 합치기를 요청해요. 핵심은 **원본을 건드리지 말고 새 파일로 저장**하게 하는 것, 그리고 **검산할 수 있는 숫자**를 받는 것이에요.

   <PromptBox>
   이 폴더의 엑셀 파일들을 하나의 표로 합쳐서 "합친결과.xlsx"라는 새 파일로 저장해 줘. 원본 파일은 절대 수정하거나 삭제하지 마. 합친 표에는 맨 앞 열에 "원본 파일명"을 추가해 줘. 끝나면 (1) 합치기 전 파일별 행 수 (2) 합친 뒤 전체 행 수 (3) 금액 열의 합계를 알려 줘. 합쳐지지 않은 파일이나 열이 있으면 숨기지 말고 알려 줘.
   </PromptBox>

   <ScreenshotPlaceholder caption="Claude Code가 새 파일을 만들겠다며 승인을 묻는 화면" officialUrl="https://code.claude.com/docs/en/quickstart" />

   승인 화면에서는 세 가지만 보세요. **(1) 만드는 파일 이름이 `합친결과.xlsx`인지, (2) 작업 폴더 안인지, (3) 삭제(`rm`)나 이름 변경(`mv`) 명령이 섞여 있지 않은지**예요. 요청하지 않은 삭제가 보이면 허용하지 말고 이유를 물어보세요.

5. **결과를 직접 열어서 검산하기**

   Claude의 "됐어요"라는 말만 믿지 말고 `합친결과.xlsx`를 **엑셀로 직접 열어요.** 공식 모범 사례도 Claude가 스스로 확인할 방법을 주고, 성공했다는 말 대신 증거를 보여 달라고 하라고 권해요(2026-10-26 확인). 확인할 것은 다음 네 가지예요.

   - 전체 행 수가 Claude가 보고한 숫자와 같은가요? (파일별 행 수를 내가 직접 더해 보세요.)
   - 금액 합계가 맞나요? 엑셀에서 열을 선택하면 화면 아래에 합계가 보여요.
   - 파일 하나가 통째로 빠지지 않았나요?
   - 날짜나 숫자가 글자로 바뀌지 않았나요?

   문제가 있으면 본 대로 말하세요. 예를 들면 이렇게요.

   <PromptBox>
   합친결과.xlsx를 열어 보니 전체 행이 118개인데, 파일별 행 수를 더하면 124개야. 어느 파일에서 6행이 빠졌는지 찾아서 알려 줘. 원인을 설명한 다음에 고쳐 줘.
   </PromptBox>

6. **파일 이름 일괄 정리: 미리보기 먼저**

   파일 이름 변경은 한 번 실행하면 돌아오기 어려운 대표적인 작업이에요. 그래서 **바꾸기 전에 "현재 이름 → 새 이름" 목록만** 받아요.

   <PromptBox>
   이 폴더의 엑셀 파일 이름을 "YYYY-MM-DD_거래처_종류.xlsx" 규칙으로 바꾸고 싶어. 날짜와 거래처는 현재 파일 이름이나 파일 안의 내용에서 찾아 줘. 아직 이름은 바꾸지 말고, "지금 이름 → 새 이름"을 표로 먼저 보여 줘. 이름이 겹치거나, 규칙에 맞는 정보를 찾지 못한 파일은 따로 표시해 줘.
   </PromptBox>

   표를 읽고 틀린 줄은 말로 고치세요. 모두 맞으면 아래 흐름으로 실행해요.

   <FlowSteps title="파일 이름을 안전하게 바꾸는 순서" officialUrl="https://code.claude.com/docs/en/checkpointing" steps={[
     { where: '파일 탐색기·Finder', action: '폴더를 통째로 복사해 백업 만들기', result: '이름 변경이 틀려도 되돌릴 원본 확보' },
     { where: 'Claude Code', action: '"현재 이름 → 새 이름" 표를 받아 읽고 고치기', result: '실행 전에 결과를 눈으로 확인' },
     { where: 'Claude Code', action: '"이 표대로 이름을 바꿔 줘. 삭제는 하지 마"라고 요청', result: '승인 화면이 나옴' },
     { where: '승인 화면', action: 'mv(이름 변경) 명령이 표 내용과 맞는지 읽고 허용', result: '파일 이름이 바뀜' },
     { where: '파일 탐색기·Finder', action: '파일 개수와 이름을 백업 폴더와 비교', result: '빠진 파일이 없는지 확인' },
   ]} />

   <Aside type="caution" title="이름 변경은 /rewind로 안 돌아올 수 있어요">
   공식 체크포인트 문서에 따르면 `mv` 같은 명령으로 바뀐 파일은 되돌리기 대상이 아니에요. 이름을 잘못 바꿨다면 Claude에게 "백업 폴더의 원래 이름으로 되돌려 줘"라고 요청하거나, 백업에서 다시 복사하세요.
   </Aside>

7. **CSV 정리: 새 파일로 받기**

   CSV는 쉼표로 나뉜 단순한 표 파일이라 정리 요청이 비교적 간단해요. 마찬가지로 원본은 두고 정리본을 새 파일로 받아요.

   <PromptBox>
   "거래내역.csv"를 정리해서 "거래내역_정리본.csv"로 저장해 줘. 원본은 수정하지 마. 정리 내용은 (1) 완전히 빈 줄 제거 (2) 모든 열의 앞뒤 공백 제거 (3) 날짜는 YYYY-MM-DD 형식으로 통일 (4) 완전히 같은 줄이 있으면 지우지 말고 몇 개인지만 알려 줘. 끝나면 정리 전후 행 수와 바꾼 내용을 요약해 줘.
   </PromptBox>

   정리본을 엑셀로 열었을 때 한글이 깨지면 파일 저장 방식(인코딩) 문제일 수 있어요. 이 부분의 원인을 공식 문서로 확인하지는 못했어요. 깨진 모습을 그대로 설명하고 "엑셀에서 한글이 깨지지 않게 저장해 줘"라고 요청해 보세요.

8. **전체 폴더에 적용하고 마무리하기**

   연습 폴더에서 결과가 맞는 것을 확인했다면, **실제 자료의 복사본 폴더**에서 같은 요청을 해요. 아직도 원본에는 직접 쓰지 않아요. 끝난 뒤에는 이렇게 점검하세요.

   <PromptBox>
   방금 이 폴더에서 네가 새로 만들거나 바꾸거나 삭제한 파일을 모두 목록으로 알려 줘. 원본이라고 할 수 있는 파일 중에 수정된 게 있는지도 알려 줘. 아직 아무것도 바꾸지 마.
   </PromptBox>

   같은 작업을 다음 달에도 한다면, 지금 쓴 요청 문장을 메모해 두거나 안내 메모(CLAUDE.md)에 "원본은 수정하지 않고 새 파일로 저장한다"를 적어 두세요. CLAUDE.md는 [6편](/coding/06-claude-code-start/)의 7단계와 [C14](/claude/c14-claude-code-features/)에 있어요.

</Steps>

## 안전하게 쓰기

| 습관 | 이유와 방법 |
| --- | --- |
| **작업 전 폴더 복사** | 명령으로 바뀐 파일은 `/rewind`로 안 돌아와요. 복사본이 가장 확실해요. |
| **원본은 읽기만, 결과는 새 파일로** | 프롬프트에 "원본은 수정·삭제하지 마"를 꼭 넣으세요. |
| **적은 수로 시험하고 전체로 확대** | 파일 3~5개로 규칙이 맞는지 본 뒤 전체에 적용해요. |
| **승인 화면에서 `rm`을 찾는다** | 삭제 명령이 요청한 적 없는데 나오면 허용하지 말고 이유를 물어요. |
| **결과를 내 눈으로 검산** | 행 수와 합계를 직접 맞춰 보세요. |
| **민감한 자료는 신중히** | 급여, 주민등록번호, 고객 연락처는 대화와 폴더에 두지 않는 게 기본이에요. 사내 자료를 외부 서비스에 써도 되는지는 회사 정책이 먼저예요. 자세한 기본 원칙은 [개인정보와 안전](/basics/05-privacy-safety/)에서 봐요. |

### 자동 승인 모드는 천천히

승인 질문이 많아 답답할 수 있어요. 공식 권한 모드 문서(2026-10-26 확인)에 따르면 `acceptEdits` 모드는 파일 편집과 `mkdir`, `touch`, `mv`, `cp` 같은 일반 파일 명령을 묻지 않고 실행해요. 편해지지만 **이름 변경이 묻지 않고 바로 실행**된다는 뜻이기도 해요. 같은 문서가 auto 모드도 안전을 보장하지 않고, 방향을 신뢰하는 작업에 쓰라고 안내해요. 백업을 만들고 연습 폴더에서 규칙이 맞는 것을 확인한 다음에만 쓰세요. 모드 종류는 [C14](/claude/c14-claude-code-features/)에 정리돼 있어요.

## 자주 막히는 지점

### 합친 결과의 행 수가 맞지 않아요

- **원인**: 파일마다 맨 위에 제목 줄이 있거나 열 이름이 다르거나, 일부 시트가 빠졌을 수 있어요.
- **해결**: 3단계의 "읽고 보고만" 요청으로 돌아가 파일별 구조를 확인하세요. 그리고 "행 수가 안 맞는 파일을 찾아줘"라고 요청해요. 앞에서 안내한 대로 숫자를 직접 맞춰 보는 습관이 중요해요.

### 승인 질문이 너무 많이 나와요

- **원인**: 기본 모드는 변경마다 승인을 요구해요.
- **해결**: 파일 수를 줄여 한 번에 묶어 요청하거나, 백업 후에 `acceptEdits` 모드를 쓰세요. 단 위 [안전하게 쓰기](#안전하게-쓰기)의 주의를 읽고 쓰세요.

### 엑셀에서 열면 한글이 깨져요

- **원인**: 파일 저장 방식 문제일 수 있지만 공식 문서로 확인하지는 못했어요.
- **해결**: 증상을 설명하고 엑셀에서 열었을 때 깨지지 않게 다시 저장해 달라고 요청해 보세요. 원본은 그대로 있는지 확인하세요.

### 이름을 잘못 바꿨어요

- **원인**: 이름 변경 명령은 `/rewind` 대상이 아니에요.
- **해결**: 백업 폴더에서 원래 이름을 확인하고 "백업 폴더의 이름을 기준으로 되돌려 줘"라고 요청하거나 직접 복사해 오세요.

### 같은 문제를 계속 고쳐도 안 돼요

- **원인**: 대화에 실패한 시도가 쌓였을 수 있어요.
- **해결**: 공식 모범 사례의 권장대로 `/clear`로 새로 시작하고, 지금 상태와 원하는 결과를 더 구체적으로 적어 다시 요청하세요.
