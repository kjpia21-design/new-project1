<Summary>
- 반복 업무를 맡기는 순서는 **① 손으로 한 번 해 보기 → ② 스킬로 형식 고정 → ③ 서브에이전트로 조사·검토 분리 → ④ 루틴으로 자동 실행**이에요.
- **스킬**은 "이런 형식으로 이렇게 해"라는 지침서(`SKILL.md`), **서브에이전트**는 자기 컨텍스트와 도구 권한을 가진 보조 에이전트, **루틴**은 프롬프트·저장소·커넥터를 저장해 클라우드에서 자동 실행하는 기능이에요.
- 루틴은 사람이 보지 않는 동안 자율 실행돼요. **프롬프트는 자기완결적으로, 커넥터와 저장소는 필요한 것만** 두세요.
- 루틴은 현재 리서치 프리뷰예요(2026-10-26 기준). 동작과 한도가 바뀔 수 있어요.
- 공식 문서는 이 기능을 이제 **예약 작업(scheduled tasks, 예전 이름 routines)**이라고 불러요. 이 편은 이어서 "루틴"이라고 쓰지만, 화면과 문서에서는 둘 중 어느 이름이든 보일 수 있어요. 주소(claude.ai/code/routines)와 `/schedule`(별칭 `/routines`)은 그대로예요.
- 이 편의 시나리오(주간 보고서, 문서 점검)는 이 사이트가 만든 **예시**예요. 공식 문서에 같은 이름의 사례가 있는 것은 아니에요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- 반복 업무 중 에이전트에게 맡기기 좋은 것과 아닌 것을 가릴 수 있어요.
- 스킬(`SKILL.md`)을 만들어 보고서 형식 같은 반복 지침을 고정할 수 있어요.
- 서브에이전트를 만들어 초안과 검토를 분리할 수 있어요.
- 스케줄 루틴(예약 작업)을 만들고 시험 실행(Run now)과 실행 기록 확인까지 할 수 있어요.

## 먼저 알아둘 개념

| 도구 | 한 줄 설명 | 비유 |
| --- | --- | --- |
| **스킬(Skill)** | 지침과 예시를 담은 폴더. `SKILL.md`에 쓰고 `/스킬이름`으로 부르거나 설명에 맞으면 Claude가 자동으로 불러와요. 자세한 내용은 [C8](/claude/c08-skills/) | 업무 매뉴얼 |
| **서브에이전트(Subagent)** | 자체 컨텍스트, 시스템 프롬프트, 도구 권한을 가진 보조 에이전트. 긴 출력은 자기 안에 두고 요약만 돌려줘요. 자세한 내용은 [C14](/claude/c14-claude-code-features/) | 전담 담당자 |
| **루틴(Routine)** | 프롬프트 + 저장소 + 커넥터를 저장해 클라우드에서 자동 실행해요. 스케줄·API·GitHub 이벤트 트리거가 있어요. 자세한 내용은 [C13](/claude/c13-cloud-sessions/) | 정기 업무 알람 |

세 도구는 서로 보완해요. 스킬은 **어떻게**, 서브에이전트는 **누가**, 루틴은 **언제**를 맡아요.

### 어떤 업무를 맡기면 좋을까요?

| 맡기기 좋은 업무 | 맡기기 조심할 업무 |
| --- | --- |
| 입력과 결과 형식이 정해져 있어요 | 매번 판단 기준이 바뀌어요 |
| 결과를 사람이 최종 검토할 수 있어요 | 결과가 검토 없이 바로 외부에 나가요 |
| 틀려도 되돌릴 수 있어요 (브랜치, 초안) | 되돌릴 수 없어요 (발송, 결제, 삭제) |
| 자료가 저장소나 커넥터에 있어요 | 자료가 내 머릿속이나 종이에만 있어요 |

<Aside type="caution" title="루틴은 사람이 보지 않는 동안 실행돼요">
루틴은 만들 때 권한 모드를 고르지 않아요. 공식 문서(2026-10-26 기준)에 따르면 Anthropic 클라우드에서 실행되는 세션은 자동(auto) 모드로 시작해서, 분류기가 승인 대기 중인 동작을 허용하거나 막아요(자동 모드를 쓸 수 없으면 시작한 권한 모드를 유지해요). 그래서 셸 명령 실행과 연결된 커넥터의 쓰기가 사람 승인 없이 진행될 수 있어요. 다만 ask 규칙에 걸리는 동작이나 반복 차단이 있으면 실행이 멈추고 답을 기다려요. 그래서 **되돌릴 수 있는 결과물(브랜치와 초안)** 을 만들게 하고, 마지막 발송이나 병합은 사람이 하는 구조로 설계하세요. 루틴이 한 커밋과 PR은 내 GitHub 사용자 이름으로 남아요.
</Aside>

## 단계별 따라하기

이번 시나리오는 **"매주 금요일 오후, 한 주의 메모를 모아 주간 보고서 초안을 만든다"**예요. 연습용 저장소에 `notes/` 폴더를 만들고, 그 주에 한 일을 날짜별 메모로 적어 둔다고 가정해요(실제 업무 기밀은 넣지 마세요).

<Steps>

1. **업무를 정의하기**

   아래 네 가지를 문장으로 적어요. 이 글이 곧 나중에 루틴의 프롬프트가 돼요.

   - **입력**: `notes/` 폴더의 이번 주 메모 (파일 이름이 `2026-10-05.md`처럼 날짜)
   - **출력**: `drafts/weekly-YYYY-MM-DD.md` 한 파일 (금요일 날짜)
   - **형식**: 이번 주 한 일 / 다음 주 계획 / 막힌 점
   - **성공 기준**: 메모에 없는 내용을 지어내지 않고, 모르는 항목은 "확인 필요"로 표시

2. **손으로 한 번 해 보기**

   루틴으로 만들기 전에 Claude Code(6편)에서 직접 한 번 실행해서 결과가 쓸 만한지 보세요. 여기서 마음에 안 드는 점이 곧 스킬에 적을 지침이에요.

   <PromptBox>
   notes 폴더의 이번 주(월~금) 메모를 읽고 주간 보고서 초안을 drafts/weekly-2026-10-09.md로 만들어 줘. 형식은 "이번 주 한 일, 다음 주 계획, 막힌 점" 세 부분이야. 메모에 없는 내용은 지어내지 말고 모르면 "확인 필요"라고 적어 줘. 쓰기 전에 어떤 메모를 읽을지 목록을 먼저 보여 줘.
   </PromptBox>

3. **스킬로 형식 고정하기**

   손으로 해서 나온 규칙을 스킬 파일로 옮겨요. 프로젝트 안에서 팀과 함께 쓰려면 저장소의 `.claude/skills/<이름>/SKILL.md`에 두고, 나 혼자 모든 프로젝트에서 쓰려면 `~/.claude/skills/<이름>/SKILL.md`에 둬요.

   <PromptBox>
   .claude/skills/weekly-report/SKILL.md 파일을 만들어 줘. frontmatter에는 name을 weekly-report로, description을 "notes 폴더의 이번 주 메모를 모아 주간 보고서 초안을 drafts 폴더에 만든다. 사용자가 주간 보고서, 주간 정리를 요청할 때 사용한다."로 넣어 줘. 본문에는 입력(notes 폴더의 날짜별 메모), 출력(drafts/weekly-날짜.md), 형식(이번 주 한 일, 다음 주 계획, 막힌 점), 규칙(메모에 없는 내용을 지어내지 않는다, 모르면 "확인 필요"로 표시한다, 한 문장은 짧게 쓴다)을 정리해 줘.
   </PromptBox>

   만들어진 파일은 이런 모양이에요.

   ```md title=".claude/skills/weekly-report/SKILL.md"
   ---
   name: weekly-report
   description: notes 폴더의 이번 주 메모를 모아 주간 보고서 초안을 drafts 폴더에 만든다. 사용자가 주간 보고서, 주간 정리를 요청할 때 사용한다.
   ---

   # 주간 보고서 초안 만들기

   1. notes 폴더에서 이번 주(월~금) 날짜의 메모를 모두 읽는다.
   2. drafts/weekly-YYYY-MM-DD.md (금요일 날짜)에 아래 형식으로 쓴다.
      - 이번 주 한 일
      - 다음 주 계획
      - 막힌 점
   3. 규칙
      - 메모에 없는 내용을 지어내지 않는다.
      - 모르는 항목은 "확인 필요"로 표시한다.
      - 문장은 짧게 쓴다.
   ```

   세션 안에서 `/weekly-report`로 직접 부르거나, 보고서를 요청하면 설명(description)에 맞춰 Claude가 자동으로 불러와요. 파일 이름 표기는 문서마다 `skill.md`와 `SKILL.md`로 달라요. Claude Code 문서 기준은 `SKILL.md`예요.

   <Aside type="caution" title="남이 만든 스킬은 열어 보고 쓰세요">
   스킬에는 스크립트와 외부 연결이 들어갈 수 있어요. 신뢰할 수 있는 출처의 스킬만 설치하고, 활성화하기 전에 포함된 파일을 읽어 보세요. API 키나 비밀번호는 스킬에 적지 마세요.
   </Aside>

4. **(선택) 서브에이전트로 검토 분리하기**

   초안을 쓰는 에이전트와 검토하는 에이전트를 나누면, 검토가 초안 작성의 긴 맥락에 오염되지 않아요. 서브에이전트는 `.claude/agents/`에 Markdown 파일로 정의하고, 필수 항목은 `name`과 `description`이에요.

   ```md title=".claude/agents/report-reviewer.md"
   ---
   name: report-reviewer
   description: 주간 보고서 초안을 notes 폴더의 원본 메모와 대조해 근거 없는 내용을 찾는다. 초안 작성이 끝난 뒤 검토할 때 사용한다.
   tools: Read, Glob, Grep
   model: sonnet
   ---

   너는 보고서 검토 담당자야. drafts 폴더의 초안을 읽고, 각 문장이 notes 폴더의 메모에 근거하는지 확인해.
   근거가 없는 문장은 목록으로 알려 주고, 파일은 수정하지 마.
   ```

   `tools`로 읽기 도구만 주면 이 에이전트는 파일을 바꿀 수 없어요. `model`에는 `sonnet`, `opus`, `haiku`, `fable`, `inherit` 등을 쓸 수 있어요. 에이전트는 Claude에게 만들어 달라고 해도 돼요. 참고로 `/agents` 명령은 현재 버전에서 안내 문구만 보여 주고, v2.1.197 이하에서는 대화형 마법사가 나왔어요.

   <PromptBox>
   report-reviewer 서브에이전트로 방금 만든 drafts/weekly-2026-10-09.md를 검토해 줘. 메모에 근거가 없는 문장이 있으면 어느 문장인지 알려 줘.
   </PromptBox>

5. **저장소에 올리기**

   루틴은 클라우드에서 저장소를 클론해서 실행해요. 스킬과 서브에이전트 파일이 클라우드 세션에서 보이려면 **저장소에 커밋되어 push되어 있어야 해요.** Claude Code에게 "새로 만든 `.claude` 폴더와 `notes/`를 커밋해서 push해 줘"라고 요청하거나 8편의 방식을 쓰세요. 공식 문서는 루틴이 저장소에 커밋된 스킬을 쓴다고 설명하고, 내 컴퓨터의 개인 스킬 폴더(`~/.claude/skills`)에 있는 스킬은 클라우드 예약 작업에서 "not found"로 나온다고 안내해요(데스크톱 예약 작업은 읽어요). 서브에이전트는 클라우드 세션 문서가 "저장소의 `.claude/agents/`에 정의한 서브에이전트를 자동으로 인식한다"고 안내하고, 루틴은 클라우드 세션으로 실행돼요. 그래도 처음에는 로컬에서 동작을 확인하고, 루틴 실행 기록에서 실제로 쓰였는지 보세요.

6. **스케줄 루틴 만들기**

   [claude.ai/code/routines](https://claude.ai/code/routines)에서 **New task**를 눌러 **New scheduled task** 창을 열어요(계정에 따라 버튼이 **New routine**이고 전체 페이지 양식이 열릴 수 있어요). 터미널이라면 `/schedule`로 대화형으로 만들 수 있어요(예: `/schedule daily PR review at 9am`). 웹 양식의 항목은 이래요.

   - **이름**: 주간 보고서 초안
   - **프롬프트**: 루틴은 자율 실행이라 프롬프트가 **자기완결적이고 성공 기준이 분명**해야 해요.

   <PromptBox label="루틴 프롬프트 예시">
   weekly-report 스킬을 사용해서 notes 폴더의 이번 주(월~금) 메모로 주간 보고서 초안을 drafts/weekly-날짜.md에 만들어 줘. 날짜는 이번 주 금요일이야. 메모에 없는 내용은 지어내지 말고 "확인 필요"로 표시해. 만든 뒤에는 초안의 각 문장이 메모에 근거하는지 한 번 더 확인하고, 근거 없는 문장은 고쳐. 마지막에 PR을 만들 수 있게 변경 내용을 요약해 줘. main 브랜치에는 직접 push하지 마.
   </PromptBox>

   - **저장소**: 연습 저장소 하나. 선택한 저장소는 매 실행마다 기본 브랜치에서 클론돼요. Claude는 `claude/` 접두사의 브랜치에 push해요.
   - **환경**: **Default**(Trusted 네트워크)면 충분해요.
   - **트리거**: Schedule에서 daily나 weekly 같은 프리셋을 고르고 시간은 내 시간대로 입력해요. 프리셋에 없는 주기는 만든 뒤 편집 창에서 **Custom**을 골라 cron 식으로 정해요(cron 식의 시각은 UTC예요). **정각은 몇 분 늦게 시작할 수 있어서** 16:00 대신 16:07처럼 분을 어긋나게 권해요. 최소 간격은 1시간이에요.
   - **커넥터**: 기본으로 연결된 커넥터가 전부 포함돼요. Claude는 포함된 커넥터의 모든 도구를 쓰기까지 쓸 수 있으니 **이 루틴에 필요 없는 것은 모두 빼세요.**

   마지막으로 **Create**를 눌러요.

   <FlowSteps title="루틴 만들고 시험 실행하기" officialUrl="https://code.claude.com/docs/en/routines#create-from-the-web" steps={[

7. **Run now로 시험하고 실행 기록 확인하기**

   루틴 상세 화면에서 **Run now**를 눌러 바로 한 번 실행해 보세요. 실행마다 새 세션이 만들어져서, 열어 보면 Claude가 무엇을 했는지, 변경 내용, PR 생성 여부를 볼 수 있어요.

   <Aside type="caution" title="초록색은 성공이 아니에요">
   실행 목록의 초록색 상태는 "세션이 인프라 오류 없이 시작해서 끝났다"는 뜻일 뿐, 프롬프트의 작업이 성공했다는 뜻이 아니에요. 차단된 네트워크 요청, 빠진 커넥터 도구, 작업 자체의 실패는 세션 기록에 나타나요. 처음 몇 번은 반드시 기록을 열어 결과를 확인하세요.
   </Aside>

   결과가 마음에 들면 만들어진 브랜치의 PR을 읽고 병합하는 것은 사람이 해요. 마음에 안 들면 루틴의 **Edit**에서 프롬프트나 스킬을 고쳐요. 루틴 화면의 켜기/끄기 스위치로 일시 중지할 수도 있어요.

## 자주 막히는 지점

### 루틴은 초록색인데 보고서가 안 만들어졌어요

- **원인**: 초록색은 인프라 오류 없이 끝났다는 뜻이에요. 프롬프트가 모호하거나, 저장소에 파일이 없거나, 네트워크가 막혔을 수 있어요.
- **해결**: 실행(run)을 열어 세션 기록을 읽으세요. 프롬프트에 입력 위치, 출력 위치, 성공 기준을 더 구체적으로 쓰세요.

### 루틴이 스킬을 못 찾아요

- **원인**: 스킬 파일이 저장소에 커밋·push되지 않았거나 다른 저장소에 있을 수 있어요. 루틴은 선택한 저장소를 기본 브랜치에서 클론해요.
- **해결**: 스킬이 기본 브랜치에 병합되어 있는지 확인하세요. 프롬프트에서 스킬 이름을 명시하고, 안 되면 스킬 내용을 프롬프트에 직접 포함시키세요.

### `/schedule`을 입력하니 알 수 없는 명령이라고 나와요

- **원인**: 공식 문서에 따르면 Console API 키나 클라우드 제공자로 로그인한 경우, claude.ai 구독 로그인이 아니면 숨겨져요. 클라우드 세션 안에서는 쓸 수 없고, 조직 정책으로 루틴이나 클라우드 세션이 꺼져 있을 수도 있어요(Team·Enterprise Owner는 조직 설정의 "Scheduled tasks (Was Routines)" 토글로 꺼요).
- **해결**: `/login`으로 claude.ai 구독 계정에 로그인하세요. 그래도 안 되면 웹(claude.ai/code/routines)에서 만들고, 조직 정책이라면 Owner에게 문의하세요.

### 정해진 시간보다 늦게 실행돼요

- **원인**: 정각에 예약하면 몇 분 늦게 시작할 수 있어요.
- **해결**: 9:00 대신 9:07처럼 분을 어긋나게 예약하세요.

### 한동안 실행되지 않다가 꺼졌어요

- **원인**: GitHub 연결이 끊기거나 만료되면 루틴이 실행을 건너뛰어요. 공식 문서에 따르면 최대 72시간까지 건너뛰다가 그 뒤에는 루틴이 꺼져요.
- **해결**: GitHub를 다시 연결하고, 꺼졌다면 루틴을 다시 켜세요.

### 사용량이 빨리 줄어요

- **원인**: 루틴은 대화형 세션과 같은 구독 사용량을 써요.
- **해결**: 실행 빈도를 줄이고(주 1회 등), 프롬프트 범위를 좁히고, 사용량(Settings > Usage)을 확인하세요. 한도 구조는 [C2](/claude/c02-plans-limits/)를 보세요.

## 실전 팁

- **처음엔 손으로, 다음엔 스킬로, 마지막에 루틴으로.** 순서를 거꾸로 하면 무엇이 잘못됐는지 알기 어려워요.
- **결과물은 항상 "초안"과 "브랜치"로.** 사람이 읽고 병합하는 자리를 남겨 두세요.
- **스킬 설명(description)은 구체적으로.** Claude가 이 설명을 보고 언제 쓸지 판단해요. 하나의 스킬은 하나의 워크플로에 집중시키세요.
- **서브에이전트에는 필요한 도구만.** 검토용이면 읽기 도구만 주면 돼요.
- **개인 계정 소유라는 점을 기억하세요.** 루틴은 팀원과 공유되지 않고, 커밋과 PR은 내 이름으로 남아요. 팀 업무는 팀 정책을 먼저 확인하세요.
- **비밀 값은 프롬프트나 스킬에 쓰지 마세요.** 환경 변수는 그 환경을 쓰는 사람이 읽을 수 있어요.
