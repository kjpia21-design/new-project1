<Summary>
- Claude의 **Gmail·Google Calendar 커넥터**를 연결하면 "오늘 일정 + 답장이 필요한 메일"을 한 번에 정리한 **아침 브리핑**을 받을 수 있어요.
- 처음에는 **읽기 전용**으로 직접 실행해 보고, 프롬프트가 마음에 들면 **루틴(Routines)**으로 저장해 평일 아침에 자동으로 돌려요.
- 루틴은 승인 없이 자율 동작하므로 프롬프트에 **"읽기만 하고 보내거나 지우지 마"**를 꼭 적으세요.
- 메일 본문에 숨은 지시(프롬프트 인젝션)에 주의하고, 필요 없는 도구는 끄세요.
</Summary>

## 이 튜토리얼로 할 수 있게 되는 것

- Gmail과 Calendar를 Claude에 연결하고, 오늘 일정과 중요한 메일을 한 화면으로 정리할 수 있어요.
- 내 업무에 맞는 **브리핑 프롬프트**(우선순위 기준, 출력 형식)를 만들 수 있어요.
- 같은 프롬프트를 **루틴**으로 저장해 평일 아침에 자동 실행하는 방법을 알 수 있어요.
- 읽기와 쓰기를 구분해 안전하게 쓰는 규칙을 지킬 수 있어요.

## 먼저 알아둘 개념

| 용어 | 뜻 |
| --- | --- |
| **커넥터(Connector)** | Claude가 내 서비스에 접근해 데이터를 가져오게 하는 연결이에요. Claude는 내 권한을 그대로 상속해요. |
| **Gmail 커넥터** | 메일 검색·읽기, 초안 작성, 전송·답장·전달, 라벨 관리를 해요. 첨부 파일 내용은 볼 수 없어요. |
| **Calendar 커넥터** | 일정 조회·생성·수정·삭제, 공통 가능 시간 찾기 등을 해요. |
| **루틴(Routines)** | 프롬프트와 커넥터 등을 저장해 두고 클라우드에서 자동 실행하는 기능이에요. 2026-10-10 기준 리서치 프리뷰예요. |
| **읽기 / 쓰기 작업** | 읽기는 데이터를 바꾸지 않아요. 쓰기는 보내기·삭제·수정이에요. 브리핑은 읽기만으로 충분해요. |

커넥터 연결 절차 자체는 [C7. 커넥터](/claude/c07-connectors/)에서 자세히 다뤄요. 여기서는 연결이 끝났다고 보고 브리핑 만들기에 집중해요.

```text
[아침 브리핑 흐름]
커넥터 연결 → 읽기 전용으로 직접 실행 → 프롬프트 다듬기 → 루틴으로 저장 → 평일 아침 자동 실행
```

## 단계별 따라하기

<Checklist items={[
  'Gmail과 Calendar 커넥터를 연결했어요',
  '읽기 전용 브리핑 프롬프트를 직접 실행해 봤어요',
  '우선순위 기준과 출력 형식을 내 업무에 맞게 고쳤어요',
  '"보내기·삭제 금지"를 프롬프트에 넣었어요',
  '(선택) 루틴으로 저장하고 평일 아침으로 예약했어요',
  '첫 자동 실행 결과를 확인하고 불필요한 커넥터를 뺐어요',
]} />

<Steps>

1. **Gmail·Calendar 커넥터 연결하기**

   채팅 입력창의 **+** > Connectors에서 Gmail과 Google Calendar를 골라 Google 계정으로 로그인하고 동의해요. Team/Enterprise라면 조직 Owner가 먼저 커넥터를 켜 둬야 해요. 자세한 절차와 문제 해결은 [C7. 커넥터](/claude/c07-connectors/)를 보세요.

   <ScreenshotPlaceholder caption="Connectors에서 Gmail과 Google Calendar를 켠 화면" officialUrl="https://support.claude.com/en/articles/10166901-use-google-workspace-connectors" />

2. **읽기 전용 브리핑 직접 실행하기**

   새 대화에서 두 커넥터를 켜고 아래처럼 요청해요. 처음에는 결과를 눈으로 확인하는 게 목적이에요.

   <PromptBox label="아침 브리핑 기본 프롬프트">
   오늘(한국 시간 기준) 아침 브리핑을 만들어 줘. 읽기만 하고, 메일을 보내거나 일정·메일을 수정·삭제하지 마.

   1) 오늘 일정: 시간순으로 제목, 시간, 참석자, 장소(또는 화상회의 링크)를 표로 정리하고, 일정 사이에 30분 이상 비는 시간도 알려 줘.
   2) 메일: 최근 24시간 동안 받은 메일 중 내가 답장해야 할 것만 골라 줘. 각각 보낸 사람, 한 줄 요약, 왜 답장이 필요한지, 긴급도(높음/보통/낮음)를 써 줘. 광고·뉴스레터는 건수만 말해 줘.
   3) 오늘 꼭 챙길 것 3가지를 마지막에 정리해 줘.
   확실하지 않은 내용은 추측하지 말고 "확인 필요"라고 써 줘.
   </PromptBox>

3. **프롬프트를 내 업무에 맞게 다듬기**

   결과를 보고 고칠 곳을 정해요. 아래 항목을 바꿔 가며 몇 번 돌려 보세요.

   - **긴급도 기준**: "대표님·고객사 메일은 무조건 높음"처럼 이름이나 조건을 적어요.
   - **범위**: "라벨이 '프로젝트A'인 메일만" 같이 좁히면 정확해져요.
   - **분량**: "전체 20줄 이내"처럼 길이를 정해요.
   - **기억할 점**: 첨부 파일 내용은 Gmail 커넥터가 읽지 못해요. 첨부 안에 중요한 내용이 있으면 따로 확인해야 해요.

4. **답장은 초안까지만 시키기 (선택)**

   브리핑 뒤에 답장이 필요한 메일의 초안을 만들게 할 수도 있어요. 보내기는 하지 마세요. 초안으로 남기면 내가 읽고 직접 보낼 수 있어요.

   <PromptBox>
   방금 정리한 "긴급도 높음" 메일 2건에 대해 정중한 답장 초안을 Gmail 초안으로 만들어 줘. 절대 보내지는 마. 내가 직접 읽고 보낼게.
   </PromptBox>

   <Aside type="caution" title="쓰기 작업은 승인 창에서 한 번 더 확인하세요">
   Claude는 메일 전송·답장·전달 전에 기본적으로 승인을 물어요(조직 Owner가 이 설정을 바꿀 수 있어요). 받는 사람과 내용을 읽고 승인하세요. 습관적으로 누르지 마세요.
   </Aside>

5. **루틴으로 저장해 평일 아침 자동 실행하기 (선택)**

   프롬프트가 안정되면 루틴으로 저장해요. 루틴은 claude.ai/code/routines, 데스크톱 앱, 또는 터미널의 `/schedule`로 만들 수 있어요. 웹에서는 새 루틴(New routine)에서 이름, 프롬프트, 트리거(스케줄)를 정해요. 스케줄은 매시간·매일·평일·주간 중에서 고르거나 특정 시각에 1회만 실행하도록 정할 수 있고, 화면의 정확한 입력 항목은 **화면 안내에 따르세요.** 공식 문서 기준으로 루틴은 프롬프트에 저장소(repository)와 환경도 함께 고르게 되어 있어요. 메일 브리핑에는 저장소가 필요 없지만 선택 항목이 나오면 화면 안내를 따르세요. 루틴 자체에 대한 설명은 [C13. 클라우드 세션](/claude/c13-cloud-sessions/)에 있어요.

   루틴에 쓸 때 지킬 점이에요.

   - 프롬프트 맨 앞에 "읽기만 하고 보내기·삭제·수정 금지"를 넣어요. 루틴은 **실행 중 승인을 묻지 않고 자율적으로 동작**해요.
   - 정각(예: 8:00)에 맞추면 몇 분 늦게 실행될 수 있어요. 공식 문서는 분을 어긋나게 잡으라고 권해요(예: 8:07). 스케줄 최소 간격은 1시간이에요.
   - 루틴에는 연결한 커넥터가 기본으로 포함돼요. 브리핑에 필요한 Gmail·Calendar만 남기고 나머지는 제거하세요.
   - `claude mcp add`로 내 컴퓨터에만 추가한 서버는 루틴에서 못 써요. claude.ai에 커넥터로 추가해야 해요.
   - 루틴은 구독 사용량을 써요. 한도가 모자라면 추가 사용량(usage credits) 설정에 따라 동작이 달라져요. 사용량은 [C2. 요금제와 사용량 한도](/claude/c02-plans-limits/)를 보세요.

   ```text
   /schedule 평일 아침 브리핑: 오늘 일정과 답장이 필요한 메일을 읽기만 해서 정리해 줘
   ```

   <ScreenshotPlaceholder caption="루틴 만들기 화면에서 이름, 프롬프트, 스케줄을 정하는 모습" officialUrl="https://code.claude.com/docs/en/routines" />

   <FlowSteps title="아침 브리핑을 루틴으로 저장하기" officialUrl="https://code.claude.com/docs/en/routines" steps={[
     { where: '채팅 입력창', action: '+ > Connectors에서 Gmail, Google Calendar 고르기', result: 'Google 계정 로그인하고 동의' },

     { where: 'claude.ai/code/routines', action: '새 루틴(New routine)에서 이름, 프롬프트, 트리거(스케줄) 정하기', result: '평일 아침 자동 실행' },
   ]} />

6. **첫 자동 실행 확인하고 다듬기**

   예약한 시간이 지나면 루틴 상세 페이지의 지난 실행 목록에서 확인해요. 실행마다 새 세션이 만들어지고, 열어 보면 Claude가 한 일의 기록을 볼 수 있어요. 목록의 초록색 상태는 실행이 오류 없이 끝났다는 뜻일 뿐 작업이 성공했다는 뜻은 아니니, 꼭 열어서 내용을 확인하세요. 틀린 요약이나 빠진 일정이 있으면 프롬프트를 고쳐서 루틴을 업데이트하세요.

</Steps>

## 빠른 참조표

### 브리핑 프롬프트 구성 요소

| 요소 | 예시 | 이유 |
| --- | --- | --- |
| 안전 규칙 | "읽기만 하고 보내기·삭제 금지" | 루틴은 승인 없이 동작 |
| 기준 시각 | "한국 시간 기준 오늘" | 날짜 혼동 방지 |
| 일정 형식 | 시간순 표 + 비는 시간 | 하루 계획에 바로 사용 |
| 메일 범위 | 최근 24시간, 라벨 지정 | 양과 정확도 조절 |
| 우선순위 기준 | 사람·키워드·마감 | 판단 기준을 명시 |
| 불확실성 | "모르면 확인 필요" | 추측 방지 |

### 읽기 vs 쓰기

| 작업 | 종류 | 권장 |
| --- | --- | --- |
| 메일·일정 보기와 요약 | 읽기 | 브리핑의 기본 |
| 메일 초안 만들기 | 쓰기(저장만) | 가능, 직접 확인 후 발송 |
| 메일 전송·전달, 일정 삭제 | 쓰기 | 루틴에서는 금지 |

## 자주 막히는 지점

### 커넥터가 목록에 없거나 동작하지 않아요

- **원인**: 조직에서 커넥터를 안 켰거나 인증이 꼬였을 수 있어요.
- **해결**: [C7. 커넥터](/claude/c07-connectors/)의 막히는 지점을 보세요. 연결을 해제하고 다시 연결하는 게 가장 간단해요.

### 중요한 메일이 빠졌어요

- **원인**: 검색 범위나 기준이 좁거나, 중요한 내용이 첨부 파일 안에 있을 수 있어요(첨부 내용은 읽지 못해요).
- **해결**: 범위를 넓히고 기준을 구체적으로 적으세요. 첨부가 중요한 메일은 직접 확인하세요.

### 예약한 시간에 결과가 안 왔어요

- **원인**: 정각 실행은 몇 분 늦을 수 있어요. 한도 초과나 커넥터 인증 만료도 가능해요.
- **해결**: 분을 어긋나게(예: 8:07) 잡고 실행 기록을 확인하세요. 인증이 만료됐으면 커넥터를 재연결하세요.

### 메일 내용이 이상한 지시를 해요

- **원인**: 외부에서 온 메일에 AI를 속이는 문구가 숨어 있을 수 있어요(프롬프트 인젝션).
- **해결**: 브리핑 루틴에서는 쓰기 도구를 쓰지 않도록 프롬프트에 못 박고, 이상한 요약은 원문을 열어 확인하세요.

### 개인 계정과 회사 계정이 섞였어요

- **원인**: 커넥터는 로그인한 Google 계정 하나에 연결돼요.
- **해결**: 어떤 계정을 연결했는지 확인하고, 회사 메일을 연결하기 전에 사내 규정을 확인하세요.

## 실전 팁

- **먼저 수동으로 일주일 써 보세요.** 프롬프트가 안정된 뒤에 루틴으로 옮기세요.
- **브리핑은 짧을수록 읽혀요.** 분량을 제한하고, 긴급도 높음부터 보여 달라고 하세요.
- **필요한 커넥터만 남기세요.** 루틴에는 기본으로 모든 커넥터가 들어가요.
- **일정 조율은 읽기부터.** "이번 주 30분 이상 비는 시간"은 안전한 활용 예예요.
- Claude 외에도 Gemini를 쓴다면 Gmail 안에서 바로 요약하는 방법을 [19. Google Workspace의 Gemini](/automation/19-google-workspace-gemini/)에서 볼 수 있어요.
