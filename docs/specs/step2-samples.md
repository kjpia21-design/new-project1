# 작업 명세 — 2단계: 튜토리얼 템플릿 확정 + 샘플 2편

작성: 기획 담당 · 구현: 코딩 에이전트

먼저 읽을 것: `docs/PLAN.md`, `docs/specs/step1-skeleton.md`, `README.md`, 그리고 근거 자료 `docs/research/claude/C02-plans-usage.md`, `docs/research/claude/C13-claude-code-cloud.md`.

## 목표

1. 튜토리얼 한 편의 **표준 구조**를 확정하고 재사용 가능한 템플릿으로 만든다.
2. 그 템플릿으로 샘플 2편을 실제로 완성한다.
   - `src/content/docs/claude/c02-*.mdx` — **C2. 요금제와 사용량 한도** (수준: 입문)
   - `src/content/docs/claude/c13-*.mdx` — **C13. Claude Code 클라우드 세션: GitHub 연동, 환경, 루틴** (수준: 실무)

이 사이트 운영자는 이 두 편을 **직접 참고서로 쓴다.** 상세하고 정확해야 하며, 나중에 다시 찾아보기 쉬워야 한다.

## 사실 정확성 규칙 (가장 중요)

- 본문의 모든 사실은 위 연구 파일에 있는 내용만 쓴다. 각 사실에는 연구 파일에 적힌 출처가 있다.
- 연구 파일에 없는 내용이 꼭 필요하면, 공식 페이지(code.claude.com, support.claude.com, claude.com, platform.claude.com)를 WebFetch로 직접 읽고 확인한 경우에만 쓰고, 그 URL을 frontmatter `sources`에 추가한다. 기억으로 채우지 말 것.
- 연구 파일의 "확인 못 함 / 주의" 항목은 본문에서 단정하지 말 것. 특히:
  - **Fable 한도**: 공식 문서 두 곳의 설명이 다르다. 두 설명을 모두 소개하고 "Settings > Usage 화면에서 실제 표시를 확인하세요"로 안내.
  - **절대 수치(메시지 몇 개 등)**: 공식적으로 공개되지 않았다고 명시.
  - **클라우드 세션 크레딧**: 공식 문서는 "클라우드 세션은 별도 VM 요금 없이 플랜 사용량에 합산"이라고 설명한다. 다만 일부 계정의 Settings > Usage 화면에는 "클라우드 세션 크레딧" 항목이 표시되며, 화면 설명은 "클라우드 세션에 자동으로 적용되고, 모두 쓰거나 만료되면 플랜의 일반 사용량이 적용된다"이다. 이를 "계정에 따라 보일 수 있는 항목"으로 소개하고, 공식 문서에는 아직 설명이 없다는 점(2026-10-10 기준)을 밝힌다. 금액·만료일 같은 특정 계정 정보는 쓰지 말 것.
  - 가격은 미국 기준이며 지역에 따라 다를 수 있다고 표기.
- 가격·한도처럼 자주 바뀌는 정보 옆에는 "2026-10-10 기준"을 붙인다.

## 표준 튜토리얼 구조

frontmatter: 1단계 스키마 그대로. 샘플 2편은 `status: published`, `lastVerified: 2026-10-10`, `sources`는 본문에 쓴 출처 전부. `duration`, `prerequisites`, `tools`는 실제 내용에 맞게 다시 쓴다.

본문 순서:
1. **한눈에 요약** — 3~5줄 핵심 요약 상자 (새 컴포넌트 `Summary.astro`, 친근한 카드). 참고서로 다시 볼 때 이것만 봐도 되게.
2. **이 튜토리얼로 할 수 있게 되는 것** — 결과 중심 bullet 3~4개.
3. **먼저 알아둘 개념** — 용어 설명. 필요하면 간단한 인라인 SVG 도식 1개 (C2: 세션 한도 → 주간 한도 → 추가 사용량(usage credits) 흐름. C13: 내 브라우저/앱 ↔ 클라우드 VM ↔ GitHub 관계). 다크 모드에서도 읽히게 `currentColor`·CSS 변수 사용.
4. **단계별 따라하기** — Starlight `<Steps>`. 각 단계 아래 필요하면 `<PromptBox>`(Claude에게 그대로 붙여넣을 요청 문구), `<ScreenshotPlaceholder caption="…">`(실제 화면 캡처 들어갈 자리). 페이지 끝이 아니라 따라하기 섹션 시작 직전에 `<Checklist>`로 전체 단계 체크리스트.
5. **빠른 참조표** — 다시 찾아볼 정보를 표로 (C2: 플랜별 가격·포함 기능·Claude Code 여부·클라우드 세션 여부. C13: 시작 방법별 명령/위치, 네트워크 접근 수준 4가지, 자주 쓰는 명령어, 리소스 상한).
6. **자주 막히는 지점** — 문제 → 원인 → 해결, 3~6개. Starlight `<Aside>` 또는 소제목 형식.
7. **실전 팁** — 사용량 아끼기 등. C13에는 "이 사이트도 클라우드 세션에서 기획은 Opus, 구현은 Sonnet 하위 에이전트로 만들었다"는 짧은 사례 박스 (C15로 링크).
8. **다음에 볼 튜토리얼** — 관련 튜토리얼 링크 2~3개 (C1, C12, C14, C15 등, base 경로 주의).
9. **출처** — frontmatter `sources`를 자동으로 렌더링하는 `Sources.astro` 컴포넌트를 만들고, 모든 튜토리얼 페이지 하단에 자동으로 붙게 한다 (PageTitle 오버라이드처럼 Starlight 오버라이드 활용, 또는 MDX 레이아웃). "마지막 확인일"과 함께.

## 템플릿 파일

- `docs/templates/tutorial-template.mdx` — 위 구조를 주석과 함께 담은 빈 템플릿. 새 튜토리얼 작성 시 복사해서 쓰도록.
- `README.md`의 "새 튜토리얼 추가 방법"을 이 템플릿 기준으로 갱신.

## 문체

- 한국어 존댓말, 친근하고 짧은 문장 ("~해요", "~하세요").
- 메뉴·버튼 이름은 화면 표기대로 영어 병기: 예) 설정(Settings) > 사용량(Usage).
- 명령어는 코드 서식.

## 완료 기준

1. `npm run build` 성공, 링크 검사 통과.
2. 두 페이지가 홈 "최근 업데이트"와 `/tutorials/`에 "준비 중"이 아닌 상태로 나온다.
3. 스크린샷을 `docs/screenshots/step2/`에 저장 (`scripts/screenshot.mjs`를 확장하거나 인자로 받게 수정): 두 페이지 각각 데스크톱·모바일, 라이트·다크, 전체 페이지. 홈 데스크톱 1장. 직접 열어 보고 넘침·대비·깨진 도식을 고친다. 참고: 이 컨테이너에서는 jsDelivr 글꼴이 차단돼 기본 글꼴로 보이는 것은 정상.
4. git 커밋은 하되 푸시하지 말 것. `docs/PLAN.md`, `docs/research/`는 수정 금지. 커밋 메시지 영어, 끝에:
   ```
   Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>
   Claude-Session: https://claude.ai/code/session_018cdTexUA7yq5gcfmybuxoc
   ```
5. 보고: 만든 것, 명세와 다르게 한 점, 연구 파일 외에 새로 추가한 출처(있다면 URL과 확인한 내용), 스크린샷 경로, 커밋 목록.
