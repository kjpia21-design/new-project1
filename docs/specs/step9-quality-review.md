# 작업 명세 — 9단계: 사이트 전체 품질 검수

작성: 기획 담당 · 검수: 코딩 에이전트 4명

## 목표

여러 에이전트가 나눠 쓴 튜토리얼 51편과 보조 페이지가 **하나의 사이트처럼 일관되게** 읽히도록 검수하고, 작은 문제는 직접 고친다.

## 점검 항목

1. **사실 일관성 (편끼리 숫자와 이름이 같은가)**
   - 기준값은 `docs/research/claude/C01-models.md`, `C02-plans-usage.md`, 그리고 `claude/c01`, `c02`, `c16` 본문이다.
   - 모델 이름과 ID, API 가격, 요금제 이름과 가격, Fable 정책, 날짜("2026-10-10 기준" 등)가 기준과 다르면 기준에 맞춘다.
   - 기준 자체가 의심스러우면 고치지 말고 보고한다.
   - 다른 회사 도구(ChatGPT, Gemini, Canva 등)의 수치가 편마다 다르면, 조사 노트의 근거를 따라 맞춘다.
2. **용어 통일**
   - 같은 개념은 사이트 전체에서 같은 말로 쓴다.
   - 예: 추가 사용량(usage credits), 커넥터, 스킬, 아티팩트, 클라우드 세션, 루틴, 에이전트, effort.
   - 처음 나올 때만 영어를 병기한다.
3. **링크**
   - 다른 편을 가리키는 링크의 대상이 실제로 그 내용을 다루는지 확인한다. 링크 문구와 대상 제목이 맞는지도 본다.
   - "다음에 볼 튜토리얼"에 새로 생긴 섹션(agents, dev, claude-news) 중 관련 있는 편이 빠졌으면 추가한다.
4. **구조와 형식**
   - 9개 섹션 구조(요약 → … → 출처)를 따르는지 본다.
   - frontmatter가 실제 내용과 맞는지 본다: level, duration, prerequisites, tools.
   - "확인 중" Aside 문구가 실제 남은 미확인 항목과 맞는지 본다.
5. **문체**
   - 존댓말 "~해요"체로 통일한다. 딱딱한 "~한다"체나 번역투가 있으면 고친다.
   - 같은 내용이 한 편 안에서 반복되면 정리한다.
6. **화면**
   - `npm run build` 뒤 Playwright로 담당 페이지를 375px에서 열어 본다.
   - 확인할 것: 가로 넘침, 표 깨짐, 코드 블록 넘침, 빈 섹션.
   - Chromium은 미리 설치되어 있다(`scripts/screenshot.mjs` 참고). 미리보기 서버는 다른 에이전트와 겹치지 않게 아래 포트를 쓰고, 끝나면 `npx astro preview stop`으로 끈다.
     - R1: 4501
     - R2: 4502
     - R3: 4503
     - R4: 4504
   - 빌드는 `--outDir`을 담당별로 따로 지정해 다른 에이전트의 빌드와 충돌하지 않게 한다. 예: `npx astro build --outDir /tmp/claude-0/-home-user-new-project1/899c231a-447f-5eba-b940-f751b36c7171/scratchpad/dist-R1`. 미리보기도 그 폴더로 띄운다.

## 원칙

- **작은 문제는 직접 고친다**: 숫자 불일치, 용어, 링크, 문체, 오타, 형식.
- **큰 문제는 고치지 말고 보고한다**: 사실 판단이 필요한 것, 구조를 크게 바꿔야 하는 것.
- 새 사실을 추가하지 않는다. 기존 조사 노트와 기준 편의 범위 안에서만 맞춘다.
- 담당 범위 밖 파일은 수정하지 않는다. 범위 밖에서 발견한 문제는 보고만 한다.
- 수정한 편은 `lastVerified`를 바꾸지 않는다. 공식 출처를 다시 확인한 것이 아니기 때문이다.
- git 커밋·푸시는 하지 않는다.
