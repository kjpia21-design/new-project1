# 작업 명세 — 6단계: 남은 빈칸 채우기와 재점검

작성: 기획 담당 · 구현: 코딩 에이전트 4명

## 배경

5단계 이후에도 남은 빈칸은 두 종류다.

1. **미확인 사실**: "원문 미확인", "확인하지 못", "공식 페이지에서 확인하세요" 같은 표시가 붙은 부분이다. 대부분 OpenAI(ChatGPT), Canva, Make 관련이다. 이 회사들의 메인 사이트는 자동 접근을 403으로 막는다.
2. **스크린샷 자리**: `<ScreenshotPlaceholder>` 약 70개가 사이트에서 빈 상자로 보인다.

## 새로 쓸 수 있는 공식 출처 (2026-10-10 확인, 200 응답)

| 회사 | 열리는 공식 출처 | 막힌 곳 (403) |
| --- | --- | --- |
| OpenAI | developers.openai.com | help.openai.com, openai.com, chatgpt.com, platform.openai.com |
| Canva | www.canva.dev | canva.com 전체 |
| Make | help.make.com, developers.make.com, apps.make.com | www.make.com (가격 페이지 포함) |
| 공통 | 앱 스토어의 **개발사 공식 등록 페이지**: apps.apple.com, play.google.com. 개발사가 직접 쓴 설명과 인앱 구매 가격 표시가 있다. | — |

출처 사용 규칙:
- 앱 스토어 정보는 개발사가 직접 등록한 공식 정보로 인정한다.
  - 본문에는 "App Store 표시 기준(미국 스토어, 2026-10-10)"처럼 출처의 성격을 밝힌다.
  - 인앱 구매 가격은 요금제 이름과 정확히 대응될 때만 쓴다. 이름이 애매하면 쓰지 않는다.
- 한국 스토어 페이지(`/kr/`)가 열리면 한국 가격도 함께 확인한다.
- 페이지는 한 번에 하나씩 읽는다. WebFetch가 호스트를 찾지 못하면 `curl -sL -m 20 -A "Mozilla/5.0" <url>` 한 번으로 읽고, 짧은 python으로 태그를 제거해 필요한 부분만 본다.
  - 여러 페이지를 한꺼번에 받는 스크립트는 금지한다.
  - curl이 권한 시스템에서 거부되면 우회하지 말고 멈춘 뒤 보고한다.
- 그래도 확인하지 못한 항목은 지금처럼 단정하지 않는 표현을 유지한다. 지어내지 않는다.

## 스크린샷 자리 개선 (W4)

**목표**: 빈 상자를 "화면 안내 카드"로 바꾼다. 실제 화면을 흉내 낸 가짜 UI는 만들지 않는다.

- `caption` prop은 지금처럼 받는다. 기존 사용처 70여 곳을 수정하지 않아도 되게 한다.
- 카드 구성:
  - 작은 아이콘
  - 제목 "이 단계에서 보게 될 화면"
  - caption 본문
  - 작은 안내 "실제 화면은 서비스 업데이트에 따라 다를 수 있어요"
- 점선 빈 상자 느낌을 없앤다. 대신 본문과 어울리는 옅은 배경과 왼쪽 강조선을 쓴다(Aside와 비슷하지만 구분되게). 높이는 내용에 맞게 줄인다.
- 선택 사항으로 `src` prop을 받는다. 나중에 실제 캡처 이미지 경로를 넣으면 이미지와 caption을 함께 보여준다. 지금은 아무 페이지도 쓰지 않는다.
- 라이트·다크, 375px에서 확인한다. 스크린샷 1~2장을 `docs/screenshots/step6/`에 저장한다.
