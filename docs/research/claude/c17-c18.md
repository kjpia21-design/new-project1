## C18 (자동 실행) 확인한 사실

### 루틴 — https://code.claude.com/docs/en/routines
- 리서치 프리뷰. Pro/Max/Team/Enterprise. 트리거: 스케줄(매시간·매일·평일·주간 또는 1회성), API(HTTP POST + 베어러 토큰), GitHub(pull request, release).
- 생성: claude.ai/code/routines, 데스크톱 앱(Routines > New routine > Cloud; Local은 데스크톱 예약 작업), CLI `/schedule`(별칭 `/routines`). 세 곳은 같은 계정에 저장.
- 권한 모드 선택 없이 자율 실행, 커넥터는 기본 전부 포함, `claude/` 접두사 브랜치, 커밋·PR은 내 GitHub 사용자.
- 정각 대신 9:07처럼. 최소 간격 1시간. 커스텀 cron은 `/schedule update`. 1회성은 실행 후 자동 비활성(Ran).
- 한도: 스케줄 실행(1회성 포함) 계정당 시간당 100, Run now·API·1회성 재실행 루틴당 시간당 30, Run now 계정당 100, API 계정당 100(별도). 모두 overage 없음. 사용량은 구독 사용량, usage credits 켜져 있으면 초과분 종량제.
- GitHub 연결이 끊기면 최대 72시간 건너뛰고 이후 꺼짐. 구독 일시중지 중에는 보류.
- 초록 상태는 인프라 오류 없이 종료라는 뜻이지 작업 성공이 아님.
- `/schedule list|update|run`, 실행 기록 질문은 v2.1.227 이상. GitHub 트리거 CLI 추가는 v2.1.225 이상.
- `/schedule` Unknown command 원인: Console API 키·클라우드 제공자 인증. 조직 Owner가 Routines 토글로 끌 수 있음.
- 아티팩트 재발행 규칙은 C13에 이미 있어 C18에서는 다루지 않음.

### 세션 예약 / `/loop` — https://code.claude.com/docs/en/scheduled-tasks
- 비교표(Cloud/Desktop//loop): 최소 간격 1시간/1분/1분, 컴퓨터·세션 요건.
- `/loop 5m ...`, 간격 생략 시 Claude가 1분~1시간에서 선택, 인자 없으면 내장 유지 프롬프트 또는 loop.md.
- 반복 작업 7일 만료(마지막 1회 실행 후 삭제), 세션당 최대 50개, 세션이 열려 있고 대기 상태일 때만 실행, 놓친 실행은 한 번만. 자연어 1회성 알림 지원. 지터 규칙.

### 데스크톱 예약 작업 — https://code.claude.com/docs/en/desktop-scheduled-tasks
- Routines > New routine > Local, 폴더 필수, worktree 옵션, 프리셋(Manual/Hourly/Daily/Weekdays/Weekly), 앱이 열리고 깨어 있을 때만 실행, 최근 7일 내 놓친 실행은 한 번만 따라잡기, 권한 모드는 작업별, Run now로 always allow 설정 권장.

### Claude 앱 예약 작업 — https://support.claude.com/en/articles/13854387-schedule-recurring-tasks-in-claude-cowork
- 모든 유료 플랜. 새 Claude 경험(Pro/Max 순차 적용)에서는 대화에서 설명 후 Schedule 클릭. Cowork는 사이드바 Scheduled > New task > Create with Claude / Set up manually(이름, 프롬프트, 승인 방식, 주기 hourly/daily/weekly/weekdays/manually, 모델, 폴더).
- 원격 실행이라 컴퓨터가 잠자도 돈다고 안내. 단 로컬 파일·앱이 필요하면 로컬에서만 실행. 커넥터·스킬·플러그인 사용 가능. 일시정지/재개/삭제/즉시 실행.

- 크레딧 금액·계정 정보는 쓰지 않음. 사이트 루틴 사례는 일반화한 패턴만 서술.
